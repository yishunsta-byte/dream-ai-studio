# Dream Screen 사용자용 API 연동 안내

2026년 11월 20일 기준. 화면에서 프로젝트를 조회하고 완성본을 게시하거나 참고 자료를 분석할 때, 연결 상태에 따라 사용할 수 있는 기능을 안내한다. 아래 주소는 운영 사이트 기준이다. 키나 토큰을 입력할 필요 없이 화면에서 로그인한 계정으로 시작한다.

## 운영 관리자에서 메뉴를 이용하려면

2026년 11월 20일 운영 버전 `ba983c7` 기준이다. 관리자 계정으로 로그인한 뒤 상단의 메뉴 일곱 개를 이용한다. 메뉴에 들어가면 선택한 항목이 강조 표시된다. [운영 관리자 열기](https://dream-ai-studio-orpin.vercel.app/admin) · [운영 배포 확인](https://vercel.com/yishunsta-6158/dream-ai-studio/38U7w7kVU7DMSHYh72MYdMcXf4oW)

| 렌더 대기열 | **렌더 작업 대기열**을 열고 **렌더 대기열 다시 조회**를 누를 수 있다. 현재 운영에서는 목록 조회가 연결 오류로 돌아오며 렌더 작업 취소·재시도 제어는 미연결이다. |
| 계정 설정 | 로그인 계정을 확인하고 **비밀번호 바꾸기**로 이동할 수 있다. 화면 상단에서 로그아웃할 수 있다. |

### 내 프로젝트를 확인하려면

1. 관리자 계정으로 로그인하고 ‘내 프로젝트’를 선택한다. 이 목록은 현재 계정이 소유한 클라우드 프로젝트를 표시한다. [관리자 화면](https://dream-ai-studio-orpin.vercel.app/admin)
2. 조회 시각과 목록이 보이면 제목을 눌러 상세를 연다. ‘내 프로젝트가 0개예요’와 조회 시각이 함께 보이면 조회가 정상 완료된 것이다.
3. ‘미연결’이면 운영 담당자에게 **프로젝트 읽기 연결 확인**을 요청한다. ‘불러오지 못했어요’이면 잠시 뒤 ‘다시 불러오기’를 한 번 누른다. 문제가 계속되면 화면 이름, 문구, 발생 시각을 전달한다.

운영 점검에서 관리자 로그인과 메뉴 이동은 가능했고 프로젝트 목록은 ‘미연결’이었다. Supabase Data API는 응답했지만 앱에서 요청한 읽기 스키마를 노출하지 않아 406을 반환했다. 운영 담당자는 기존 프로젝트에서 읽기 뷰 설치, 계정별 권한, 노출 스키마를 확인한다. [T362 운영 읽기 실측](../handoffs/T362-DATA-API-LIVE-READ.md)

### 렌더 대기열을 다시 확인하려면

**렌더 대기열**에서 **렌더 대기열 다시 조회**를 누른다. ‘렌더 대기열에 연결할 수 없어요’가 계속 표시되면 운영 담당자에게 메뉴 이름, 화면 문구, 발생 시각을 알려 준다. 503은 현재 조회할 수 없다는 응답이다. 구체적인 원인은 운영 담당자가 확인한다. 여기서 다시 조회하는 동작은 목록을 다시 읽는다. [운영 미연결 안내 검토](admin-topnav-options/LIVE-CONNECTION-REVIEW.md)

### 비공개 PNG로 쇼핑숏츠 프로젝트를 만들려면

**파일 선택란이 보이지 않을 때** — 로그인 화면으로 이동하면 로그인한 뒤 ‘새 프로젝트’로 돌아간다. ‘아직 클라우드에서는 새 프로젝트를 만들 수 없어요’가 보이면 해당 환경에서는 업로드를 제공하지 않는다. 이미 옮긴 프로젝트를 보려면 안내 안의 ‘내 프로젝트’를 선택한다. 현재 구현은 로그인된 로컬 시험 환경에서 비공개 업로드와 프로젝트 저장이 모두 연결됐을 때 파일 선택란을 표시한다. 운영·Vercel 환경에서는 준비 안내를 표시하도록 설정돼 있다. [화면 표시 조건 시험](../../tests/t207-cloud-read-ui.test.ts)

파일 선택란이 있는 ‘새 프로젝트’ 화면에서 **1 MiB(1,048,576바이트) 이하 PNG 한 장**을 선택하고 제작 정보를 입력한다. ‘저장하고 시작’을 한 번 누른다. 앱이 사진을 올린 뒤 프로젝트를 저장한다. ‘프로젝트를 저장했어요’가 보이면 ‘저장한 프로젝트 열기’를 선택한다.

‘사진 출처·권리 메모’는 선택 사항이다. 직접 촬영한 사진이라면 ‘직접 촬영한 제품 사진’처럼 출처나 사용 허락 내용을 500자 이내로 적을 수 있다. 업로드 응답이 끊겨 **동일한 요청을 다시 시도하려면 파일과 메모를 그대로 둔다**. 메모 앞뒤 공백은 무시한다. 메모 내용을 고치거나 지우면 같은 사진도 새 업로드 요청으로 처리한다. 메모는 사진과 함께 보관되며 공개 게시에는 별도의 권리 확인이 필요하다.

| 화면에서 본 상황 | 다음 행동 |
|---|---|
| ‘1 MiB 이하의 PNG 사진 한 장을 선택해 주세요’ | 사진 형식과 크기를 확인하고 조건에 맞는 PNG를 선택한다. |
| ‘사진을 올리지 못했어요’ 또는 연결 오류 | 연결을 확인하고 **같은 화면에서 파일 선택을 그대로 둔 채** ‘저장하고 시작’을 다시 누른다. 파일을 다시 고르면 이름이 같아도 별도 업로드가 될 수 있다. |
| 사진을 올린 뒤 프로젝트 저장 응답이 끊김 | 입력과 사진을 그대로 두고 다시 제출한다. 앱이 사진 업로드 성공 응답을 이미 받았다면 기존 사진을 사용해 프로젝트 저장만 다시 요청한다. |
| 다른 제품 사진으로 교체하려고 함 | 파일 선택란에서 새 사진을 선택하고 제작 정보를 확인한다. 이전 사진과 파일명이 같아도 새로 선택한 사진이 사용된다. |

이 절차의 업로드·저장과 재시도는 로컬 HTTP 및 클라이언트 함수 시험에서 확인했다. 실제 운영 브라우저의 파일 선택부터 저장 완료까지는 검증 대기 중이다. [업로드·저장 독립 검수](../handoffs/FIRST-WORK-PRIVATE-PNG-UPLOAD-HTTP-REVIEW.md) · [클라이언트 복구 시험](../../tests/private-png-client-recovery.test.ts)

### 새 프로젝트를 제출한 뒤 응답이 끊겼을 때

로컬 생성 폼에서는 생성 버튼을 한 번 누른 뒤 화면 이동을 기다린다. 통신 오류가 나면 **같은 폼을 열어 둔 채 같은 내용으로 다시 제출**한다. 앱이 처음 요청의 식별자를 재사용한다. 입력값을 바꿔 제출하면 새 요청이 된다. 이미 창을 닫았거나 새로고침했다면 내 프로젝트 목록에서 생성 여부부터 확인한다. 목록도 조회할 수 없다면 생성 시각과 제목으로 운영 담당자에게 확인을 요청한다. [생성 폼 재시도 검증](../handoffs/T371-FORM-REQUEST-RETRY.md)

## 비공개 WAV 음원을 등록하고 들으려면

로컬 ‘새 프로젝트’에 **비공개 음원** 패널이 보일 때 이용한다. ‘음원 선택’에서 1 MiB 이하의 16비트 정수 PCM WAV 한 곡을 고른다. 모노·스테레오, 8–192 kHz를 지원한다. ‘기기에서 선택됨’ 아래의 재생기로 파일을 확인하고, 필요한 경우 ‘음원 출처·권리 메모’에 500자 이내로 적는다. 준비되면 **비공개 음원 등록**을 누른다.

- **등록 결과를 확인하지 못했을 때**는 같은 화면에서 파일 선택과 메모를 유지한 채 다시 등록한다. 앱은 같은 요청 번호를 사용한다. 형식 오류라면 파일을 16비트 정수 PCM WAV로 내보낸 뒤 다시 선택한다.
- **‘비공개 자료로 등록됨 · 프로젝트 연결 전’이 보이면** 등록이 끝났다. ‘등록한 음원 듣기’로 서버에 저장된 본인 파일을 확인한다. 이 재생기에서 오류가 나면 ‘등록한 음원 다시 불러오기’를 누른다. 음원을 다시 올릴 필요는 없다.
- **로컬 쇼핑숏츠 프로젝트에 연결하려면** 새 프로젝트 화면에서 제품 사진과 제작 정보를 먼저 저장하거나, 본인 프로젝트 상세를 연다. 음원 등록 후 **등록한 음원을 프로젝트에 연결**을 누른다. ‘프로젝트 연결 음원’ 목록에 제목과 길이가 나타나고 **이 프로젝트에 연결됨**이 표시되면 연결이 확인된 것이다. 이후 상세를 다시 열면 목록에서 해당 음원을 들을 수 있다. 타임라인 배치와 렌더는 별도 단계다.
- **연결 결과를 확인할 수 없으면** 파일을 다시 올리기 전에 ‘프로젝트 연결 음원’ 목록을 확인한다. 조회에 실패하면 **연결 목록 다시 확인**을 누른다. 목록에 해당 음원이 있으면 연결이 끝났고, 없으면 같은 등록 음원으로 연결을 다시 시도한다.
- **다른 파일로 바꾸면** 권리 메모가 초기화된다. 새 음원의 출처를 다시 적는다. 같은 파일의 등록 응답만 끊긴 경우에는 파일과 메모를 그대로 둔다.

로컬 HTTP·PG17에서는 등록, 동일 요청 복구, 소유자 전체·구간 조회와 기존 프로젝트에 대한 중복 없는 연결을 독립 검증했다. 위 버튼과 문구는 로컬 화면 구현을 기준으로 한다. 운영 제공 여부는 별도 확인 대상이다. [음원 등록 검수](../handoffs/FIRST-WORK-PRIVATE-WAV-HTTP.md) · [프로젝트 연결 검수](../handoffs/FIRST-WORK-PRIVATE-WAV-PROJECT-HTTP.md)

### 프로젝트 상세에서 편집할 음원을 골라 들으려면

로컬 PG17 연결이 활성화된 본인 쇼핑숏츠 프로젝트에서 이용한다. **프로젝트 상세 → 편집 음원 선택**을 열고 ‘프로젝트에 연결된 음원’에서 곡을 고른다. 재생기 위에서 길이와 입력해 둔 권리 메모를 확인하고 재생을 누른다. 다른 곡을 들으려면 같은 목록에서 곡을 바꾼 뒤 재생한다.

선택한 곡은 현재 페이지 주소에 기록된다. 같은 주소를 새로고침하면 목록을 다시 조회하고, 그 곡이 여전히 연결돼 있을 때 선택이 복원된다. 타임라인에 넣으려면 아래 **배경 음악 저장**에서 별도로 저장한다.

| 보이는 문구 | 다음 행동 |
|---|---|
| 연결된 음원이 없어요 | **프로젝트 상세로 돌아가기**를 눌러 비공개 음원을 프로젝트에 연결한 뒤 다시 연다. |
| 음원 목록을 불러오지 못했어요 | **목록 다시 확인**을 눌러 연결 목록을 조회한다. |
| 선택했던 음원을 사용할 수 없어요 | 현재 목록에서 다른 곡을 고른다. 필요한 곡이 빠졌다면 프로젝트 상세에서 연결 상태를 확인한다. |
| 음원을 재생할 수 없어요 | **연결 상태 다시 확인**을 누른다. 복구되면 같은 음원의 재생기에 초점이 이동하고 Space로 재생할 수 있다. 목록 조회가 다시 실패하면 초점이 **목록 다시 확인** 버튼으로 이동한다. |

로컬 390px·1280px 브라우저에서 재생기 초점 복귀와 Space 재생을 독립 검증했다. [편집 음원 선택 검수](../handoffs/LOCAL-PROJECT-EDITING-AUDIO-PICKER.md)

### 첫 타임라인을 만들려면

제작을 승인하고 사용할 장면 결과를 모두 선택한 로컬 쇼핑숏츠 프로젝트에서 **편집 음원 선택 → 첫 타임라인 저장**을 누른다. 저장에 성공하면 선택한 장면이 순서대로 이어진 타임라인의 번호와 내용 리비전이 표시된다. 이미 기준 타임라인이 있으면 같은 화면에서 배경 음악 저장으로 넘어간다.

- **장면 제작을 먼저 승인해 주세요**가 표시되면 장면 결과의 선택과 제작 승인 상태를 확인한다.
- 저장 응답이 끊기면 같은 화면에서 **같은 저장 요청 다시 확인**을 누른다. 다른 곳에서 먼저 저장했다는 안내가 나오면 최신 기준을 불러온 뒤 이미 저장된 타임라인이 있는지 확인한다.

로컬 PG17과 390px 브라우저에서 최초 저장, 키보드 재시도 후 결과로 초점 이동, 새로고침 후 배경 음악 저장 활성화를 독립 검증했다. [최초 타임라인 저장 검증](../handoffs/FIRST-WORK-PG-INITIAL-TIMELINE.md)

### 선택한 음원을 타임라인에 저장하려면

제작 승인이 완료되고 기준 타임라인이 준비된 로컬 쇼핑숏츠 프로젝트에서 이용한다. **배경 음악 저장**의 ‘저장할 음원’ 이름을 확인하고 **타임라인에 배경 음악 저장**을 누른다. 성공 안내에 나온 타임라인과 내용 리비전 번호가 저장 확인 기준이다.

- **저장 결과를 확인하지 못했어요**가 표시되면 ‘다시 확인할 음원’ 이름을 확인하고, 같은 화면에서 **같은 저장 요청 다시 확인**을 누른다.
- **저장 기준이 달라졌어요**가 표시되면 최신 기준 확인이 끝날 때까지 기다린다. **저장 기준 다시 확인**이 보이면 누른다. 현재 선택한 음원을 확인한 뒤 다시 저장한다.

저장 성공, 응답 유실 후 같은 요청 복구, 동시 수정 후 기준 갱신은 로컬 브라우저와 PG17에서 확인했다. [배경 음악 저장 검증](../handoffs/FIRST-WORK-WAV-TIMELINE-SAVE-UI-READINESS.md)

## 자막을 수정한 뒤 현재 버전 MP4를 받으려면

1. 로컬 쇼핑숏츠의 편집 화면에서 글자 목록 위 **현재 재생 위치**의 시간과 장면을 확인한다. 미리보기가 다음 장면으로 넘어가도 선택한 자막은 유지되므로, 수정할 자막 행을 직접 고르고 ‘문구’를 고친다. 이전 저장본과 수정 문구를 비교한 뒤 **장면·글자·소리 설정 저장**을 누른다. 저장 결과에 표시된 타임라인 번호와 ‘저장 전’, ‘저장 후’ 문구를 확인한다. [자막 목록의 재생 위치](../handoffs/P2-SUBTITLE-PLAYHEAD.md)
2. 편집 화면에서 현재 내용 검수로 이동한다. 같은 타임라인의 결과가 있으면 **이 버전 MP4 확인**을 눌러 해당 결과 카드를 연다. 현재 버전의 영상이 아직 없으면 **영상 만들기로 이동**을 눌러 저장한 타임라인으로 새 영상을 만든다.
3. 결과 카드에서 **현재 저장본 · 타임라인 r번호**가 검수 화면의 번호와 같은지 확인한다. **영상 보기**로 수정한 자막이 나오는 구간을 확인하고 **이 버전 MP4 내려받기**를 누른다. 이전 버전의 파일은 ‘보관본’ 표시와 **보관본 MP4 내려받기**로 구분한다.

검수 화면에 타임라인 재저장이 필요하다고 표시되면 편집으로 돌아가 지금 선택한 장면으로 저장한다. **영상 만들기**가 비활성인 경우에도 Tab으로 버튼에 이동해 차단 사유를 확인할 수 있다. ‘만들기 전에 고칠 것’에 표시된 항목을 먼저 해결한다. 영상 만들기가 실패하면 결과 카드의 사유를 확인하고 **다시 만들기**를 이용한다. 이 절차는 로컬 렌더 결과를 받는 방법이다. [자막 저장 결과](../handoffs/P2-SUBTITLE-SAVE-RESULT.md) · [검수 화면에서 현재 MP4 확인](../handoffs/P2-REVIEW-CURRENT-MP4.md) · [영상 만들기 차단 사유 확인](../handoffs/P2-RENDER-BLOCKED-KEYBOARD.md)

### 로컬 PG 프로젝트에서 자막을 편집하려면

1. 기준 타임라인을 저장한 뒤 **프로젝트 상세 → 자막 편집**을 연다. **자막 추가**를 누르거나 기존 자막 행을 고른다.
2. 문구와 시작·끝 프레임을 입력한다. 편집 기준은 30fps다. 시작은 0 이상의 정수, 끝은 시작보다 큰 정수로 적고 화면의 **입력 가능한 끝 프레임**을 확인한다. 필수 표기와 잠긴 글자 레이어는 보호된다.
3. **저장 전 비교**로 수정할 행을 확인한 뒤 **자막 저장**을 누른다. 변경이 저장되면 새 내용 버전의 편집 완료와 검수를 다시 진행한다. 기존 내용과 같으면 같은 버전이 유지된다.

응답이 끊기면 **같은 저장 요청 다시 확인**을 누른다. 다른 탭에서 먼저 저장했다면 **최신 저장본과 내 초안 비교**에서 두 문구를 확인한 뒤 **최신 저장본 기준으로 다시 저장**을 선택한다. 로컬 **영상 만들기**에서 저장 후 검수를 승인한 버전의 한글 자막이 MP4 화면에 표시된다. 광고 등 필수 표기가 필요한 작품은 표기가 영상 전체 구간에 있어야 출력할 수 있다. [390px 자막 편집 독립 검수](../handoffs/FIRST-WORK-PG-SUBTITLE-SAVE.md) · [한글 자막과 필수 표기 검증](../handoffs/LOCAL-PG-MP4-TEXT-RENDER.md)

### 승인된 자막을 SRT·VTT 파일로 받으려면

자막을 저장하고 현재 내용 버전의 검수를 승인한다. **프로젝트 상세 → 자막 편집 → 승인된 자막 받기**에서 화면의 내용 리비전과 자막 개수를 확인한 뒤 **SRT 받기** 또는 **VTT 받기**를 누른다. 파일에는 승인된 저장본의 자막이 들어간다. 승인본에 자막이 없으면 화면에 안내가 표시된다.

다른 탭에서 타임라인이 바뀌면 다운로드가 차단되고 두 받기 버튼이 숨겨진다. 작업 중인 초안은 그대로 남는다. 초안을 계속 쓰려면 문구와 프레임 값을 먼저 따로 적어 둔다. **저장된 자막 다시 불러오기**를 누르면 최신 저장본을 읽고 현재 초안을 지운다. 최신 자막을 확인하고 그 버전을 검수·승인하면 SRT·VTT 받기 버튼이 다시 표시된다. 로컬 390px 브라우저에서 충돌부터 새 승인본의 SRT 다운로드까지 확인했다. [SRT·VTT 화면 독립 검수](../handoffs/FIRST-WORK-PG-SUBTITLE-DOWNLOAD.md)

### 로컬 PG 프로젝트의 현재 버전을 검수하고 승인하려면

1. 제작을 승인하고 타임라인을 저장한 뒤 편집 화면에서 **수정 확인 완료 · 검수로**를 누른다. 검수 화면의 내용 버전 번호를 확인한다.
2. 필수 항목을 하나씩 확인하고 **통과** 또는 **보류**를 선택한다. 보류할 때는 이유를 적고 **보류 사유 저장**을 누른다. 배경 음악을 넣었다면 음악 권리 항목도 확인한다.
3. 모든 필수 항목이 통과하고 수정한 검수 메모가 저장되면 **검수 승인**을 누른다. 승인 결과의 내용 버전을 확인하고 **영상 만들기로 이동**을 누른다.

승인 응답을 받지 못했으면 **승인 상태 다시 확인**을 누른다. 편집 내용이 바뀌면 최신 내용 버전에서 검수 항목을 다시 확인한다. 로컬 PG17의 390px·1280px 브라우저에서 화면 승인부터 렌더 요청 접수까지 독립 검증했다. 이 시험의 제작 승인과 PNG는 시험 자료로 준비했다. [편집·검수 화면 검수](../handoffs/LOCAL-PG-REVIEW-APPROVAL-UI.md)

### 로컬 PG 프로젝트에서 MP4를 요청하고 실행하려면

제작과 현재 내용의 검수 승인을 마친 쇼핑숏츠 프로젝트에서 **프로젝트 상세 → 영상 만들기**를 연다. 로컬 렌더는 PNG 장면 1~2개, 컷 전환, 타임라인에 저장한 첨부 WAV 음원 1~2개, 승인된 한글 자막과 필수 표기를 최대 16MB MP4로 출력한다. 두 장면은 승인한 타임라인 순서로 출력된다. 필수 표기나 실행 조건을 확인하라는 안내가 나오면 해당 사유를 해결한 뒤 다시 실행한다. [두 PNG 장면 출력 검수](../handoffs/FIRST-WORK-PG-TWO-PNG-RENDER.md) · [한글 자막과 필수 표기 검증](../handoffs/LOCAL-PG-MP4-TEXT-RENDER.md)

1. **이 버전으로 영상 요청**을 눌러 작업을 접수한다. 대기 상태가 표시되면 **영상 만들기 실행**을 눌러 렌더를 시작한다.
2. 완료 안내와 현재 타임라인 번호를 확인하고 **현재 버전 MP4 받기**를 누른다.
3. 요청 응답이 끊겼으면 **같은 요청 다시 확인**을 누른다. 실행 결과를 받지 못했으면 **상태 다시 불러오기**로 완료 여부를 먼저 확인한다. 이미 실행 중이면 상태가 갱신될 때까지 기다린다. **영상 만들기가 중간에 멈췄어요**가 표시되면 출력 파일이 없으므로 같은 작업에서 **다시 실행**을 누른다.

새로고침하면 접수·실행 상태를 다시 읽는다. 편집으로 내용 버전이 바뀌면 기존 요청은 ‘이전 버전 요청’에 표시된다. 새 버전을 검수하고 승인한 뒤 그 버전으로 다시 요청한다. 이 제작 흐름은 로컬 개발 환경에서 제공되며 운영용 서버에서는 로컬 렌더 실행이 차단된다. [로컬 PG 렌더 화면 검수](../handoffs/FIRST-WORK-PG-RENDER-EXECUTION.md) · [운영 빌드 실행 제한 검증](../handoffs/LOCAL-PG-RENDER-PRODUCTION-BUILD.md)

### 로컬 PG 프로젝트의 재편집 ZIP을 받으려면

1. 현재 내용 버전의 검수를 승인하고 **프로젝트 상세 → 재편집 ZIP**을 연다. 생성할 내용 리비전을 확인하고 **이 버전으로 ZIP 만들기**를 누른다.
2. ZIP이 준비되면 표시된 버전과 크기를 확인하고 **현재 버전 ZIP 받기**를 누른다. 장면 PNG, 타임라인, 권리 기록이 기본으로 들어간다. 해당 타임라인에 사용한 WAV가 있으면 그 원본을, 저장된 자막이 있으면 SRT·VTT를 함께 넣는다.
3. 생성 결과를 받지 못하면 같은 화면에서 **같은 요청 다시 확인**을 누른다. 화면을 새로 열면 보관된 결과를 다시 불러온다. 다른 탭의 편집으로 버전이 충돌하면 화면이 최신 상태를 자동으로 조회한다. **최신 상태를 불러오지 못했어요**가 표시되면 **ZIP 만들기**와 **ZIP 받기** 버튼이 숨겨지고 오류 안내로 초점이 이동한다. Tab 한 번으로 **상태 다시 불러오기**에 도달한다. 최신 리비전을 조회하면 미승인 버전의 만들기 버튼은 비활성으로 표시된다. 새 버전을 검수·승인한 뒤 해당 버전의 ZIP을 만든다.

로컬 PG17과 390px 브라우저에서 재시도, 새로고침, 다운로드 파일명·해시, 이전 버전 다운로드 차단을 독립 검증했다. [재편집 ZIP 보관·화면 검수](../handoffs/LOCAL-PG-EDITING-ZIP-STORAGE.md)

## 완성본을 게시하거나 내리려면

운영의 **완성본 검수·게시**에는 **게시 서버 미연결**이 표시된다. 게시나 철회가 필요한 경우 운영 담당자에게 게시 서버 연결을 확인해 달라고 요청한다. 아래 절차는 게시 큐가 연결된 검수 환경을 기준으로 한다. 비교 시안은 시험 작품으로 두 철회 상황을 보여준다. [운영 배포 기록](../handoffs/ADMIN-WORK-CONSOLE-LIVE-DEPLOYMENT.md) · [준비 취소·공개 철회 비교 시안](admin-topnav-options/publication-revocation/compare.html)

### 완성본을 게시할 때

1. 관리자 메뉴의 **완성본 검수·게시**에서 본인 소유 완성본의 제목과 버전을 확인한다. 권리 증빙과 표시 문구를 확인하고 해당 버전의 **게시 준비**를 누른다.
2. **준비된 세대** 번호와 권리 증빙·표시 문구를 다시 확인한 뒤 해당 **세대 N 게시**를 누른다. 게시 완료 후 카드의 **게시 중 세대**와 응답 세대가 일치하는지 확인하고 공개 홈을 다시 열어 해당 작품과 표지를 확인한다. [게시·철회 기능 검수 요약](../handoffs/T370-T362-REA-MASTER-REPORT.md)

### 준비를 취소하거나 공개를 종료할 때

해당 작품의 제목과 **준비된 세대**, **게시 중 세대**를 먼저 확인하고 **철회…**를 누른다. **세대 N 철회 확정**의 번호가 내리려는 세대와 같을 때만 확정한다. 번호가 다르면 **취소**를 누른다.

| 카드에 보이는 상태 | 확정 후 확인할 내용 |
|---|---|
| 준비된 세대가 있음 | 준비된 세대가 먼저 철회된다. 확정 후 **준비된 세대**가 ‘없음’인지 확인한다. 게시 중인 세대가 있었다면 그 번호가 유지되고 공개 목록과 표지도 그대로다. 공개도 종료하려면 **목록 다시 불러오기**로 준비 세대가 없고 게시 중 세대 번호가 맞는지 다시 확인한 뒤 별도의 철회로 진행한다. |
| 준비된 세대가 없고 게시 중인 세대가 있음 | 확정 대상이 **게시 중 세대**와 일치하는지 확인한다. 완료 후 카드에서 해당 세대가 내려갔는지 확인하고 공개 홈을 다시 열어 작품이 목록에서 빠졌는지 확인한다. 해당 세대의 표지 주소를 확인해 둔 경우 다시 열어 접근할 수 없는지 확인한다. |

현재 화면은 준비 세대 철회에도 공개 목록과 표지에서 내려간다는 공통 문구를 표시한다. 철회 결과는 카드의 두 세대 값을 기준으로 확인한다. [게시 상태와 철회 대상 대조](admin-topnav-options/PUBLICATION-STATE-REVIEW.md)

### 게시나 철회 버튼을 누른 뒤 결과가 불분명할 때

먼저 해당 작품 카드에서 제목, ‘게시 중 세대’, ‘준비된 세대’를 확인한다. 세대 번호는 같은 작품의 어느 게시본을 가리키는지 구분한다. 준비 완료는 공개 전 단계다.

| 카드에 보이는 상황 | 다음 행동 |
|---|---|
| 요청 중 | 버튼에 표시된 작업이 끝날 때까지 기다린다. 다른 창에서 같은 작업을 새로 시작하지 않는다. |
| 처리 여부가 불분명하고 ‘같은 … 요청 다시 시도’가 보임 | **목록 다시 불러오기**로 현재 버전과 두 세대를 확인한다. 조회가 성공한 뒤 같은 작품·버전에 재시도 버튼이 남아 있고 작업이 여전히 필요하면 그 버튼을 한 번 누른다. 앱은 처음 요청의 식별자와 대상 세대를 재사용한다. |
| ‘게시 목록을 불러오지 못했어요’ | 목록 조회를 다시 시도한다. 조회가 실패한 동안에는 이전 게시·철회의 처리 여부가 확인되지 않는다. 새 요청을 시작하기 전에 정상 목록에서 작품과 세대를 확인한다. |
| ‘그사이 다른 곳에서 상태가 바뀌었어요’ | 목록을 다시 불러오고 현재 세대와 권리 표시를 확인한다. 예전 세대를 기준으로 철회하거나 게시하지 않는다. 작품이 사라지면 다른 작품을 대신 선택하지 않는다. |
| 원본이 바뀌었거나 미완성이라고 표시됨 | 원본 완성본과 대상 리비전을 확인한 뒤 목록을 갱신한다. 권한이 없다는 안내가 뜨면 로그인 계정과 작품 소유권을 운영 담당자에게 확인한다. |

목록 다시 불러오기는 현재 상태를 조회한다. 미확정 요청 재시도는 처음과 같은 식별자로 같은 작업을 다시 보낸다. [게시 큐 동작](../../components/admin/publication-queue.tsx) · [조회 실패 뒤 재시도 계약](../handoffs/T289-F2-ADMIN-PUBLICATION-QUEUE-FAILED-LOAD.md)

## 공개 작품을 열려면

로그인 없이 작품 설명을 보려면 공개 홈의 대표 작품에서는 **작품 자세히 보기**를 누르고, 검색·필터 결과에서는 원하는 작품의 표지 버튼(접근성 이름 **〈작품 제목〉 자세히 보기**)을 누른다. 확인된 운영 버전은 소개 작품을 보여준다. 재생 파일이 연결되지 않은 작품의 상세에는 **아직 재생할 수 있는 영상 파일이 연결되지 않았어요** 또는 음악에 해당하는 문구가 표시된다. 작품 설명을 읽은 뒤 닫기 버튼 또는 Escape로 탐색 화면에 돌아갈 수 있다. [공개 홈](https://dream-ai-studio-orpin.vercel.app/) · [운영 화면 확인 범위](../handoffs/T370-T362-REA-MASTER-REPORT.md)

### 재생이 연결된 검수 환경에서 확인할 때

| 상세에 보이는 상황 | 다음 행동 |
|---|---|
| **표지를 불러오지 못했어요** | 표지 조회에 실패한 상태다. 재생 조작이 보이면 영상·음악 재생을 시도할 수 있다. 재생 파일 연결 상태는 플레이어와 별도 안내에서 확인한다. |
| **재생할 수 있는 영상 파일이 아직 연결되지 않았어요** 또는 음악에 해당하는 문구 | 연결된 재생 파일이 없는 상태다. 상세에서 작품 설명을 확인하고 목록으로 돌아간다. |
| **재생 파일을 불러오지 못했어요** | **재생 파일 다시 불러오기**를 누르면 현재 상세에서 같은 파일을 다시 불러온다. 그래도 오류가 계속되면 상세를 닫고 **DREAM SCREEN 처음 화면** 로고를 누르거나 브라우저를 새로고침한다. 새로 열린 목록에서 작품을 다시 찾아 현재 공개 여부를 확인한다. |

격리된 로컬 검수에서는 MP4 영상과 M4A 음악을 재생하고 다른 시점으로 이동했다. 재생 파일 전송 중 작품을 철회하면 다음 데이터 전송이 끊기고 같은 세대의 새 구간 요청이 거절됐다. 이미 기기에 받은 분량은 잠시 재생될 수 있다. 운영 담당자는 실제 게시 작품의 재생과 기기별 동작을 별도로 확인해야 한다. [공개 재생 상태 대조](t232-public-showcase/PLAYBACK-STATE-REVIEW.md) · [로컬 재생·철회 실측](../handoffs/T370-PUBLIC-PLAYBACK-HTTP-VERIFICATION.md)

## 이미지·음악·영상 분석을 이용하려면

### 관리자 화면에서 URL 또는 파일 분석·공개하기

운영의 스펙트럼 랩에서 JPG·MP3·MP4의 직접 URL과 파일 업로드를 각각 실행해 여섯 건 모두 분석 결과를 확인했다. 관리자 공개 목록 조회도 확인했다. 실제 공개·철회는 이번 운영 검수 범위에서 제외했다. [운영 분석기 열기](https://dream-ai-studio-orpin.vercel.app/admin#admin-reference-analysis) · [공개 결과 페이지 열기](https://dream-ai-studio-orpin.vercel.app/analysis-results) · [운영 검수 기록](../handoffs/ADMIN-SPECTRUM-LAB-INDEPENDENT-DESIGN.md)

1. 관리자 계정으로 로그인하고 상단에서 **콘텐츠 분석·공개**를 선택한다. **URL 주소** 또는 **파일 업로드**를 고른 뒤 이미지·음악·영상 중 해당하는 항목을 선택한다. 직접 HTTPS 주소를 넣거나 4 MiB 이내의 파일을 선택한다. **지원 원본·형식 보기**에서 제공처와 파일 한도를 확인할 수 있다. 분석할 권리가 있는 자료라면 **권리 확인하고 분석**을 누른다.
2. **관찰 근거**에서 시간 구간이나 이미지 영역을 확인하고, **생성 프롬프트**에서 초안을 검토한다. **공개 준비**에서 공개할 결과를 고르고 제목·요약·생성 프롬프트를 확인한다. 공개할 문구는 이 양식에서 직접 고친다.
3. 공개할 권리를 확인하고 공개 페이지 표시 동의 항목을 선택한 뒤 **공개하기**를 누른다. **공개한 분석 결과**에 항목이 보이면 **공개 결과 페이지 보기**에서 표시를 확인한다. 공개 페이지에는 제목·요약·생성 프롬프트·매체·공개 시각이 표시된다.
4. 공개를 중단하려면 **공개한 분석 결과**에서 해당 항목의 **공개 철회 → 공개 철회 확인**을 누른다. **공개 결과 페이지 보기**에서 해당 항목이 내려갔는지 확인한다.

분석 도중 멈추려면 **분석 취소**를 누른다. 주소나 파일을 바꾸면 현재 분석 결과가 지워지므로 자료를 확인하고 분석 버튼을 다시 누른다. 공개 요청 뒤 응답을 받지 못했으면 **목록 새로고침**으로 같은 결과가 이미 공개됐는지 확인한다.

- **같은 공개 요청이 다른 내용으로 이미 처리됐어요**가 표시되면 **공개한 분석 결과**를 먼저 확인한다. 목록을 불러오지 못했다면 **목록 새로고침**을 누른다. 새로 공개할 내용이 있으면 공개 문구와 권리를 확인하고 동의를 다시 선택한 뒤 **공개하기**를 누른다.
- 철회하려는 항목을 찾을 수 없거나 이미 철회됐다는 안내가 보이면 **공개한 분석 결과** 목록에서 현재 상태를 확인한다. 목록을 불러오지 못했다면 **목록 새로고침**을 누른다.
- **이 파일은 지금 분석할 수 없어요**가 표시되면 **지원 원본·형식 보기**에서 파일 주소와 형식을 확인한다. 지원되는 파일에서도 오류가 계속되면 화면에 표시된 문구와 파일 형식, 발생 시각을 운영 담당자에게 전달한다.
- 지원하지 않는 주소를 입력하고 **권리 확인하고 분석**을 누르면 주소 입력란으로 초점이 돌아가고 오류가 안내된다. 주소가 `blob:`으로 시작하면 처음 자료를 열었던 화면에서 사용 권리가 있는 원본을 파일로 저장한다. **저장한 원본 업로드**를 눌러 파일 선택으로 이동하고 해당 매체의 4 MiB 이내 파일을 추가한다.
- **다시 로그인이 필요해요**가 보이면 로그인 후 메뉴를 다시 연다. **관리 권한이 없어요**가 보이면 운영 담당자에게 계정의 관리자 권한을 확인한다.

### 클라우드 작업실의 콘텐츠 분석 메뉴

**현재 운영에는 클라우드 콘텐츠 분석 메뉴가 배포되지 않았다.** 검수 환경에서는 허용된 계정으로 로그인한 뒤 작업실 상단의 **콘텐츠 분석**을 연다. **등록 자료 분석을 준비 중이에요**가 보이면 자료 선택과 실행이 꺼져 있고 자료 전송과 결과 생성은 일어나지 않는다. **내 프로젝트로 이동**을 누르면 로그인한 계정으로 접근 가능한 프로젝트 목록이 열린다. 화면에 보이는 PNG·M4A·MP4는 자료 형식 예시다. 실제 분석이 필요하면 운영 담당자에게 화면 제공 및 연결 상태를 확인한다. [클라우드 진입 검수 후보](../handoffs/REA-CLOUD-ENTRY-RELEASE-SCOPE.md)

### 로컬 작업실에서 공개 파일을 분석하는 방법

1. 로컬 작업실의 **레퍼런스 분석**(`/studio/reference-analysis`)에서 **공개 URL 분석**을 연다. `interactive-examples.mdn.mozilla.net`, `mdn.github.io`, `tonejs.github.io`에서 제공하는 미디어 파일의 직접 HTTPS 주소를 **미디어 파일 URL**에 붙여 넣는다. 로컬 검수에서 이미지 JPG, 음악 MP3, 영상 MP4를 확인했다.
2. 파일을 분석할 사용 권한이 있으면 **이 자료를 분석할 권리가 있어요**를 체크하고 **URL 분석 실행**을 누른다. YouTube·Instagram·Threads·TikTok 등의 게시물 주소와 프로필 주소는 지원하지 않는다.
3. **관찰 근거**에서 이미지 영역, 음악 측정 구간, 영상 프레임 시각을 확인한다. **분석 추정**이 있으면 해당 근거와 함께 읽는다. **분석으로 생성한 초안**을 참고해 **내 수정본**에서 문구를 다듬고 **변경 내용**에서 원래 문구와 비교한다. 제작자가 공개한 프롬프트는 확인되지 않았다는 안내가 함께 표시된다. [로컬 공개 파일 검증](../handoffs/REA-PUBLIC-URL-LOCAL-STUDIO.md) · [결과 화면 실측](../handoffs/REA-LOCAL-RESULTS-INDEPENDENT-REVIEW.md)
4. 편집하기 전에는 **초안 복사**, 문구를 바꾼 뒤에는 **수정본 복사**를 누른다. 브라우저가 클립보드 쓰기를 막으면 편집란에 선택된 문구를 `Ctrl+C` 또는 `⌘C`로 복사한다.
5. **저장된 분석 버전**이 표시되는 로컬 작업실에서는 목록에서 이전 결과와 그 결과에 작성했던 수정본을 다시 열 수 있다. 결과와 수정본은 사용한 브라우저에 저장된다. 이전 결과를 연 뒤 새 분석을 실행하려면 권리를 다시 확인한다.

#### 주소를 바꿨거나 오류가 표시될 때

- **주소를 바꾼 경우** 화면에 열려 있던 원본 링크·분석 결과·수정본이 닫히고 권리 체크가 풀린다. 새 주소와 사용 권리를 확인한 뒤 다시 실행한다.
- **권리 확인을 해제한 경우** 주소는 남고 화면에 열려 있던 결과와 수정본이 닫힌다. 사용 권리를 다시 확인하고 실행해야 새 결과를 받을 수 있다.
- **‘분석하지 못했어요. 지원하는 공개 파일 주소와 파일 형식·길이를 확인해 주세요’가 표시된 경우** 허용된 원본의 직접 HTTPS 파일 주소인지, 실제 파일의 형식과 길이가 지원 범위인지 확인한다. 화면의 안내 범위는 음악 24초, 영상 20초·240프레임까지다. 주소 형식이 잘못됐으면 URL 입력칸에서 고친다.
- **같은 주소로 다시 실행하는 경우** ‘분석 결과를 받지 못했어요. 다시 시도해 주세요’ 같은 오류가 나면 새 결과 영역이 비어 있다. 주소를 바꾸지 않았고 사용 권리 확인이 유지돼 있으면 **URL 분석 실행**을 다시 누를 수 있다. 저장된 이전 결과는 **저장된 분석 버전**에서 다시 연다.

결과 제목 초점 보완이 적용된 로컬 검수본에서는 분석 성공 뒤 **분석 결과** 제목에 초점이 간다. 실행 중 다른 곳으로 초점을 옮겼다면 그 위치가 유지된다. [주소·권리 변경과 오류 대조](rea-cloud-analysis/LOCAL-URL-RECOVERY-REVIEW.md)

### 음악 등록과 합성 체험 범위

프로젝트 제작용 **비공개 WAV 등록·미리 듣기**와 콘텐츠 분석은 별도 기능이다. 등록 음악 분석은 접근 권한을 확인한 일부 PCM WAV로 격리 시험을 진행했으며, 현재 운영 클라우드 작업실에서는 등록 음악을 골라 분석할 수 없다. 로컬 작업실에서 검증한 공개 MP3 직접 파일 분석은 위 절차를 따른다. [등록 PCM WAV 검증](../handoffs/REA-REGISTERED-PCM-WAV-AUTHORITY-VERIFICATION.md)

‘레퍼런스 분석 · 합성 체험’이 제공되는 작업실에서는 ‘합성 표본’을 고르고 ‘표본 분석 시작’을 누른다. ‘근거’에서 분석 근거를 살펴보고 ‘편집용 프롬프트’에서 문구를 다듬는다. ‘프로젝트 미리보기’에서 사용할 근거를 고른다. 합성 체험에서 URL·파일을 선택했을 때 보이는 ‘입력 방식 확인’은 입력 방식 안내다. 표본 미리보기에서 프로젝트가 저장되지는 않는다. 적용 기능을 제공하는 환경에서 저장 응답이 끊기면 다시 적용하기 전에 ‘적용 결과 확인’으로 기존 결과를 확인한다.

## 운영 담당자에게 문의할 때

| 사용자 작업 | 앱의 연결 경로 | 필요한 권한과 확인 항목 |
|---|---|---|
| 비공개 WAV 등록·미리 듣기 | `POST /api/assets/upload?format=wav&filename=…`, `GET /api/assets/[id]?format=wav` | 로그인한 소유자. 등록 응답을 잃으면 같은 요청을 재시도하고, 등록 후 재생 오류는 조회만 다시 시도한다. |
| 등록 음원을 프로젝트에 연결·확인 | `PUT /api/projects/[id]/audio-assets/[assetId]`, `GET /api/projects/[id]/audio-assets` | 프로젝트와 음원을 소유한 계정. 연결 결과가 불명확할 때 목록에서 같은 음원이 있는지 먼저 확인한다. |
| 새 프로젝트 생성 | `POST /api/projects` | 로그인한 생성자. 로컬 연결 후보에서 검증된 비공개 이미지에 대한 소유·접근 권한을 확인한다. 운영 제공 여부는 별도 확인이 필요하다. |
| 내 프로젝트 목록·상세 | `GET /api/projects`, `GET /api/projects/[id]` | 로그인한 소유자. T362 읽기 스키마와 사용자별 조회 권한을 확인한다. 관리자 페이지는 서버에서 같은 조회 기능을 사용한다. |
| 완성본 조회·게시 준비·게시·철회 | `GET /api/admin/publications`, `POST /api/admin/publications` | 관리자 권한과 대상 소유권. 게시에는 권리 확인과 완성본이 필요하다. 게시 서버·저장소를 별도로 확인한다. |
| 공개 작품 표지 | `GET` 또는 `HEAD /media/public/[slug]/[generation]/cover.webp` | 공개가 유효한 작품 세대. 오래된 주소가 열리지 않으면 공개 홈의 최신 목록에서 작품을 다시 찾는다. 재생 연동은 T370에서 별도 검증한다. |
| 관리자 콘텐츠 분석 | `POST /api/admin/reference-analysis` | 관리자 권한과 분석 권리 확인이 필요하다. 지원되는 HTTPS 직접 파일 주소 또는 4 MiB 이내 파일을 사용한다. |
| 분석 결과 공개 목록·공개·철회 | `GET`, `POST`, `DELETE /api/admin/reference-publications` | **콘텐츠 분석·공개** 메뉴가 제공되는 환경에 적용한다. 관리자 권한과 공개 저장소 연결이 필요하며, 공개할 때는 공개 권리를 확인한다. |
| 작업실 등록 자료 분석 | `POST /api/studio/reference-analysis` | 로그인, 자료 접근 권한, 분석 연결이 필요하다. 분석 화면 제공 여부와 자료 선택 가능 여부를 먼저 확인한다. |

문의에는 **화면 이름, 누른 버튼, 보이는 문구, 발생 시각**을 적는다. 화면 캡처에 계정 이메일이나 비공개 작품 정보가 있으면 가리고 보낸다. 비밀번호와 API 키는 보내지 않는다.
