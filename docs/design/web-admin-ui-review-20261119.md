# 공개 홈과 관리자 화면 디자인 검토

2026년 11월 19일 한국시간 22시대, 운영 사이트의 공개 홈과 로그인된 관리자 화면을 Chromium에서 확인했다. 1280·390·320 CSS 픽셀에서 문서 가로 넘침, 메뉴 노출, 조작 영역 높이를 측정했다. 390픽셀에서는 첫 화면과 검수 메뉴 이동 후 화면을 눈으로 확인했다. 휴대폰은 브라우저 폭으로 재현했다.

| 순서 | 위치와 관찰 | 제안 | 반영 후 확인 |
|---|---|---|---|
| 1 | 공개 홈의 대표 버튼과 작품 표지에 ▶가 붙는다. 운영에서 누르면 작품 설명 창이 열리고 파일 미연결 안내가 나온다. | 상세 열기는 ‘작품 자세히 보기’와 화살표로 통일한다. 실제 재생은 상세 안의 플레이어에서 시작한다. T359/T360 개선과 T369 후보를 먼저 대조한다. | 표지만 있는 작품과 재생 가능한 작품을 각각 열어 첫 버튼이 예고한 동작과 결과가 일치하는지 확인한다. |
| 2 | 주 메뉴 ‘크리에이터’와 본문의 ‘뮤직 컬렉션’이 같은 위치로 이동한다. 도착 제목 ‘한 장의 커버, 무한한 상상.’만으로는 목적지를 알아보기 어렵다. | 현재 콘텐츠가 음악 컬렉션이라면 메뉴도 ‘뮤직 컬렉션’으로 맞추고 도착 제목에 ‘음악’을 넣는다. | 두 링크가 안내한 컬렉션에 도착하고 키보드 이용자도 해당 섹션을 식별한다. |
| 3 | 관리자 ‘내 프로젝트’가 미연결이어도 개요에 ‘내 프로젝트 전체 화면’ 링크가 주요 행동처럼 보인다. 게시 영역에도 미연결 설명은 있지만 다음 행동을 찾기 어렵다. | 상태 옆에 ‘연결 상태 도움말’을 둔다. 도움말에 운영 담당자가 확인할 항목과 일반 사용자가 다시 시도할 조건을 안내한다. 프로젝트 조회와 게시 연결은 각각 표시한다. | 미연결·일시 실패·정상 0건에서 도움말, 재시도, 빈 목록을 구별한다. |
| 4 | 390픽셀 공개 홈에서는 상단 메뉴·검색·안내를 지난 뒤 대표 이미지가 약 272픽셀에서 시작한다. 높이 844픽셀의 첫 화면이 대표 카드에서 끝나 작품 탐색이 아래로 밀린다. | 네온 이미지와 큰 제목을 유지하면서 모바일 대표 영역의 세로 여백을 줄이고, 첫 화면 아래쪽에 다음 섹션 제목이 보이는 안을 시험한다. | 390×844에서 두 대표 버튼과 다음 섹션 진입 단서가 보이고, 320픽셀·글자 확대 시 내용이 자연스럽게 늘어난다. |
| 5 | 관리자 모바일 ‘운영 연결 범위’에서 사용 불가 항목 6개가 각각 같은 잠금 배지와 설명을 반복한다. | ‘아직 연결되지 않은 운영 기능 6개’로 묶고 세부 목록을 펼치게 한다. 프로젝트·게시처럼 당장 수행하려던 작업의 상태는 계속 노출한다. | 키보드로 펼치고 닫을 수 있고 보조기술에 펼침 상태와 항목 수가 전달된다. |
| 6 | 관리자 로그아웃 버튼은 1280픽셀에서 높이 32픽셀이다. 모바일에서 측정한 조작 요소는 모두 44픽셀 이상이었다. | 데스크톱에서도 클릭 영역 높이를 44픽셀로 맞춘다. | 이메일이 긴 경우와 200% 확대에서도 계정 표시와 버튼이 겹치지 않는다. |

### 새 프로젝트에서 비공개 음원 한 곡 첨부

**진입 예시**는 뮤직비디오 프로젝트의 음원 입력란이다. 현재 로컬 PG17에서 확인된 범위는 WAV 등록과 소유자 파일 조회(전체·구간)까지다. 기존 쇼핑숏츠 제품 사진 입력은 PNG용이다. 아래는 음원 입력란을 제공할 환경을 위한 설계이며, 실제 음악 프로젝트 저장·렌더와 운영 업로드는 별도 검증이 필요하다. [비공개 WAV HTTP 검증](../handoffs/FIRST-WORK-PRIVATE-WAV-HTTP.md) · [현재 프로젝트 생성 폼](../../components/project-form.tsx)

| 사용자가 하는 일 | 화면과 상태 전환 |
|---|---|
| 1. 음원 선택 | **음원 선택** 옆에 ‘16비트 정수 PCM WAV 한 곡 · 모노/스테레오 · 8–192 kHz · 최대 1 MiB’를 표시한다. 선택하면 파일명과 크기, ‘기기에서 선택됨’을 보여준다. |
| 2. 미리 듣고 메모 확인 | **선택한 파일 미리 듣기**는 기기에서 연 파일을 사용한다. 자동 재생 없이 재생·일시정지·탐색을 제공한다. 파일을 바꾸면 기존 재생을 멈추고 새 선택에서 시작한다. ‘음원 출처·권리 메모(선택, 500자 이내)’ 아래에 ‘예: 직접 녹음한 피아노 연주’를 제시한다. 등록 전에 파일명과 메모를 함께 확인한다. |
| 3. 비공개 자료로 등록 | **비공개 음원 등록**을 누르면 ‘등록 중’을 표시하고 중복 제출을 막는다. 서버에서 자산 ID를 받은 뒤에만 ‘비공개 자료로 등록됨’을 표시한다. 이때 **등록한 음원 듣기**는 로그인한 소유자의 조회 경로를 사용한다. 기기 미리 듣기와 서버 파일 재생 성공을 구분한다. |
| 4. 프로젝트 연결 확인 | 등록 후 ‘프로젝트 연결 전’을 표시한다. 저장 경로가 지원될 때만 **이 음원으로 프로젝트 저장**을 제공하고 저장 응답과 프로젝트 상세에서 같은 음원을 확인한 뒤 ‘연결됨’으로 전환한다. 현재 검증 범위에서는 ‘비공개 음원 등록 완료 · 프로젝트 연결 준비 중’에서 끝난다. |

**복구 안내**

- MP3·압축 WAV·24비트 WAV 등 지원하지 않는 형식은 ‘16비트 PCM WAV로 내보낸 뒤 다시 선택해 주세요’, 용량 초과는 ‘1 MiB 이하 파일을 선택해 주세요’로 안내한다. 브라우저에서 들을 수 있어도 서버 형식 검증은 별도로 수행한다.
- 등록 응답이 끊기면 선택과 메모를 유지하고 **같은 음원 등록 다시 시도**를 제공한다. 원래 요청 키와 같은 파일명·내용·정규화한 메모로 보낸다. 파일이나 메모를 변경하면 새 등록 요청으로 구분한다. 충돌 응답이 오면 자동 재전송을 멈추고 현재 선택을 다시 확인하게 한다.
- 등록 후 듣기에 실패하면 **등록한 음원 다시 듣기**로 조회만 재시도한다. 로그인이 풀리면 재로그인을 안내한다. 파일을 찾을 수 없으면 현재 계정의 접근 가능 여부를 확인하도록 한다. 향후 프로젝트 저장만 실패하면 등록된 ID를 유지하고 프로젝트 저장 단계만 재시도한다.

**반영 확인** — 390px에서 파일명·재생 조작·메모·등록 결과 순으로 읽히고, 1280px에서도 같은 순서로 키보드 이동한다. 기다리는 동안과 실패·완료 시에는 상태 문구를 제공한다. 선택 취소, 지원하지 않는 파일, 등록 응답 유실, 다른 계정에서의 조회, 등록 후 프로젝트 미연결을 각각 확인한다. [소유자 조회와 재시도 계약](../../lib/cloud/local-private-wav.ts)

### 쇼핑숏츠 한 장면의 자막 수정과 MP4 재출력

편집자는 선택한 장면의 영상과 소리를 유지하면서 자막 한 줄을 고친다. 기존 기획의 완료 기준은 원본·이전 버전 보존, 수정 누락 확인, 현재 버전의 MP4 출력이다. [부분 수정 원칙](../PLAN.md) · [첫 출시 기준](../MASTER_DEVELOPMENT_PLAN.md)

| 단계 | 현재 동작과 막히는 지점 | 제안할 화면 상태와 위치 |
|---|---|---|
| 1. 자막 선택 | 편집의 글자 목록에는 문구와 시작·끝 시간이 있다. 같은 문구가 여러 장면에 있으면 어느 장면인지 목록만으로 고르기 어렵다. ‘장면 제작 → 버전 비교·선택’은 생성된 클립의 버전을 바꾼다. | **편집 → 글자 레이어**에서 재생 위치·장면 이름·자막 구간을 함께 보여준다. 예시로 ‘장면 2 · 제품 사용 / 00:03–00:05’처럼 표시한다. 여러 장면에 걸친 자막은 실제 범위를 표시한다. 필수 표기는 기존 잠금 안내를 유지한다. |
| 2. 이전 문구 비교 | 기존 입력란은 수정할 문구를 보여주고 저장 전 변경 배지를 표시한다. 이전에 저장한 문구와 현재 입력을 같은 위치에서 대조하기 어렵다. | **‘문구’ 입력란 아래**에 ‘이전 저장본 r4 / 수정 중’ 두 값을 같은 레이어 ID 기준으로 표시한다. 예시 ‘하루 종일 사용’ → ‘한 번 충전해 사용’. 390px은 위아래, 1280px은 좌우로 읽는다. 색과 함께 ‘이전·수정’ 라벨을 쓴다. 비교할 저장본이 없으면 ‘첫 저장 전’으로 표시한다. |
| 3. 저장과 검수 | ‘장면·글자·소리 설정 저장’은 타임라인·내용 버전을 갱신한다. 저장 도중 다른 창에서 편집했거나 더 최신 버전이 생길 수 있다. | **저장 결과**에 서버가 반환한 타임라인 번호를 표시하고 같은 자막의 저장 전후 문구를 유지한다. 다른 편집도 함께 저장됐다면 ‘자막만 변경’이라고 표시하지 않는다. 충돌 시 기존 복구 안내를 우선하고, 최신 버전에서 다시 대조한다. ‘수정 확인 완료 · 검수로’에서 현재 내용으로 검수를 진행한다. |
| 4. 새 MP4 확인 | ‘영상 만들기’는 저장한 타임라인을 사용한다. 이전 결과와 새 결과가 함께 남고, 사용 가능한 결과에 ‘영상 보기·내려받기’가 있다. 편집용 ZIP에는 완성 MP4가 없고 ‘완성 영상 내보내기’는 잠겨 있다. | **현재 리비전의 렌더 결과 카드**에 ‘영상 보기’와 ‘이 버전 MP4 내려받기’를 모은다. 이전 결과에는 해당 리비전과 ‘보관본’을 표시한다. 실패·취소·파일 없음이면 같은 카드에서 사유와 ‘다시 만들기’를 보여준다. 검수 승인·최종 내보내기·게시 상태는 각각 실제 서버 판정에 맞춘다. |

반영 확인은 같은 자막이 두 장면에 있는 경우부터 시작한다. 한 레이어만 수정해 원본 클립 선택·다른 자막·이전 결과 파일이 유지되는지 확인한다. 새 결과의 리비전이 저장본과 맞고 수정한 구간에 새 문구가 보일 때 해당 MP4를 내려받는다. 이 절은 기존 구현과의 설계 대조이며 실제 렌더·휴대폰 재생은 별도 검증 대상이다. [편집 저장](../../components/editing-panel.tsx) · [글자 선택·입력](../../components/text-editor/text-editor.tsx) · [클립 버전](../../components/production-panel.tsx) · [영상 결과](../../components/render-panel/render-panel.tsx) · [편집용 ZIP](../../components/exports-panel.tsx)

**검수 화면에서 영상 결과로 이동할 때의 키보드 초점.** 독립 검수에서 390px·1280px 모두 현재 MP4와 새 영상 만들기 영역에 도착했지만, Enter 직후 초점은 문서 본문에 있었다. 만들기 버튼이 비활성인 경우 다음 Tab은 이전 영상의 보관 카드로 이동했다. ‘이 버전 MP4 확인’으로 이동하면 해당 결과 카드 제목에, ‘영상 만들기로 이동’이면 ‘새 영상 만들기’ 제목에 초점을 둔다. 제목에서 이어지는 읽기 순서에 현재 리비전 또는 만들기 제한 사유가 먼저 나온다. 재검수에서는 Enter 직후 화면 위치와 활성 제목을 함께 기록하고, 현재 버전 결과가 있는 경우와 이전 보관본만 있는 경우를 각 화면 폭에서 확인한다. ### 로컬 PG 자막 편집의 화면 차이

장면·구간 확인, 이전 저장본과 수정본 비교, 저장 후 재검수 흐름은 기존 시안을 따른다. 로컬 PG 편집에서는 현재 기준의 편집 가능한 자막 목록과 저장에 필요한 프레임 상한을 서버에서 받는다. [자막 부분 수정 시안](subtitle-revision-review.html) · [기존 내보내기 조사](../handoffs/LOCAL-PG-SUBTITLE-EXPORT-READINESS.md)

| 상황 | 로컬 PG에서 표시할 내용과 동작 |
|---|---|
| 자막 프레임 입력 | ‘시작 프레임’과 ‘끝 프레임’을 각각 표시한다. 30fps이며 시작은 0 이상, 끝은 시작보다 커야 한다. 저장 범위 상한은 응답의 `maxEndFrame`을 표시한다. ‘영상 길이’(`videoFrames`)와 ‘입력 가능한 끝 프레임’은 값이 다를 수 있으므로 이름을 구분한다. 기존 범위가 상한을 초과해도 해당 행을 그대로 유지할 수 있다. 그 행을 수정하면 새 범위를 확인하게 한다. 한 자막은 공백만으로 구성할 수 없고 500자까지, 전체는 100개까지 입력할 수 있다. |
| 보호 레이어와 목록 저장 | 목록에는 서버가 반환한 편집 가능한 자막만 표시한다. ‘필수 표기와 잠긴 글자 레이어는 보호돼요’라고 안내한다. 보호 레이어의 문구·시간·삭제 조작은 제공하지 않는다. 제출은 편집 가능한 자막 전체 목록이며, 사용자가 삭제한 행만 제출에서 빠진다. 저장 전에는 초안에서 삭제를 취소할 수 있게 한다. |
| 저장 기준이 바뀌거나 응답이 끊김 | **있던 초안을 유지**하고, 다른 탭에서 먼저 저장한 경우 최신 저장본을 읽어 기존 비교 방식으로 보여준다. 최신 목록을 기준으로 수정할 행을 다시 확인한 뒤 새 요청으로 저장한다. 자동 병합하거나 초안을 덮어쓰지 않는다. 응답 유실 때는 **같은 저장 요청 다시 확인**으로 원래 키와 본문만 다시 보낸다. |
| 저장 결과와 승인 상태 | `changed: true`이면 서버의 새 타임라인 번호·내용 리비전을 표시하고 **‘자막을 저장했어요. 현재 내용의 편집 완료와 검수를 다시 진행해 주세요.’**라고 안내한다. 기존 승인은 이전 버전에 귀속된다. `changed: false`이면 ‘저장된 자막과 같아요’라고 안내하고 같은 리비전을 표시한다. |

데이터 기준은 `GET /api/projects/{id}/timeline/subtitles`의 `timelineId`, `contentRevision`, `timelineRevision`, `subtitles`, `videoFrames`, `maxEndFrame`, `blockedReason`이다. 제작 승인, 기준 타임라인의 유무·유효성, 현재 선택 장면이 맞지 않으면 해당 차단 사유와 돌아갈 화면을 안내한다. POST는 UUIDv7 요청 키와 `expectedTimelineId`, `expectedContentRevision`, `subtitles`를 보낸다. 새 자막은 UUIDv7 ID를 사용한다. [자막 경로](../../app/api/projects/%5Bid%5D/timeline/subtitles/route.ts) · [자막 편집 범위](../../lib/cloud/local-subtitle-edits.ts) · [저장과 승인 상태 갱신](../../lib/cloud/local-timeline-audio.ts)

**390px 키보드 검수.** 자막 행을 선택하고 문구 → 시작 프레임 → 끝 프레임 → 저장 순으로 이동한다. 범위 오류가 나면 해당 입력에 초점을 두고 안내를 읽을 수 있어야 한다. 저장 결과나 충돌 안내에 초점을 둔 뒤 Tab으로 다음 확인 또는 재시도에 도달해야 한다. 두 탭에서 같은 자막을 수정해 최신본과 초안이 함께 남는지, 한 자막의 변경으로 기존 WAV와 선택 장면이 보존되는지도 확인한다.

별도 SRT/VTT 다운로드와 MP4 화면의 자막 표시는 후속 기능이다. 현재 화면에는 자막 저장과 재검수까지만 안내한다. [내보내기 연결과 MP4 제약](../handoffs/LOCAL-PG-SUBTITLE-EXPORT-READINESS.md)

### 로컬 PG 편집 완료와 현재 버전 검수

쇼핑숏츠 편집에서 **수정 확인 완료 · 검수로**를 누르면 저장 기준을 확인하고 해당 버전의 검수로 이동한다. 작업실의 공통·분야·조건별 항목과 ‘필수 N개 중 M개 통과’를 재사용한다. 상단에는 서버가 반환한 **내용 버전**을 표시하고, 요청에는 같은 응답의 타임라인 ID를 함께 보낸다. 타임라인 번호를 따로 확인할 수 있는 화면에서는 두 숫자의 이름을 각각 표시한다. [기존 편집 화면](../../components/editing-panel.tsx) · [기존 검수 화면](../../components/review-panel.tsx)

| 사용자 상황 | 화면과 조작 |
|---|---|
| 제작 미승인, 기준 없음, 선택한 장면이 바뀜 | ‘장면 제작을 먼저 승인해 주세요’, ‘편집에서 기준 타임라인을 저장해 주세요’, ‘편집에서 지금 선택으로 저장해 주세요’를 각각 표시하고 해당 단계로 연결한다. 현재 기준으로 편집을 완료할 때까지 항목 저장과 승인은 잠긴다. |
| 편집 완료 | 서버가 확인한 편집 완료를 받은 뒤 검수 제목으로 초점을 옮긴다. 제작·자막 수정으로 버전이 바뀌면 최신 기준으로 다시 편집 완료한다. |
| 항목 판정과 메모 | 항목마다 ‘미확인 / 통과 / 보류’의 저장 상태와 메모를 표시한다. 기존 UX대로 보류를 고르면 사유 칸에 초점을 두고 사유를 적은 뒤 저장한다. 저장 중 동일 작업의 중복 입력을 막고, 성공 응답에서 받은 판정과 메모로 표시를 확정한다. 실패 시 입력을 유지하며 재시도 위치를 안내한다. |
| 필수 항목이 남음 | ‘필수 N개 중 M개 통과’와 남은 항목을 표시한다. 항목을 열 수 있게 하고, 승인 조작에는 ‘필수 N개를 통과해야 해요’라는 이유를 연결한다. 자동 검사의 근거는 사람이 확인할 때 참고한다. |
| 승인 가능 | 모든 필수 항목이 저장된 ‘통과’일 때 **검수 승인**을 제공한다. 승인 결과를 받으면 ‘내용 버전 rN의 검수를 승인했어요’로 표시하고 확인 문구로 초점을 옮긴다. 승인한 항목과 메모는 읽기 전용으로 표시하고 **영상 만들기로 이동**을 제공한다. 렌더 화면에서는 ‘새 영상 만들기’ 제목에 초점을 둔다. |
| 구버전 또는 승인 응답 유실 | 새 버전과 충돌하면 ‘내용이 바뀌었어요. 최신 버전에서 검수해 주세요’를 표시하고 최신 상태를 조회한다. 승인 응답이 끊기거나 이미 승인됐다는 응답이 오면 **승인 상태 다시 확인**으로 먼저 조회한다. 같은 기준이 승인돼 있으면 완료로 표시한다. 같은 기준이 여전히 미승인이고 필수 항목을 충족할 때만 승인 버튼을 다시 제공한다. |

**예정 API와 상태 연결.** 로컬 소유자 `GET /api/projects/{id}/review`의 `revision`, `timelineId`, `editCompleted`, `approved`, `items`, `blockedReason`을 사용한다. `POST`는 동일 기준과 `complete-edit`, `review-item`, `approve-review` 중 하나를 보낸다. 항목 저장의 `input`은 `itemId`, `status`, `note`다. 성공 본문으로 서버 상태를 갱신한다. `CURRENT_TIMELINE_CONFLICT`와 `REVIEW_ALREADY_APPROVED`는 재조회로, `EDIT_COMPLETION_REQUIRED`는 편집 완료로, `REQUIRED_ITEMS_INCOMPLETE`는 최신 필수 항목 표시로 연결한다. 익명 응답은 로그인으로, 접근 불가 응답은 프로젝트 목록으로 안내한다. 렌더 요청 가능 여부는 현재 리비전과 타임라인에 귀속된 승인을 서버에서 확인한다. [로컬 PG 렌더 승인 조건](../handoffs/FIRST-WORK-PG-RENDER-REQUEST.md)

**완료 기준.** 390px·1280px 키보드 조작으로 편집 완료, 판정·메모 저장, 승인, 렌더 제목 도착을 각각 확인한다. 보류 사유 입력과 필수 미완료 시 승인 차단, 이전 버전에서의 쓰기 거절, 응답 유실 후 재조회로 승인 한 건 확인을 포함한다. 저장 결과·오류를 알리고, 조작이 사라지면 상태 또는 복구 조작에서 이어갈 수 있어야 한다. 승인 자체와 출력 완료는 각각 서버가 확정한 상태로 표시한다.

### 첫 작품 게시 전 점검

**진입 위치**는 관리자 ‘완성본 검수·게시’의 작품 카드 안, 권리 확인 체크 상자 바로 위다. 먼저 작품 제목·종류·대상 리비전을 보여준다. 게시 서버 미연결이면 기존 연결 안내를 표시한다. 목록 읽기 실패면 ‘목록 다시 불러오기’, 조회 성공 후 빈 목록이면 ‘검수할 완성본이 없어요’를 표시한다. 작품이 있어야 아래 점검을 시작한다.

| 점검 항목 | 카드에서 확인할 수 있는 정보 | 확인이 필요한 경우와 수정 위치 |
|---|---|---|
| 사진 출처·권리 | ‘권리 증빙 확인됨/미확인’과 운영자의 명시적 확인 체크. 목록 응답에는 사진 출처 메모 본문이 없다. | 메모를 입력하는 위치는 로컬 ‘새 프로젝트 → 사진 출처·권리 메모’다. 이미 등록한 메모의 편집 경로는 검증되지 않았다. ‘권리 증빙 미확인’이면 원본과 사용 허락을 권리 검수 담당자에게 전달하고 목록을 갱신한다. 메모 입력만으로 게시 권한을 부여하지 않는다. |
| 표지 | 관리자 목록에는 표지 이미지나 해당 리비전의 표지 검증 상태가 없다. **이 화면에서 표지 확인 불가**로 표시할 수 있다. | 표지 검수 담당자가 같은 작품·리비전의 표지와 저장소 증빙을 확인한다. 준비 중인 세대의 공개 주소는 확인 수단으로 사용하지 않는다. 게시 후 공개 홈에서 같은 작품의 표지가 표시되는지 확인한다. |
| 재생 파일 | 영상·음악은 종류와 원본 완성 여부를 확인할 수 있다. 완성 여부만으로 실제 재생 성공을 판단할 수 없다. 이미지 작품은 **재생 점검 대상 아님**으로 표시한다. | 영상·음악은 렌더·게시 담당자가 해당 리비전의 결과 파일과 검증 기록을 대조한다. 원본이 바뀌면 수정한 완성본과 증빙을 다시 준비한다. 관리자 카드에 재생 결과가 전달되기 전에는 **재생 확인 필요**로 안내한다. |

**게시 순서** — 원본이 미완성이거나 권리 증빙이 미확인이면 기존 사유를 표시한다. 요건을 갖춘 작품은 운영자가 권리와 표시 문구를 확인하고 ‘게시 준비’를 누른다. ‘준비된 세대’ 번호를 확인한 뒤 해당 세대의 ‘게시’를 누른다. 새 리비전이나 충돌 안내가 오면 목록을 갱신하고 대상 작품부터 다시 확인한다. 표지·재생 상태를 화면에서 확인할 수 없다는 이유만으로 새 차단 규칙을 추가하지 않는다. 최종 게시 여부는 기존 서버 판정을 따른다.

**반영 검수** — 이미지에는 재생 버튼을 표시하지 않고, 영상·음악에는 실제 확인 전 ‘재생 가능’ 배지가 뜨지 않아야 한다. 미연결·목록 실패를 작품의 표지 누락으로 표시하지 않는다. 320픽셀에서 항목명·상태·다음 행동이 순서대로 읽히며, 색상 없이도 확인 가능 여부가 구분돼야 한다. 향후 미리보기나 항목별 상태를 제공하려면 현재 리비전에 대응하는 검증 결과와 권한을 확인한 읽기 계약이 필요하다. [관리자 목록 계약](../../components/admin/publication-model.ts) · [응답 필드 검사](../../components/admin/publication-http-provider.ts) · [게시 서버의 미디어 검증](../handoffs/T370-PLAYBACK-PUBLICATION-PG17.md)

### 뮤직 컬렉션 메뉴 적용 문구

| 위치 | 적용 문구와 동작 |
|---|---|
| 주 메뉴의 세 번째 링크 | **뮤직 컬렉션**. 클릭하거나 Enter를 누르면 현재 음악 컬렉션 섹션으로 이동한다. |
| 작품 목록 오른쪽 링크 | **뮤직 컬렉션 ↗**. 주 메뉴 링크와 같은 섹션으로 이동한다. 장식 화살표는 접근성 이름에서 제외한다. |
| 도착 섹션의 제목 | **뮤직 컬렉션**. 섹션에 초점이 이동했을 때 보조기술에도 같은 이름이 전달되도록 제목과 섹션을 연결한다. |
| 제목 아래 소개 | **한 장의 커버, 무한한 상상.** 기존 대표 문구를 소개 문장으로 옮긴다. |

‘크리에이터 로그인’은 계정 진입점이므로 원래 이름을 사용한다. 음악 카드가 0개여도 제목과 현재 빈 목록 안내를 보여준다. 반영 후 320·390·1280픽셀에서 두 링크가 같은 제목에 도착하는지, 320픽셀에서 주 메뉴 세 항목이 잘리지 않는지, 상세를 닫으면 선택했던 음악 카드로 초점이 돌아가는지 확인한다.

대표 작품 상세에서 Escape를 누르면 창이 닫히고 원래 표지 버튼으로 초점이 돌아왔다. 관리자 모바일에서 ‘완성본 검수·게시’를 누르면 대상 섹션으로 초점이 이동하고 선택 메뉴의 현재 위치 표시도 바뀌었다. 세 화면 폭에서 홈과 관리자 모두 페이지 전체 가로 넘침이 없었다. 후속 수정 때 이 동작을 회귀 확인한다.

운영의 클라우드 분석 주소는 ‘찾는 화면이 없어요’를 표시했다. 분석 결과 화면의 가독성·입력 오류·재생 중 조작은 해당 버전이 배포된 뒤 확인할 항목이다. 이 점검에서는 게시·철회, 계정 변경 또는 운영 데이터 쓰기를 실행하지 않았다.

### 수정 후보 재검수 기준
