# 클라우드 콘텐츠 분석 화면 인계

[HTML 시안 열기](http://127.0.0.1:8769/docs/design/rea-cloud-analysis/index.html) · [시안 원본](index.html)

| 동작 | 시안의 완료 기준 |
|---|---|
| 이미지·음악·영상/쇼츠 | 종류별로 등록 자료를 선택한다. PNG·M4A·MP4는 **검증 범위를 보여주는 예시**로 표시한다. 영상·쇼츠는 등록 MP4를 선택하는 화면이다. |
| 입력 출처와 권리 | 자료를 고른 뒤 분석 권리를 확인하면 실행할 수 있다. 자료·종류·입력 출처를 바꾸면 이전 권리 선택과 분석 결과를 초기화한다. 실제 구현은 계정, 프로젝트 접근권과 검증된 등록 사본을 서버에서 확인한다. |
| 게시물 URL | YouTube·Instagram·TikTok 등의 게시물 주소를 고르면 미지원 안내와 등록 자료 선택 방법을 보여준다. 직접 파일 URL의 JPG·MP3·MP4 시험은 로컬 작업실의 제한된 원본 범위에서 진행됐다. [로컬 공개 파일 URL 검증](../../handoffs/REA-PUBLIC-URL-LOCAL-STUDIO.md) |
| 접근 제한·미연결·빈 결과 | 접근 제한과 공급자 미연결에서는 파일명·결과를 표시하지 않고 실행을 잠근다. 빈 결과에는 ‘표시할 관찰 근거가 없어요’와 다음 행동을 안내한다. 제품의 보호된 셸은 현재 권한 공급자 연결 전 자료를 전달하지 않는다. [보호된 셸 검수](../../handoffs/T317-R-REA-CLOUD-ANALYSIS-PROTECTED-SHELL-REVIEW.md) |
| 결과와 초안 | 직접 관찰과 분석 추정을 각각 표시하고 근거 위치를 붙인다. ‘분석으로 생성한 초안’과 ‘내 수정본’을 보여주고 제작자가 공개한 프롬프트의 확인 여부를 표시한다. 등록 자료의 경로·계정·내부 ID는 공개하지 않는다. [등록 사본 분석 계약 검수](../../handoffs/T284-R-REA-STUDIO-ANALYSIS-CONTRACT-REVIEW.md) |

390×844·1440×900 Chromium에서 세 종류 변경, 파일 선택 전·권리 확인 전의 실행 차단, 키보드 Space→Tab→Enter로 결과 제목 초점 이동, 미지원 게시물 URL 및 접근 제한·미연결·빈 상태를 확인했다. 두 폭에서 가로 넘침은 0px이었다. 1440px에서는 입력과 결과가 두 열이고 390px에서는 위아래로 이어진다. 캡처는 `tmp/rea-cloud-analysis-proof/`에 있다.

HTML은 상태와 인터랙션을 보여주는 자체 검증용 예시다. 제품에서 결과 동선이 연결되면 작업실의 실제 401/403·미연결 및 승인된 분석 공급자 응답을 사용해 별도로 검수한다.

## 관련 시안 이동

분석 입력과 결과 아래의 **관련 시안**에서 [등록 자료 선택과 접근 상태](registered-cases.html), [PNG·WAV·MP4 결과 비교](result-comparison/index.html), [세션 확인·401·403 안내 비교](session-guidance/compare.html)를 바로 열 수 있다.

390×900에서는 링크 1열, 1440×900에서는 3열이었다. 각 링크의 높이는 44px 이상이고 문서 가로 넘침은 0px이었다. 첫 Tab은 기존 상태 선택에 도달했고, 수정본에서 다음 Tab으로 세 링크를 순서대로 통과했다. Shift+Tab 역방향 이동과 Enter로 각 목적지의 URL·제목을 두 폭에서 확인했다. 외부·API 요청은 0건이었다.

결과 비교와 세션 안내를 직접 열어도 **콘텐츠 분석 전체 시안** 링크로 돌아갈 수 있다. 두 폭에서 기존 조작 뒤 마지막 Tab으로 복귀 링크에 도달하고 Enter로 전체 시안을 열었다.
