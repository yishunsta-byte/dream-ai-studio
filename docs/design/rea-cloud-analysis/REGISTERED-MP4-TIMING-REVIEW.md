# 등록 MP4 분석 결과의 시간 표시 대조

고정 격리 검수 `c07ebbe`와 같은 리비전의 결과 렌더러·DTO를 기존 콘텐츠 분석 시안과 대조했다. Front가 소유 PG17과 루프백 브라우저에서 검증한 것은 등록 MP4의 선택, 분석, 권한 철회와 계정 전환이다. 이번 대조는 소스와 기존 결과를 읽었다. 음악은 실측 범위 밖이며 실제 Next 페이지와 운영 연결은 별도 검증 대상이다. ## 원본 시간과 편집 시간

| 화면에 보이는 항목 | 고정 결과와 표시의 의미 | 권장 안내 |
| --- | --- | --- |
| 원본 프레임 표시 시각 | 검수에서 디코딩 프레임 결과가 `0 ms`와 `1000 ms`로 나왔다. 전환 후보의 원본 프레임도 `1000 ms`다. 결과의 `sourceSeek.ptsMs`는 그 결과에 포함된 실제 디코딩 프레임의 표시 시각이다. 기존 시안의 `992ms`는 별도의 시험 값이다. | 동일 시각의 선택지에도 프레임 관찰과 장면 전환 후보의 이름을 붙여 구분한다. 상세에는 **원본 프레임 표시 시각**과 단위 `ms`를 그대로 표시한다. |
| 인접 프레임의 평균 RGB 차이 | 세 번째 결과에서 `967–1000 ms` 사이의 인접 프레임 평균 RGB 차이 `74.51%`가 표시됐다. 이후 프레임의 디코딩 시각 `1000 ms`도 같은 결과의 관찰에 포함된다. | 비교한 구간과 차이 값을 **관찰 근거**에 함께 둔다. 앞뒤 프레임의 색 변화 크기를 설명하고 전환 후보의 판정은 별도 항목으로 표시한다. |
| 장면 전환 후보 | 세 번째 결과의 **분석 추정**은 `967–1000 ms` 구간을 가리키고 디코딩 프레임과 RGB 차이의 관찰 번호를 참조한다. 두 프레임 관찰 결과의 추정 항목에는 ‘이 결과에 포함된 추정이 없어요’가 표시된다. | **장면 전환 후보**에 관찰 번호와 구간을 붙인다. 창작에 쓰는 전환 선택은 편집할 초안에서 이해할 수 있게 한다. |
| 30fps 편집 기준 | 고정 화면은 `editGridApproximation`이 있는 경우 창작 초안에 ‘편집 그리드 기준 약 N프레임 · 30 fps’를 표시한다. 코드는 원본 시각을 초로 바꾼 뒤 편집 격자에 반올림한다. 예를 들어 `1000 ms`는 편집 기준 약 30프레임이다. 이 값은 코드에서 대조했고, `c07ebbe` 실측 스크립트의 결과 수집은 원본 시각·관찰을 대상으로 한다. | **편집 기준 약 30프레임 · 30 fps**를 초안 옆에 둔다. 원본 프레임 시각을 읽는 곳과 편집용 근사치를 읽는 곳을 분리한다. |
| 창작 초안 | 등록 화면은 **창작 초안**, **프롬프트 편집**, **초안 복사**를 표시한다. 원본 PTS와 편집 프레임은 결과의 표시값이다. 이 화면의 조작은 결과 선택과 초안 편집·복사다. | 초안의 대상 결과가 어떤 관찰인지 읽을 수 있게 하고 **분석으로 생성한 초안**과 **내 수정본**을 구분한다. ‘제작자가 공개한 프롬프트는 확인되지 않았어요’를 초안 옆에 둘 수 있다. |

고정 표시는 `c07ebbe:components/reference-analysis/studio-registered-analysis.tsx`, 시각·편집값 계산은 `c07ebbe:lib/reference-analysis/project-preview.ts`에서 확인했다. ## 권한과 계정이 바뀔 때

| 단계 | 격리 실측 또는 코드에서 확인한 동작 | 390px·1440px 안내와 초점 기준 |
| --- | --- | --- |
| 선택과 분석 성공 | 두 폭 모두 첫 진입에서 초점을 가져가지 않았다. 자료 선택 다음 Tab은 권리 체크였다. 체크 후 Enter로 분석하면 **분석 결과** 제목에 초점이 왔고, 결과 선택 상자에서 키보드로 세 결과를 넘겼다. | 결과 제목이 보이고 다음 조작으로 결과 선택에 도달해야 한다. 선택을 바꿀 때 해당 결과의 프레임·관찰·추정·초안이 함께 갱신돼야 한다. |
| 접근 제한 감지와 재조회 | 권한 철회 뒤 **다시 분석**을 실행했을 때 `source_unavailable`로 처리됐다. 코드에서는 이전 분석 화면을 지우고 목록 로딩 안내를 그린 뒤 초점을 옮긴다. | 이전 결과와 편집본은 바로 숨긴다. 안내가 표시된 뒤 초점을 로딩 상태에 놓는다. 목록 갱신이 끝나기 전까지 이전 선택이나 결과를 복원하지 않는다. |
| 목록 갱신 완료 | 실측에서는 목록이 비었고 선택·권리 체크·원본 시각·초안이 모두 사라졌다. 초점은 **분석할 수 있는 등록 자료가 없어요**에 갔다. 자료가 남는 분기는 같은 고정 코드에서 선택 상자로 초점을 보낸다. | 빈 경우는 빈 목록 안내와 다시 조회, 남아 있는 경우는 접근 불가 안내와 새 선택을 제공한다. 남은 자료는 사용 권리를 다시 확인한다. |
| 계정 전환 | 검수는 B 계정으로 바꾼 뒤 시험 페이지를 새로 열었다. B 자신의 자료만 표시됐고 선택·체크·결과가 초기화된 상태로 시작했다. 브라우저의 새 계정 분석도 B의 자료만 사용했다. | 새 계정의 자료 목록에서 선택을 시작한다. 이전 계정의 자료 이름, 시각, 추정·초안, 이전 요청을 복원하지 않는다. 첫 진입처럼 초점을 강제로 이동시키지 않는 흐름을 확인한다. |

기존 브라우저 기록은 분석 성공 시 세로 900px에서 결과 카드가 너비 390px에서는 입력 아래, 1440px에서는 입력 옆에 놓였고 권한 철회 후 빈 목록에서는 두 폭 모두 문서의 가로 넘침이 0px이었음을 보여 주며, 성공 화면의 가로 넘침은 후속 확인 항목이다. 후속 확인에서는 긴 밀리초 범위와 편집 프레임 단위가 잘리지 않고, 결과 선택·초안·다시 조회의 키보드 순서가 두 폭에 맞는지 대조한다. 권한과 실제 Next 연결의 독립 검증은 별도 범위다. ## 후속 확인 · 격리 Next 작성자 실행의 보존 기록

`2d782af`의 작성자는 실제 Next 보호 셸의 격리 빌드 사본에 소유 PG17의 등록 MP4 시험 공급원을 연결했다. 보존 `round-next-report.json`, 글자 수를 정정한 `13271f8`, UI Tester의 읽기 전용 독립 대조 `msg_b77cfe0d0541`을 확인했다. 위 `c07ebbe`는 일반 HTML 격리 실행이며, `0894c66`은 고정 결과값의 시간 표시 시안이다. [격리 Next 인계](../../handoffs/REA-CLOUD-PROTECTED-MP4-NEXT-PG17.md) · [시간 비교 시안 인계](mp4-result/HANDOFF.md) · [시안 독립 검수](../../handoffs/REA-R-REGISTERED-MP4-TIMING-PROTOTYPE-REVIEW.md)

| 작성자 보존 기록 | 관측 범위 |
| --- | --- |
| 390×900·1440×900 가로 넘침 | A·B의 분석 성공 화면 4건과 A 승인 철회 뒤 빈 화면 2건에서 `scrollWidth - clientWidth`가 모두 0px이었다. 철회 뒤 A에서 선택·권리 체크·결과·초안을 지우고 **분석할 수 있는 등록 자료가 없어요** 안내에 초점을 뒀다. 그동안 B의 목록은 유지됐으며 B의 철회 화면은 측정하지 않았다. |
| 세션과 첫 화면 | `127.0.0.1`의 A 탭과 `localhost`의 B 탭으로 세션을 나눠 각자 본인 목록 하나와 교차 요청 거절을 확인했다. 첫 진입의 BODY 초점은 A에서 기록했다. B의 새 화면은 미선택·미체크 상태였고 초안이 없었다. 쿠키 속성과 동일 탭에서 로그아웃 후 다른 계정으로 전환하는 동작은 측정하지 않았다. |
| HTML·Flight와 프리페치 요청 | 로그인 A가 HTML과 수동 헤더로 Flight·라우터·세그먼트 프리페치 응답을 확인했다. 셸 응답 4건은 200, 보호 목록의 RSC·라우터 프리페치 요청 2건은 204였고 이 요청들이 목록 조회를 시작한 횟수는 0이었다. 자발적 브라우저·라우터 프리페치와 실제 Next의 `Sec-Purpose`는 측정하지 않았다. 본문 값은 `r.body.length`로 센 글자 수이며 실제 전송 바이트 수는 측정하지 않았다. |

독립 대조는 보존 JSON·실행 기록·고정 계약을 읽은 결과다. 격리 Next의 독립 기동·재실측은 보류 중이며 운영 연결은 별도 범위다. 이 절은 보존 자료를 읽어 작성했다.
