# 로컬 공개 URL 분석 입력 오류와 복구 대조

로컬 작업실 구현 `1ae0e2e`, 결과 비교 후보 `13ca0b0`, 독립 검수 `436cb3c`와 후속 성공 초점 수정 `a0c7757`을 읽기 전용으로 대조했다. 이 흐름은 이 PC의 **레퍼런스 분석 → 공개 URL 분석**이다. 정상 결과는 공개 원본 링크, 관찰 근거, 분석 추정, 생성 초안과 내 수정본을 보여주는 미리보기다. [로컬 URL 실측](../../handoffs/REA-PUBLIC-URL-LOCAL-STUDIO.md) · [세 파일과 오류의 독립 검수](../../handoffs/REA-LOCAL-RESULTS-INDEPENDENT-REVIEW.md)

## 확인된 지원 범위

- 허용된 원본은 `interactive-examples.mdn.mozilla.net`, `mdn.github.io`, `tonejs.github.io`의 HTTPS 직접 파일 주소다. 고정 소스는 주소의 사용자 정보·쿼리·해시와 리디렉션을 거절한다. 허용된 원본에서도 파일 형식과 크기, 재생 시간을 확인한다. 화면에는 음악 24초, 영상 20초·240프레임까지라고 표시된다.
- 실제 브라우저에서 확인한 조합은 MDN의 JPG와 MP4, Tone.js의 MP3다. 해당 표본에서 이미지 색·밝기 분포, 음원의 채널과 RMS, 영상의 디코딩 프레임 시각을 관찰했다. WAV 표본의 시간축 검증 실패도 기존 기록에 있으므로 확장자만 보고 분석 가능하다고 안내하지 않는다.
- YouTube 게시물 주소에서 오류를 표시하고 이전 결과를 제거한 동작을 독립 검수에서 확인했다. Instagram·Threads·TikTok 게시물과 프로필 주소는 고정 원본 허용 조건 밖이다. 이번 대조에서는 이 플랫폼들을 요청하거나 그 콘텐츠를 분석하지 않았다.

주소와 오류 판정은 `13ca0b0:lib/reference-analysis/local-media-url.ts`와 `13ca0b0:app/(studio)/studio/reference-analysis/actions.ts`에서 확인했다. [로컬 결과 폼](../../../components/reference-analysis/local-url-analysis.tsx)

## 현재 복구 동작과 권장 안내

| 상태 | 소스와 독립 기록에서 확인한 동작 | 화면 안내 기준 |
| --- | --- | --- |
| 주소를 바꿈 | 주소 입력을 수정하면 권리 체크가 풀리고 이전 근거·원본 링크·수정 초안과 오류가 지워진다. 새 주소와 권리 확인 전에는 실행할 수 없다. | 새 주소를 확인한 뒤 **이 자료를 분석할 권리가 있어요**를 다시 체크하도록 안내한다. 키보드 초점은 URL 입력을 유지한다. |
| 권리 확인을 해제함 | 주소는 유지되고 현재 결과와 오류가 제거되며 실행 버튼이 비활성화된다. 확인을 다시 해도 새 분석 실행 전까지 이전 결과가 돌아오지 않는다. 실행 중에는 주소와 체크 조작이 비활성화된다. | 해제 직후 현재 체크에 초점을 둔다. 자료 권리를 확인할 수 있는 경우에만 다시 체크하고 실행한다. 실행 중 조작이 잠기는 범위를 안내한다. |
| 주소 형식이 잘못됨 | `type="url"`의 브라우저 검증이 제출을 막는다. 이 경우 결과가 없고 URL 필드에서 형식을 고칠 수 있다. | ‘미디어 파일의 전체 HTTPS 주소를 입력해 주세요’처럼 수정 지점을 안내한다. 기존 주소를 바로 고칠 수 있게 한다. |
| 미지원 게시물 또는 파일을 가져오지 못함 | 제출을 시작할 때 이전 결과를 제거한다. `13ca0b0`은 서버 오류를 `role="alert"`에 표시한다. YouTube 사례는 ‘분석하지 못했어요. 지원하는 공개 파일 주소와 파일 형식·길이를 확인해 주세요’가 나왔고 원본 링크와 편집기가 사라졌다. | 입력 도움말에 허용된 직접 파일과 게시물 주소의 지원 여부를 밝힌다. 동일한 오류 문구만으로 주소 문제·파일 형식·연결 실패를 특정하지 않는다. 사용 권리가 있는 직접 파일 주소를 다시 확인하도록 안내한다. |
| 분석 근거·제안 부족 또는 전송 실패 | 근거가 부족해 분석 또는 제안을 만들 수 없으면 URL 분석기가 예외를 내고 서버는 ‘분석하지 못했어요. 지원하는 공개 파일 주소와 파일 형식·길이를 확인해 주세요’를 반환한다. URL 분석기의 성공 결과는 항상 `ready`이므로 이 경로에서는 ‘관찰 근거를 찾지 못했어요’에 도달하지 않는다. 클라이언트의 서버 액션 호출 자체가 실패하면 별도로 ‘분석 결과를 받지 못했어요. 다시 시도해 주세요’를 표시한다. 결과 UI는 비워 둔다. 바뀌지 않은 주소는 권리를 유지한 상태에서 같은 폼으로 재시도할 수 있다. | 오류가 나온 뒤에는 URL 입력과 실행으로 다시 닿는 위치를 제공한다. 수정이 필요하면 URL부터 확인한다. 사용자가 폼 밖으로 이동한 경우 기존 초점을 유지하는 것을 후속 검수 기준으로 둔다. |

## 390px·1440px 키보드 검수 기준

| 상태 | 확인·완료 기준 |
| --- | --- |
| 성공 | URL → Tab 권리 확인 → Space → Tab 실행 → Enter 순이다. `13ca0b0` 독립 검수에서는 성공 직후 초점이 본문으로 돌아갔다. `a0c7757`의 후속 수정은 성공 시 제목으로 초점을 옮기고, 사용자가 폼 밖으로 옮긴 초점은 유지한다. 다음 Tab으로 결과 선택이나 공개 원본 링크 등 현재 결과의 첫 조작에 닿아야 한다. |
| 변경·해제·오류 | 두 폭 모두 URL 변경과 체크 해제, 새 분석 실패에서 이전 원본 링크와 결과·편집 영역이 보이지 않아야 한다. 잘못된 주소는 입력칸에서 수정하고, 서버 실패는 오류 알림을 읽은 뒤 입력 또는 실행에 다시 닿을 수 있어야 한다. `a0c7757`의 자동 초점 변경은 성공 경로에 적용됐다. |
| 배치 | 390px에서는 근거 다음에 편집이 이어지고, 1440px에서는 근거와 편집을 양쪽에서 읽는다. 독립 검수에서 두 폭의 문서와 결과 영역의 가로 넘침은 0px이었다. 긴 허용 원본 주소와 오류 문구, 폼으로 돌아가는 초점은 두 폭에서 함께 확인한다. |

이 문서의 안내 기준은 후속 제안이다. 신규 분석 요청이나 플랫폼 검수는 수행하지 않았다. [후속 키보드 검수 스크립트](../../../tests/reference-analysis/local-url-analysis-screen.ego.mjs) · [사용자 안내의 기존 입력 범위](../api-user-manual.md)

## 결과 전환과 다시 분석 시 수정본 범위

`85e8958` 독립 검수는 `26065fd`의 로컬 URL 분석 화면에 같은 시험 URL의 두 합성 결과를 주입했다. 영상 근거는 첫 실행에 0·1000 ms, 두 번째 실행에 0·2000 ms를 사용했다. Chromium 390×844·1440×900에서 한 실행 안의 결과 전환, 같은 주소의 재분석, 새로고침을 각각 확인했다. [버전 저장·복원 독립 검수](../../handoffs/REA-R-LOCAL-URL-VERSION-PERSISTENCE-REVIEW.md)

| 조작 | 확인된 상태와 안내 기준 |
| --- | --- |
| 한 실행 안에서 결과를 바꿈 | 방향키로 근거 위치를 오갈 때 수정본이 결과별로 복원됐다. 화면에서 보고 있는 수정본은 **초안 복사**로 복사할 수 있다. 버튼은 현재 입력값을 복사한다. |
| 같은 주소로 다시 분석함 | 새 관찰과 생성 초안이 표시됐고 이전 결과와 수정본은 지워졌다. 안내 제안은 ‘다시 분석하면 현재 결과와 수정본이 바뀌어요. 필요한 수정본은 먼저 복사해 주세요.’다. |
| 페이지를 새로고침함 | 주소 입력·권리 확인·결과·수정본이 초기화됐고 브라우저 저장소에도 저장 항목이 없었다. 안내 제안은 ‘수정본은 현재 분석 결과에서만 유지돼요. 새로고침하면 지워져요.’다. |

현재 진입점에서 확인한 기능은 한 실행의 근거·초안 비교다. 같은 주소의 서로 다른 분석 실행을 저장하고 새 문서에서 양쪽 근거와 수정본을 복원하는 기준은 별도 후속으로 남아 있다.
