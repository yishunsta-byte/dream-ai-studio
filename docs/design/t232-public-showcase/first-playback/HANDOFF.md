# 공개 작품 최초 재생 조작 비교

[키보드 비교 시안 열기](http://127.0.0.1:8769/docs/design/t232-public-showcase/first-playback/compare.html) · [HTML 원본](compare.html) · [공개 재생 상태 대조](../PLAYBACK-STATE-REVIEW.md)

같은 영상 예시 **옥상 너머**를 두 화면에서 연다. 기존 Dream Screen 시험 표지를 사용했으며 재생·일시 정지는 문구와 버튼으로 모의 표시한다. 두 화면은 모두 상세의 **닫기**에 첫 초점을 두고 Escape나 닫기 조작 뒤 각 카드의 상세 열기 버튼으로 돌아온다. [시험 표지 자산 기록](../assets/ASSETS.md)

| 비교 화면 | 시안의 키보드 경로 |
| --- | --- |
| 브라우저 기본 재생 버튼 경로 | **닫기** → **미디어 요소 예시** → **재생**. 미디어 요소 예시에서 Enter·Space를 누르면 Tab으로 모의 재생 버튼에 이동하는 안내가 나온다. 버튼에서 누르면 모의 재생 상태가 바뀐다. |
| 최초 재생 시작 버튼 제안 | **닫기** → **재생 시작**. 첫 Tab으로 명시적인 버튼에 닿고 Enter·Space로 모의 상태가 바뀐다. 조작 뒤 해당 버튼에 초점을 유지하고 상태 문구를 갱신한다. |

`81ddad2`의 최초 입력 기록에는 390×844·1440×900 Chromium과 시험 MP4·M4A가 쓰였다. 전체 개발 서버에서는 미디어 요소를 대상으로 한 최초 Space·Enter가 0/8, 별도 배포 모드 UI에서는 브라우저 기본 재생 버튼을 대상으로 한 최초 입력이 8/8이었다. 별도 UI에서 기본 버튼까지 Tab은 2–6회였으며 미디어 요소 자체 입력은 7/8이었다. 위 시안의 기본 경로는 탐색 순서를 단순화해 설명한다. **재생 시작**은 새 디자인 제안이며 후속 전체 빌드·실제 운영은 별도 검수 범위다. [최초 재생 독립 검수](../../../handoffs/T370-R-PLAYBACK-INITIAL-KEYBOARD-REVIEW.md)

## 작성자 브라우저 검수

- 390×844에서 카드 한 열, 1440×900에서 두 열로 표시됐다. 각 폭 20개 확인 지점에서 문서·상세의 가로 넘침은 0px이고 보이는 버튼 높이는 44px 이상이었다.
- Tab·Shift+Tab과 Enter·Space로 두 상세 열기, 모의 재생·일시 정지, Escape 복귀를 확인했다. 상세를 다시 열면 재생 전 상태로 초기화됐다. 닫은 직후 다음 카드로 이동하는 빠른 키 입력도 폭마다 5회 확인했다.
- 요청은 로컬 HTML·시험 표지·글꼴뿐이었다. 외부·API·운영·미디어 파일 요청은 각각 0건이었다. 화면 캡처는 로컬 `tmp/first-playback-proof/`에 있다.
