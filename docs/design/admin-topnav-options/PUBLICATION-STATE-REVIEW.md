# 관리자 완성본 검수·게시 상태 대조

운영 배포 기록 `073f919`, 해당 배포의 고정 코드 `e4fa378` 및 T289·T297 계약을 읽기 전용으로 대조했다. 운영의 **완성본 검수·게시**는 상단 관리자 메뉴에서 열린다. 기존 화면 기록에서는 ‘게시 서버 미연결’ 안내만 보였으며, T289의 정상 준비·게시·철회 동작은 연결된 격리 공급자에서 확인됐다. ## 목록 상태와 가능한 조작

| 상태 | 현재 제품과 응답 계약 | 화면 안내 기준 |
| --- | --- | --- |
| 운영 공급원 미연결 | 서버 초기 목록 또는 인증된 GET의 `200 {kind:"closed"}`가 ‘게시 서버 미연결’ 카드로 표시된다. 이 경우 목록 재조회, 권리 확인, 준비·게시·철회 버튼이 없다. 저장소 없이 들어온 POST는 `503 PUBLICATION_UNLINKED`다. | 운영 공급원 미연결이 확인된 환경이라면 ‘게시 서버가 연결되면 이 화면에서 완성본을 게시하거나 철회할 수 있어요. 운영 담당자에게 게시 서버 연결을 확인해 달라고 요청해 주세요’로 안내한다. |
| 목록 이용 불가 | 연결된 서비스도 현재 게시 권한을 확인하지 못하면 `closed`를 반환할 수 있다. 현재 UI는 이 경우에도 ‘게시 서버 미연결’로 표시한다. | `closed`만 확인한 경우 ‘게시 기능을 사용할 수 없어요’로 안내하고 계정 권한 또는 연결 상태 확인을 요청한다. 공급원 미연결을 확정하는 문구는 별도 근거가 있는 경우에 사용한다. |
| 목록 조회 실패 | `200 {kind:"failed"}`, 응답 형식 오류·네트워크 실패·GET 인증 오류는 UI에서 ‘게시 목록을 불러오지 못했어요’로 처리된다. ‘목록 다시 불러오기’가 제공된다. | 재조회는 목록 읽기로 안내한다. 이 상태에서 0건이나 운영 미연결로 표시하지 않는다. 인증 상태를 별도로 확인할 수 있을 때는 해당 로그인·권한 안내를 사용한다. |
| 정상 조회, 빈 목록 | `200 {kind:"ok",items:[]}`이면 ‘검수할 완성본이 없어요’가 표시된다. 목록 다시 불러오기는 그대로 있고 작품별 조작은 없다. | ‘검수할 완성본이 없어요. 내 프로젝트에서 완성본을 확인한 뒤 목록을 다시 불러와 주세요’로 다음 행동을 안내한다. |
| 정상 조회, 작품 있음 | 연결된 서비스에서 게시 권한을 가진 계정의 소유 작품을 돌려준다. 목록은 작품명·종류·주소 이름, 대상 리비전, 준비·게시 세대, 원본과 권리 상태를 제공한다. | 상태와 작업 대상이 한 작품 안에서 이어지게 표시한다. 원본·권리 조건이 부족하면 확인할 사유를 보여준다. 소유자 식별자, 저장소 경로, 내부 요청 식별자는 안내 문구에 넣지 않는다. |

## 권리 확인과 철회 확인

| 화면 단계 | 현재 조작 | 확인·결과 안내 기준 |
| --- | --- | --- |
| 검수 대기 | 완성된 원본과 확인된 권리 증빙이 있는 작품에서 ‘권리 증빙과 표시 문구를 확인했어요’를 체크하면 `vN 게시 준비`를 사용할 수 있다. | ‘게시 준비를 마쳤어요. 권리와 표시 문구를 다시 확인한 뒤 게시해 주세요.’ 준비 성공 뒤 체크가 해제되고 공개 목록은 그대로다. |
| 게시 준비됨 | 준비된 세대와 권리를 다시 확인한 뒤 `세대 N 게시`를 실행한다. 확인된 성공 응답의 대상 세대가 요청과 일치해야 화면에 반영한다. | ‘세대 N을 공개 목록에 게시했어요.’ 성공 뒤 체크를 해제하고 게시 중 세대를 표시한다. |
| 게시 중, 준비 세대 없음 | `철회…` → `세대 N 철회 확정` 또는 `취소`. 철회에는 게시용 권리 체크가 필요 없다. | 확정 전에 작품과 게시 중 세대를 밝히고 공개 목록과 해당 표지가 내려간다고 안내한다. 확인 응답을 받은 뒤 내려간 세대를 알린다. |
| 준비된 세대 철회 | 준비된 세대가 있으면 준비 세대 한 건부터 철회한다. 기존 게시 세대가 함께 있으면 게시 세대는 유지된다. 현재 성공 알림은 준비를 철회해도 ‘공개 목록과 표지 주소에서 내려가요’라고 표시한다. | 확정 문구에 ‘준비 세대 N 철회’를 표시한다. 결과는 ‘세대 N의 게시 준비를 취소했어요.’로 알리고 기존 게시 세대가 있으면 ‘게시 중인 세대 M은 계속 공개돼요’를 덧붙인다. |

목록 재조회와 쓰기 재시도는 다른 동작이다. 쓰기 HTTP 200의 본문에는 성공과 업무 실패가 모두 있으므로 본문의 처리 상태를 확인한다. 변경 충돌, 원본 변경, 요청과 맞지 않는 결과가 오면 새 목록이나 원본 확인을 안내한다. 쓰기 처리 여부가 미확정이면 ‘요청 결과를 확인하지 못했어요’를 표시하고 **같은 게시 준비·게시·철회 요청 다시 시도**를 제공한다. 동일한 요청 식별자와 대상 버전·세대를 유지한다. 조회 자체가 실패했을 때는 처리 결과를 알 수 없으므로, 다음 정상 목록에서 같은 버전의 줄이 확인될 때만 재시도를 다시 표시한다. ## 390px·1440px 완료 기준

| 폭 | 화면 검수 기준 |
| --- | --- |
| 390×844 | 상단 **완성본 검수·게시** 진입 후 제목과 상태가 보인다. 작품명·세대·확인 문구가 줄바꿈되고 가로 넘침은 0px다. 확인과 취소는 분리하고 각 조작 영역은 44px 이상이다. |
| 1440×900 | 제목과 목록 재조회가 함께 보이며 각 작품 안에서 준비·게시 중 세대와 대상 작업을 읽을 수 있다. 준비 세대 철회와 공개 세대 철회의 문구가 각각 대상 작업 바로 옆에 보인다. |
| 두 폭 공통 | 키보드로 진입, 증빙 확인, 준비, 재확인, 게시, 철회 확인·취소를 순서대로 수행한다. 철회 확인이 열리면 대상·영향을 읽은 뒤 확정 또는 취소에 도달하고, 취소하면 초점이 철회 조작으로 돌아온다. 재조회 또는 결과 메시지를 상태 영역에서 알리고 조작이 사라지면 작품 또는 목록 제목 쪽으로 초점을 이동한다. 미연결·조회 실패·정상 빈 목록·응답 미확정·두 종류의 철회 결과가 각각 맞는 문구와 조작을 표시하는지 확인한다. |

390px·1440px 운영 기록은 상단 메뉴와 화면 배치의 확인 근거다. 게시 작업 자체의 기존 브라우저 확인은 격리 공급자에서 390px·1280px로 진행됐다. 위 완료 기준은 연결된 격리 후보의 후속 검수에 적용한다. 이번 대조에서는 운영 요청과 게시·철회를 실행하지 않았다. [기존 격리 검수](../../handoffs/T289-R-ADMIN-PUBLICATION-QUEUE-REVIEW.md)
