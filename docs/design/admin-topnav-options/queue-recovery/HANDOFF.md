# 렌더 대기열 조회 상태 시안 인계

[상태 비교 HTML 열기](http://127.0.0.1:8769/docs/design/admin-topnav-options/queue-recovery/compare.html) · [HTML 원본](compare.html)

| 상태 | 표시 기준과 다음 행동 |
|---|---|
| 503 `ADMIN_RENDER_QUEUE_UNAVAILABLE` | ‘대기열을 불러오지 못했어요’를 표시한다. 응답 코드가 대기열 조회 실패를 가리키며, 미설정과 일시 오류의 구체적 원인은 응답에서 구분할 수 없다. **렌더 대기열 다시 조회**로 목록을 읽는다. 조회 중 중복 요청을 막고 결과를 알린다. 실패가 계속되면 화면 이름, 문구, 발생 시각을 알려 달라고 안내한다. |
| 503 `AUTH_UNAVAILABLE` | ‘관리자 계정을 확인할 수 없어요’를 표시하고 운영 담당자에게 인증 확인 실패를 알릴 문구를 제공한다. 인증 처리 실패와 대기열 조회 실패는 서로 다른 응답 코드다. |
| 401 `AUTH_REQUIRED` | ‘관리자 로그인이 필요해요’를 표시하고 관리자 로그인으로 안내한다. |
| 403 `AUTH_FORBIDDEN` | ‘이 계정은 대기열을 볼 수 없어요’를 표시한다. 사용 계정을 확인하고 계속 제한되면 운영 담당자에게 권한 확인을 요청하도록 안내한다. |
| 200 조회 성공 | 확인된 계정의 최근 작업을 표시하고 프로젝트 상세로 연결한다. 성공한 응답이 빈 목록이면 ‘렌더 작업이 없어요’와 내 프로젝트 이동을 표시한다. |
| 확정 미연결 | 별도 상태 근거로 공급원이 연결되지 않았음을 확인했을 때만 ‘렌더 대기열 미연결’을 표시하고 연결 문의 문구를 제공한다. 현재 GET에는 확정 미연결 신호가 없다. |

비교 화면은 상태별 안내 제안이다. 현재 제품 UI는 두 503 응답을 같은 상태로 처리한다. 표의 재조회는 대기열 목록 읽기이며 렌더 작업을 다시 실행하지 않는다. [대기열 HTTP 계약](../../../handoffs/ADMIN-RENDER-QUEUE-HTTP.md) · [서비스 상태 코드](../../../../lib/services/postgres/admin-render-queue.ts) · [현재 대기열 구현](../../../../components/admin/admin-render-queue.tsx)

390×844·1440×900 Chromium에서 1열·3열, 가로 넘침 0px을 확인했다. Tab과 Enter로 재조회를 연속 실행했을 때 한 번만 처리되고 끝까지 버튼에 초점이 유지됐다. 문의 문구 펼치기와 401 로그인 예시도 조작한 위치에 초점을 유지했다. 조회 성공 예시에서 아래 화살표로 빈 목록을 고른 뒤 Tab과 Enter로 내 프로젝트 이동 예시를 확인했다. 브라우저 요청에는 루프백 HTML과 글꼴만 있었으며 운영 및 API 요청은 각각 0건이었다. 캡처는 `tmp/admin-queue-code-proof/`에 저장했다.
