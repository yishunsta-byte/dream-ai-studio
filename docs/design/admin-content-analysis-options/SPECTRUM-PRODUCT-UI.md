# 스펙트럼 랩 제품 적용과 독립 UI 검수

2026년 11월 20일 · 사용자 선택 2안 · 디자인 `322875a` · Master 배정 `msg_8e5225c8df36`. [선택 시안](option.html?view=spectrum) · [관리자 콘텐츠 분석 인계](../../handoffs/ADMIN-REFERENCE-ANALYSIS-UI.md)

## 적용 순서

1. **분석 진입과 입력** · 기존 상단 **콘텐츠 분석·공개** 메뉴와 `#admin-reference-analysis` 진입을 사용한다. 소스는 **직접 URL / 파일**로 선택하고 **이미지 / 음악 / 영상**을 지정한다. URL은 지원 출처의 직접 HTTPS 파일 주소만 받는다. Threads 게시물처럼 지원되지 않는 주소는 입력란 바로 아래에 해결 방법을 표시한다. 파일은 4 MiB 이내이며, 허용 형식과 크기를 파일 선택란 옆에서 확인할 수 있게 한다.
2. **단일 실행 동작** · 분석 입력에는 권리 체크박스를 두지 않는다. 버튼 이름은 **권리 확인하고 분석**이며, 분석할 권리가 있는 자료만 실행한다는 안내와 연결한다. 실제 실행 시에만 요청에 권리 확인을 전달한다. 소스 방식·주소·파일·매체를 바꾸면 기존 결과와 공개 준비를 비우고, 실행 중 **분석 취소**로 중단할 수 있게 한다. 앞선 요청의 늦은 응답이 새 입력의 결과나 공개 초안을 바꾸지 않게 한다.
3. **관찰 근거와 분석 추정** · 결과를 열면 매체 종류와 결과 수를 먼저 표시한다. 기본 보기는 **관찰 근거**다. 결과가 여러 개면 실제 `selectionId`에 맞춰 구간·영역을 고를 수 있게 한다. 관찰값을 먼저 보여주고, 추정이 있을 때만 해당 근거 번호와 함께 별도 영역에 표시한다. 민트색 강조와 구간 구분은 보조 수단으로 쓰고 시간·위치·수치를 텍스트로 읽을 수 있게 한다.
4. **생성 프롬프트와 공개** · 같은 결과의 **생성 프롬프트** 보기에 생성 원문, 내 수정본, 변경 내용, 초안·수정본 복사를 둔다. 결과 선택을 바꿨다가 돌아와도 다른 결과의 수정과 섞이지 않아야 한다. **공개 준비**에서 실제 게시될 제목·요약·프롬프트를 확인할 수 있게 하고, 공개 권리와 동의는 기존대로 별도로 확인한다. 공개 결과 페이지에는 승인된 제목·요약·생성 프롬프트·매체·공개 시각만 전달한다. 기존 공개·철회와 요청 재시도 규칙을 사용한다.

## 매체별 실제 데이터 표시

| 매체 | 1차 제품에서 표시할 값 | 구간·영역 시각화 |
|---|---|---|
| 이미지 | 영역의 위치·크기, 주요 색과 각 비중, 밝기 구간 비중 | 주요 색을 색상표와 함께 표시한다. 색상 코드와 비중을 함께 표기한다. |
| 음악 | 관찰 시작·끝, 채널 수, 최대 정규화 RMS. 에너지 시작점이 있으면 시각과 간격 중앙값, 추정 템포가 있으면 BPM 및 근거 번호 | 실제 시각을 표 또는 구간 목록으로 표시한다. 시간 구간이 여러 개일 때는 측정 범위 안에서 시작점 표식을 추가할 수 있다. |
| 영상 | 디코딩된 프레임의 표시 시각, 응답에 있을 때 인접 RGB 차이와 장면 전환 후보 | 점은 실제 프레임 시각, 구간은 실제 관찰 시작·끝을 사용한다. 한 프레임만 있으면 해당 시각을 텍스트로 표시한다. |

현재 DTO에는 파형 샘플, 전체 길이, 썸네일이 포함되지 않는다. 따라서 시안의 합성 파형·시간 눈금·장면 이미지는 제품 결과에 넣지 않는다. 비어 있는 상태에는 입력 방법과 다음 동작을 안내한다. 색상표 또는 구간 표식의 데이터가 충분하면 텍스트 근거와 함께 표시한다. [실제 결과 형식](../../../lib/reference-analysis/studio-analysis-result-dto.ts)

## 390px·1440px 독립 검수표

| 확인 항목 | 390px | 1440px 및 공통 |
|---|---|---|
| 배치 | 입력 → 관찰 근거·프롬프트 → 공개 준비 → 공개 목록 한 열. URL·파일 전환이나 긴 주소·파일명·프롬프트를 넣어도 가로 넘침 없이 사용 | 입력과 결과를 나란히 두고 결과 열에 더 넓은 폭을 준다. 공개 영역과 기존 상단 메뉴를 유지한다. 오류·로딩·결과에서 좌우 폭이 갑자기 바뀌는지 확인한다. |
| 입력과 지원 안내 | 소스 방식·매체·실행·취소 버튼을 손가락으로 누를 수 있고, 도움말을 열어도 실행 버튼과 오류가 가리지 않음 | 초기 **미디어 파일 URL** 또는 파일 입력에 명시된 라벨이 붙는다. URL·파일·매체 변경 및 지원하지 않는 주소·잘못된 형식·4 MiB 초과의 안내가 해당 입력에 연결된다. |
| 결과 데이터 | 길거나 여러 개인 관찰 근거가 줄바꿈된다. 시간·수치가 생략되지 않고 프롬프트를 읽고 편집할 수 있음 | 실제 JPG·MP3·MP4의 응답 근거와 화면 값이 일치하고, 추정과 원문·수정본이 구분된다. 파일과 URL로 동일한 작업 흐름을 확인한다. |
| 공개 관리 | 공개 동의, 공개 확정, 철회 확인이 서로 다른 동작으로 인식됨 | 실패한 분석에서 공개 준비가 열리지 않음. 공개 성공, 확정 충돌의 새 동의, 응답 미확정 재시도, 철회 확인과 목록 복귀를 검수한다. |
| 시각 상태 | 상태의 의미가 문구로 보이고 고정 메뉴가 조작이나 초점을 덮지 않음 | 기본/선택/비활성/오류 표시와 키보드 초점 표시를 확인한다. 민트색 자체로만 활성·오류를 구분하지 않는다. |

## 키보드 검수 순서

1. 상단 메뉴에서 **콘텐츠 분석·공개**로 들어가 제목이 보이는지 확인한다. Tab과 Shift+Tab으로 소스 선택, 매체 선택, 주소 또는 파일, 지원 안내, 실행을 오간다. 기본 버튼은 Enter·Space로, 기본 라디오 그룹은 화살표로 동작하는지 확인한다.
2. 잘못된 주소나 파일을 넣고 실행하면 오류 안내와 수정할 입력에 접근할 수 있어야 한다. 정상 실행 직후에는 **분석 취소**에 초점이 가고, 취소하면 실행 버튼으로 돌아간다. 성공 또는 실패하면 결과나 오류 제목을 읽을 수 있어야 한다. 진행 중 다른 조작으로 옮긴 초점은 유지한다.
3. 두 결과 보기와 결과 선택을 키보드로 전환한다. 사용자 입력을 다시 선택해도 해당 초안이 유지되는지 확인한다. 복사 허용·거절을 각각 시험하고, 자동 복사가 막히면 편집란의 문구가 선택되는지 확인한다.
4. 공개 동의부터 공개 및 철회 확인까지 마우스 없이 진행한다. 확인을 취소했을 때 원래 버튼, 철회가 끝났을 때 공개 목록 제목이나 남은 조작으로 초점이 이어지는지 확인한다.

고정 결합본의 UI와 접근성을 독립 검수한다. 합성 상태로 화면 경계를 검사한 결과와 실제 URL·파일로 확인한 결과를 구분해 남긴다. 기존 운영 422 개선 Preview와 이번 제품 UI·파일 분석의 결합본은 각각 확인한다.
