## 2. 토큰

값은 `tokens.css`에만 있다. 컴포넌트 코드에 색상 코드·px를 직접 쓰지 않는다 (예외: 1px 선 두께, 아이콘 크기 15/18/28px).

| 토큰 | 쓰는 곳 |
|---|---|

| `--bg-surface` 흰색 | 카드·입력·패널 |

| `--accent`, `--accent-hover`, `--accent-press` | 흰 글자가 올라가는 강조 배경: 주 버튼, 숫자 칩, 현재 위치 칩 (민트 700, 흰 글자 4.87:1) |

### 2.2 상태 색 — 각각 `-fg` `-bg` `-line` 3개

### 2.3 글자

| 토큰 | px | 쓰는 곳 |
|---|---|---|
| `--text-2xl` | 24 (휴대폰 22) | 페이지 제목 h1 |
| `--text-xl` | 20 | 섹션 제목 h2 |
| `--text-lg` | 17 | 카드 제목 h3, 장면 이름 |
| `--text-md` | 15 | 본문 기본 — **본문 최소** |
| `--text-sm` | 14 | 표 셀, 도움말, 버튼 글자 |
| `--text-xs` | 13 | 칩·배지·메타 정보만. 문장 금지 |

- 글꼴: Pretendard(자체 호스팅, OFL) → Noto Sans KR → 시스템. 구현은 `next/font/local`로 Pretendard Variable woff2를 `public/fonts`에 둔다. 시안은 Google Fonts Noto Sans KR로 대신 보여 준다.
- 한국어 줄바꿈: 앱 전역 `word-break: keep-all; overflow-wrap: break-word` (단어 중간에서 끊지 않음, 긴 파일명만 끊음).
- 숫자 열·시간·버전 번호는 `font-variant-numeric: tabular-nums`.
- 파일명·오류 코드·단계 칩(P1)은 `--font-mono`.

### 2.4 간격·모양·크기

- 간격 4px 단위 `--sp-1`(4) ~ `--sp-12`(48). 카드 안쪽 16×20, 카드 사이 16, 섹션 사이 24 (휴대폰 20).
- 모서리 `--radius-sm` 6(버튼·입력·칩) / `md` 10(카드) / `lg` 14(확인 패널) / `pill`.
- 버튼·입력 높이 32 / **40 기본** / 48. 휴대폰 주 버튼 48. 누르는 영역 최소 44 (작은 버튼은 주변 여백으로 확보).
- 사이드바 248, 위 띠 56, 본문 최대 1200, 입력 폼 최대 720.
- 움직임 120 / 200ms. `prefers-reduced-motion`이면 0 (도는 아이콘은 멈춰도 글자로 상태가 보이므로 문제 없음).

```
┌──────────┬────────────────────────────────────────────┐
│ 사이드바  │ 위 띠 56: [≡] 경로 > 현재 화면   [샘플 모드][만드는 중 n] │
│ 248      ├────────────────────────────────────────────┤
│ 브랜드    │ 본문 (최대 1200, 좌우 24 / 휴대폰 16)          │

│ 작업 대기열│  내용…                                      │
│ 자료·캐릭터│                                            │
│ ─ 분야 그룹│                                            │
│ ─ 업무공간 │                                            │
│ 설정      │                                            │
└──────────┴────────────────────────────────────────────┘
```

- **사이드바**: 위 고정 3개(작업실 · 작업 대기열 · 자료·캐릭터) → 분야 그룹 5개(menus.json `group` 순서) → 업무공간 2개(자물쇠, "별도 개발") → 맨 아래 설정.
  - 분야 이름은 menus.json `label`. 준비 단계 분야는 흐린 글자 + 단계 칩(`P4`). 눌러도 분야 소개는 열린다 (만들기만 막음, M-5).
  - 작업 대기열 옆 숫자: 진행 수(민트), 실패 수(빨강 `!n`). 0이면 숨김.
- **위 띠**: 경로(분야 > 프로젝트). 휴대폰은 마지막 한 칸만. 오른쪽에 전역 상태 — `MOCK_MODE`면 항상 "샘플 모드" 칩.
- **휴대폰·태블릿(<1024)**: 사이드바는 왼쪽에서 밀려 나오는 서랍. ≡ 버튼 `aria-expanded`, 바깥 누르면 닫힘, 화면 이동 시 닫힘.
- 사이드바 현재 위치는 `aria-current="page"` + 왼쪽 민트 3px 막대.

## 5. 패턴

### 5.1 게이트 (기획 승인·검수 승인, PLAN R6·S2·S3)

- Stepper 이름 옆 "승인" 표시로 게이트 단계를 구분한다.
- 승인 버튼은 조건을 못 채우면 `disabled` + 이유 글("보류 1개, 미확인 1개가 남아 있어 승인할 수 없어요.").
- 승인 후 화면 위 Callout(info): "승인된 기획 v2 기준으로 만들어요. 기획을 고치면 새 버전이 생기고, 다시 승인할 때까지 그 내용으로는 만들 수 없어요."
- 서버가 막는다. 화면 비활성은 안내일 뿐이며, 서버 거절(409 등)도 같은 문장으로 보여 준다.

### 5.2 작업 상태 표시 (PLAN 9장)

| 작업 상태 | 화면 |
|---|---|
| queued | StatusPill queued "대기" + "작업 대기열 n번째" |
| running | StatusPill running "만드는 중 · 40초 지남", 썸네일 자리에 진행 막대(진행률을 모르면 흐르는 막대). 취소 버튼 |
| succeeded | 새 버전 칩 생성, Toast "장면 2를 만들었어요. v2가 새로 생겼어요. 선택은 그대로예요." — **새 버전이 생겨도 선택은 자동으로 바뀌지 않는다** (첫 버전만 자동 선택) |
| failed | 카드 선 빨강, 썸네일 자리 경고 아이콘, 실패 상자: 굵은 첫 문장(무슨 일) + 다음 행동 + 작은 글씨 코드·재시도 여부·청구 여부 |
| canceled | StatusPill canceled "취소됨", 이전 선택 유지 |

실패 문장 예시 (오류 코드 → 사용자 문장은 `lib/ui/errors.ts` 한 곳에서):

| 코드 | 첫 문장 | 다음 행동 |
|---|---|---|
| CONTENT_REJECTED | 제공사가 요청을 거절했어요. | 이유 + 바꿀 것을 안내, 자동 재시도 안 함 |
| TIMEOUT | 시간이 너무 오래 걸려 멈췄어요. | "다시 시도"(청구됐는지 함께 표시) |
| RATE_LIMITED | 잠시 요청이 많아요. | "n분 뒤 자동으로 다시 시도해요" |
| BUDGET_EXCEEDED | 이번 달 예산을 넘어 시작하지 않았어요. | 설정 > 예산 링크 |
| STORAGE_FAILED | 결과는 받았지만 저장하지 못했어요. | "저장 다시 시도" — 다시 생성하지 않음 (A-2) |
| INVALID_INPUT | 입력에 빠진 것이 있어요. | 해당 칸으로 이동 링크 |

### 5.3 장면 카드 (P1-7)

- 구성: 번호 · 9:16 썸네일(108px, 휴대폰 72px) · 이름 + 상태 · 설명 한 줄 · 대사 · 버전 칩 · 오른쪽 행동 버튼.
- 버전 칩: `v1`, `v2 · 선택`. 선택된 칩은 남색 채움. 실패 버전은 점선 빨강, 고를 수 없음.
- "버전 비교" 펼침: 버전별 썸네일 + 만든 시각·제공자·비용·기준 기획 버전. 선택 안 된 버전에 "이 버전으로 되돌리기".
- 선택 기준은 `scenes.selected_version_id` 하나 (S5). 화면은 이것만 읽는다.
- 기획이 바뀌어 장면 내용이 달라졌으면 StatusPill warning "기획 변경 후 확인 필요" + "v2 기준으로 다시 만들기" / "이대로 둘게요".
- 다시 만들기는 그 장면만 (R3). 일괄 버튼은 "결과 없는 장면만 만들기" 한 가지.

### 5.4 샘플 표시 (R5)

- mock 결과 썸네일: 왼쪽 위 SampleBadge. 파일명 접미사 `_SAMPLE`.
- 위 띠 "샘플 모드" 칩은 `MOCK_MODE=true`인 동안 항상.
- 내보내기 행·manifest·검수 화면에 "샘플 포함" 표시. 검수 공통 항목에 "샘플 결과가 최종본으로 표시되지 않았다" 자동 근거.
- 비용은 "0원(샘플)"으로 쓴다.

### 5.5 내용 버전과 검수 무효화 (S4)

- 프로젝트 머리에 Badge "내용 버전 r12" (title: "장면·대사·글자·규격이 바뀔 때마다 올라가는 번호").
- 검수 화면 위 Callout(warning): "내용 버전 r12 기준 검수예요. 장면·글자·규격을 바꾸면 버전이 올라가고 검수를 다시 해야 해요."
- 무효화되면 Toast(error 아님, info) + 검수 단계 Stepper가 다시 "검수 필요".

### 6.1 검수 항목 (ReviewItem)

- 항목 글은 menus.json `review` 그대로. 그룹: 공통 → 분야 → 조건부("광고·협찬 포함이라 추가된 항목").
- 버튼은 통과 / 보류 두 개(누른 것 다시 누르면 미확인). 보류는 **사유 필수** — 보류를 누르면 사유 입력칸이 열리고, 비우면 저장 안 됨.
- 자동 확인 근거가 있으면 "자동 확인됨 · 1080×1920"처럼 회색 작은 글. **자동 확인은 근거일 뿐, 통과는 사람이 누른다.**
- 진행 막대: 통과(초록) · 보류(노랑) · 미확인(회색). "필수 12개 중 10개 통과".

### 6.2 내보내기 (P1 = 편집용 묶음, E-1)

- 이름은 "편집용 묶음". "완성 영상"·"최종본" 표현 금지 (P2부터).
- 미리보기는 폴더 나무(mono) + 예상 크기. 샘플 포함이면 Badge.
- 내보내기 화면(`#export`): 검수 승인 기준 내용 버전 표시 → "편집용 묶음 만들기" → 진행(작업 대기열과 같은 상태 표시) → 완료 행(파일명·크기·해시 앞 8자리·만든 시각·내용 버전) + "내려받기". 내보내기 기록은 바뀌지 않으며, 내용 버전이 올라가면 예전 묶음 옆에 "지금 내용과 다름" Badge (S5).
- 실패: "묶음을 만들지 못했어요" + 원인(파일 누락·디스크 부족·해시 불일치) + 다시 시도. 반쯤 만든 파일은 보이지 않는다 (E-5).

### 6.3 자료·캐릭터 보관함 (`#library`, P1-4)

- 위: 탭(전체 · 이미지 · 영상 · 오디오 · 문서 · 링크 · 캐릭터) + 검색 + "파일 올리기" + "링크 등록".
- 올리기 영역: 끌어 놓기 또는 버튼. 허용 형식을 글로 표시. 파일마다 진행 → 확인(실제 형식 검사) → 완료/거절.
  - 거절 문장: "**지원하지 않는 형식이에요.** 파일 이름은 .jpg인데 실제 내용은 실행 파일이에요." (F-3) / "**파일이 너무 커요.** 2GB까지 올릴 수 있어요." (F-4) / "**디스크 공간이 부족해요.**"
- 목록: 카드 격자(PC 4열, 태블릿 3열, 휴대폰 2열). 카드 = 미리보기 · 제목 · 형식·크기·해상도/길이 · 출처·권리 칩 · 사용 중인 프로젝트 수.
- 권리 칩: 직접 촬영 / 브랜드 제공 / 허락 받음 / **확인 필요(경고색)**. 권리 메모 없는 자료는 경고 칩.
- 링크 등록(F-7): 주소·제목·메모만 저장한다는 안내 "링크 정보만 저장해요. 파일을 받아 오지는 않아요."
- 보관: 카드 메뉴 "보관" → ConfirmPanel(되살리는 방법 포함). 사용 중인 자료는 "프로젝트 2개에서 쓰는 중 · 보관해도 그 프로젝트에는 그대로 남아요".
- 원본 표시: 원본(original) 자료는 Badge "원본" — 덮어쓰기·편집 버튼 없음 (R1).

### 6.4 기획·장면표·승인 (`#plan`, P1-5)

- 위: 기획 버전 선택(v1 승인됨 · v2 작성 중) + 상태 칩. 승인된 버전은 읽기 전용 + 자물쇠 "승인됨 · 고칠 수 없어요. 고치려면 새 버전을 만들어요".
- 본문: `planSteps` 순서대로 장면표 행 — 단계 이름 · 장면 설명 · 대사/내레이션 · 길이(초) · 사용할 자료. 합계 길이와 목표 길이 차이 표시("목표 30초 · 지금 27초").
- 확인된 사실 연결: `facts`에서 온 문장에만 Badge "확인된 사실". 효능 표현을 자동으로 판별하지는 않는다(믿을 수 없는 경고를 만들지 않음) — 사람이 배지 없는 효능 문장을 보고 고치고, 검수 `shop.no-exaggeration`에서 다시 본다 (R8).
- 버전 비교: 두 버전 나란히, 바뀐 행 노란 배경.
- 승인 영역(게이트): 승인할 것 요약 "기획 v2 · 장면 5개 · 27초" + "기획 승인". 승인하면 장면표 스냅샷이 저장되고 장면 제작이 열린다는 문장. 이미 만든 장면이 있으면 "만든 장면 2개는 지우지 않고 '기획 변경 후 확인 필요'로 표시돼요" (S3).

### 6.5 작업 대기열 (`#queue`, P1-6)

- 묶음: 만드는 중 → 대기 → 실패 → 최근 완료(24시간). 각 행 = 상태 · 무엇(프로젝트 › 장면 4 · 이미지) · 경과/대기 순서 · 제공사(샘플이면 SampleBadge) · 행동.
- 행동: 대기·진행 중 = "취소"(ConfirmPanel 없이, Toast에 취소됨). 실패 = "다시 시도"(재시도 가능한 오류만) / "장면으로 가기".
- 위 띠 숫자·사이드바 숫자와 같은 값이어야 한다.
- 워커가 꺼져 있으면 맨 위 Callout(warning): "작업 처리기가 꺼져 있어요. `npm run worker`를 켜면 대기 중인 작업이 시작돼요." (개발 단계 문구, P7에서 바꿈)
- 취소 뒤 늦게 도착한 결과: 새 버전으로만 추가, 선택 안 함, 행에 "취소 후 도착" 표시 (9장).

### 6.6 수정·조립 (`#edit`, P1-8 · P1 범위)

- 왼쪽: 9:16 정지 화면 미리보기(선택된 장면 이미지 위 글자 겹침, 안전 영역 점선). 오른쪽: 글자 레이어 목록 + 편집 칸(문구 · 크기 · 색 · 위치 프리셋 위/가운데/아래 · 시작·끝 초).
- 장면 순서 목록(위아래 이동 버튼, 끌기는 선택 사항). 순서·글자를 바꾸면 내용 버전 +1 안내.
- 광고 표기 레이어(`isAd`): 기본 생성되고 지울 수 없으며 "광고" 문구 고정, 위치만 바꿈.
- 시간 칸 검증: 끝 ≤ 시작이면 "끝 시간은 시작보다 뒤여야 해요." SRT 미리보기(읽기 전용).
- "P2부터 움직이는 글자·영상 미리보기" 안내 한 줄. 재생 버튼 없음.
- 휴대폰: 미리보기 위, 레이어 목록 아래(편집은 펼침).

### 6.9 영상 만들기·내보내기 (`#p2-render`, P2-4·6)

- 진행 카드: 진행 막대(`--accent-bar`) + 퍼센트·경과 + 4단계 목록(준비 → 장면과 글자 합치기 → 소리 맞추기(−14 LUFS) → 파일 확인) + 취소. "창을 닫아도 작업 처리기가 켜져 있으면 계속돼요."
- 결과 행: 9:16 썸네일 · 파일명 · 확인 칩(해상도·길이·코덱·음량·자막 오차) · 재생·내려받기. **파일 확인(ffprobe)을 통과해야만** "파일 확인 통과" (11.4). 샘플 장면이 들어 있으면 SampleBadge.
- 확인 실패는 실패로 보인다: "파일은 만들었지만 소리 트랙이 없어요. 그래서 완성으로 치지 않았어요." + 다시 만들기 (R4).
- 글자만 바꾼 뒤 다시 만들 때 안내: "장면은 다시 만들지 않아요 · 약 40초" (T-1, P2 종료 기준).
- 영상 내보내기: 검수 승인 전에는 잠김 + 이유. 받는 것: MP4 · SRT·VTT · 다시 편집용 묶음(장면·글자 설정·타임라인·글꼴 라이선스).

### 6.10 예산·비용 (`#p3-budget`·`#p3-cost`, P3-1, PLAN 15장)

**금액 표시 규칙**
- 제공사가 청구하는 통화(미국 달러) 그대로 쓴다: `$0.40`, 소수 둘째 자리. 0보다 크고 1센트 미만이면 `<$0.01`, 정확히 0이면 `$0.00`. 반올림은 표시 때만 (B-7). 원화 환산은 쓰지 않는다(환율로 틀린 숫자가 생김). 저장은 정수 마이크로 단위(PLAN 7장).
- 금액 앞 말로 단계를 구분: **예상**(시작 전) → **예약됨**(진행 중) → **실제**(정산) / **추정**(제공사가 금액을 안 알려 줌, 노란 칩) / **반환됨**(취소·실패로 예약을 돌려받음).
- 실패여도 제공사 청구가 있으면 그대로 적는다. "실패 = 0원"으로 쓰지 않는다 (B-4). 샘플 결과는 계속 "0원(샘플)".

**예산 화면 (`#p3-budget`)** — 설정의 예산 구역
| 구역 | 내용 |
|---|---|
| 이번 달 | 큰 글자 "남은 예산 $25.96 / 한도 $40.00" + BudgetMeter(lg) + 범례(사용 · 그중 추정 / 예약 · 진행 중 작업 수 / 남음). 기간과 새로 시작하는 시각(매달 1일 0시, 한국 시간) |

| 제공사별 · 프로젝트별 | 표: 사용 · 예약 · 작업 수. 추정이 섞이면 "추정 $0.62" 칩 (B-6) |

| 한도 없음 | Callout(warning, 자물쇠) "월 한도를 정해야 실제 AI로 만들 수 있어요. 샘플 모드는 그대로 쓸 수 있어요." + 빈 한도 칸 + "한도 정하기" (B-2) |

- 탭 아래 예산 띠(Card): "실제 AI로 만들어요 · 제공사" + BudgetMeter(sm) + "예산 보기" 링크. 샘플 모드에서는 띠 대신 기존 샘플 표시.
- 생성 버튼에 CostTag: "만들기 · 예상 $0.40", "결과 없는 장면만 만들기 · 예상 $1.60". 확인 금액 이상이면 CostConfirmPanel.
- 장면 카드 메타 한 줄: 진행 중 "$0.40 예약됨 · 끝나면 실제 청구로 정산해요", 끝난 뒤 "실제 $0.38 (예약 $0.40에서 정산)". 버전 비교에도 같은 금액.
- 실패 카드 작은 글자: "코드 PROVIDER_DOWN · 제공사 청구 $0.12 (예약 $0.40 중 $0.28 반환)".
- CostConfirmPanel 내용: 제목 "실제 AI로 장면 4개를 만들까요?" / 예상 비용(장면당·길이) / 이번 달 남은 예산 "$25.96 → $24.36" / 시작하면 예약 후 정산 / "실제 청구는 제공사 기준이라 조금 다를 수 있어요. 실패해도 제공사가 청구하면 그 금액은 빠져요." / 취소 · "$1.60 예약하고 만들기".
- 시작할 수 없을 때: 한도 없음 → 버튼 비활성 + 이유 글 + "설정 > 예산" 링크 (B-2). 한도 초과 → Callout(danger) "이번 달 예산을 넘어 시작하지 않았어요." + 남은 예산·이번 예상 + 링크 + 작은 글자 "코드 BUDGET_EXCEEDED · 예약하지 않았고 청구 없음" (B-3).
- 화면의 남은 예산은 참고용. 막는 기준은 서버의 원자적 예약 계산이다 (B-3). 동시에 두 번 눌러도 한도를 넘지 않는다.

## 8. 글쓰기 (화면 문구)

- 존댓말 "~해요"체. 짧게. 한 문장에 하나.
- 버튼은 동사: "저장하고 시작", "다시 만들기", "보관 해제". "확인"·"OK"·"제출" 단독 금지.
- 사용자를 탓하지 않는다: "잘못 입력했습니다" ✗ → "확인된 장점을 하나 이상 적어 주세요." ○
- 숫자는 아라비아 숫자, 시간은 "14:20", 날짜는 "11월 15일" (올해가 아니면 연도).
