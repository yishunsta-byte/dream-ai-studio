## 2. 토큰

값은 `tokens.css`에만 있다. 컴포넌트 코드에 색상 코드·px를 직접 쓰지 않는다 (예외: 1px 선 두께, 아이콘 크기 15/18/28px).

### 2.1 역할 색

| 토큰 | 쓰는 곳 |
|---|---|
| `--bg-app` 크림 | 앱 배경 |
| `--bg-surface` 흰색 | 카드·입력·패널 |
| `--bg-sunken` | 표 머리, 눌린 칸, 빈 썸네일 |
| `--bg-sidebar` 남색 | 사이드바 |
| `--bg-accent-soft` | 강조 배지·선택된 옅은 배경 |
| `--fg-strong` / `--fg-default` / `--fg-muted` / `--fg-subtle` | 제목 / 본문 / 보조 / 비활성 (subtle은 15px 이상만) |
| `--fg-accent`, `--fg-link` | 강조 글자, 링크 (민트 700) |

| `--line`, `--line-strong`, `--line-focus` | 카드 선 / 입력 테두리 / 포커스 |

### 2.2 상태 색 — 각각 `-fg` `-bg` `-line` 3개

| 상태 | 토큰 | 아이콘 | 기본 글자 |
|---|---|---|---|
| 완료·선택·통과 | `--st-success-*` | 체크 | 완료 / 선택됨 / 통과 |
| 만드는 중 | `--st-running-*` | 도는 원 | 만드는 중 |
| 대기·취소·잠김 | `--st-locked-*` | 시계 / X / 자물쇠 | 대기 / 취소됨 / 잠김 |
| 승인 대기 (게이트) | `--st-approval-*` | 체크 | 승인 대기 |
| 확인 필요·보류 | `--st-warning-*` | 삼각 느낌표 | 확인 필요 / 보류 |
| 실패 | `--st-danger-*` | 삼각 느낌표 | 실패 |
| 샘플 (mock) | `--st-sample-*` | 플라스크 | 샘플 |

**샘플 보라색은 mock 표시 외에 쓰지 않는다.** 시안 주석(`.anno`)도 같은 색이지만 제품에는 없다.

### 2.3 글자

| 토큰 | px | 쓰는 곳 |
|---|---|---|
| `--text-2xl` | 24 (휴대폰 22) | 페이지 제목 h1 |
| `--text-xl` | 20 | 섹션 제목 h2 |
| `--text-lg` | 17 | 카드 제목 h3, 장면 이름 |
| `--text-md` | 15 | 본문 기본 — **본문 최소** |
| `--text-sm` | 14 | 표 셀, 도움말, 버튼 글자 |
| `--text-xs` | 13 | 칩·배지·메타 정보만. 문장 금지 |

- 숫자 열·시간·버전 번호는 `font-variant-numeric: tabular-nums`.
- 파일명·오류 코드·단계 칩(P1)은 `--font-mono`.

### 2.4 간격·모양·크기

- 간격 4px 단위 `--sp-1`(4) ~ `--sp-12`(48). 카드 안쪽 16×20, 카드 사이 16, 섹션 사이 24 (휴대폰 20).
- 모서리 `--radius-sm` 6(버튼·입력·칩) / `md` 10(카드) / `lg` 14(확인 패널) / `pill`.
- 버튼·입력 높이 32 / **40 기본** / 48. 휴대폰 주 버튼 48. 누르는 영역 최소 44 (작은 버튼은 주변 여백으로 확보).
- 사이드바 248, 위 띠 56, 본문 최대 1200, 입력 폼 최대 720.
- 움직임 120 / 200ms. `prefers-reduced-motion`이면 0 (도는 아이콘은 멈춰도 글자로 상태가 보이므로 문제 없음).

```
┌──────────┬────────────────────────────────────────────┐
│ 사이드바  │ 위 띠 56: [≡] 경로 > 현재 화면   [샘플 모드][만드는 중 n] │
│ 248      ├────────────────────────────────────────────┤
│ 브랜드    │ 본문 (최대 1200, 좌우 24 / 휴대폰 16)          │
│ 작업실    │  PageHeader                                │
│ 작업 대기열│  내용…                                      │
│ 자료·캐릭터│                                            │
│ ─ 분야 그룹│                                            │
│ ─ 업무공간 │                                            │
│ 설정      │                                            │
└──────────┴────────────────────────────────────────────┘
```

- **사이드바**: 위 고정 3개(작업실 · 작업 대기열 · 자료·캐릭터) → 분야 그룹 5개(menus.json `group` 순서) → 업무공간 2개(자물쇠, "별도 개발") → 맨 아래 설정.
  - 분야 이름은 menus.json `title`. 준비 단계 분야는 흐린 글자 + 단계 칩(`P4`). 눌러도 분야 소개는 열린다 (만들기만 막음, M-5).
  - 작업 대기열 옆 숫자: 진행 수(민트), 실패 수(빨강 `!n`). 0이면 숨김.
- **위 띠**: 경로(분야 > 프로젝트). 휴대폰은 마지막 한 칸만. 오른쪽에 전역 상태 — `MOCK_MODE`면 항상 "샘플 모드" 칩.
- **휴대폰·태블릿(<1024)**: 사이드바는 왼쪽에서 밀려 나오는 서랍. ≡ 버튼 `aria-expanded`, 바깥 누르면 닫힘, 화면 이동 시 닫힘.
- 사이드바 현재 위치는 `aria-current="page"` + 왼쪽 민트 3px 막대.

| 폭 | 이름 | 바뀌는 것 |
|---|---|---|
| ≥1024 | PC | 사이드바 고정, 작업실 4열, 분야 소개 3열 |

## 4. 컴포넌트

이름은 코드 컴포넌트 이름과 같게 한다 (`components/ui/` 아래). 시안 `#components` 화면에 실물이 있다.

| 컴포넌트 | 변형·속성 | 규칙 |
|---|---|---|
| **Button** | `variant`: primary · secondary · ghost · danger / `size`: sm 32 · md 40 · lg 48 / `loading` / `disabled` + `disabledReason` | 한 화면 primary는 하나. loading이면 도는 아이콘 + "저장 중"처럼 진행형 글자, 두 번 누름 막기. `disabledReason`이 있으면 버튼 옆(또는 위)에 글로 보여 준다 — 툴팁만으로는 안 됨. 글자는 동사로 끝 ("저장하고 시작", "다시 만들기") |
| **IconButton** | `label` 필수 | 40×40, `aria-label` = label. 아이콘만 있는 버튼은 이것만 |
| **Card** | `padding`: none · md / `tone`: default · danger | 흰 바탕, 선 1px, 그림자 1. 실패 장면은 tone=danger(선만 빨강) |
| **StatusPill** | `status`: done · running · queued · approval · warning · failed · canceled · locked · sample / `children`(글자 바꿀 때) | 2.2 표의 색·아이콘·기본 글자. running만 아이콘이 돈다. 내부에서 상태→표시 한 곳(`lib/ui/status.ts`)에서 매핑 |
| **SampleBadge** | `size`: sm · md | `is_mock` 결과의 썸네일 왼쪽 위, 파일 행, 내보내기 행. StatusPill sample과 같은 모양 |
| **Badge** | `tone`: neutral · accent | 분야 그룹, 비율·길이, 내용 버전 같은 정보 칩. 상태 표시에 쓰지 않는다 |
| **PhaseChip** | `phase`: 0~8 | `--phase-n` 배경 + 흰 글자 + mono "P1" |
| **Stepper** | `steps[]`: {key, label, state: done·current·waiting·locked, gate, note} | 7단계 고정 순서(등록·요구 확인·기획·장면 제작·수정·조립·검수·내보내기). 게이트 단계는 이름 옆 "승인" 표시. 각 단계 아래 한 줄 메모("v2 승인 · 11/15", "3/5 선택됨", "장면 완료 후"). 휴대폰은 가로 스크롤 허용(이 부품만 예외) |
| **Tabs** | `items[]`: {key, label, href, locked, lockedReason} | `role=tablist/tab`, `aria-selected`. 잠긴 탭은 자물쇠 + `aria-disabled` + title(이유). 잠긴 이유는 Stepper 메모에도 같은 말로 |
| **PageHeader** | `title`, `description`, `chips`, `actions` | h1 하나. 칩은 제목 위, 행동 버튼은 오른쪽(휴대폰은 아래 꽉 차게) |

| **FormErrorSummary** | `errors[]` | 저장 실패 시 폼 맨 위 `role=alert`: "n개 항목을 확인해 주세요." + 칸 이름. 첫 오류 칸으로 포커스 이동 |

## 5. 패턴

### 5.1 게이트 (기획 승인·검수 승인, PLAN R6·S2·S3)

- Stepper 이름 옆 "승인" 표시로 게이트 단계를 구분한다.
- 승인 버튼은 조건을 못 채우면 `disabled` + 이유 글("보류 1개, 미확인 1개가 남아 있어 승인할 수 없어요.").
- 승인 후 화면 위 Callout(info): "승인된 기획 v2 기준으로 만들어요. 기획을 고치면 새 버전이 생기고, 다시 승인할 때까지 그 내용으로는 만들 수 없어요."
- 서버가 막는다. 화면 비활성은 안내일 뿐이며, 서버 거절(409 등)도 같은 문장으로 보여 준다.

### 5.2 작업 상태 표시 (PLAN 9장)

| 작업 상태 | 화면 |
|---|---|
| queued | StatusPill queued "대기" + "작업 대기열 n번째" |
| running | StatusPill running "만드는 중 · 40초 지남", 썸네일 자리에 진행 막대(진행률을 모르면 흐르는 막대). 취소 버튼 |
| succeeded | 새 버전 칩 생성, Toast "장면 2를 만들었어요. v2가 새로 생겼어요. 선택은 그대로예요." — **새 버전이 생겨도 선택은 자동으로 바뀌지 않는다** (첫 버전만 자동 선택) |
| failed | 카드 선 빨강, 썸네일 자리 경고 아이콘, 실패 상자: 굵은 첫 문장(무슨 일) + 다음 행동 + 작은 글씨 코드·재시도 여부·청구 여부 |
| canceled | StatusPill canceled "취소됨", 이전 선택 유지 |

실패 문장 예시 (오류 코드 → 사용자 문장은 `lib/ui/errors.ts` 한 곳에서):

| 코드 | 첫 문장 | 다음 행동 |
|---|---|---|
| CONTENT_REJECTED | 제공사가 요청을 거절했어요. | 이유 + 바꿀 것을 안내, 자동 재시도 안 함 |
| TIMEOUT | 시간이 너무 오래 걸려 멈췄어요. | "다시 시도"(청구됐는지 함께 표시) |
| RATE_LIMITED | 잠시 요청이 많아요. | "n분 뒤 자동으로 다시 시도해요" |
| BUDGET_EXCEEDED | 이번 달 예산을 넘어 시작하지 않았어요. | 설정 > 예산 링크 |
| STORAGE_FAILED | 결과는 받았지만 저장하지 못했어요. | "저장 다시 시도" — 다시 생성하지 않음 (A-2) |
| INVALID_INPUT | 입력에 빠진 것이 있어요. | 해당 칸으로 이동 링크 |

### 5.3 장면 카드 (P1-4)

- 구성: 번호 · 9:16 썸네일(108px, 휴대폰 72px) · 이름 + 상태 · 설명 한 줄 · 대사 · 버전 칩 · 오른쪽 행동 버튼.
- 버전 칩: `v1`, `v2 · 선택`. 선택된 칩은 남색 채움. 실패 버전은 점선 빨강, 고를 수 없음.
- "버전 비교" 펼침: 버전별 썸네일 + 만든 시각·제공자·비용·기준 기획 버전. 선택 안 된 버전에 "이 버전으로 되돌리기".
- 선택 기준은 `scenes.selected_version_id` 하나 (S5). 화면은 이것만 읽는다.
- 기획이 바뀌어 장면 내용이 달라졌으면 StatusPill warning "기획 변경 후 확인 필요" + "v2 기준으로 다시 만들기" / "이대로 둘게요".
- 다시 만들기는 그 장면만 (R3). 일괄 버튼은 "결과 없는 장면만 만들기" 한 가지.

### 5.4 샘플 표시 (R5)

- mock 결과 썸네일: 왼쪽 위 SampleBadge. 파일명 접미사 `_SAMPLE`.
- 위 띠 "샘플 모드" 칩은 `MOCK_MODE=true`인 동안 항상.
- 내보내기 행·manifest·검수 화면에 "샘플 포함" 표시. 검수 공통 항목에 "샘플 결과가 최종본으로 표시되지 않았다" 자동 근거.
- 비용은 "0원(샘플)"으로 쓴다.

### 5.5 내용 버전과 검수 무효화 (S4)

- 프로젝트 머리에 Badge "내용 버전 r12" (title: "장면·대사·글자·규격이 바뀔 때마다 올라가는 번호").
- 검수 화면 위 Callout(warning): "내용 버전 r12 기준 검수예요. 장면·글자·규격을 바꾸면 버전이 올라가고 검수를 다시 해야 해요."
- 무효화되면 Toast(error 아님, info) + 검수 단계 Stepper가 다시 "검수 필요".

### 5.6 확인이 필요한 행동

| 행동 | 확인 방식 |
|---|---|
| 보관(숨김)·보관 해제 | ConfirmPanel (danger 톤 아님, 되살릴 수 있으므로 default) |
| 비용이 드는 생성 (실제 제공자) | ConfirmPanel: 예상 비용·이번 달 남은 예산 표시 (B-1) |
| 승인 | 버튼 한 번. 대신 승인 직전 요약(무엇을 승인하는지)을 버튼 위에 |
| 되돌리기(버전 재선택) | 확인 없음 + Toast에 "되돌리기" |
| 게시·제출 | **P1에 없음.** 생기면 반드시 ConfirmPanel + 사람이 직접 (R9) |

### 6.1 검수 항목 (ReviewItem)

- 항목 글은 menus.json `review` 그대로. 그룹: 공통 → 분야 → 조건부("광고·협찬 포함이라 추가된 항목").
- 버튼은 통과 / 보류 두 개(누른 것 다시 누르면 미확인). 보류는 **사유 필수** — 보류를 누르면 사유 입력칸이 열리고, 비우면 저장 안 됨.
- 자동 확인 근거가 있으면 "자동 확인됨 · 1080×1920"처럼 회색 작은 글. **자동 확인은 근거일 뿐, 통과는 사람이 누른다.**
- 진행 막대: 통과(초록) · 보류(노랑) · 미확인(회색). "필수 12개 중 10개 통과".

### 6.2 내보내기 (P1 = 편집용 묶음, E-1)

- 이름은 "편집용 묶음". "완성 영상"·"최종본" 표현 금지 (P2부터).
- 미리보기는 폴더 나무(mono) + 예상 크기. 샘플 포함이면 Badge.

## 8. 글쓰기 (화면 문구)

- 존댓말 "~해요"체. 짧게. 한 문장에 하나.
- 버튼은 동사: "저장하고 시작", "다시 만들기", "보관 해제". "확인"·"OK"·"제출" 단독 금지.
- 사용자를 탓하지 않는다: "잘못 입력했습니다" ✗ → "확인된 장점을 하나 이상 적어 주세요." ○
- 숫자는 아라비아 숫자, 시간은 "14:20", 날짜는 "11월 15일" (올해가 아니면 연도).
