## Master 하네스 체크포인트

CMD-20261122-001의 [실제 하네스 운영](../../harness/OPERATIONS.md)을 적용한다. 새 구조화 배정·결과·관리자 지시는 단일 Controller에 접수하고, 기존 Orca 보고는 그쪽의 wake에서 확인한다. 양쪽 모두 플랜·HTML을 먼저 갱신한다. 이전 체크포인트와 역할별 직접 배정 이력은 이어서 사용한다.

- 현재 Master에서 Orca wake가 오면 `node scripts/master-harness.mjs wake`를 실행한다. 이 명령은 기존 run·터미널에서 지정된 Orca check를 실행하고, 아직 판정하지 않은 메시지를 Orca 받은편지함에서 다시 찾는다. 예약 작업은 점검 알림만 보낸다.
- 세션 시작 또는 중단 후 `node scripts/master-harness.mjs resume`으로 미처리 메시지·전송 미확정 배정을 확인한다. 이 명령은 Orca 읽음 상태를 바꾸지 않는다. 최근 250건에서 마지막 체크포인트를 찾지 못하면 공식 작업표와 Orca 기록을 대조해 누락 범위를 먼저 확인한다.
- 근거·판정·후속 조치를 마스터 플랜과 Controller에 반영한 다음 `node scripts/master-harness.mjs done <메시지ID> "<판정 및 근거>"`로 처리 완료를 저장한다. 선행 메시지가 처리될 때까지 체크포인트는 건너뛰지 않는다.
- 신규 배정은 Controller 큐에서 전달한다. 이미 발송된 배정과 독립 착수는 기존 영수증을 사용한다. 전송 어댑터는 Controller가 호출한다. 읽음과 역할의 수락·착수는 별도로 확인한다.
- 현재 PC의 체크포인트는 Git에서 제외된 `tmp/master-harness/`에 보관한다. Orca가 메시지 원본을 유지하며 로컬 기록에는 판정·작업 키·영수증만 저장한다. 작업 키에는 비밀값을 넣지 않는다.
