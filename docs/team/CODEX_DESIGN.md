## UI 시안 전달

- 새 디자인 방향의 선택이 필요한 시안 제작은 서로 다른 3안을 함께 제시한다. 지정 원본 복원·승인된 디자인의 작은 수정은 기준 화면과 변경 결과를 비교해 검수한다. 유지할 시안이 있으면 1안으로 두고, 같은 요구사항을 다루는 새 2안과 3안을 만든다.
- 하나의 HTML 비교 페이지에 1안·2안·3안의 같은 화면을 나란히 배치한다. 작은 화면에서는 카드가 세로로 이어지도록 하고, 각 안을 전체 크기로 열 수 있는 링크와 핵심 차이를 한 줄씩 표시한다.
- 사용자에게는 브라우저에서 직접 열 수 있는 비교 페이지의 HTTP(S) 주소를 먼저 전달한다. 로컬 프리뷰라면 실행 중인 서버 주소를 제공하고, 페이지와 각 안의 링크를 브라우저에서 실제로 열어 데스크톱·모바일에서 확인한다.
- 시안에 예시 데이터를 사용하면 페이지에 표시한다. 전달할 때 비교 페이지, 개별안 링크, 적용 상태를 안내한다.

## 작업 완료 후 다음 작업

- 작업을 마치면 산출물 경로, 커밋, 검증 결과와 남은 문제를 Orca로 Master에게 즉시 보고한다. 구현·검수에 필요한 내용은 담당 세션에도 전달한다.
- 완료 보고 뒤 마스터 개발 플랜의 결과·담당 상태와 팀 최신 배정을 다시 확인한다. 새 배정이 있으면 그 범위를 따른다. 배정이 없으면 이미 반영된 플랜에서 진행 가능한 디자인·UI 작업을 골라 기존 담당과 수정 범위를 대조한다. 작업 ID·기준 커밋·산출물·검수 기준을 Master에게 알리고, 기존 승인 범위 안의 작업을 진행한다. 결과 반영을 기다리거나 담당 범위가 겹치면 의존하거나 담당이 겹치는 부분을 Master와 조정한다. 다른 독립 작업은 팀 공통 기준에 따라 계속한다.
- 승인이나 선행 결정이 필요한 일은 필요한 조건을 Master에게 알리고, 그동안 진행할 수 있는 독립 작업을 찾는다. 진행 가능한 일이 모두 막혔을 때만 필요한 조건을 기다린다. 작업을 마치면 결과를 보고하고 같은 순서를 반복한다.
