# PCM 등록 증거 발급·폐기와 요청 원장 격리 검증

2026-11-20 KST · Codes(Backend) · Master 배정 `msg_ca0168ce5683` · 경계 문서 `ead6758`

**소유 루프백 PG17.12에서 실제 등록 WAV의 증거 발급·폐기와 요청 원장을 한 트랜잭션으로 확정했다.** 기존 등록 핸들러와 두 소유자의 PCM 원본, 비공개 조회 역할 및 실제 음악 분석의 고정 검증을 재사용했다. 새 증거·원장·COMMIT 보류 트리거는 전용 시험 스키마에만 있다. [등록 권한 검증](REA-REGISTERED-PCM-WAV-AUTHORITY-VERIFICATION.md) · [기존 T312 원장 검증](T312-REA-ISSUANCE-LEDGER-STORAGE-INTEGRATION.md)

## 시험 계약

- 고정 PCM 승인 실행기의 해시, 기존 T367의 소유 루프백·서명·정리 조건을 유지했다. 실제 기존 핸들러로 등록한 WAV의 본인 `rea-reference` 승인, 등록 세대, 승인 세대, SHA-256과 바이트 수를 현재 증거로 비교했다. Auth, 전환 작업 번호 및 검증 갱신·승인은 시험 데이터다.
- 단일 시험 스토어에서 같은 복원 세대·요청 키에 소유자와 입력 지문을 고정했다. 먼저 별도 커밋으로 예약한 후, 제어 행 → 요청 잠금 → 자료 범위 잠금 → 현재 등록 증거와 포인터의 예상 리비전을 대조했다. 시험 제어자가 등록·승인 갱신도 같은 범위 잠금을 사용하도록 맞췄다.
- 발급 또는 폐기에서 포인터 변경과 요청 원장 종결을 함께 커밋했다. 분리된 읽기 역할은 현재 승인·등록 증거와 일치하는 발급 포인터에서만 본인 원본을 읽는다. 증거 발급 역할은 지정 함수만 호출한다.

## 실제 실행 결과

| 시험 | 관측 및 판정 |
| --- | --- |
| 등록·발급과 계정 격리 | A·B의 실제 WAV를 기존 핸들러로 등록했다. 각자의 정상 발급 리비전 1에서 읽은 바이트와 등록 SHA·길이가 일치했다. 사전 예약 없는 발급 및 같은 예약 트랜잭션의 발급은 거절됐다. 타인 자료와 타인 원장 조회·키 재사용은 차단했다. |
| 권한·입력 충돌 | 발급 역할의 포인터 직접 수정과 원장 삭제, 읽기 역할의 발급 함수 및 원본 테이블 직접 조회는 모두 권한 거절 `42501`. 같은 키에 다른 입력은 충돌로, 별도 키에 잘못된 SHA나 최신 승인이 없는 등록 세대는 증거 불일치로 판정됐다. |
| 철회·늦은 발급·재승인 | A의 폐기 포인터와 원장이 리비전 2로 같이 확정됐다. 폐기 전 예약 요청의 늦은 발급과 이전 등록 세대 재사용은 차단됐다. 기존 발급 요청을 다시 읽어도 폐기 상태가 바뀌지 않았다. 원본 SHA가 같아도 새 검증과 현재 세대의 새 명시적 승인이 생긴 뒤에만 재발급할 수 있었다. B 자료는 계속 읽혔다. |
| 진행 중 COMMIT과 같은 키 | 실제 지연 트리거에서 COMMIT을 보류했다. 다른 연결은 예약과 이전 포인터만 읽었고 새 자료는 반환하지 않았다. 같은 키 재시도가 최초 트랜잭션을 기다리는 것을 `pg_blocking_pids`와 실제 쿼리로 확인했다. 최초 커밋 응답은 시험 요청자에게 전달하지 않았으며, 재시도는 리비전 3의 기존 확정을 반환했다. 포인터와 원장 변경은 한 번이었다. |
| COMMIT 취소와 재시도 | 실제 대기 중인 시험 연결의 COMMIT을 취소해 `57014`를 관측했다. 별도 조회에서 원장·포인터가 이전 상태로 함께 돌아왔다. 같은 키로 다시 적용해 리비전 4로 단일 확정했고, 또 호출하면 같은 결과를 읽었다. |
| 제어 번호와 정리 | 시험 제어 번호를 전진시키고 구 번호의 요청을 차단했다. 새 번호에서 기존 결과를 읽어도 포인터는 변경되지 않았다. 두 계정의 원본 대조, 임시 사본·테스트 연결·postmaster·루프백 리스너와 클러스터의 정리를 확인했다. |
