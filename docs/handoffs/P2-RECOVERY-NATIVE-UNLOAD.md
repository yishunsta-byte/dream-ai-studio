# P2 편집기 · 복구 상자가 열린 상태의 이탈 경고

T100과 T171에서 남겨 둔 브라우저 기본 확인창을 데스크톱 Chrome 157.0.8103.50(headless)에서 검증했다. 작업 기준 7b40aff와 T173 격리 앱 44b036a에서 editing-panel.tsx와 text-editor.tsx의 Git 차이는 없다. 가상 프로젝트 runtime의 새 사본과 로컬 Next 서버를 사용했다.

## 재현 조건

1. A 탭에서 문구 A를 저장한다. 실제 타임라인 POST가 서버에서 200으로 처리된 뒤 Chrome DevTools Protocol의 응답 단계에서 A 탭으로 전달되는 응답만 잠시 잡아 둔다.
2. A 탭의 문구를 다시 고쳐 초안을 만든다. B 탭에서 편집 페이지를 새로 열어 서버에 저장된 문구 A를 확인한 뒤, 같은 문구를 B로 변경해 저장한다. B 탭의 실제 200 응답을 확인한다.
3. A의 응답을 전달한다. A의 입력란은 B 문구를 표시하며 저장 버튼은 비활성이고 ‘변경 취소’ 버튼은 없다. 복구 상자에는 A가 보낸 뒤에 입력한 초안이 남아 있다.
4. A에서 새로고침과 탭 닫기를 각각 취소한다. 브라우저가 beforeunload 확인창을 열었는지, 취소 전후 문서 식별값(performance.timeOrigin), B의 입력값, 상자 안의 A 초안이 유지되는지 확인한다. 이후 아래 세 종료 경로를 개별 실행한다.

| 종료 경로 | 실제 관찰 |
|---|---|
| 복구 상자의 ‘확인했어요’ 클릭 후 새로고침 | 추가 경고 없이 새 문서가 열렸다. 입력란에 B 문구가 있고 복구 상자는 사라졌다. |
| 상자가 열린 채 새로고침 승인 | 기본 확인창이 다시 열렸다. 승인 후 새 문서에 B 문구가 표시됐고 상자는 사라졌다. |
| 상자가 열린 채 탭 닫기 승인 | 기본 확인창이 다시 열렸다. 승인 후 A 탭이 브라우저 대상 목록에서 사라졌다. |

세 종료 경로 모두 취소 두 건이 통과했다. 각 경로에서 실제 저장 요청은 A와 B 각 1회였으며 추가 타임라인 POST는 0건이었다. Chrome 프로필은 실행마다 분리했다. 첫 예비 시도는 완료 결과를 확보하지 못해 제외했고, 브라우저 명령에 시간 제한을 추가한 뒤 세 경로를 끝까지 실행했다. 로컬 서버를 종료했다.

실행 스크립트와 회차별 결과는 작업본의 `tmp/p2-recovery-unload/{probe.mjs,dismiss.json,accept.json,close.json}`에 있다. 휴대폰 및 다른 브라우저는 후속 검증 대상이다.

> 플래너 전달문 — 저장 경합 후 일반 변경 없이 복구 상자만 남아 있어도 데스크톱 Chrome이 새로고침·탭 닫기를 경고했습니다. 취소하면 복구 자료가 남고, 상자를 명시적으로 닫으면 경고가 해제됐습니다. 외부 최신 문구를 덮어쓰는 추가 저장은 없었습니다.
