## 2. 단위와 표기 규칙 (T-079 7.1 답 + Master 정합 요청)

### 2.1 글자 크기 — 저장 단위 경계

| 사실 (코드 확인) | 값 |
|---|---|
| P1 미리보기(`d7a1c17` editing-panel) | `fontSize ÷ (16:9면 1920, 아니면 1080) × 100cqw` → **캔버스 폭 1080(16:9는 1920) 기준 px** |
| P2 미리보기 컴포지션(`PREVIEW_SIZE`) | 9:16 = 1080×1920, 16:9 = 1920×1080, 1:1 = 1080×1080 → 세 비율 모두 **짧은 변 1080**. `TextView`는 저장값을 컴포지션 px 그대로 그림 |
| spec `units.fontSize` | "짧은 변 1080px 기준. 실제 크기 = 값 × (짧은 변 / 1080)" |

→ **세 정의는 저장 비율에서 모두 같은 크기를 낸다.** 9:16·1:1은 폭 = 짧은 변 = 1080, 16:9는 P1이 폭 1920 기준이었고 P2 컴포지션 폭도 1920이라 같은 px다. 그래서:

- **규칙(권장, 확정 요청):** 저장값의 크기 단위는 하나 — **"짧은 변 1080 기준 px"**. 지금 컴포지션에서는 그 숫자 그대로 px. 짧은 변이 1080이 아닌 크기로 렌더할 때(P2-4 이후 720p 등)만 `× 짧은 변/1080`.
- **P1에서 옮긴 값(r1의 28·40 등)은 다시 해석하지 않는다.** 위 이유로 P1 화면과 같은 크기가 이미 나온다(T-072에서 본 작은 "광고" 28은 P1에서도 같은 비율 크기).
- **새 프리셋 값**(자막 56·훅 104 등)도 같은 단위. 새 글자와 옮긴 글자가 한 화면에 섞여도 단위 경계는 없다 — 다른 것은 **값**뿐(P1 자막 40 vs 새 자막 56). 이것은 의도된 차이이고 자동으로 맞추지 않는다(N-2). 화면 안내(권장): 옮긴 글자를 고르면 크기 칸 아래 "P1에서 옮긴 크기예요. 새 자막 기본은 56이에요." (빠른 모양을 누르면 사라짐)
- 미리보기 전용 비율(P2-2)은 지금처럼 같은 px로 그린다(짧은 변이 모두 1080이라 spec 공식과 같음). 저장 비율 바깥 결과는 경고로 세지 않는다(5.1).

### 2.2 자간·외곽선·띠 — 같은 단위, 바깥 경계

| 값 | 뜻(권장, 확정 요청) | 지금 코드 | 기존 저장값 영향 |
|---|---|---|---|
| `letterSpacing` | **짧은 변 1080 기준 px**(fontSize와 같은 기준). 훅 −1 → 104px 글자에서 약 −0.01em | `TextView`가 `em`으로 그림 → −1이면 −1em(겹침) | P1 이관·지금 편집기가 쓰는 값은 모두 **0**(`textFromP1` 고정) → 0em = 0px라 **재해석 대상 없음**. 스키마 범위 −1~1은 px로도 그대로 쓸 수 있음 |
| `stroke.width` | **바깥으로 보이는 두께**(글자 획 바깥쪽만). spec `units.box`의 "줄바꿈 폭 = widthRatio×W − 2×(paddingX + 외곽선 두께)"와 같은 뜻 | `-webkit-text-stroke: width` + `paint-order: stroke fill` → 가운데 기준이라 바깥은 width/2 | 이관·지금 편집기 값은 모두 `stroke:null` → **재해석 대상 없음**. 그리는 법은 "바깥 = width"가 되도록(예: 2×width + paint-order) T-079가 브라우저에서 확인 |
| `background.paddingX/Y`·`radius` | 같은 단위 px | 그대로 | 이관값 `null` |
| 바깥 경계(실측·widthRatio) | 글자 획 + 외곽선 두께 + 띠 여백(+그림자 x·y·blur, 지금 프리셋은 모두 없음) | — | — |

- **원칙:** 이 세 값은 P2-3 이전에 제품이 0/null 이외 값을 쓴 적이 없으므로 뜻을 정해도 저장값을 바꾸지 않는다. T-079 시험에 "P2-3 이전 경로(P1 이관·정적 편집기)는 letterSpacing 0·stroke null·background null만 쓴다"를 넣어 근거로 남기길 권장.
- 그래도 저장 행 중 0이 아닌 자간·외곽선이 발견되면(직접 API 저장 등) **조용히 바꾸지 않고** 새 뜻으로 그린다는 사실을 T-079 보고에 적는다(화면 경고는 만들지 않음).
- spec 변경안은 12.1(`units.letterSpacing`·`units.strokeWidth` 문장). 실제 수정은 Master 배정 뒤.

### 2.3 표기 글자 — 지우기·시간·문구

| 항목 | 정리 | 근거 |
|---|---|---|
| 지우기 | **등록값이 요구하는 표기는 지울 수 없다.** "이 글자 빼기" 자리에 글 "필수 표기라 지울 수 없어요. 광고로 등록한 프로젝트예요."(종류별: AI 생성 → "실사형 AI 영상으로 등록한 프로젝트예요." · 가상인물 → "가상인물 추천으로 등록한 프로젝트예요."). 확인 패널 없음 | 서버가 이미 거절(T-079 7.1-3), 확인 후 지워도 검수에서 막히므로 지우는 길을 열 이유 없음 |
| 필수가 아닌 잠긴 글자 | 지금 없음. 생기면 그때 ConfirmPanel(DESIGN 6.8 문구) | T-079 7.1-3 |

## 5. 고른 글자 편집 칸

칸 이름은 짧게(문구·글꼴·크기…), 편집 칸 제목("{종류} · {문구 앞부분}")을 `aria-describedby`로 잇는다.

### 5.1 머리

종류 select(8종 spec label, 표기는 고정) · 시간 `{시작}–{끝}`. 종류를 바꿔도 모양은 그대로 + 칸 아래 "종류만 바꿨어요. 모양은 빠른 모양에서 골라요."(권장).

### 5.2 문구

textarea 500자. 아래 "최대 {m}줄 · 지금 {n}줄"(실측 전 "줄 수 확인 중"). spec `recommendedCharsPerLine`은 안내만 "한 줄에 {k}자 안팎이 읽기 좋아요."

### 5.3 빠른 모양

- 칩 **7개**(자막·훅·강조·제목·엔딩·가사·브랜드). **표기는 넣지 않는다** — 표기 모양을 일반 글자에 입히면 잠긴 표기처럼 보이고, 표기 글자에는 칩 자체가 없다(T-056 G1). T-079 3.1 "8 프리셋 칩"은 7개로 맞춰 주기를 요청.
- 바꾸는 것 = `style`·`animation`. 그대로 = 문구·시간·위치·종류·잠금(T-079 `applyPreset`).
- 옆 체크 "기본 위치도 함께"(기본 꺼짐, T-079) — 켜면 `box`도 프리셋 값.
- 적용 뒤 Toast "'{이름}' 모양을 적용했어요. 위치·문구·시간은 그대로예요." + "되돌리기"(이 적용 하나만).
- 옮겨 온 P1 글자에는 칩 위 안내 "P1에서 옮긴 모양 그대로예요. 누르기 전까지 바뀌지 않아요."

### 5.4 글꼴·굵기

- select, fonts.json 순서, **설치·검사 통과한 글꼴만**(N-3). T-079 3.1의 "설치 안 된 글꼴은 disabled + (설치 전)"은 **보이지 않게로 바꾸길 요청** — fonts.json 원칙("목록에 나오지 않는다")과 같고, 사용자가 화면에서 해결할 수 없는 항목이다.
- 항목 이름은 "이름 — 역할"(예 "Black Han Sans — 굵은 제목"), 그 글꼴로 그림(로드 실패 시 기본 글꼴, T-079). 아래 견본 한 줄 "가나다 ABC 123"(권장).
- 쓸 수 있는 글꼴이 8개보다 적으면 "지금 쓸 수 있는 글꼴 {n}개예요."(지금은 Pretendard 1개).
- 굵기 = 그 글꼴 `weights`만. 하나면 글 "굵기 {w} 하나만 있어요."
- 저장값의 글꼴을 지금 쓸 수 없으면: select에 "{이름} · 지금 없음"을 고른 상태로 보이고(다른 항목은 고를 수 있음), 미리보기는 P2-2 칩 "글꼴 없음 · 대신 보여요". 실측은 "글꼴을 불러오지 못해 크기를 확인하지 못했어요."(통과 아님). 저장은 T-079 2.3(바뀌지 않은 글자는 통과)대로.
- **Master 채택(`msg_c6438d3ed41c`, T-079 `5c1efb7`):** 읽을 수 있는 글꼴 목록(늘리기만)과 고를 수 있는 목록(spec ∩ 설치 ∩ 라이선스)을 나눈다. 화면은 **고를 수 있는 목록만** 보이고, 읽을 수만 있는 저장값은 위 "지금 없음" 표시 + 원문 그대로 보존 + 대체 글꼴 경고. 이 앱보다 예전 빌드가 새 글꼴 행을 읽지 못하는 제한은 문서에 적고, 화면·안내에서 "예전 버전에서도 열 수 있어요" 같은 말은 쓰지 않는다.

### 5.5 크기·색·외곽선·띠

| 칸 | 기준 |
|---|---|
| 크기 | 18~120 + 단위 글 "1080 기준 크기"(2.1). P1 글자에는 2.1의 안내 한 줄 |
| 색 | 견본 버튼(흰 #FFFFFF · 노랑 #FFD84D · 검정 #111111 · 남색 #172636 — spec에 나온 색만) + 색 고르기 |
| 외곽선 | 켬/끔 → 색·두께(0~40, "바깥 두께", 2.2). 켤 때 기본 = 그 종류 프리셋 값, 없으면 #111111·7 |
| 띠·그림자 | 켬/끔만(값은 프리셋 그대로, T-079 3.1). 켤 때 프리셋에 없으면 강조 프리셋 띠 값 |

대비 경고는 하지 않는다(장면마다 달라 실측 근거 없음).

### 5.6 위치

- "가로 위치 %"·"세로 위치 %"·"폭 %" 숫자 칸(0~100, 0.5 단위) — T-079와 같음. 기준점은 저장값 `anchor` 그대로.
- 위·가운데·아래 빠른 버튼은 두지 않는다(숫자 칸 + "기본 위치도 함께" + 안으로 옮기기로 충분). 지금 정적 편집기의 위/가운데/아래 select는 P2-3a에서 사라진다 — 옮겨 온 글자의 y 0.16·0.50·0.74 값은 숫자 칸에 16·50·74로 그대로 보인다.
- 숫자로 직접 고친 위치에는 "위치 확인 필요"를 붙이지 않는다.

### 5.7 움직임

| 칸 | 선택지(spec 이름 ∩ 스키마) |
|---|---|
| 나타날 때 | 없음 · 서서히 · 톡 튀어나옴 · 아래에서 위로 · 타자 치듯 |
| 강조 | 없음 · 통통 튐 · 흔들림 · 커졌다 작아짐 |
| 사라질 때 | 없음 · 서서히 · 위에서 아래로 |

- 길이·easing 칸 없음(1.2). 권장: 옆 "움직임 보기" = 그 글자 시작 0.5초 전으로 seek 후 재생(저장 아님).
- 움직임 줄이기가 켜진 컴퓨터: 움직임이 있는 글자에만 "움직임 줄이기가 켜져 있어 미리보기에서는 바로 나타나요. 만든 영상에는 움직임이 들어가요."

### 5.8 시간 (표기 제외)

- 시작·끝 `MM:SS.FF` 글 칸 + 각각 "지금 재생 위치로"(T-079). 도움말 "1/30초 단위 · 예 00:02.15 = 2.5초".
- 오류 문구(칸 아래, `aria-invalid`): 형식 "시간은 00:02.15처럼 적어 주세요." · 프레임 "프레임은 00~29까지예요." · 순서 "끝은 시작보다 1프레임 이상 뒤여야 해요."(서버 문구와 같음). 상한을 넘으면 저장은 되고 지금의 "영상보다 긴 글자예요."(자르지 않음).
- 오류가 있으면 저장 잠김 이유 "시작·끝 시간을 먼저 확인해 주세요."(지금 문구), 미리보기는 마지막으로 맞았던 내용(G-4).

### 5.9 빼기

일반 글자: "이 글자 빼기" → 바로 빠지고 Toast "글자를 뺐어요." + "되돌리기"(저장 전까지). 초점 = 다음 줄(없으면 "글자 추가"). 표기: 2.3.

## 6. 실측 경고

### 6.1 재는 법 (화면 쪽 기준 — 방법은 T-079 4.1)

- 저장 비율 크기의 컴포지션 좌표, 미리보기와 같은 글꼴 파일, **움직임이 없는 모양**으로 2.2의 바깥 경계를 잰다.
- 글꼴을 다 불러온 뒤에만 판정. 그 전에는 "확인 중", 실패·시간 초과는 "글꼴을 불러오지 못해 크기를 확인하지 못했어요."(통과 아님, 회색 "확인 전").
- 미리보기 전용 비율에서 걸치는 것은 세지 않는다. 그 상태의 칩 옆 글 "미리보기 비율에서는 경고를 세지 않아요."(권장).

### 6.2 문구

| 경우 | Callout(warning) 제목 | 설명 | 행동 |

| 9:16 아래 20% | 아래 안전 영역(20%)에 걸쳐 있어요. | 휴대폰 앱의 설명 글·버튼에 가려질 수 있어요. | 안전 영역 안으로 옮기기 |
