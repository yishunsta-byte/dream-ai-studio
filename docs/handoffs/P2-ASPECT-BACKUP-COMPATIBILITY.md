# 지원되는 비율 변경과 P1 백업 호환성

편집기의 16:9·1:1 조작은 PlayerPanel의 화면 상태만 바꾼다. 타임라인 저장은 프로젝트 비율과 다른 값을 거절한다. 프로젝트의 SQLite 생성 경로에서 비율을 설정하며, 기존 프로젝트의 편집·승인 경로는 내용 리비전이나 승인 기획 ID를 갱신한다. 백업 검증은 P1에서 이관한 r1의 비율을 프로젝트 비율과 대조한다. [미리보기](../../components/player/player-panel.tsx) · [타임라인 저장](../../lib/services/timeline.ts) · [P1 검사](../../lib/db/timeline-data.ts)

고정 s9 백업의 합성 복제본을 로컬 Next와 Chrome에서 열었다. 9:16 프로젝트에서 16:9와 1:1을 차례로 선택하면 각각 미리보기 전용 상태가 표시되고 저장된 타임라인 ID는 그대로였다. 1:1 미리보기를 켠 채 자막을 입력해 화면 저장을 실행했다. 새 리비전에 자막이 들어갔고 프로젝트와 타임라인 모두 9:16이었다. 새 탭에서 미리보기도 9:16으로 시작했다. HTTP에 16:9·1:1을 직접 보내는 두 시험은 각각 비율 불일치 400을 받았고 리비전은 생성되지 않았다.

이후 복제본에서 고정 백업이 담고 있던 과거 실행 중 작업 1개를 비활성 상태로 정리한 뒤 제품 백업·복원을 수행했다. 복원 전후 P1 이관 검사가 통과했고 프로젝트 비율과 현재 타임라인 ID·JSON이 일치했다. 관련 테스트 82건 통과. 65efabd의 거절은 이전 화면 시험에서 합성 프로젝트의 비율을 DB에 직접 바꿨을 때만 재현됐다.

> 플래너 전달문 — 지원되는 비율 전환과 자막 저장 뒤 P1 백업·복원은 정상입니다. 16:9·1:1 직접 저장 요청은 각각 400이었고, 이전 불일치는 시험 DB 직접 변경에서 발생했습니다.
