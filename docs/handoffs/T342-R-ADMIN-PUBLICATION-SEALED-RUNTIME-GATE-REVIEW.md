# T342-R 관리자 게시 연결 조건 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `633d319` · Master 배정 `msg_471ac982e70d`

**격리 검수 통과.** 제공된 소유 PG17/TLS와 실제 Supabase SDK 루프백에서 위임 설치 재확인, 세 공급원의 일괄 비활성, 정상 게시·표지·철회와 정리를 재현했다.

- 검증 DSN과 런타임 구성은 호스트·포트·DB·클러스터 승인값에 맞췄다. 별도 TLS 세션의 T341 검증이 DB OID와 계정·역할 OID, 설치 이력·카탈로그 및 회수를 확인했다. 다른 DB, 클러스터 불일치, 잘못된 TLS·계정·역할, 고정 권리 조회 함수와 다른 설정은 거절됐다. 소스상 T330의 DB OID 검사는 런타임 연결 그룹 내부에서 별도로 고정한다. T342가 검증 계획의 OID를 런타임 각 연결과 직접 대조하는 경로는 이번 후보 범위에 없다.
- 설치 전, 회수 대기, 권한 회수 후 기존 설치 세션 잔류, 이력 불일치와 부분 조립 실패에서 관리자 목록은 `closed`, 쓰기는 503, 홈은 샘플, 해당 표지는 404였다. 실패 흐름에서 실제 작품·표지와 Storage 호출은 0건이었다. 승인 작업 잠금이 끝난 뒤 기존 승인으로 새 런타임을 여는 요청도 닫혔다.
- 첫 읽기 스냅숏과 공급원 공개 전에 수행한 두 번째 읽기 전용 트랜잭션 사이에 이력을 변경했다. 동시에 시작한 두 호출 모두 비활성이었고 DB 세션을 정리했다. 초기 확인이 잠금에서 대기하는 동안 런타임을 종료한 경우도 공급원이 노출되지 않았다.
- 정상 `sealed` 상태에서는 관리자 HTTP로 준비·게시한 뒤 공개 피드와 WebP 바이트를 확인했다. SDK는 고정 버킷 메타데이터와 정규 객체를 인증된 GET으로 읽었다. 철회 후 작품이 피드에서 빠지고 표지는 404였으며 Storage 요청은 늘지 않았다.
- T342 전용 모드, T341 별도 모드와 무인자 T328 TLS 22건 및 T330·T332·T336이 모두 통과했다. 검증·런타임 DB 세션과 소유 PG 프로세스 0건을 확인했다. 루프백 Storage 서버, 세 PG 실행의 리스너·임시 클러스터 및 검수 사본을 정리했다.

## 회귀와 판정 범위

인계의 병렬 Vitest에는 기존 Storage 스트리밍 시험 한 건의 시간 초과가 기록돼 있다. 이번 검수의 시간 제한 민감한 비공개 자산 파일은 PG 종료 후 단일 워커로 실행했다. 독립 단일 워커 회귀는 27파일 696건이 모두 통과했다. 비공개 자산 파일을 제외하고 먼저 실행한 병렬 회귀 26파일 642건도 통과했다. 소스 타입 검사, 변경 TypeScript 4개 ESLint와 diff 공백 검사를 통과했다.

기본 제품 설정은 비활성이다. 이 판정은 명시 설정의 최초 공급원 조립 시점과 합성 Storage에 한정한다. 관리형 대상과 제품 호스트 활성화, 가동 중 이력 재검증은 범위 밖이다. 운영·빌드·배포 변경은 없었다.
