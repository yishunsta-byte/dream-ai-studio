- 담당: CC-DATA-01 · 지시: Master msg_9da061bde3f2 · 기준: PLAN 18장 P2 종료 기준 "자막 오차 0.2초 이내", T-057 검증 방법
- 바꾼 파일: `scripts/remotion/measure-subtitle.ts`(새, 독립 스크립트), `tests/measure-subtitle.test.ts`(새), 이 보고서. 제품 DB·API·UI·migrations·packages·spec은 바꾸지 않았어요.
- 상태: 자체 검수(독립 검수 아님). **이 시험은 가상 시험 영상 3개의 측정이에요. 사용자가 만든 영상의 "자막 표시 오차" 칩은 계속 "측정 전"이에요.**

## 1. 무엇을 쟀나
- **기대값:** 수동으로 정한 가상 자막의 시작·끝(초) → 제품 규칙 `secondsToFrames`(30fps, 밀리초 반올림)로 바꾼 프레임. 표시 구간은 `[시작 프레임, 끝 프레임)`.
- **① SRT:** 같은 타임라인 글자로 제품 `timelineSrt`가 쓴 SRT를 읽어 기대값과 비교했어요(글자로 짝지음). **VTT는 제품에 없어서 재지 않았어요(미구현).**
- **② 실제 렌더 영상:** 처리기와 같은 렌더 경로(`runRenderAttempt` → 렌더 자식 → Composition → 고정 브라우저)로 만든 MP4를 프레임마다 디코드해서, 자막별 띠(ROI)에서 보이기 시작한 첫 프레임과 마지막 프레임+1을 찾았어요. DB 없이 OS 임시 폴더에서만 실행했어요.
- **판정:** 각 자막의 시작·끝 절대 오차 중 최댓값 ≤ 0.2초. 대조 띠는 0프레임이어야 하고, 앱의 출력 확인(ffprobe)도 통과해야 해요.

## 2. 시험 영상
- 4초(120프레임), 9:16(1080×1920) · 16:9(1920×1080) · 1:1(1080×1080).
- 배경: 0~2초 이미지 장면(0x335577 단색), 2~4초 영상 장면(0x6a4a2a 단색 H.264). 흰색이 아닌 고정 배경이에요.
- 글자: Pretendard 700, 64px, 흰 글자에 검은 테두리 3px(고대비). 자막마다 다른 높이에 둬서 띠가 겹치지 않아요.

| 자막 | 종류 | 수동 시작–끝(초) | 기대 프레임 [시작, 끝) |
|---|---|---|---|
| c1 | 애니메이션 없음 | 0.37–1.52 | 11–46 |
| c2 | 애니메이션 없음, 장면 경계(2.0초) 걸침 | 1.71–3.08 | 51–92 |
| c3 | 페이드 들어옴·나감(10프레임) | 0.55–2.43 | 17–73 |
| c4 | 타자기 | 1.18–3.61 | 35–108 |

모든 시각은 프레임 경계가 아니에요(예: 0.37초 = 11.1프레임).

- **검출 규칙:** 띠는 높이의 ±7%, 가로 20~80%예요. 기준 띠는 왼쪽 2~5%로, 글자가 닿지 않는 곳이고 그 프레임의 배경색을 줘요.
  - 기준 띠 배경색과 비교해 가장 큰 채널 차이가 **48**을 넘으면 다른 화소로 셌어요.
  - 다른 화소가 **40개 이상**인 프레임을 "표시"로 봤어요.
- **읽은 범위:** 비율마다 0–119 전 프레임(120개)을 rgb24로 디코드했어요.
- **대조 띠:** 높이 88% 위치이고, 자막이 들어가지 않아요.

  - 단색 배경의 H.264 압축 잡음(수 단계)보다 충분히 커요.

## 4. 측정기 검증 (자기 임시 데이터, `tests/measure-subtitle.test.ts` 6개 통과)
- 초→프레임 사본이 제품 `secondsToFrames`와 0~5초의 모든 밀리초에서 같아요. 자막 기대 프레임 표도 확인했어요.
- 끝 = 마지막 보인 프레임+1. 오차 0 / 1프레임(0.033초) / 6프레임(0.2초, 통과) / 7프레임(0.233초, 실패), 검출 없음은 실패.
- 제품 SRT를 읽고 시작 순 정렬이어도 글자로 짝지어요.
- ffmpeg 합성 영상(배경색이 60프레임에서 바뀜)으로 확인했어요.
  - 흰 상자를 그린 프레임 [11–45], [51–91]을 정확히 찾았어요. 대조 띠는 0프레임이에요.
  - 1프레임 늦게 그리면 12–47(0.033초, 통과), 7프레임 늦게 그리면 18–53(0.233초, 실패)으로 잡았어요.
  - 배경과 거의 같은 색(임계값 아래)은 세지 않았어요(가짜 검출 없음).

## 5. 재지 않은 것 · 한계
- **VTT:** 제품이 만들지 않아요(미구현). SRT와 타임라인 JSON이 같다는 것만으로 통과라고 하지 않았고, 영상 화소를 따로 쟀어요.
- **목소리와의 의미적 싱크:** 사람이 평가해요. 실행하지 않았어요.
- **실제 휴대폰 재생:** 실행하지 않았어요(390 에뮬레이션은 대신할 수 없음).
- **사용자 영상:** 측정하지 않았어요. 화면의 측정 값(null → "측정 전")은 그대로예요. 이 결과로 측정 완료를 표시하지 않아요.
- 단색 배경과 고대비 글자로 한 시험이에요. 복잡한 영상 배경에서는 이 화소 규칙을 그대로 쓸 수 없어요(별도 방법 필요).
- 렌더는 DB를 거치지 않는 같은 렌더 자식·Composition 경로예요. 처리기의 DB 단계(요청·게시)는 T-114 e2e가 따로 확인해요.
- 실제 사용자 data/storage/DB, 기존 성공 MP4는 열지도 바꾸지도 않았어요.
