# 새 로컬 PG 프로젝트의 제작부터 MP4 다운로드까지

## 기준과 실행

`2b892d9` 고정 사본에 합성 소유자 세션, 루프백 Storage, PG17.12와 실제 Next를 구성했다. 새 프로젝트는 제품 HTTP로 생성했다. 시험 중 프로젝트의 장면·타임라인·승인·출력을 SQL로 설정하지 않았다. 결과 점검에만 SQL을 사용했다. 제품 화면 단계는 390px Chrome에서 키보드로 진행했다.

격리 사본 `D:/starwork/p2-pg-first-work-e2e`에서 `tests/postgres/first-work-e2e.probe.mjs`를 공용 HTTP 검사에 연결하고 아래 명령을 실행했다.

```powershell
$env:T371_VERIFY_HTTP='1'
$env:T371_VERIFY_RENDER_AUDIO='1'
$env:T371_VERIFY_FIRST_WORK_ONLY='1'
node --conditions=react-server --import tsx tests/postgres/t368-run-private-image-project-create.mjs
```

## 동일 PNG 두 장면

- 서로 다른 PNG 두 장은 업로드됐다. 프로젝트 생성에 두 ID를 넘기면 HTTP 400이었고, 단일 PNG로 생성한 프로젝트에서 연결하지 않은 두 번째 PNG를 장면 결과로 등록하면 HTTP 404였다.
- 첫 PNG로 새 프로젝트를 만든 뒤 브리프 확인, 두 장면 기획 저장·승인, 각 장면 결과 등록·선택, 제작 승인, 초기 타임라인, WAV 업로드·연결·저장을 제품 HTTP로 진행했다. 타임라인 r2·내용 r5에 서로 다른 장면 결과 두 개가 30·60프레임 순으로 저장됐다.
- 편집 완료, 필수 검수 13항목 통과, 검수 승인, 렌더 제목 초점, 렌더 요청 HTTP 202, 실행 HTTP 200, Chrome 기본 다운로드까지 진행했다. 다른 계정의 같은 파일 요청은 HTTP 404였다.
- 다운로드가 33,109바이트였고 DB와 응답의 SHA-256 `c86ce1195f0f86a4b86eda501c9b9816d0e3ab439089f44f334fc0298edd8418`과 일치했다. 실제 파일을 다시 검사해 H.264 1080×1920, 30fps·90프레임·3초, AAC-LC 48kHz 스테레오 1트랙을 확인했다.
- DB에서 브리프·기획·제작·편집·검수 완료, 단일 렌더 요청·실행·완료, 두 장면 등록·선택 각 2건을 확인했다. 격리 실행 종료 코드는 0이었고 PG 리스너와 임시 클러스터는 정리됐다.
- 첫 고정본의 렌더 범위 안내는 PNG 한 장으로 표시됐다. Front가 `7430984`와 `314b73e`에서 PNG 1~2장·WAV 1~2개 안내를 반영했다.

## 서로 다른 PNG 두 장면

- 두 번째 원본 연결이 포함된 `63c8ed9`로 고정 사본을 바꿨다. 같은 실행 명령에 `T371_VERIFY_FIRST_WORK_MODE=two`를 추가했다. 새 프로젝트에 연결하기 전 두 번째 PNG 장면 등록은 HTTP 404였다. 제작 API에서 연결 HTTP 201, 동일 요청 재전송 HTTP 200, 새로고침 조회의 서로 다른 PNG 두 장을 확인했다. DB 추가 연결 및 감사 기록은 각 한 건이었다.
- 빨간 PNG와 파란 PNG를 장면별로 등록·선택한 뒤 제작 승인, WAV 저장, 브라우저 검수·승인, 렌더 요청·실행 및 다운로드를 같은 새 프로젝트에서 통과했다. 렌더 안내에서 PNG 1~2개와 WAV 1~2개가 표시됐다.
- 390px Chrome이 내려받은 파일은 31,195바이트였고 응답·DB SHA-256 `61c524903c0202ae5076890bfcea53bba634533d275bc783459a2a8d1afca752`와 일치했다. 타 계정 다운로드는 HTTP 404였다. 출력은 1080×1920 H.264, 30fps·90프레임·3초, AAC-LC 48kHz 스테레오 1트랙이었다.
- 0부터 센 29·30·89프레임의 중심 RGB는 각각 `[255,1,0]`, `[1,0,255]`, `[1,0,255]`였다. 모노로 디코드한 48kHz 오디오 144,000샘플에서 600Hz 성분이 WAV 재생 구간에 있었고 이후에는 기준 미만이었다. 렌더 요청·실행·완료는 각 한 건이었다.
- 실행 종료 코드는 0이었다. PG 리스너와 임시 클러스터를 정리했다. 이 통합 검증은 합성 로컬 자료를 사용했다. 실제 사용자 작품으로 운영 내보내기와 재편집 ZIP을 확인하는 단계가 남아 있다.

> 새 로컬 PG 프로젝트에서 서로 다른 두 PNG와 WAV로 브리프부터 90프레임 MP4 다운로드까지 통과했습니다. 폴더나 승인 상태를 시험 중에 SQL로 만들지 않았고, 다운로드 SHA와 DB 기록이 일치했습니다. 경계 프레임에서 빨간 장면이 파란 장면으로 바뀌는 것을 직접 측정했습니다.
