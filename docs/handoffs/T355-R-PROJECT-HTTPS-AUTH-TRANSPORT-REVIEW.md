# T355-R 프로젝트 조회 인증 전송·쿠키 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `fe965a8` · Master 배정 `msg_f7f9cc29c5d7`

**격리 검수 통과.** 고정 4경로는 공용 SSR 헬퍼, 프로젝트 조회 조립기, 집중 시험, 인계다. 설치된 SSR/Auth SDK를 실행했고 Next 쿠키 저장소와 상류 응답은 모의로 구성했다.

- 첫 SDK Auth부터 승인 origin의 정확한 사용자 GET과 라우트에서만 허용되는 갱신 POST를 확인했다. 예상 밖 경로·메서드·외부 대상은 네트워크 전에 차단됐다. 갱신 본문은 토큰 필드 한 개였고 쿠키 헤더는 전송되지 않았다. `no-store`, 쿠키 제외, 리디렉션 거부 및 호출자 취소·5초 제한 신호가 적용됐다. 시험에서 사용자 호출의 제한 신호와 갱신 호출의 취소를 각각 발생시켰으며 후속 재시도·데이터 조회 없이 고정 503이었다.
- 쓰기 가능한 모의 라우트 쿠키는 갱신을 받았고 새 토큰만 후속 Auth와 조회에 전달됐다. 처음부터 쓰기 실패한 경우와, 다중 쿠키 중 첫 쓰기는 성공하고 두 번째에서 실패한 독립 시험 모두 503 `no-store`로 닫혔다. 실패 뒤 추가 Auth·조회는 없었다. 부분 실패에서는 선행 쿠키 기록이 모의 저장소에 남았다. 시험 결과가 쿠키 일괄 롤백을 보장하지는 않는다.
- 렌더에서 만료 쿠키는 갱신 POST가 전송되기 전에 401로 닫혔고 쿠키 쓰기는 없었다. 이후 요청에 새 쿠키를 주면 동일 토큰으로 Auth GET 두 번과 데이터 조회가 정상 동작했다. 기존 공용 헬퍼의 옵션 없는 호출은 전송 기본값과 쿠키 쓰기 실패를 무시하는 동작을 유지했다. 앱 응답의 `no-store`와 자격·공급자 오류 비노출을 확인했다.
- 제공 조립 시험 26건을 포함한 관련 회귀는 391건 통과·30건 조건부 건너뜀이었다. 검수 사본의 추가 독립 시험 2건, 소스 타입·변경 TypeScript ESLint·커밋 diff 공백 검사도 통과했다. 사본을 정리했다.

제품 라우트는 후보 조립기를 호출하지 않는다. 실제 Supabase, 실제 Next proxy/라우트/렌더의 쿠키 전달과 부분 기록 복구는 범위 밖이다. 운영 접속·빌드·배포·새 세션 생성은 없었다.
