# T322 전송 의도와 철회 완료 장벽 격리 검증

2026-11-19 KST · Codes(Backend) · 설계 `6dcee21`, 고정 통합 기준 `e16d213` · T322 `msg_7687c7bd2947` · F322-1 기준 `6c793aa`, 배정 `msg_2732006d6510`

소유 루프백 PostgreSQL 17.12에 해시를 고정한 T319·T320 시험 SQL과 T322 확장을 적용했다. 각자 다른 PID와 포트의 HTTPS 송신자 두 개 및 별도 제어기를 사용했다. 보호 JSON·주체는 합성 값이며 클라이언트는 임시 인증서와 루프백 IP·피어 지문을 검증했다. [T321 계획](T321-REA-PROTECTED-EGRESS-STAGING-PLAN.md) · [T320 통합 근거](T320-REA-HTTPS-DURABLE-EGRESS-INTEGRATION.md) · [T322 SQL](../../tests/reference-analysis/t322-egress-intent-revocation.sql)

제어 트랜잭션과 송신 의도는 같은 게이트 행을 잠근다. 최초 쓰기 직전의 DB 확인에서 허가·소유 번호·권한 리비전·제어기 번호·주체·채널·기한·본문 다이제스트를 결합한 전송 의도가 한 행으로 커밋된다. 철회가 접수되면 신규 발급·소비·전송 의도를 닫는다. 기존 미종결 의도가 남아 있으면 철회 완료와 새 세대 활성화가 대기한다. 송신자의 실제 소켓 종료 관측을 기존 허가 상태와 같은 트랜잭션에 종결 기록으로 남긴다.

F322-1에서 감독 역할의 호출을 T322 격리 함수로 변경했다. 기존 T319 격리 검증을 사용해 현재 세대·송신자·감독자가 관측한 PID를 대조한다. 성공한 경우 같은 트랜잭션에서 허가와 같은 채널·세대·송신자·주체·권한 번호의 미종결 전송 의도에 `isolated`와 종료 시각을 기록한다. 매칭되지 않는 미종결 행이 대상 범위에 남으면 허가와 송신자 갱신까지 롤백한다. 감독 역할에는 이 결합 경로만 부여한다.

| 시험 | 실제 관측 |
| --- | --- |
| 최종 DB 판정 뒤 첫 쓰기 전 | 전송 의도가 커밋된 뒤 송신자를 보류했다. 별도 연결에서 의도와 비어 있는 첫 쓰기·종료 필드를 확인했다. 같은 허가 반복은 409·본문 0바이트였다. |
| 실제 첫 바이트 뒤 최초 보고 누락 | 다른 연결의 보호 접두부를 실제 클라이언트가 받았다. 시험 스위치로 최초 송신 보고만 생략했고 원장은 여전히 `starting`과 미종결 의도를 보였다. 이 상태를 미송신으로 처리하지 않았다. |
| 철회 접수와 새 작업 차단 | 같은 철회 ID 재접수는 대기 상태를 반환했고 다른 주체의 완료 시도는 거절됐다. 접수 전에 소비는 했으나 의도가 없던 제3의 TLS 요청을 진행하자 409·본문 0바이트였고 의도 행은 없었다. 접수 이후 신규 발급과 새 세대 활성화가 차단됐으며 기존 주체 권한은 아직 변경되지 않았다. |
| 제어기 재시작과 미확정 의도 | 기존 제어 PID를 종료하고 새 제어기를 실행했다. 제어기 번호가 바뀐 뒤에도 두 의도와 대기 상태가 유지됐다. 첫 요청을 실제 종료하고 취소를 기록했지만 두 번째 요청이 남아 있어 완료와 전환이 계속 대기했다. |
| 두 채널 종료와 철회 완료 | 두 번째 클라이언트를 실제 끊었고 접두부만 수신한 사실과 송신 측 소켓 종료를 확인했다. 이후 종료 기록을 일부러 보류하자 철회 완료와 세대 활성화는 계속 거절됐다. 종료 관측을 원장에 반영한 뒤에만 철회가 완료됐다. 별도 DB 조회에서 두 종료 기록의 시각이 접수 이후, 완료 이전임을 확인했다. 완료 재조회는 권한 리비전을 두 번째로 올리지 않았다. |
| F322-1 감독 격리 | 정상 종료 보고 없이 기존 송신자 프로세스를 실제 종료했다. 두 클라이언트 연결이 닫혀도 감독 기록 전에는 철회와 전환이 계속 보류됐다. 증거 누락·잘못된 PID·송신자·세대를 거절했다. 의도와 허가의 채널 불일치를 주입하면 SQL 오류가 발생하고 기존 허가·의도·송신자·이벤트 상태가 그대로였다. 정상 채널로 복구한 뒤 감독 트랜잭션을 일부러 롤백해 별도 연결에서 무변경을 확인했다. 정상 커밋에서만 두 허가와 의도가 함께 종결됐으며 반복 호출은 최종 상태를 유지했다. 이전 세대의 합성 비교 행과 다른 송신자의 상태는 그대로였다. 감독 기록 후 철회 완료와 새 세대의 정상 HTTPS 응답을 확인했다. |
| 철회 완료 뒤 재시도와 다음 세대 | 기존 송신자에 늦은 송신 재개 지시를 보내고 양쪽 TLS 리스너에서 이전 허가를 반복했다. 새 보호 본문은 0바이트였고 추가 시작 기록도 없었다. 기존 송신 PID의 실제 종료와 감독 역할의 격리 기록 뒤 다음 세대를 열었다. 다른 주체의 새 허가는 전체 응답을 한 번만 보냈고 반복은 409·본문 0바이트였다. |

수정본 실행에서 정상 종료와 감독 격리 시나리오가 각각 별도 소유 클러스터에서 통과했다. ESLint가 통과했고 제한 DB 세션과 마지막 송신자의 소켓·작업·클라이언트 요청은 0건이었다. 각 실행에서 두 TLS 포트의 재접속 거절, 소유 제어/송신/PG 종료, PG PID 파일·리스너·임시 클러스터와 인증서 제거를 확인했다. [실행기](../../tests/reference-analysis/t322-egress-intent-revocation.pg17.mjs)

**관측 범위.** TLS 본문·접두부, 클라이언트/서버 소켓 종료, 해당 원장 커밋과 프로세스 교체는 실측했다. 격리 보고의 근거는 시험 감독자가 실제로 관측한 소유 자식 프로세스 종료이며, 원장은 감독 역할이 전달한 대상과 PID를 검증한다. 최초 송신 보고 생략과 종료 기록 지연은 시험용 제어다. 마지막 DB 판정과 실제 소켓 삽입 사이에는 미확정 의도를 보존하고 완료를 기다리는 계약을 시험했다. COMMIT 응답의 네트워크 유실, DB·소켓의 물리적 원자성, 다중 호스트와 프록시 큐·실제 TLS 진입점, 제품 대기 시간 정책과 유료 스테이징은 미확정이다. 제품·운영·외부 자원·비용·배포 변경은 없었다.

**Master 전달문** · T322-F1에서 검증된 감독 격리 시 해당 허가와 미종결 전송 의도를 함께 종결하도록 수정했다. 종료 증거 부재·대상/채널 불일치와 롤백은 보류 상태를 유지했고, 다른 송신자·이전 세대 행은 보존됐다. 정상 종료와 감독 복구 뒤 철회 완료·새 세대 HTTPS 및 정리 회귀를 확인했다. 독립 재현을 요청한다.
