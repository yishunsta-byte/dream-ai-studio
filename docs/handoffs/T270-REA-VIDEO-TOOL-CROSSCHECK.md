# T270 rea-video와 REA 영상 대조 검증

2026-11-19 KST · Codex(Tester) · 배정 `msg_82ca8d8907d9`

**지정 합성 하드컷 대조 통과.** rea-video와 제품의 두 고정 버전은 `2.000s`에서 같은 첫 파랑 프레임을 가리켰다. 컷의 관측 구간, 대표 프레임의 형식과 영상 제작 방식 추정은 각각 별도 의미로 보존한다.

## 같은 입력의 실측

설치된 rea-video `538eb3a757db94826cb90c4297279e50c5dd0f83`의 `rea-video.cmd summary`로 기존 `breakdown.json`을 읽었다. 기존 `VIDEO.md`, 타임라인, 리듬 문서, 스토리보드와 양쪽 샷 연락표를 대조했다. 입력 `synthetic-cut.mp4`는 4,233 byte라 도구의 64 MiB 선두 해시 범위에 전부 들어간다. 파일 전체 SHA-256 `87417f78c6a109ecc6a86437951a7d63138b090b038f79c502e76a9c91b4cb27`가 `source.sha256_head` 및 `VIDEO.md`의 `source.sha256`과 일치했다. 별도 ffprobe는 160×90, 24fps, 96프레임, 총 4000ms를 확인했다.

| 항목 | 독립 기준 | 기존 rea-video | 제품 `701afe2`와 `232957e` |
| --- | --- | --- | --- |
| 컷 / 샷 구간 | 빨강 `[0,2000)` → 파랑 `[2000,4000)` | 샷 `[0,2)` 및 `[2,4)`초, 프레임 경계 `0/48/96`, 둘째 샷 `transition_in=cut` | 컷 후보 `[1958,2000]ms`, 차이 `0.660131`, 프레임 47→48 사이 관측 |
| 컷 오차 | ffprobe 프레임 47은 1958ms, 프레임 48은 2000ms | 둘째 샷 시작 2000ms | 후보의 첫 이후 프레임 2000ms 비교 오차 **0ms·0프레임**. 이전 프레임과의 42ms는 관측 구간 폭이다. |
| 대표 프레임 | 첫 빨강과 첫 파랑 | `keyframes` `0.000s @0`, `2.000s @48`, `first` 역할. 해당 160×90 JPEG 중앙 RGB `[254,0,0]` / `[0,0,254]` | 64×36 RGB24 파생 프레임, 0ms와 2000ms. 중앙 `[252,0,0]` / `[0,0,253]`. 픽셀은 서버 내부 파생물이고 검사 JSON에는 없다. |
| 끝 경계 | 마지막 실제 프레임 3958ms | 샷 끝 4000ms 및 종료 인덱스 96 | 트랙 끝 4000ms, 마지막 관측 3958ms. 종료 인덱스·시간은 탐색 가능한 프레임으로 가져오지 않는다. |

두 제품 버전은 각 커밋의 분석기와 로컬 검사 의존 파일을 임시 경로에 추출해 같은 입력으로 실행했다. 커버리지, 후보, 픽셀 표본과 검사 finding이 같았다. 제품의 `video-cut-1`은 `video-difference-1` 관찰과 `video-frame-2`를 참조하는 추정이다. rea-video 샷 연락표는 여러 내부 시각의 축소 이미지를 모은 것으로, JSON의 `first` 키프레임과 같은 파일이나 시각으로 취급하지 않는다.

## 비교 허용오차

- rea-video의 샷 검출은 로컬 소스상 색 히스토그램과 픽셀 차이 결합, 주변 변화·프레임 내 변화 비율 및 후속 전환 판정을 사용한다. 제품은 실제 PTS의 인접 RGB 평균차 `0.22` 이상을 후보로 남긴다. rea-video의 `boundary_score=1.0`과 제품의 `0.660131`은 서로 다른 점수이므로 동일 임계값이나 신뢰도로 환산하지 않는다. 이 표본의 일치는 급격한 단색 전환에 한정한다. [제품 분석기](../../lib/reference-analysis/video-features.ts)
- 이 표본 회귀는 컷 한 건, 프레임 48, 2000ms와 1958–2000ms 범위를 고정한다. 별도 CFR 하드컷 교차 검증은 0기준 원본 프레임 번호를 우선해 **±1프레임**을 권장한다. 24fps에서 정수 ms 표시는 **±42ms**이며, 제품 구간과 도구 샷 시작을 비교하기 전에 첫 변화 후 프레임으로 의미를 맞춘다. 중복·누락 컷은 시각 오차로 흡수하지 않는다.
- VFR·오프셋 영상은 `fps × 초`로 원본 위치를 복원하지 않는다. 확인된 트랙 기점과 실제 인접 PTS를 먼저 맞춘다. 탐색 근거가 미확인이면 불일치를 허용 범위에 넣지 않는다. 페이드·디졸브는 이 허용오차를 적용하기 전에 전환의 시작·중앙·끝을 별도로 정의한다.

## JSON과 VIDEO.md의 안전한 필드 매핑

| rea-video 필드 | 제품 사용 경계 |
| --- | --- |
| JSON `schema`, `tool`; `VIDEO.md`의 `videomd`, `generator` | 버전이 맞는 검수 자료의 출처 태그. `VIDEO.md`는 사람의 교차 확인에 사용하고 기계 검증은 구조화 JSON과 로컬 프로브를 사용한다. |
| `source.width/height/fps/duration`, `VIDEO.md source.size/fps/duration` | 로컬 확인 뒤 양의 유한 기술값만 대조에 사용한다. 재생 시간과 탐색 위치는 제품이 검증한 트랙과 PTS가 기준이다. `sha256_head`/Markdown 해시는 내부 동일 입력 확인에만 쓰고, 비교 입력이 64 MiB를 넘으면 선두 해시를 전체 파일 지문으로 해석하지 않는다. |
| `shots[].start/end/start_frame/end_frame`, `keyframes[].t/frame/role`, `video/rhythm.md` | 타임코드를 ms로 명시 변환하고 상승 순서, 자료 범위, 종료 배타성, 실제 프레임을 확인한다. 첫 프레임 등 역할은 허용한 열거값만 수용한다. 샷 분류와 키프레임 위치는 별도로 대조한다. |
| `transition_in`, `boundary_score`, `made~`, 추정 분류·신뢰도 | 공급 도구의 추정 또는 점수로 출처를 명시할 때만 사용한다. `code_render 0.861` 및 `Made with 100%`는 모델 또는 실제 제작 방식의 증거로 승격하지 않는다. 후자는 각 샷의 추정 분류를 길이로 집계한 표시다. |
| `source.path/filename`, 산출물 참조, 원문·프롬프트·제작 계획, 데이터·픽셀 | 원본 경로, 비공개 파일명, 해시, 임의 문구, 경로 문자열과 이미지 bytes는 화면·공유 DTO에 그대로 전달하지 않는다. 기존 JPEG는 검수 중 실제 픽셀 확인에만 사용했다. 파생물 연결 시 서버 관리 경로와 소유권을 검증한 참조를 사용한다. [제품 출력 계약](../../lib/reference-analysis/projection.ts) |

기존 산출물에서 VLM과 OCR이 꺼져 있고 음성·분리 트랙 결과가 비어 있음을 확인했다. `summary`와 로컬 읽기·제품 분석만 실행했다. 새 rea-video 분해, 추가 무컷 표본, 다운로드, 외부 전송은 없었다. 합성 1건이 허용오차 제안의 실측 범위이며, 임시 추출을 정리하고 보고서 한 파일을 추가했다.
