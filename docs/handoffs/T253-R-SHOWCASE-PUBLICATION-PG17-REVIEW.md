# T253-R 공개 승인 저장 SQL·러너 독립 검수

**판정 수정 필요 · 주소 오류는 보완본에서 해소, 경쟁과 RLS 증거 보완 필요**

대상 `e08133f2127306c368e61f99aab1d032d23b9b3c` · 설계 `c9d5674980203181fc98639abf6839e38fd44f42` · 재검수 `33f6c64762f94b15797ad0afbb613069a3cf393c`

타입과 린트는 통과했다. 러너가 최초 DDL 전에 정상 루프백을 거부하는 문제는 보완본 `64b5b383e21643ab73aa5d1993cab323b9d30980`에서 해소됐다. 완료와 철회가 같은 준비 세대를 대상으로 경쟁하는 경우의 SQL 동작과 RLS 시험 증거는 보완이 필요하다.

## 필수 수정

1. **F1 · 루프백 주소 비교, `64b5b38`에서 해소.** 원래 러너 83행은 `inet_server_addr()::text`를 선택하고 87행은 `127.0.0.1`과 비교했다. PostgreSQL 17은 `inet`을 명시적으로 `text`로 변환할 때 netmask를 붙이므로 `127.0.0.1/32`가 된다. 첫 연결에서 108행의 폐기 DB 생성 전에 거부되는 구조였다. 보완 커밋은 조회 표현식 한 줄을 `host(inet_server_addr())`로 바꿨다. DB 이름·major·데이터 경로·주소·포트 검사와 SQL 파일은 유지됐다. 보완 러너의 범위 타입·린트도 다시 통과했다. [PostgreSQL 17 네트워크 주소 함수](https://www.postgresql.org/docs/17/functions-net.html)
2. **F2 · 같은 준비 세대의 철회가 완료 선행 시 유실된다.** SQL 154행은 철회 요청의 세대를 금지하고, 229행은 현재 버전이 조금이라도 바뀌면 충돌을 원장에 기록한다. 예약 버전 1을 관찰해 시작한 철회가 완료와 같은 행에서 대기하다가 완료 커밋 버전 2를 만나면 `conflict`로 끝나고 세대 1은 활성 상태다. 같은 요청 ID를 재시도해도 저장된 충돌을 돌려준다. 러너 252–259행은 철회에 아직 관찰할 수 없는 다음 버전 `"2"`를 넣어 이 경우를 검증하지 않는다. 설계 §4처럼 같은 대상의 완료가 먼저라면 이어진 철회가 그 세대를 닫아야 한다. 철회 명령을 관찰한 대상 세대에 묶어 잠금 뒤 그 세대가 준비 중이거나 활성일 때 닫거나, 동일 대상만 재확인·철회하도록 서버 명령 계약을 정의하고 검증한다. 두 연결에서 두 명령 모두 같은 준비 상태를 관찰하도록 하고, 동시 완료가 없는 대조군과 이미 다른 세대로 교체된 대조군도 확인한다. [PostgreSQL 17 READ COMMITTED](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-READ-COMMITTED)
3. **F3 · 활성 행 RLS 증거가 부족하다.** 러너 215–218행에서 함수 소유자가 읽을 때 슬롯에는 활성 `example`만 있다. 앞선 준비 상태의 함수 조회는 함수 자체의 활성 조건만 있어도 빈 결과를 반환한다. 그 상태로는 RLS 정책이 실행되지 않아도 두 시험이 통과한다. 활성 한 행과 준비 중·철회 행을 동시에 만든 뒤 두 함수 소유자의 직접 허용 열 SELECT가 활성 행만 반환하는지 확인한다. 두 배포 자격의 반대 함수 및 기저 조회 거부에 발행 함수 실행 거부를 추가하고, `FORCE RLS`, 함수 소유자, 역할 속성 및 상호 membership을 합성 DB에서 대조한다. `SET ROLE` 시험과 실제 분리 로그인·프로비저닝 근거는 별개다.

## 정적 대조 결과

- SQL은 목록·파일·발행 호출 역할을 분리한다. 각 함수는 별도의 NOLOGIN·NOBYPASSRLS 소유자 및 `SECURITY DEFINER`를 쓰고, 고정 `search_path`와 한정 관계 이름을 사용하며 PUBLIC 실행권을 제거한다. 목록과 파일 소유자에 허용된 열이 서로 다르다. 목록은 공개 표시 필드와 기준 ms·세대만, 파일은 해당 활성 주소의 키·MIME·크기·해시만 반환한다. 발행 actor GUC는 신뢰된 합성 호출자가 설정하는 계약이다. 실제 인증과 트랜잭션 단위 actor 격리는 후속 서버 연결에서 검증할 범위다.
- 요청 원장 지문에는 명령·slug·버전·세대와 전체 JSONB manifest가 포함된다. 러너는 문구·권리·사본 SHA 변경을 각각 거부하고, 같은 ID의 완료 결과를 다른 연결에서 읽으며, 철회 후 성공 영수증의 재생으로 다시 활성화되지 않는지 검사하도록 작성됐다. 순차 재생이므로 실제 커밋 응답 유실을 주입한 시험 결과로 집계할 수 없다.
- 경쟁 시험은 물리 연결 두 개의 PID와 `pg_blocking_pids`를 확인한 뒤 첫 트랜잭션을 커밋하고 두 번째 결과를 검사한다. 단순 Promise 실행 순서보다 강한 대기 증거다. F2 수정과 함께 두 결과 뒤 목록·파일의 활성 상태를 확인한다. 준비 이후 원본 리비전·SHA·완료 상태가 바뀌면 완료가 거부되는 경우도 추가한다. 원본이 변경 가능한 실제 공급원에 연결할 때는 완료의 원본 재확인과 동시 변경 정책을 별도로 정의한다.
- DDL 롤백 후 스키마 및 함수 소유자 역할 부재, 기존 합성 테이블 보존, 명령 롤백 시 슬롯과 원장 부재를 확인하도록 작성됐다. 역할 여섯 개 전체의 롤백을 직접 확인하면 DDL 근거가 완결된다. 25행 한도와 동률 ASCII 정렬 시험은 SQL 출력까지 검증하도록 작성됐다. 최종 24건 및 T249 HTML/RSC 연결은 후속 범위다.

## 실제 SQL 실행 권고 조건

F2–F3 보완과 고정 SHA 재확인 뒤, 서명과 패치 버전이 일치하는 Windows PostgreSQL 17 도구로 독립 합성 수용 실행을 권고한다. `64b5b38`을 환경·DDL 진단에 사용한다면 실행 결과는 그 목적 범위로 기록한다. 러너는 새 UUID 이름의 `tmp` 경로, 별도 SCRAM 자격, loopback 전용 임시 포트 및 전용 DB를 만들고, 종료 전 자신이 만든 PID 파일의 data 경로·포트를 검사한다. 기존 클러스터를 중지하거나 서버 데이터 디렉터리를 삭제하는 명령은 없다.

첫 실행은 `PG*` 자격·설정이 없는 프로세스에서 시작한다. 러너의 필터는 하위 실행 파일 환경에만 적용되며, Node의 `pg` 클라이언트는 현재 프로세스의 `PGOPTIONS` 등도 읽을 수 있다. 전용 연결의 격리 수준과 물리 PID를 확인하고 SQL·러너 해시, 단일 실행의 검사 결과, 종료 및 해당 postmaster 리스너 부재를 남긴다. 현재 러너의 PID 파일 부재는 리스너 부재를 직접 관찰한 결과와 구분한다. 관리형 이관과 Storage, HTTP, 실제 자료 공개와 배포는 이 시험 범위 밖이다.

## 수행한 검사와 Master 전달문

- 고정본과 세 경로의 작업 사본 차이는 없었다. SQL과 러너 SHA-256은 작성자 보고와 일치했다. Git diff 공백 검사도 통과했다.
- TypeScript 직접 파일 호출에서 TS5112가 발생해 `--ignoreConfig`를 명시해 다시 실행했다. `node node_modules/typescript/bin/tsc --ignoreConfig --noEmit --strict --skipLibCheck --target esnext --module esnext --moduleResolution bundler tests/t253-showcase-publication-native-owned.ts`가 통과했다. 파일 단위 ESLint `--max-warnings 0`도 통과했다.
- `node --import tsx tests/t253-showcase-publication-native-owned.ts`는 예상대로 exit 1과 절대 `--bin` 경로 안내를 반환했다. SQL을 실행하거나 PG 프로세스를 시작하지 않았다.

T253-R 수정 필요. 루프백 주소 문제는 `64b5b38`의 조회 표현식 한 줄로 해소됐고 식별 검사는 유지됐다. 원본과 보완본의 타입·린트는 통과했다. 같은 준비 세대의 완료 선행 시 철회를 처리하고, 함수 소유자의 RLS는 활성·비활성 공존 자료로 보강해야 한다. 보완 SHA와 서명된 PG17 도구로 소유 폐기 DB에서 수용 검증을 권고한다.
