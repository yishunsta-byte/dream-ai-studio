# T328 게시 DB 대상·권한·TLS 사전 검사

2026-11-19 KST · Codes(Backend) · 기준 `fa52ca4` · Master 배정 `msg_3aae909018fb`

`verifyPublicationDatabase()`는 서버에서 명시적으로 승인한 PostgreSQL 17 대상과 관리자 쓰기·공개 목록·표지용 자격을 검사한다. 세 연결은 동일 호스트·포트·DB 이름을 사용하고, 각 세션에서 PostgreSQL 클러스터 식별자·DB·서버 포트·TLS 사용 여부를 확인한다. 기존 `createPostgresPool()`의 인증서 및 호스트 검증과 연결 제한을 적용하고, 클라이언트 측 조회 제한도 둔다. 연결은 세 자격 모두 검증돼야 성공한다. [사전 검사](../../lib/public-showcase/publication-db-preflight.ts) · [공용 연결](../../lib/db/postgres/connection.ts)

- 의도한 로그인과 현재 세션 역할이 일치해야 한다. 로그인별로 서로 다른 자격을 사용하고, `t293_app`, `t295_list`, `t295_file`의 지정 기능만 상속할 수 있다. 검사에는 추가 역할 경로, 역할 부여 권한, 관리자 속성 및 RLS 우회 여부가 포함된다.
- 관리자는 쓰기 가능한 서버의 세션에서 T293 게시자 확인과 T295 쓰기 권한을, 공개 역할은 각각 T295 목록과 표지 함수 권한을 가져야 한다. 구형 T253/T293 게시 경로, 게시 스키마 DDL, 공개 역할의 원본 테이블·컬럼 접근 등 경계를 벗어난 권한이 있으면 닫힌다. 검사 중 게시 함수는 실행하지 않는다.
- 결과는 `verified`와 자격을 포함하지 않은 `targetId`, 또는 `inactive`다. 성공과 실패 모두 시험 연결을 닫고 반환한다. 실제 공급원을 여는 후속 초기화는 새 연결에서 동일한 대상과 역할을 확인해야 한다. 이 검사 결과는 검사 당시 세션을 식별한다.

## 운영 연결 전 확인할 사항

세 로그인은 `pg_catalog.pg_control_system()`을 실행할 수 있어야 한다. 격리 DB에서는 이 함수의 공개 권한을 제거하고 세 로그인에만 부여했으며, 관리자 그룹에서 `t293.apply_t253` 실행 권한을 제거했다. 실제 게시 어댑터의 운영자·소유권 계약, DB 계정 구성과 배포, 비공개 Storage 연결은 후속 범위다. 제품 런타임의 서버 구성은 아직 미구성 상태다.

## 격리 검증 방법

`node --conditions=react-server --import tsx tests/public-showcase/t328-publication-db-preflight.pg17.ts`로 실행한다. 고정 경로 EnterpriseDB 17.12 바이너리의 서명과 버전을 검사하고, 폐기용 루프백 DB에 기존 T253·T293·T295 시험 SQL을 설치한다. 로컬 시험 인증서 및 별도 비신뢰 인증서로 TLS 검증을 재현한다. 각 사례 뒤 `pg_stat_activity`에서 사전 검사 세션이 0개인지 확인한다. 최종 정리에서 소유 프로세스와 리스너를 확인한 뒤 중지하고 임시 클러스터의 제거를 확인한다. [격리 실행기](../../tests/public-showcase/t328-publication-db-preflight.pg17.ts)

## 자체 검증 결과

- 네이티브 PG17·TLS 21건 통과. 정상과 복구, 설정·계정 누락, DB·클러스터 불일치, 비신뢰 CA와 인증서 호스트 불일치, 인증 실패, 읽기 권한 교차, 구형 쓰기 권한, 원본 컬럼 접근, 추가 역할·부여 권한, RLS 우회 및 읽기 전용 쓰기 세션을 확인했다. 클러스터 정보를 조회할 권한을 한 연결에서 제거하자 전체 검사가 비활성화됐으며, 모든 시험 연결이 닫혔다. 시험 클러스터 디렉터리와 루프백 리스너 제거를 확인했다.
- 관리자·공개·홈 회귀 228건과 변경 TypeScript ESLint 통과. 프로젝트의 생성된 `.next` 검증 파일을 제외한 소스 521개 진입 파일 타입 검사에서 오류 0건.
