# T302 작업실 분석용 단일 비공개 파일 인계

T284 서버 계약 · T300 단일 검증 사본 · Backend 자체 검증

`createIsolatedVerifiedStorageAnalysis`는 신뢰 서버가 제공한 현재 로그인과 소유·등록·권한 세대를 확인한 뒤 T300 `useVerifiedFile`로 비공개 자료를 한 번 받습니다. 인계 메타데이터의 파일 종류·MIME·크기·SHA가 등록값과 일치해야 합니다. T284 분석과 디코딩 사본 처리는 콜백 수명 안에서만 실행됩니다. 콜백이 사본 경로를 유지하지 않으며, 최종 결과에는 기존의 검증 근거와 프롬프트 초안만 돌아갑니다. [구현](../../lib/reference-analysis/studio-verified-storage-analysis.ts)

다운로드 뒤 디코딩 전에 권한과 등록 정보를 다시 검증하고, T284가 분석 후 같은 범위를 재확인합니다. T300이 사본을 정리한 뒤에도 최종 인증과 등록 조회를 한 번 더 실행합니다. 소유자·링크·권한·스토리지 또는 등록 세대가 달라지거나 결과 반환 전 취소·기한 초과가 발생하면 분석 결과를 폐기합니다. 늦은 인증 또는 권한 오류가 결과를 다시 열지 않습니다.

## 검증

- 실제 루프백 HTTP에서 A/B의 등록 이미지와 MP4를 검증했습니다. 각 성공 분석에서 비공개 버킷 확인 후 객체 GET을 한 번만 사용했고 다른 소유자, 미입증 등록, 공개 버킷과 변조 파일은 분석되지 않았습니다. 다운로드 뒤 철회, 정리 뒤 계정·권한·자료 세대 변경, 늦은 조회 오류를 확인했습니다.
- Windows의 공유 읽기 핸들이 남은 상태에서도 읽기 원본 경로가 사라지는 것을 확인했습니다. 네이티브 영상 검사 중 취소 뒤 실제 자식 프로세스가 닫히고 디코더 사본이 제거됐습니다. Windows 삭제를 막는 외부 핸들의 제한은 기존 T300 계약과 같습니다. [집중 시험](../../tests/reference-analysis/studio-verified-storage-analysis.test.ts)
- 집중 8건을 포함한 저장소·REA·공개·관리자 큐 회귀 **35개 파일 441건 통과, 1건 건너뜀**. 범위 TypeScript와 ESLint `--max-warnings 0` 통과.

## T301 연결 계약

서버 분석 함수는 `(input, signal?)`에 `{ projectId, assetId }`를 받고 T284 DTO를 반환합니다. T301의 현재 파일 경로 조회 공급자 자리에 이 함수를 직접 넣으면 T300의 콜백 수명을 지킬 수 없습니다. 향후 등록 자료 목록과 분석에 동일 권한 공급원을 쓰고 POST가 이 함수 전체를 호출하도록 담당자에게 공유했습니다. [T301 연결 코드](../../lib/reference-analysis/studio-analysis-connection.ts)

이 공급자는 합성 루프백의 현재 비공개 저장 계약에서 지원하는 이미지·영상만 받습니다. 실제 관리형 권위 공급자, 두 작업실 페이지·API, 공용 Auth 및 운영 배포에는 연결하지 않았습니다.
