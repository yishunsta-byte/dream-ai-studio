# T281-R 관리형 REA 권한 세대 후보 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `4d586b67dbc39ef0d29e8d1a30bd551625fdc586` · Orca `msg_c30cf63330fc`

**판정 — PG17 격리 후보 범위 통과.** 고정 SQL1–4 위에서 첫 승인 직렬화, 제한 A/B 역할, 링크 변경과 철회, 이동 중복 실패 롤백을 확인했습니다. 미등록 소유자의 승인 거절이 비활성 기준 행을 남기는 동작도 확인했으며, 후속 계약에서 이 동작의 허용 여부를 명시해야 합니다. [T281 인계](T281-REA-MANAGED-AUTHORITY-GENERATIONS-PROBE.md)

## 실행 근거

고정 커밋 대비 제품·SQL·실행기 변경이 없음을 확인했습니다. 실행 전 EDB 서명과 로컬 `17.12` 바이너리 경로를 대조했습니다. 실행기가 연결 전에 새 임시 클러스터의 데이터 경로·PID·실행 파일 및 `127.0.0.1` 리스너 소유를 확인하는지 검토했습니다. 원본 실행을 한 번 완료하고 별도 임시 클러스터에서 독립 경합을 추가했습니다. 두 실행 모두 정지 후 PID 파일과 리스너 부재, 임시 클러스터 삭제를 확인했습니다. 실행기 `node --check` 및 ESLint 경고 0도 통과했습니다. [로컬 대상 검증](../../tests/reference-analysis/managed-authority-generations.pg17.mjs#L97)

| 범위 | 실제 PostgreSQL 결과 |

| SQL1–4와 원문 SQL5 | 고정 SQL1–4의 해시 대조와 적용에 성공했습니다. SQL5 원문은 PG17에서 `B27_PREFLIGHT_UNVERIFIED`로 거절됐고 롤백 뒤 예약 스키마와 역할이 존재하지 않았습니다. PG18 조건을 완화하지 않았습니다. |
| 두 액터와 제한 역할 | 합성 API·운영자·worker 로그인을 사용했습니다. 소유자와 범위의 강제 RLS가 A/B를 분리했고, 타 소유 범위 승인 및 링크 변경, API의 승인 함수 호출, API·worker의 링크 및 보관 직접 변경이 거절됐습니다. 거절 전후 후보 행과 링크 상태가 같았습니다. 독립 세션에서 액터 설정 없이 되돌아온 API 조회도 0건이었습니다. |
| 동시 최초 승인 | 최초 소유자 및 최초 범위 승인에서 `pg_blocking_pids`로 실제 대기를 확인했습니다. 첫 요청 커밋 뒤 두 번째 요청은 승인하지 않았고 세대가 한 번 증가했습니다. 독립 사례에서 첫 소유자 승인 요청을 롤백하자 대기 요청이 성공했고 최종 세대는 1이었습니다. |
| 삭제·재연결·이동 | 같은 트랜잭션의 제거·재연결은 링크 세대를 두 번 진행시키고 기존 승인을 닫았습니다. 일반 용도 제거는 권한 세대를 유지했습니다. 프로젝트와 자료를 함께 옮길 때 양쪽 범위가 진행했습니다. 목적지 중복의 `23505` 뒤 소유자·범위·링크 스냅샷이 시도 전과 같았습니다. |
| 승인과 철회 순서 | 범위 철회 및 소유자 철회 후 재승인에서도 옛 범위는 비활성이었습니다. 독립 시험에서 소유자 철회가 보유한 행 잠금 뒤로 같은 소유자의 범위 승인을 대기시켰습니다. 철회를 커밋하자 대기 승인은 `false`였고 다른 소유자의 상태가 유지됐습니다. |

## 후속 계약에 반영할 동작

처음 보는 합성 소유자에게 프로젝트·자료 행을 만들고 REA 링크 없이 `scope_permission(..., true)`를 호출했습니다. `false`가 반환됐지만 커밋 후 `owner_state`에 `enabled=false`, `generation=0` 한 행이 남았습니다. `lock_owner()`가 승인 조건에 앞서 기준 행을 생성하기 때문입니다. 활성 권한·범위·링크에는 변화가 없었습니다. 대상 이동 중복의 SQL 예외와 전체 롤백은 별도로 통과했습니다. 후속 진입점은 예상된 거절이 비활성 기준 행을 남겨도 되는지 정하고, DB 무변경을 계약으로 선택하면 해당 초기화도 롤백하도록 검증해야 합니다. [기준 행 초기화](../../tests/reference-analysis/managed-authority-generations.sql#L73) · [범위 승인 조건](../../tests/reference-analysis/managed-authority-generations.sql#L124)

Auth는 트랜잭션 로컬 합성 액터로 대체했습니다. 실제 Auth 및 세션 철회, 실 스토리지 검증, PG18의 SQL5 호환과 잠금 상호작용, 종결 영수증·복원 게시·타임라인 적용은 별도 검증 범위입니다. 제품 역할의 열별 권한은 후보의 광범위 회수 결과만으로 승인할 수 없습니다. [T280-F1-R 범위](T280-F1-R-REA-MANAGED-AUTHORITY-GENERATIONS-REVIEW.md)

**Master 전달문** — T281-R PG17 격리 후보 범위 통과. A/B RLS와 승인·철회, 최초 승인 경합, 링크 이동/재연결, 중복 전체 롤백 및 원문 SQL5 거절을 확인했습니다. 거절이 선택적으로 비활성 기준 행을 만드는 동작은 후속 계약에 명시해야 합니다. 두 임시 클러스터와 리스너를 정리했습니다.
