# T370-R 공개 재생 철회 독립 검수

실제 HTTP 검수 기준 `9fa2334`에서 통과했다. 후보의 별도 사본으로 루프백 Next 개발 서버를 실행했다. 공개 경로, 내부 rewrite, Node instrumentation, Pages 응답 처리기를 거쳤다. 공급원에는 게시 상태와 청크 읽기 시점을 제어할 수 있는 합성 데이터 786,432바이트를 주입했다.

| 조건 | 클라이언트 관찰 결과 |
| --- | --- |
| 정상 | 전체 GET은 200과 786,432바이트, 11–17 구간은 206과 7바이트였다. 두 응답의 Content-Length와 실제 수신 바이트가 일치했다. HEAD는 전체 길이를 반환했고 본문은 비어 있었다. |
| 첫 청크 전달 전 철회 | 첫 저장소 읽기를 지연시키고 철회한 뒤 재개하자 해당 Range 요청은 404였다. |
| 전체 GET 전송 중 철회 | 첫 262,144바이트를 받은 뒤 두 번째 저장소 읽기 중 철회했다. 클라이언트의 다음 본문 읽기가 오류로 끝났고 같은 세대의 새 Range는 404였다. |
| 100–650000 구간 전송 중 철회 | 206 응답에서도 첫 262,144바이트 뒤 같은 순서로 중단됐다. 후속 Range는 404였고 Content-Range가 없었으며 Cache-Control은 no-store였다. |

초기 후보 재생 단위 시험 17건도 통과했다. 최초 HTTP 준비 실행은 이전 instrumentation이 남은 복사본에서 정상 대조 요청이 404여서 제외했다. 고정 커밋을 다시 추출하고 등록 코드를 확인한 후 위 결과를 얻었다. 실제 Vercel 스트리밍, 운영 공급자, 모바일 플레이어의 기존 버퍼 재생 시간은 미측정이다.
