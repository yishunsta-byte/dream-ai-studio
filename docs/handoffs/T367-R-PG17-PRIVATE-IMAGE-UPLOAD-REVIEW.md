# T367-R PG17 비공개 이미지 업로드 독립 검수

**판정 보류.** 등록 직후 수신 파일 삭제가 실패하고 정책이 갱신되면, 후보 서비스에서 해당 수신 파일의 정리를 재시도할 수 없다. 수신 바이트와 미완료 정리 기록이 남아 설치 회수도 차단됐다.

## 발견 사항

고정 후보 `1f66427a1d47d78177f7df39905bbc5c98c6cabd`의 제품 코드에 손대지 않고, 소유 PG17.12와 루프백 Storage 시험에 삭제 실패를 추가했다.

1. PNG를 올리고 완료를 호출했다. 최종 등록은 커밋됐고, 그 직후 수신 파일 삭제가 503으로 끝났다. 호출 결과는 `UNAVAILABLE`이었다. 최종 파일과 수신 파일이 모두 존재했고, 객체는 `registered`, 수신 정리 항목은 `pending`이었다.
2. Storage 검증 정책을 새 세대로 갱신했다. 같은 요청의 `complete`는 `CLOSED`를 반환했고 `cancel`은 `registered`를 반환했다. 두 호출 뒤에도 수신 바이트와 `pending`이 남았다. 최종 파일의 바이트는 보존됐다.
3. 회수 SQL은 미완료 정리 항목을 감지해 `T367_PENDING_STORAGE_WORK`를 반환했다.

등록된 객체의 `complete`는 현재 정책으로 영수증을 재검사한 뒤 수신 정리를 호출한다. 정책이 바뀌면 재검사 단계에서 끝난다. `cancel`은 등록 상태를 확인하면 즉시 종료한다. 두 동작 모두 남은 수신 정리에 도달하지 못하는 순서가 있다. [완료 경로](../../lib/services/postgres/private-image-upload.ts#L356) · [취소 경로](../../lib/services/postgres/private-image-upload.ts#L270) · [회수 조건](../../lib/db/postgres/private-image-upload/0001_remove.sql#L15)

현재 정책에 맞는 영수증을 확인하는 조건을 유지하면서, 등록이 끝난 객체의 수신 정리만 독립적으로 재시도할 수 있어야 한다. 그 재시도에서 최종 키 보존, 수신 객체의 부재 확인, 정리 기록 완료, 회수 성공을 함께 검증해야 한다.
