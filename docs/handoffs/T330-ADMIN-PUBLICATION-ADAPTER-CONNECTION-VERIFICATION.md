# T330 게시 어댑터의 실제 PostgreSQL 세션 검증

2026-11-19 KST · Codes(Backend) · 기준 `e990c77` · T328 검수 기준 `023ac39` · Master 배정 `msg_84be0dadcaf8`

`openVerifiedPublicationDatabase()`는 명시 서버 설정을 받아 관리자 쓰기·공개 목록·표지 세 연결을 모두 검사한다. 정상일 때 서버 어댑터에 `withAdmin()`, `withList()`, `withCover()`를 제공한다. 각 호출은 검증에 사용한 동일한 세션에서만 콜백의 SQL을 실행한다. 연결을 새로 열 때마다 T328의 TLS·클러스터·DB·실제 역할·권한 검사를 반복하고, 첫 연결에서 확인한 DB OID도 대조한다. 연결은 PostgreSQL에 직접 접속하는 구성을 전제로 한다. 같은 이름의 다른 DB로 바뀌거나 역할·인증·연결이 실패하면 세 경로에서 새 호출과 후속 쿼리를 함께 닫는다. [서버 연결 모듈](../../lib/public-showcase/publication-db-preflight.ts)

각 역할에는 동시에 한 연결을 빌려 준다. 요청이 끝날 때마다 세션을 닫아 남은 세션 설정과 미완료 트랜잭션이 다음 요청으로 이어지지 않게 한다. SQL 함수는 콜백 범위와 연결 그룹이 유효한 동안만 호출할 수 있다. 이미 전달된 SQL은 DB에서 처리될 수 있으므로, 권한을 바꾸거나 서비스를 중지할 때 호스트는 먼저 할당된 요청을 비워야 한다. `close()`는 여러 호출이 같은 종료 작업을 기다리도록 한다. T328의 `verifyPublicationDatabase()`는 동일 검사를 사용하고, 연결을 모두 닫은 뒤 기존 `targetId` 반환 계약을 유지한다.

## 실제 게시 요청에서 발견한 권한 조건

격리 DB에서 T295 `apply()`를 실제 실행해 보니, T328의 시험용 `t293_app` 직접 권한 제거가 T295 함수 소유자의 내부 `t293.apply_t253()` 호출까지 막고 있었다. 격리 DB에서는 `t295_writer`에만 내부 함수 권한을 부여했다. 서버 검사는 관리자 로그인의 구형 함수 직접 실행을 거절하고, T295 `SECURITY DEFINER` 함수의 내부 소유 역할과 호출 권한을 함께 확인한다. 관련 권한 변경은 임시 시험 DB에서만 적용했다.

## 자체 검증

- `node --conditions=react-server --import tsx tests/public-showcase/t328-publication-db-preflight.pg17.ts` 통과. 기존 사전 검사에 내부 함수 권한 누락 검증을 더해 22건을 확인했다.
- 실제 제한 세션으로 T295 게시 준비·완료·철회를 실행했다. 목록에서 공개 세대 표시와 제거, 표지 메타데이터의 제공과 차단, 관리자·목록·표지의 교차 실행 거절을 확인했다. 커밋하지 않은 쓰기는 세션을 반납하자 롤백됐고, 다음 요청에서 새로운 백엔드 PID를 확인했다.
- 초기 자격·TLS 실패, 개통 후 역할 철회 및 로그인 비활성화, 대여 중인 백엔드 세션 종료, 같은 이름과 권한을 가진 DB로 교체하는 상황에서 연결 그룹이 닫혔다. 실패한 역할은 SQL 콜백에 도달하지 않았다. 각 사례 뒤 사전 검사 세션 수가 0이고 시험 리스너와 임시 클러스터가 제거됐음을 확인했다. [PG17·TLS 실행기](../../tests/public-showcase/t328-publication-db-preflight.pg17.ts)
- 관리자·공개·홈 회귀 231건 및 변경 파일 ESLint 통과. `.next` 생성 검증 파일을 제외한 소스 521개 진입 파일의 TypeScript 검사에서 오류 0건.
