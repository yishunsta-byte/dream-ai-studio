# T344 가동 중 게시 설치 상태 재검증

2026-11-19 KST · Codex(Backend) · Master 배정 `msg_fa1f9d13bece` · 기준 `5eecc8e`

T342 명시 구성은 승인 잠금 아래 최초 설치를 검증하고 공급원을 조립한다. 그 이후부터는 관리자 트랜잭션, 공개 목록 조회, 공개 표지 권한 조회, 공개 응답용 표지 다운로드, 전송 직전 표지 권한 확인에 앞서 새 TLS 읽기 전용 세션으로 설치 상태를 다시 확인한다. 이미 전달된 공급원 참조도 동일한 검사를 거친다. `get()`은 공급원 참조를 반환하며 실제 검사는 각 작업 경계에서 실행된다.

기존 T341 대조를 재사용해 DB OID·클러스터·검증 계정 OID, 최초 이력의 시각·해시와 카탈로그, 역할·DB 권한, 이전 설치 세션 종료를 확인한다. 가동 중 검증에는 설치 잠금이나 관리 자격 증명이 필요하지 않다. 상태 쓰기나 원격 예약 작업을 추가하지 않았다. 각 런타임 역할 접속에서 T343의 실제 DB OID 대조 역시 계속 적용된다.

- 동시에 검증을 기다리는 작업은 같은 읽기 트랜잭션의 결과를 공유한다. 이후 별도 작업에는 새 검증 세션을 사용한다. 요청 취소는 해당 요청만 중단하고 공용 검증과 다른 요청은 계속된다. 런타임 종료 시 진행 중인 검증 접속도 닫는다.
- 검증이 불가능하거나 승인 상태가 달라지면 해당 런타임은 세 공급원을 함께 비활성화한다. 다음 작업은 DB 작업이나 표지 다운로드에 진입하지 못한다. 이미 전달된 참조로도 다시 열 수 없으며, 복구하려면 승인된 시작 절차로 새 런타임을 조립해야 한다.
- 검증은 작업을 허용하기 직전의 읽기 스냅샷을 확인한다. 이미 입장한 관리자 트랜잭션 내부 작업은 기존 트랜잭션 경계를 따른다. 닫기가 시작되면 뒤따르는 DB 작업이 차단된다. 이미 완료된 쓰기나 전송은 소급해 취소할 수 없다. 공개 표지 응답은 다운로드 뒤 최종 검증도 거친다.

## 소유 루프백 PostgreSQL 17 검증

- `node --conditions=react-server --import tsx tests/public-showcase/t328-publication-db-preflight.pg17.ts --sealed-publication-runtime`에서 설치 잠금 해제 뒤 정상 조회, 동시 요청 한 세션, 요청 하나 취소 후 다른 요청 완료, 이력 시각 변경, 임시 권한 재부여, 검증 로그인 실패, 검증 중 런타임 종료를 확인했다.
- 이력 변경 뒤 보관된 공급원에서 Storage 호출과 다음 관리자·목록 작업이 차단됐다. 표지 다운로드 중 이력이 바뀌면 최종 확인에서 503을 반환하고 이미지 바이트를 전송하지 않았다. 이미 진입한 합성 관리자 트랜잭션은 종료됐고, 검증 접속과 런타임 그룹을 정리했다.
- 기본 PG17/TLS와 T341 독립 설치 모드, T343 OID 회귀, Vitest 단일 워커 299건, 변경 파일 ESLint 및 생성된 `.next` 검증기 제외 소스 TypeScript 검사를 통과했다.
- 제품 기본은 비활성 구성이다. 관리형 DB와 운영 적용은 별도 검증 범위다.
