## 주입 방식

```tsx
<StudioProtectedMaterialsAnalysis listUri="…목록 GET…" analyzeUri="…단건 분석 POST…" transport={fetch 같은 함수} timeoutMs={…} />
```

- **목록:** `GET`으로 요청한다. 옵션은 `Accept: application/json`, `cache: "no-store"`, `credentials: "same-origin"`, `redirect: "error"`이고, 시간 제한이 있다.
- **분석:** 기존 공급자의 POST 계약을 그대로 쓴다.
- **서버 렌더:** 요청하지 않는다. 처음 그리는 HTML에는 ‘불러오는 중’만 있고 자료 데이터는 없다.
- **표시 이름:** 현재 목록 순서에 따른 중립 이름 `등록 자료 1…n`만 쓴다.
  - 서버 `label`, `projectId`, `assetId`는 화면 글자, 접근성 이름, 선택 값 어디에도 나오지 않는다.
  - 선택 값은 기존 부품처럼 목록 안의 순번이다.
  - 목록 응답에 종류 칸이 없으므로, 이미지·영상 같은 종류도 표시하지 않는다.

## 응답별 동작

| 목록 응답 | 화면 |
|---|---|
| 200, 자료 있음 | 기존 분석 화면에 중립 이름을 보여 준다. 선택 → 실행 → 결과 제목으로 초점이 간다. |
| 200, 빈 배열 | ‘분석할 수 있는 등록 자료가 없어요.’와 함께 ‘목록 다시 조회’, ‘내 프로젝트 열기’를 보여 준다. 기존 분석 화면은 그리지 않아서 같은 안내가 겹치지 않는다. |
| 401 | 목록과 결과를 지운다. ‘다시 로그인해 주세요.’와 `다시 로그인`(`/login?next=%2Fcloud%2Freference-analysis`)을 보여 준다. |
| 403 | 목록과 결과를 지운다. ‘이 화면에 접근할 수 없어요.’를 보여 주고, 조작 요소는 없다. |
| 503, 204, 그 밖의 상태, 연결 실패, 시간 초과, 형식 오류 | 목록과 결과를 지운다. ‘등록 자료를 불러오지 못했어요.’와 `목록 다시 조회`를 보여 준다. 응답 본문은 읽지 않고 버린다. |

**형식 오류로 보는 경우**

- 칸이 더 있다.
- 잘못된 ID다.
- 이름이 비어 있다.
- 대소문자만 다른 중복이 있다.

**철회**

- 단건 분석이 `source_unavailable`이나 `invalid_selection`을 돌려주면, 목록을 다시 받는다.
  - 다시 받는 동안 기존 선택, 결과, 수정 중인 초안을 즉시 지운다.
  - 남은 자료가 있으면 ‘선택한 자료에 접근할 수 없어요.’를 띄우고 자료 선택으로 초점을 옮긴다. 남은 자료가 없으면 빈 목록 안내를 보여 준다.
  - 이전 자료 이름과 상세 사유는 표시하지 않는다.
- 사용자가 이미 취소한 요청의 응답으로는 다시 받지 않는다.

**늦게 온 응답**

- 목록은 조회마다 세대 번호를 붙이고 이전 요청을 취소한다. 늦게 도착한 목록은 버린다.
- 분석 결과는 기존 부품의 ‘같은 공급자·같은 선택’ 규칙으로 버린다.
- 목록을 다시 받으면 새 공급자가 생기므로, 이전 결과는 되살아나지 않는다.

**초점**

- 다시 조회를 시작하면 ‘불러오는 중’ 안내로 초점이 간다.
- 끝나면 자료가 있을 때는 자료 선택으로, 없을 때는 안내로 간다.

## 사용 권리 확인 (Master 배정 `msg_02894fe628d0`)

`StudioRegisteredAnalysis`에 선택 옵션 `requireRightsConfirmation`을 추가했다. 기본값은 꺼짐이다. 보호 목록 어댑터만 이 옵션을 켠다.

**기존 동작 보존**

- 기본값이면 체크 칸이 없고 화면도 그대로다. 해당 호출자는 운영 미연결 셸 `<StudioRegisteredAnalysis />`, 로컬 URL 분석, HTTP 통합 브라우저 시험이다.
- 운영 후보 tree `1341083f`는 고정된 그대로다. 서버 권한 판정과 API는 바꾸지 않았다.

**동작**

- 체크 칸 ‘이 자료를 분석할 권리가 있어요.’는 자료를 고른 뒤에만 켤 수 있다.
- 확인은 그 공급자와 그 선택에만 묶인다. 확인이 없으면 실행 버튼이 꺼지고, `run()`도 요청하지 않는다.
- 결과는 확인된 선택에서만 보인다.
- 아래 경우에는 확인과 결과, 수정 중인 초안을 지운다.

| 경우 | 처리 |
|---|---|
| 선택 변경 | 진행 중 요청을 취소한다. |
| 체크 해제 | 진행 중 요청을 취소한다(`activeJob` 비우기·abort). 늦게 온 응답은 버린다. |
| 목록 재조회(철회·사용자 재조회) | 새 공급자가 생기므로 확인이 자동으로 무효가 된다. |
| 세션 만료(401) | 분석 화면 자체를 지운다. |

- 상태 문구: 자료를 고르고 확인하기 전에는 “이 자료를 분석할 권리가 있는지 확인해 주세요.”라고 안내한다.
