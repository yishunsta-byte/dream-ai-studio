# T341-R 위임 게시 설치 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `a8ea68c` · Master 배정 `msg_2cd915daef1f`

**격리 위임 설치 검수 통과.** 소유 PG17/TLS의 제공 전용 모드에서 제한 설치와 독립 이력 검증, 동시 작업 차단, 롤백·응답 유실, 권한 회수와 기존 세션 종료, 게시·철회를 재현했다.

- `NOCREATEROLE/NOINHERIT` 설치자는 사전 승인된 여덟 NOLOGIN 소유 역할에만 임시 전환 경로를 사용했다. 승인 계획은 대상 DB OID·클러스터, 역할 OID·부여자·옵션 및 실효 `SET/USAGE` 경로를 대조했다. 잘못된 OID·부여자, 우회 상속과 부분 스키마는 차단됐다. SQL 줄바꿈 정규화 후 SHA-256 `66a966e09207709288226544e2e6a7f20a95f8a4ba1d59246a533e9609f03375`를 별도로 재현했다. 고정 카탈로그 해시는 설치와 독립 읽기에서 모두 일치했다.
- 공통 제어 DB 잠금이 다른 대상 DB의 동시 요청을 차단했고 작업 권한은 승인 대상에 묶였다. DDL 예외 뒤에는 `prepared`로 돌아왔다. 실제 COMMIT 성공 응답을 시험에서 유실시키자 `UNKNOWN`을 반환했고 새 검증 세션에서 `pending-seal`이 확인됐다. 재설치는 거절됐다. 제어 세션을 닫은 뒤 기존 작업 권한도 거절됐고 새 잠금으로 같은 이력을 읽을 수 있었다.
- 일부 DB `CREATE`가 남은 상태는 차단됐다. 권한을 모두 회수한 뒤에도 이미 NOLOGIN 소유 역할로 전환된 설치 세션이 남으면 `pending-seal`이었다. 그 세션을 닫은 뒤에만 새 검증 세션에서 `sealed`를 반환했다. 검증 로그인은 일반 세션에서도 이력 수정, 게시 작품 조회, 영속 스키마 생성, 소유 역할 전환과 공개 함수 호출이 거절됐다. 공개 이력 ACL과 계획 해시 변경도 거절됐다. 정상 재검증에서 v2 이력 한 행과 최초 시각·해시가 보존됐다.
- 시험은 `sealed`를 확인한 뒤에만 T332를 조립했다. 준비 전후 비공개 표지 상태, 완료 후 피드·정상 WebP와 철회 후 피드 제거·404를 확인했다. Foundation 1~3 이력·Auth와 SQL4 물리 DDL 스냅샷을 보존했다. SQL4 검증 범위는 물리 공존이다.
- 무인자 T328 TLS 22건과 T330·T332·T336을 통과했다. 관련 회귀 26파일 642건과 PG 종료 뒤 비공개 자산 회귀 1파일 54건도 통과했다. 소스 타입 검사, 변경 TypeScript 4개 ESLint와 diff 공백 검사를 통과했다. 두 PG 수신기와 임시 클러스터, 검수 사본을 정리했고 검증 세션과 소유 PG 프로세스는 0건이었다.

## 판정 범위

- `sealed`를 런타임 개방에 연결한 것은 시험 코드다. 기본 제품 설정은 비활성이고 관리형의 직접 TLS·클러스터 식별자, 역할 발급·회수, 세션 종료와 복원 후 OID 재승인은 이번 판정 밖이다. 운영·빌드·배포 변경은 없었다.
- 검증 계정의 DDL 거절 증거는 영속 스키마 생성이다. 코드가 검증하는 대상 DB ACL은 `CREATE`이며, fixture는 기본 `PUBLIC TEMPORARY`를 별도로 회수하거나 검사하지 않는다. 임시 테이블까지 금지하는 계약을 채택할 때는 그 권한과 실제 동작을 별도로 확인해야 한다. [PostgreSQL 17 권한 기본값](https://www.postgresql.org/docs/17/ddl-priv.html)
