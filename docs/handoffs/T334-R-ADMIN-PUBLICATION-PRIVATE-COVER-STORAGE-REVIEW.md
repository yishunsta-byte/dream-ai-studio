# T334-R 비공개 게시 표지 읽기 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `18340be` · Master 배정 `msg_1fe217f7df76`

**판정은 통과.** 설치된 Supabase SDK와 검수 전용 루프백 서버로 표지 전용 14건을 독립 실행했다. 관련 Storage·관리자·공개·인증 회귀는 단일 워커에서 24개 파일 480건이 모두 통과했다. 소스 타입 검사, 변경 TypeScript 3개 ESLint 및 커밋 diff 공백 검사도 통과했다.

- SDK가 고정 버킷 `publication-covers-private`의 메타데이터와 정규 `slug/generation/<sha256>.webp`의 객체만 인증된 GET으로 요청했다. 버킷 ID 또는 비공개 상태가 맞지 않거나 메타데이터 요청이 실패하면 객체 GET은 실행되지 않았다. 가장 긴 유효 슬러그와 세대는 그대로 읽혔고, 비정규 키, 범위 밖 한도, 다른 관리자 UUID 및 사전 중단은 네트워크 전에 거절됐다.
- 버킷 메타데이터 64KiB와 표지 5MiB 상한을 소스에서 확인했다. 헤더 및 청크 본문 초과, 서버·호출자 한도, 압축 및 리디렉션 거부를 시험했다. 관리자 객체 GET의 404만 `null`로 처리했고 공개 읽기는 `STORAGE_NOT_FOUND`를 반환했다. 접근 거절과 제공자 실패는 고정 코드로 처리했다. 진행 중 중단과 시간 초과에서 루프백 응답이 닫혔고, 중단 후 슬롯 재사용과 시험 서버 종료를 확인했다. 표지 리더는 메모리에서 바이트를 읽는다.
- T332는 저장소 읽기 전에 DB 승인 세대·키·크기를 대조하고 응답 전 현재 권한을 재확인한다. 이 경계를 소스에서 대조했다. 루프백 전용 시험에서는 잘못된 SHA-256의 바이트가 503, 읽은 뒤 권한을 잃은 응답이 빈 404였으며 정상 바이트가 200이었다. 관리자 저장소 호출의 운영자 바인딩도 소스와 루프백 시험에서 확인했다.
- 공통 전송 설정의 분리 뒤에도 기존 자산 리더의 소유자·UUIDv7 키, 정확한 바이트 수·SHA-256, 실제 MIME과 영상 메타데이터 및 임시 파일 정리 검증이 통과했다. 첫 회귀에는 검수 사본의 FFmpeg 준비가 빠져 기존 파일이 시작되지 않았다. 승인된 FFmpeg와 ffprobe를 해시 대조 후 사본에 복사했다. 기본 워커 재시도에서는 기존 영상 검증 한 건이 고정 1.5초 제한에 걸렸고, 이어 같은 후보와 도구로 단일 워커를 사용하자 그 사례를 포함해 480건 모두 통과했다.

검수는 합성 자격과 루프백에 한정했다. 기본 제품 런타임은 승인 공급원을 반환하지 않으며, T334 팩터리는 명시 구성에 사용할 서버 의존성이다. 실제 운영 버킷과 자격 발급은 판정 범위 밖이다. 검수 사본과 복사한 도구는 정리했다.
