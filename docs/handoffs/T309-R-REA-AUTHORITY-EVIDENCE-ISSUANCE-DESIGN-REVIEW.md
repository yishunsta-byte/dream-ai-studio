# T309-R 복원·자료 증거 발급 독립 설계 검토

기준 `f4e5233` · 배정 `msg_c6338ac4fdad` · Codex(Tester)

**판정은 방향 채택, 운영 연결 전 설계 보완 필요.** 독립 복원 세대, 새 세대 기본 비활성, 공통 목록·단건 판정, 자료 단위 제외와 전체 연결 장애 구분을 유지할 수 있다. 다음 계약이 있어야 복원 또는 재시작을 가로지르는 작업과 현재 권한을 안전하게 구분할 수 있다.

## 구현 전 필수 수정

1. **F309-1 · 실제 연결을 대상 증명에 결합한다.** 같은 주소·인증서·DB 식별자가 유지되는 복원이나 승격에는 플랫폼이 확인한 복구 사건과 실제 연결의 일치 근거가 필요하다. 전환 승인 때의 확인만으로 이후 풀 연결이 같은 인스턴스임을 보장할 수 없다. 연결 생성·재연결과 대상 변경을 감시할 경계, 증명의 만료·불일치 시 풀 폐기, Auth 발급자와 검증된 소유자 매핑, 같은 Storage 키의 버전 고정 또는 변경 불가 조건을 계약에 적는다. 현재 Storage SDK 다운로드는 키로 읽고 바이트 해시를 대조한다. 버전 기반 운영안을 택하면 버전을 지정할 수 있는 읽기 경로가 필요하다. 제자리 복원을 관측하거나 통제할 수 없는 대상은 비활성을 유지한다. [설계 대상 조건](T309-REA-AUTHORITY-EVIDENCE-ISSUANCE-DESIGN.md#독립-신뢰-원천과-읽기-조건) · [Storage 읽기](../../lib/storage/supabase/reader.ts#L117)

2. **F309-2 · 전환과 응답 확정의 순서를 정한다.** 외부 활성 포인터와 DB를 두 번 확인해도 마지막 확인 후 DB 권한·외부 포인터가 바뀌고 그 뒤에 응답이 확정될 수 있다. 모든 앱 인스턴스가 공유하는 세대별 요청 허가와 최종 응답 확정 지점을 정한다. 예를 들어 외부 제어 경계에서 새 허가를 닫은 뒤 응답 확정을 마친 작업만 통과시키고, 나머지 허가는 취소 또는 만료가 확인될 때까지 새 세대를 열지 않는다. 목록 페이지의 HTML/RSC 전달과 분석 POST 모두 여기에 포함하고, 권한 철회와 응답 확정이 경합할 때 어느 쪽을 먼저 처리한 것으로 볼지도 정의한다. 이미 확정해 전송 중인 응답과 클라이언트가 보관한 데이터는 회수할 수 없으므로 서버에서 보장하는 지점과 범위를 명시한다. 현재 목록의 반환과 T302 최종 조회는 HTTP 직렬화보다 앞서 있다. [목록 반환](../../lib/reference-analysis/studio-registered-analysis-page.ts#L31) · [T302 최종 조회](../../lib/reference-analysis/studio-verified-storage-analysis.ts#L134) · [HTTP 응답](../../lib/reference-analysis/studio-analysis-http.ts#L124)

3. **F309-3 · 늦은 쓰기와 재실행을 저장 경계에서 차단한다.** 외부 포인터를 먼저 확인한 작업은 정지 후 살아날 수 있다. 외부 포인터 불일치가 옛 증거를 읽기에서 가려도, 같은 주소로 돌아온 DB·Storage의 쓰기까지 멈추지는 않는다. 준비 배치와 활성 중 재발급을 구분하고, 제한 발급·폐기와 향후 적용 쓰기가 DB 커밋을 보호하는 현재 세대·작업 번호를 검사하게 한다. 전환 완료 전에는 이전 DB 쓰기 세션을 정리하고, 이전 작업이 이미 얻은 외부 변경 권한도 만료·폐기 또는 변경 불가 조건으로 막는다. 자료 증거 CAS에는 대상 세대, 현재 SQL4 증거, 예상 자료 포인터 리비전을 포함한다. 폐기 후에도 리비전이나 폐기 기록을 남겨 같은 SQL4 튜플을 관측한 다른 오래된 요청이 증거를 되살리지 못하게 한다. 응답 유실은 정확한 현재 대상의 권위 있는 읽기로 조정한다. 같은 ID의 확정 상태 재조회는 읽기 전용이며, 미적용 재실행에도 동일 지문·현재 세대·유효한 작업 번호·예상 포인터가 필요하다. 다음 단계로 갈 때는 준비 완료가 같은 전환과 대상에 속함을 대조한다. 향후 적용은 DB의 쓰기 성공과 사용자에게 적용 결과를 다시 보여 줄 수 있는지를 독립적으로 판정한다. [발급 및 재실행 초안](T309-REA-AUTHORITY-EVIDENCE-ISSUANCE-DESIGN.md#자료-증거와-재실행-규칙) · [T282 적용 원장](T282-REA-RECEIPT-AUTHORITY-GENERATIONS.md)

4. **F309-4 · 현재 SQL4 정책과 잠금·역할을 계약에 포함한다.** T307 격리 조회는 현재 객체·검증·만료를 비교하지만 현재 `storage_policies` 행을 조인하지 않는다. 운영 조회와 발급에서 검증 기록의 정책 ID·epoch·digest를 현재 정책과 대조해 정책 교체가 즉시 새 조회를 닫게 한다. 발급 트랜잭션은 정책 공유 잠금부터 B16의 동일 객체 장벽과 정렬 순서를 사용해 검증·폐기·GC와 경합할 때 현재 튜플을 다시 판정한다. 발급에 T281 권한 행을 잠글 필요가 없다면 읽기에서 권한을 독립 판정해 잠금 경로를 분리할 수 있다. 양쪽 행을 잡는 경로가 필요하다면 T281의 소유자→프로젝트→자료 순서까지 포함한 공통 순서를 먼저 정한다. SQL4 고정본은 격리용 제약과 트리거를 제공한다. 승인된 운영 재검증 진입점 및 발급 함수, FORCE RLS 정책과 필요한 잠금 권한은 별도 마이그레이션이 필요하다. 로그인·전환 역할의 속성 외에도 전이 함수 EXECUTE, 소유권과 간접 역할 멤버십을 대조한다. 발급자는 제한 함수로 증거만 변경하고 사용자 승인·Storage 검증·외부 활성화 권한을 갖지 않는다. [SQL4 상태와 권한](../../lib/db/postgres/0004_storage_verification.sql#L24) · [B16 잠금·정책](B16-STORAGE-UPLOAD-WORKER-CONTRACT.md#capability-issuance-policy-epochs-and-creation-request-retention) · [T307 조회](../../lib/reference-analysis/studio-analysis-authority-store.ts#L49) · [T281 잠금](../../tests/reference-analysis/managed-authority-generations.sql#L74)

5. **F309-5 · 복원된 권한의 재구성 기준을 명시한다.** 백업 시점부터 전환을 여는 시점까지 Auth·소유자·범위·용도·보관 변경의 근거와 대조 완료 위치를 정한다. 권한 이력이 누락되거나 동시에 철회되면 기본 비활성을 유지한다. 재생 및 수동 재승인은 새 복원 세대와 검증된 현재 소유자에 귀속한다. 예전 적용 수신증, 미완료 확인, 오래된 Auth 세션은 새 승인 그 자체로 조회권이나 실행권을 얻지 못한다. 외부 제어 저장소 자체의 복구에서도 독립 감사 기록으로 마지막 전환의 연속성과 세대 비재사용을 확인하기 전에는 활성화하지 않는다. [T309 복원 순서](T309-REA-AUTHORITY-EVIDENCE-ISSUANCE-DESIGN.md#복원승격재바인딩-순서) · [T282 적용 권한 세대](T282-REA-RECEIPT-AUTHORITY-GENERATIONS.md)

## 운영 결정

- 플랫폼·Master가 DB/Auth/Storage의 증명 수단과 허용하는 복원·승격 유형, 전환을 강제할 권한, 외부 제어 저장소 복구와 감사의 독립성을 확정한다. 제자리 복원 감지와 SDK 버전 읽기 지원 여부는 현재 미확인이다.
- 권한·Storage 담당이 복구 지점과 권한 이력의 완전성, 재승인 및 부분 재개 범위, SQL4 재검증 마이그레이션, 기한·보존·처리량을 결정한다. 전환 중 허용 가능한 대기 시간과 서버 응답 확정의 보장 범위도 운영 기준으로 승인한다.

## 추가 시험

- 같은 주소의 PG 복원·승격, 오래된 대상 증명과 유지된 풀, Auth 대상 변경, 같은 키의 버전 변경을 각각 주입한다. 외부 제어 저장소 자체의 과거 복구와 대상 증명 조회 장애에서도 연결이 닫혀야 한다.
- 마지막 외부 확인 뒤 HTTP/RSC 응답 직전, DB 커밋 직전·직후, 외부 CAS 직전·직후에 두 프로세스를 의도적으로 정지한다. 전환 중 구 작업 재개, 성공 응답 유실, 같은 ID와 다른 ID의 경합, 발급→폐기→늦은 발급 및 철회→재승인을 합격 행렬에 추가한다. 응답과 모든 DB 변경, 외부 변경, 잔여 세션을 관측한다.
- 정책 epoch 전환, 검증 완료·실패, 증거 발급·폐기, GC, 보관·링크 변경의 양방향 경합을 실제 소유 PG17에서 실행한다. 잠금 대기·기한 후 재시도, 직접 DML·간접 역할과 함수 접근 거부, A/B 간 누출 여부를 함께 확인한다.

읽기 검토에서 설계 문서의 링크 대상 20개 중 19개를 고정 커밋에서 확인했다. T307-F1-R 보고서는 공유 작업공간에 있으나 기준 커밋에 포함되지 않아 문서 단독 체크아웃에서 끊긴다. 릴리스 근거를 고정하려면 보고서를 함께 추적하거나 추적 중인 T307-F1 문서로 연결한다. PG17·플랫폼·운영 검증과 빌드·배포는 이번 설계 검토 범위 밖이다.
