# 로컬 PG에서 PNG 두 장면을 컷으로 연결

로컬 쇼핑숏츠의 현재 승인 타임라인에서 검증된 PNG 한 장 또는 두 장과 첨부 WAV를 MP4로 렌더한다. 활성 장면 전체에서 알맞은 PNG가 확인돼야 한다. 장면 ID로 선택 버전·자산·길이를 대조하고 타임라인 배열 순서대로 인코딩한다. 작업 시작과 결과 확정 시에는 선택 버전, 소유권, 현재 파일 검증 기록과 SHA-256을 함께 대조한다. MP4 크기 상한은 기존 16 MiB다.

| 실제 Next.js·PG17 HTTP 시험 | 결과 |
|---|---|
| 1초 빨강 PNG, 2초 파랑 PNG | 조회 순서와 반대로 배치한 타임라인을 올바르게 출력했다. H.264 1080×1920, 30fps, 90프레임, 3초. 실제 다운로드를 디코딩한 29·30·89프레임의 중심 RGB는 각각 (255,1,0), (1,0,255), (1,0,255)였다. |
| 첨부 WAV 두 개 | AAC 48kHz 한 트랙, 디코딩 144,000샘플. 처음 두 구간에서 300Hz·600Hz, 이후 무음을 확인했다. |
| SHA-256 | 다운로드 40,932바이트의 해시가 저장 결과와 일치했다. 시험 출력 해시는 881e82bb98c0d5c836eaa2ad090f6645110dc7007419ab67f58b430efc0c457f였다. |
| 실행과 재시도 | 변조 파일을 거절한 뒤 재시도 성공. 중복 실행은 409, 완료 후 같은 작업 재전송은 동일 결과를 반환했다. 출력·완료 활동은 각각 한 건이다. |
| 두 번째 PNG 보관 | 실행 전 보관 시 시도 횟수 0, 실행 중 보관 시 결과 확정 거절. 이전 타임라인·타인 요청도 거절했다. 실패한 작업의 출력·완료 기록은 0건이며 임시 작업 폴더는 정리됐다. |
| 기존 PNG 한 장 | 기존 60프레임, AAC 96,000샘플과 동일 MP4 SHA-256을 확인했다. |

재현 명령은 저장소 루트에서 실행한다.

```powershell
$env:T371_VERIFY_HTTP='1'
$env:T371_VERIFY_RENDER_AUDIO='1'
node --conditions=react-server --import tsx tests/postgres/t368-run-private-image-project-create.mjs
```

## Tester 독립 검수

고정 커밋 `2b892d9937a0a171b4f326a236ef455b122040bb`의 격리 작업 트리에서 실제 로컬 Next.js·PG17·FFmpeg로 검수했다. 시험 입력은 승인 상태의 1초 빨강 PNG, 2초 파랑 PNG, 첨부 WAV 두 개였다. 두 PNG는 서로 다른 원본 치수이며 타임라인 순서와 조회 순서가 다르도록 구성됐다.

| 검수 | 독립 관찰 |
|---|---|
| 두 장면 다운로드 | 40,932바이트. 다운로드 응답·파일·DB SHA-256 모두 `881e82bb98c0d5c836eaa2ad090f6645110dc7007419ab67f58b430efc0c457f`. 프레임 90개, 1080×1920 H.264, 30fps, 3.000초. |

| 재시도와 보관 | 변조 거절 뒤 재시도로 성공했고 진행 중 중복 실행은 409였다. 완료 후 반복은 같은 결과를 반환하고 출력·완료 활동 각 1건이었다. 두 번째 PNG를 시작 전 보관하면 시도 0, 실행 중 보관하면 확정 거절과 해당 작업의 출력·완료 활동 0건이었다. 작업 폴더를 정리했다. |
