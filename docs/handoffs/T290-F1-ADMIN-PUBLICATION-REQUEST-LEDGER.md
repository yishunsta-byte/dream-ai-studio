# T290-F1 관리자 게시 확정 실패와 동일 요청 재시도

기준 `ea316f0` · Backend 자체 검증

| 결과 | 원장과 재시도 |
| --- | --- |
| 승인된 요청의 `conflict`·`source-unavailable` | 작품·공개 세대·감사 기록을 보존하고 결과 원장만 같은 트랜잭션에 기록합니다. 같은 요청 UUID와 의도는 이후 자료나 상태가 달라져도 당시 결과를 반환합니다. 다시 진행할 때는 최신 목록을 보고 새 UUID로 요청합니다. |
| `unavailable` | Auth나 증빙·스토리지 연결 장애, 읽기 시간 초과, 판단 불가, 트랜잭션 롤백에는 실패 원장을 만들지 않습니다. 커밋 성공 여부가 불명확할 때도 T289는 같은 UUID로 재시도합니다. 실제로 커밋됐다면 원장의 결과를 찾고, 롤백됐다면 같은 요청을 처리합니다. |
| `denied`·`invalid` | 미인증·게시자 금지·타 소유자·잘못된 입력을 기록 전에 차단합니다. 같은 UUID에 다른 의도를 사용하면 `invalid`입니다. 원장 조회에도 현재 인증과 게시 권한, 작품 소유 범위가 필요합니다. |

등록 증빙이 없거나 바뀐 경우, 원본과 권리 범위 불일치, 권리 만료, 검증된 불변 객체의 확정 부재, 길이·해시·형식 불일치는 확정 실패입니다. 저장소 어댑터는 객체가 없다는 사실을 확정한 경우에만 `null`을 반환해야 합니다. 시간 초과, 저장소 권한 장애, 업로드 반영이 불명확한 상황은 예외로 전달합니다. 네이티브 검증 오류에서 바이트 부적합을 확정할 수 없으면 재시도 가능한 결과로 닫습니다. [서버 서비스](../../lib/public-showcase/admin-publication-service.ts)

## 운영 어댑터 연결

앱 원장의 지문은 T289에서 받은 명령·slug·예상 버전·공개 세대·권리 확인 의도를 정규화해 계산합니다. 서버에서 새로 읽는 검수 자료는 지문에 합치지 않습니다. T253 `apply_command`의 지문에는 명령과 함께 원본 리비전·권리 참조·커버 해시 등을 담은 서버 manifest도 들어갑니다. 재시도 시에는 먼저 현재 권한을 확인하고 앱 원장으로 당시 결과를 복구해야 합니다. SQL까지 재실행이 필요한 경로라면 최초에 사용한 서버 manifest 또는 그 불변 참조를 보존해 동일한 payload를 전달해야 합니다. 현재 증빙을 다시 조합해 이미 처리한 SQL UUID에 보내면 의도와 관계없이 지문이 바뀔 수 있습니다. 앱 원장과 실제 SQL 커밋을 따로 확정하는 경우 유실·부분 커밋이 생길 수 있으므로 운영 어댑터에서 하나의 트랜잭션과 잠금 순서로 매핑하는 검증이 필요합니다.
