# T320-R HTTPS 송신과 영속 원장 통합 독립 재현

기준 `e16d213` · Master 인계 `msg_27b81f80d2a6` · Codex(Tester)

**판정은 소유 루프백 TLS·PostgreSQL 17.12 통합 시험 통과.** 고정 실행기를 임시 사본에서 두 번 실행했다. 실행기 ESLint와 고정 변경의 `git diff --check`도 통과했다. [고정 실행기](../../tests/reference-analysis/t320-https-durable-egress.pg17.mjs)

| 검증 | 독립 재현 결과 |
| --- | --- |
| 단일 허가와 역할 | 다른 PID의 두 루프백 송신자에 실제 TLS로 연결했다. 현재 송신자의 두 동시 요청과 비소유 송신자 중 하나만 200 및 전체 합성 JSON을 받았다. 다른 두 요청은 409·0바이트였고 원장의 소비와 시작 기록은 각각 한 건이었다. 제한 역할의 직접 원장 조회와 다른 역할의 변경도 거절됐다. |
| 첫 쓰기 전 제어기 교체·철회 | 요청을 `starting`에서 보류한 뒤 기존 제어기를 종료했다. 새 PID가 원장에 제어기 번호를 올린 후 기존 요청을 풀자 403·보호 본문 0바이트였다. 권한 철회 커밋 후에도 같은 결과를 받았다. 두 사례 모두 첫 바이트 기록 없이 취소됐다. 철회한 주체의 새 발급도 거절됐다. |
| 첫 쓰기 전 DB 중단 | 소유 postmaster 정지 중 발급·활성화는 `ledger_unavailable`이었고, 보류한 실제 TLS 요청은 503·보호 본문 0바이트였다. 동일 클러스터 재시작 뒤 미종결 상태가 유지됐고 중단 중 요청한 새 허가 행은 없었다. |
| 구 연결·종료 증거·새 세대 | A의 두 실제 보호 접두부 이후 전환을 요청하자 새 발급과 활성화가 보류됐다. 한 요청은 실제 소켓 종료 뒤 `finished`가 됐다. 다른 요청은 취소 후 접두부만 남았고, 소켓이 종료됐어도 종료 보고를 의도적으로 누락하자 `sending`이 유지됐다. 잘못된 PID와 실제 종료 후 감독 기록이 아직 없는 상태 모두 전환을 차단했다. 감독 역할이 기존 PID 종료를 원장에 기록한 뒤 두 미종결 항목을 `isolated`로 정리하고 새 세대의 전체 JSON을 확인했다. 이전 허가는 409·0바이트였다. |
| 자원 정리 | 두 실행 모두 제한 DB 연결과 클라이언트 요청, 마지막 송신자의 소켓·작업이 0이었다. 두 TLS 포트의 재접속 거절과 소유 Node·PG 종료, PID 파일·리스너·임시 클러스터·인증서 제거를 확인했다. 별도 호스트 조회에서도 소유 프로세스와 임시 경로가 각각 0개였다. |

TLS 클라이언트가 실제로 받은 HTTP 상태·바이트, 서버 소켓 종료, 제어기·송신 PID 및 PG 커밋과 재시작을 관측했다. 보호 본문과 사용자, 마지막 원장 조회 전 대기, 종료 보고 누락은 시험 모델이다. 송신기의 `before_write` 결과가 돌아온 뒤 `res.write`가 실행되고 그 후 `first_report`를 기록한다. 마지막 DB 판정 직후부터 첫 큐 삽입까지의 경합은 이번 시험으로 입증되지 않는다. 다중 호스트 분할, 실제 호스팅 프록시·전송 큐·운영 인증은 후속 범위다. [첫 쓰기 순서](../../tests/reference-analysis/t320-https-durable-egress.pg17.mjs#L227)

제품 코드, 빌드, 운영 DB와 배포는 변경하지 않았다.
