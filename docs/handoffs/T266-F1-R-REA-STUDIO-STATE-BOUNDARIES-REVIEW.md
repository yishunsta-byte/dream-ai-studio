## 독립 브라우저 확인

| 항목 | 1280px·390px 결과 |
| --- | --- |
| 파일 → URL 또는 본문 → 파일 | 두 경로에서 돌아온 파일 필드는 `files.length=0`, 권한은 해제 상태였다. 권한만 체크하고 제출하면 파일 선택 안내, 파일 필드 초점과 `aria-invalid=true`를 확인했다. 새 합성 PNG를 선택하면 형식 확인을 통과했다. 파일 모드 버튼을 다시 누르면 현재의 실제 선택을 유지했다. [입력 상태 처리](../../components/reference-analysis/lab-model.ts) |
| 다른 작업의 늦은 복사 | 모의 복사 요청을 보류하고 URL 확인으로 이전 결과를 닫았다. 새 작업이 완료된 뒤 프롬프트 탭의 메모 필드에 초점을 뒀다. 이전 복사 응답의 성공과 실패를 각각 전달해도 새 작업의 복사 알림은 비어 있었고 초점과 문구 선택은 바뀌지 않았다. [복사 처리](../../components/reference-analysis/reference-analysis-lab.tsx) |
| 같은 작업의 복사 실패와 편집 | 요청 후 표현 방향을 바꾸면 늦은 실패는 재시도만 안내했고 편집 필드 초점과 빈 선택을 유지했다. 그대로 다시 눌러 거절되면 미리보기로 초점을 옮겨 표시 문구를 선택했다. 일반 성공의 payload는 미리보기와 동일했으며 URL·본문·파일명·메모 표지가 없었다. |
| 기존 키보드·작업 흐름 | URL 안내에서 다음 두 `Tab`이 본문과 파일 대안으로 이동했다. 대기 시 취소 버튼, 요청 후 종료 대기 상태, 취소 완료에서는 재시작 버튼으로 초점이 이동했다. 취소 후 완료 탭이 나타나지 않았고, 실패 뒤 Enter로 재시도하면 완료 후 근거 탭으로 이동했다. `ArrowRight`, `Home`, `End`를 확인했다. |

두 폭에서 가로 넘침이 없었고 측정한 화면 내 버튼·링크의 최소 높이는 44px이었다. 실제 OS 클립보드, 물리 모바일과 보조기기 발화는 시험하지 않았다. 브라우저의 입력·작업 전환 중 관측한 fetch/XHR/beacon 요청은 0건이다. 같은 파일 모드에서 다른 파일을 선택할 때 권한 체크가 유지되는 것도 확인했다. 실제 자료 연결에서는 권한 확인을 개별 자료에 귀속해야 하며, 이번 합성 형식 확인 판정은 자료 전환 시 권한 초기화의 범위에 한정한다.
