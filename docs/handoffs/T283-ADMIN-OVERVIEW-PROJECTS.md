## 한 일

`/admin` 관리 화면 첫머리에 **내 프로젝트** 영역을 넣었어요. 지금 로그인한 운영자 계정의 클라우드 프로젝트를 목록으로 보여 줘요. 각 줄에는 제목(상세 화면 `/cloud/projects/<id>` 링크), 기록된 상태, 다음 단계, 메뉴·화면비·길이·수정 시각이 나와요. 기존 관리 메뉴와 연결 범위(회원 관리·서비스 상태 미연결)는 그대로 둬요.

- **읽기 재사용:** 읽기는 `/cloud/manage`·`/cloud/projects`와 같은 `readCloudProjects()` 한 번뿐이에요.
  - 기존 owner 범위 목록 읽기이고, owner는 서버가 확인한 계정 UUID예요.
  - lib·인증·DB 코드는 바꾸지 않았어요.
  - 다른 회원 조회, 서비스 역할, 쓰기 버튼은 없어요.
- **순서:** `app/admin/page.tsx`가 관리자 인증을 판정한 뒤에만 `loadAdminProjects()`를 불러요.
  - 미인증 401, 허용 밖 403, 설정 없음 503은 그리기 전에 관리자 로그인 화면으로 보내고, 목록은 읽지 않아요.
  - 이 PC 실행(로그인 꺼짐)은 기존 안내 화면만 보여 줘요.
- **네 가지 상태를 따로 보여 줘요.**

| 상태 | 조건 | 화면 |
|---|---|---|
| 미연결 | `DREAM_PROJECT_READ_BACKEND`가 `postgres`가 아님(이 환경에 클라우드 프로젝트 읽기 미설정) | “프로젝트 목록 미연결” 배지와 안내. 읽기 호출 없음. 0개·실패로 보이지 않음 |
| 실패 | 설정됐지만 읽기가 200이 아님 | “프로젝트 목록을 불러오지 못했어요” 경고와 다시 불러오기(같은 주소 일반 링크). 0개·조회 시각을 만들지 않음 |
| 결과 없음 | 읽기 성공, 0건 | 표시 목록 0개, 조회 시각, “이번에 불러온 목록에 프로젝트가 없어요” |
| 목록 | 읽기 성공, 1건 이상 | 건수, 조회 시각, 프로젝트 줄, “내 프로젝트 전체 화면” 링크 |

## 확인한 경계와 Backend에 필요한 것

기존 읽기 경로(`createProjectReadRequest`)는 “읽기 미설정”과 “DB 읽기 실패”를 같은 `503 PROJECT_READ_UNAVAILABLE`로 돌려줘요. 그래서 미연결 판정은 같은 선택 규칙(`selectProjectReadBackend`)의 첫 조건인 `DREAM_PROJECT_READ_BACKEND=postgres` 여부로만 먼저 갈라요. 값과 주소는 화면에 보이지 않아요.

설정값이 `postgres`인데 `DATABASE_URL` 형식이 틀린 경우 등 설정 오류는 “실패”로 보여요. 이것을 “미연결”과 정확히 나누려면 Backend가 읽기 응답에 미설정·설정 오류·조회 실패를 구분하는 안전한 코드를 추가해야 해요(예: `PROJECT_READ_NOT_CONFIGURED`). 이번 작업에서는 바꾸지 않았어요.

전체 회원·전체 프로젝트를 보는 운영 관리는 이번 범위가 아니에요. 서비스 역할이나 전용 관리자 읽기 계약이 필요하고, 지금은 “회원 관리 미연결”로 남겨 뒀어요.
