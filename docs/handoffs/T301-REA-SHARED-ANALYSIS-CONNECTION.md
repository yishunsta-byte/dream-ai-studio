# T301 클라우드 등록 분석 공통 연결

2026-11-19 KST · Codex(design) · 기준 `4779ac8` · 배정 `msg_e8388aaa9d85`

`/cloud/reference-analysis`와 `POST /api/studio/reference-analysis`가 하나의 서버 전용 연결을 참조합니다. `createStudioAnalysisConnection`은 하나의 서버 권한 공급자에서 목록 조회와 현재 등록 자료 조회 함수가 모두 주어졌을 때만 두 진입점의 설정을 함께 만듭니다. T299 화면용 `analysisApiConnected` 값은 이 구성에서만 생성됩니다. 제품의 기본 연결값은 비어 있습니다. 로그인한 계정에도 미연결 화면과 분석 실행 비활성 상태가 표시되고, 올바른 POST는 503 `analysis_unavailable`을 받습니다.

목록과 POST는 각 요청에서 기존 인증 경계를 거칩니다. 연결에 제공할 두 함수는 현재 소유·등록·분석 가능 여부를 같은 서버 정책으로 확인해야 합니다. 클라이언트 목록은 표시 이름과 두 ID로 구성되며 POST는 받은 두 ID의 권한을 현재 시점에 다시 확인합니다. 목록 조회 뒤 권한이 사라지거나 자료 소유자가 바뀐 경우 기존 계정의 POST가 차단됩니다. 분석 중 등록 또는 권한 세대가 바뀌면 기존 T284 확인 단계에서 결과가 폐기됩니다. 목록에 나온 세대가 클라이언트로 전달되거나 목록만으로 POST 권한이 부여되는 경로는 없습니다.

## 자체 검증

- 집중 시험 4개에서 실제 두 진입점의 기본 미연결, 목록만 또는 POST 조회만 주입할 때 양쪽 닫힘, A/B의 자기 자료와 다른 계정 차단, 목록 이후 철회·소유 변경, 실제 PNG 분석 중 권한 세대 변경으로 인한 결과 폐기를 확인했습니다.
- 격리 Next.js에서 기본·목록만·POST 조회만·완비 구성을 각각 실제 GET과 POST로 확인했습니다. 첫 세 구성에서는 인증된 요청도 미연결 화면 또는 503을 받았으며 자료 권한 함수 호출은 0건이었습니다. 완비 구성은 A/B 분리와 `no-store` 응답, 미인증 이동, 철회 뒤 목록 제외 및 오래된 POST 거절을 확인했습니다. 390px 헤드리스 Chromium에서 실제 GET–선택–동일 출처 POST로 PNG의 관찰 근거와 초안이 표시됐고, POST 실패 시 결과가 표시되지 않았습니다.
- `4779ac8`에 T301 변경만 적용한 고정 사본에서 공용 인증·네이티브 분석·헤드리스 포함 25개 파일 384개가 통과했습니다. Next 타입 생성과 전체 `tsc --noEmit --incremental false`, 변경 범위 ESLint도 통과했습니다.

격리용 공급자는 임시 Next 사본의 공통 연결 지점에만 주입했습니다. 운영 연결에는 실제 세션과 관리형 등록 자료 권한을 검증한 공급자가 필요합니다. 운영 적용과 배포는 이번 범위 밖입니다.

**Master 전달문** — 목록·POST 공통 연결을 구현했습니다. 기본과 부분 연결에서 화면·POST가 동시에 닫히고, 완비된 격리 연결에서는 A/B·철회·변경과 실제 PNG 분석이 검증됐습니다. 집중 4/4, 고정 사본 384/384, 전체 타입과 변경 파일 ESLint 통과입니다.
