## 응답 경계

실제 Next 라우트에서 전체 분석 분기와 기존 소스 해석 분기를 각각 실행했다. 임시 테스트 라우트는 결과만 주입했고 고정 커밋의 HTTP 응답 처리와 DTO 판정은 그대로 실행했다.

- 최상위와 중첩 필드 추가, 지원하지 않는 버전, 영상 관측 시각 불일치, 중복 관측 ID, 연결되지 않는 증거, 추가 `toJSON`을 각 분기에 넣었다. 14건 모두 일반화된 503과 `Cache-Control: no-store`를 반환했다. 원시 응답 및 소유 Next 로그에서 지정한 내부 진단 표식이 나타나지 않았다.
- 정상적인 실패 사유 다섯 가지는 두 분기에서 각각 기존 200·`no-store` DTO로 전달됐다. 합성 PNG·MP4·M4A를 네이티브 도구로 실제 분석한 응답은 분기별로 일치했고 T292 공급자가 동일하게 읽었다. 응답에는 검사용 비공개 ID, 파일 경로, SHA가 나타나지 않았다.
- 고정 소스의 실제 Next·루프백 SDK 검사에서 부분 설정, 계정 A/B/A, 객체당 GET 1건, 권한 철회, 요청 취소, 연결·스냅샷 정리와 재시도를 통과했다. 소유 리스너와 해당 실행의 임시 소스가 정리됐다.
- 네이티브 조건을 켠 표적 회귀는 42개 파일 659/659 통과했다. 별도 깨끗한 타입 생성 후 전체 TypeScript 검사와 변경 파일 ESLint가 통과했다.

DTO의 문자열 필드는 표시용 유효 데이터로 취급한다. 유효한 표시 문자열에 섞인 임의 내용을 검열하는 시험으로 범위를 확대하지 않았다. 시험에 운영 자격 증명·데이터·배포를 사용하지 않았다.
