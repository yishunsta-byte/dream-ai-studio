# T300 Supabase 비공개 원본의 검증 사본 인계

Backend 자체 검증 · 설치 SDK와 실제 루프백 HTTP · 합성 자격 및 미디어

`createPrivateObjectReader`에 서버 내부 `useVerifiedFile(actor, asset, consume, signal?)`을 추가했습니다. 기존 `verify()`와 같은 소유자·파일 등록값·비공개 버킷 검증을 통과한 뒤, 한 번 받은 사본의 크기·SHA-256·MIME과 실제 디코딩 또는 영상 미디어 검사를 확인합니다. 모두 끝난 뒤에만 콜백을 한 번 호출합니다. `verify()`의 확인 결과와 호출 형식은 기존 계약을 따릅니다. [구현](../../lib/storage/supabase/reader.ts)

콜백은 임시 파일 경로, 검증 메타데이터, 요청 취소 신호를 받습니다. 경로는 콜백 수명 안에서만 읽히는 비열거 속성입니다. 콜백 반환값은 버리고 호출 결과는 기존 검증 메타데이터만 반환합니다. 내부 오류 메시지와 원인은 고정 오류 코드로 바꿉니다. 취소 또는 기한 초과 시 콜백이 대기 중이어도 인계를 끝내고, 요청 소유 사본을 정리한 뒤 실행 슬롯을 반환합니다. 뒤늦은 콜백 거부도 처리합니다.

## 검증

- 실제 루프백에서 합성 PNG·MP4를 각각 비공개 버킷 확인 한 번과 객체 GET 한 번으로 검증했습니다. 끝나기 전까지만 같은 파일을 읽을 수 있었고, 반환값·직렬화·오류에서 임시 경로가 드러나지 않았습니다.
- 다른 소유자, 공개 버킷, 잘린 본문, 바이트 변조, MIME 불일치, 공개 폴더를 가리키는 작업 경로, 다운로드 중 취소에서 콜백이 실행되지 않았습니다. 정상 완료, 콜백 예외, 대기 중 취소·기한 초과 이후에는 파일을 정리했고 다음 요청이 같은 슬롯으로 실행됐습니다. [집중 시험](../../tests/storage-private-read.test.ts)
- 저장소·네이티브 REA 선택 회귀 24개 파일 309건 통과. 별도 DB 설정이 필요한 시험 등 20건은 건너뛰었습니다. 범위 TypeScript, 변경 파일 ESLint `--max-warnings 0`, `git diff --check`를 통과했습니다.

콜백은 신뢰 서버 코드에서 사본을 읽고 취소 신호에 따라 네이티브 처리와 파일 핸들을 정리해야 합니다. 호출자가 Windows에서 삭제를 막는 핸들을 계속 보유하면 삭제를 제한 횟수만큼 재시도하고 `STORAGE_TEMP`로 실패합니다. 이 변경에는 실제 작업실·관리자 연결, 운영 저장소 접근 및 배포가 포함되지 않습니다.
