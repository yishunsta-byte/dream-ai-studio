## 결론

- **첫 UI 차이: F255-R2 (장애 화면 문구 섞임).**
  - 공급원 장애(조회 실패·권한·계약 오류·설정 누락)일 때 목록은 "작품 목록을 불러오지 못했어요"라고 나와요.
  - 그런데 대표 영역은 "공개된 작품이 생기면 이곳에 대표 작품을 보여 드릴게요."라고 나와요.
  - 음악 영역도 "공개된 음악 작품이 생기면…"이라는 빈 목록 문구가 그대로 나와요.
  - 그래서 방문자에게 장애가 '아직 작품 없음'처럼 보여요.
- 지금 DTO의 `status`만으로 풀려요. `components/public-showcase/neon-showcase.tsx`와 그 집중 시험만 고쳤어요(CSS 변경 없음).
- 실제 재생과 실제 표지 이미지는 프론트만으로 풀 수 없어요. 공급원·미디어 계약이 필요하고, 아래 '차단 조건'에 적었어요.

## 차단 조건 (프론트만으로 못 푸는 것)

1. **실제 재생**
   - 지금 DTO에는 재생 정보가 없어요. `list_approved` 행은 `slug·generation·approvedMs·display`뿐이고, `readApprovedSnapshot`이 `artifact`를 `{state:"complete"}`로만 만들어요.
   - 그래서 승인 작품의 `media`는 항상 `null`이에요.
   - 재생하려면 Backend 계약이 필요해요:
     - 행에 공개 미디어 종류(video/audio)와 세대를 추가
     - `/media/public/…` 미디어 경로 판정과 응답 라우트(표지 T254와 같은 권한·바이트 검증)
     - `published-works`의 `PUBLIC_MEDIA_PREFIXES` 검사 통과
   - 화면은 이미 `media`가 있으면 플레이어, 불러오는 중, 오류, 다시 불러오기를 그려요(T-240 시험).
2. **실제 표지 이미지**
   - 승인 카드의 표지는 `/media/public/<slug>/<generation>/cover.webp`예요. 격리 사본은 표지 공급원이 비활성이라 모든 표지가 깨져 보였어요(5개 요청 모두 이미지 없음, T255 한계 4와 같음).
   - 실제 표시에는 공급원 조립이 활성 상태여야 해요: T304 공유 연결과 T327 런타임 설정.
   - 런타임이 꺼져 있으면 깨진 이미지 대신 대체 표시를 둘지는 디자인 결정이 필요해요.
3. **정상 빈 목록 = 예시 6개**
   - 설계 c9d5674 §5 그대로라서 바꾸지 않았어요.
   - 운영에서 실제 게시를 연 뒤에도 0건일 때 예시를 보일지 다시 정할지는 Master·사용자 판단이에요.
