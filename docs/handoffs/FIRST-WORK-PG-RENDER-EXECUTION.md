# 로컬 PG 대기 렌더 요청 수동 실행

Master 배정 msg_60face0e0c84. 기존 로컬 승인 경로에서 만든 render-prepare 작업 한 건을 /api/projects/{id}/renders/{jobId}/execute에 POST해 실행한다. 성공 응답의 같은 주소에서 소유자가 GET으로 검증된 MP4를 받을 수 있다. 기존 렌더 상태 조회의 requests에서 queued, running, failed, succeeded를 읽는다. 이 경로는 로컬 쇼핑숏츠 중 현재 검증된 PNG 장면 한 개, 컷 전환 및 첨부 WAV가 있는 승인 타임라인을 지원한다. 결과 크기는 16 MiB 이하로 제한한다.

## 실행과 결과 확정

- 소유자·프로젝트·현재 타임라인과 같은 내용 리비전의 제작/검수 승인을 확인한 뒤, 작업 행을 잠그고 시도 번호와 10분 실행 임대를 부여한다. 진행 중 동시 POST는 409를 반환한다. 실패 또는 만료된 실행은 제한된 시도 횟수 내에서 명시적으로 재실행할 수 있다. 완료된 실행을 다시 요청하면 저장된 결과를 반환한다.
- 선택된 PNG의 현재 검증 기록과 비공개 저장소 사본을 확인하고, 이전에 검증한 PG WAV 입력 어댑터로 음원을 읽는다. 기존 FFmpeg 믹서와 영상·음성 검증기를 사용한다. 출력 확정 직전에 현재 승인, 리비전, 실행 시도, 장면 선택과 WAV 첨부를 다시 확인한다.
- 검증된 바이트·생성 SHA·크기·검증 메타데이터·완료 활동을 로컬 PG에 작업 완료 상태와 원자적으로 저장한다. 이 경로의 결과는 소유자 전용 출력 테이블에 저장한다. 작업별 임시 자료는 성공·실패·기준 변경에서 정리한다.

## 실측

실제 Next.js·PG17에서 승인된 요청을 만들었다. 첫 실행에서 비공개 저장소 PNG 바이트를 같은 길이로 변조하자 409, 출력 0건, 임시 폴더 정리를 확인했다. 다음 실행을 저장소 요청 직전에 잠시 멈춰 동시 POST의 409와 DB running을 확인했다. 정상 소스를 이어받은 시도 2는 succeeded로 종료했으며, 재요청은 같은 결과를 반환했다. 결과와 완료 활동은 각 한 건, 실행 임대는 비어 있었다.

다운로드 바이트 33,773개와 저장 SHA-256 c1824d30ca69c481925bdc8fde2768c808e6e14b53ab45e7ff118cb706500369가 일치했다. H.264 60프레임, AAC 1트랙과 48kHz 디코딩 96,000샘플을 검증 메타데이터로 확인했다. 익명은 401, 다른 계정은 404였다. 별도 재실행에서 PNG 조회 중 실제 WAV 저장으로 리비전을 전진시키자 409 CURRENT_TIMELINE_CONFLICT, 출력·완료 활동 0건, 작업 실패 및 임시 폴더 정리를 확인했다.

통합 명령은 T371_VERIFY_HTTP=1 및 T371_VERIFY_RENDER_AUDIO=1로 기존 tests/postgres/t368-run-private-image-project-create.mjs를 실행한다. 최종 실행은 종료 코드 0이고 임시 PG·리스너·작업 파일이 정리됐다. 관련 인증·SQLite 렌더 회귀 191건, 타입 검사 및 ESLint 통과. 시험 도중 저장소 게이트의 Promise 처리와 응답 본문 소비 순서를 고친 뒤 전 과정을 재실행했다. 운영 큐·배포는 이 검증 범위 밖이다.
