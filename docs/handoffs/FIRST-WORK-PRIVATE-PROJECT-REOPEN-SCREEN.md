# 저장한 쇼핑숏츠 프로젝트의 상세 화면 재조회

Master 배정 msg_9155ef9df4d6, 화면 검증 범위 확정 msg_1a93b0594969. 로컬 PNG 생성 폼 b5449f1 및 메모 변경 068e1e1을 포함한 사본에서 실제 브라우저로 검증했다. Backend의 enableOwnedReadTls가 준비한 격리 PG17과 전용 CA를 기존 postgres 조회 어댑터에 연결했다. 실제 Next 서버, 합성 로그인, 루프백 Storage를 사용했다.

1. 로그인한 소유자가 /cloud/projects/new에서 제목을 ‘PG 상세 화면 재조회’로 입력하고 합성 PNG를 선택해 저장했다.
2. 완료 화면의 ‘저장한 프로젝트 열기’를 실제로 클릭했다. 이동한 경로는 /cloud/projects/01a1f416-0fcc-71ff-8ecc-24e45d562aba였다. 상세 화면의 제목, 분야 ‘쇼핑숏츠·제품 광고’, 제작 단계 7건을 확인했다.
3. 브라우저에서 같은 문서를 새로고침했다. 경로·제목·분야·단계 수가 클릭 직후 값과 모두 같았다. DB 전후 차이는 프로젝트 1, 단계 7, 자산 링크·감사·성공 원장 각 1이었다.
4. 시험이 종료 코드 0으로 끝났고 PG 프로세스·리스너와 임시 클러스터가 정리됐다. 화면 검증에는 별도 제품 코드 변경이 필요하지 않았다.

타 계정의 상세 404, 익명 401과 목록의 소유자 격리는 Backend의 5da505b 검수 기록을 인용한다. 기본 SQLite에서 저장한 프로젝트의 brief 화면을 연 결과는 이전 폼 브라우저 기록에 있다. [HTTP 검수](FIRST-WORK-PRIVATE-PROJECT-REOPEN-HTTP.md) · [기본 SQLite 검수](FIRST-WORK-PNG-CREATE-FORM.md)
