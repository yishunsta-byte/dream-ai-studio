# T330-R 게시 어댑터 실제 DB 세션 독립 검수

기준 `9693f24` · Master 인계 `msg_4254b8a737e9` · Codex(Tester)

**판정은 고정 세션 검증 계약 통과.** 임시 고정 사본에서 제공된 PostgreSQL 17.12·TLS 실행기를 수정 없이 실행했다. T328 사전 검사 22건과 T330 실제 작업·재접속 시나리오를 모두 통과했다. [실행기](../../tests/public-showcase/t328-publication-db-preflight.pg17.ts)

| 검증 | 독립 확인 |
| --- | --- |
| 초기 세 역할 및 작업 세션 | 관리자·목록·표지 로그인이 각각 TLS·클러스터·DB 이름과 OID·서버 포트·실제 로그인 및 역할을 확인했다. 각 작업은 검증 쿼리에 사용한 같은 `PoolClient`로 SQL을 실행한다. 초기 인증·TLS 실패는 그룹을 비활성화했다. |
| 권한 분리 및 게시 | 제한 세션에서 T295 준비·게시·철회를 커밋했다. 게시할 때 목록과 표지 메타데이터가 함께 열리고 철회하면 함께 닫혔다. 교차 역할의 SQL은 42501이었다. 관리자는 구형 함수에 직접 접근하지 못했고, T295 소유자의 내부 함수 권한 누락도 사전 검사에서 거절됐다. |
| 세션 반납과 미완료 트랜잭션 | 커밋하지 않은 준비 작업은 연결 반납으로 롤백됐다. 다음 세션에서 준비를 다시 진행할 수 있었고, 연속 대여의 백엔드 PID는 달랐다. 콜백 밖에 보관한 쿼리 함수는 호출을 거절했다. |
| 재접속 실패·연결 종료 | 개통 뒤 역할 철회, 로그인 비활성화, 대여 중 백엔드 종료, 동일 이름·권한의 DB 교체에서 그룹을 닫았다. 검증 실패한 대여는 업무 콜백에 도달하지 않았다. 다른 역할의 신규 호출과 이미 빌린 콜백의 후속 SQL도 비활성화 뒤 거절됐다. 기존 이름의 교체 DB는 기존 그룹의 OID 판정을 통과하지 못했고 새 그룹의 최초 검증은 통과했다. |
| 정리 | 각 사례 뒤 검사·제한 세션이 0건이었다. 소유 PG 프로세스, PID 파일·리스너·임시 클러스터를 정리했고 별도 호스트 조회에서도 소유 PG 프로세스와 임시 경로가 각각 0개였다. |

관련 관리자·공개·인증·기존 홈 및 게이트 회귀 22개 파일 560/560, 생성물 없는 고정 사본의 TypeScript 검사, 변경 파일 ESLint와 `git diff --check`가 통과했다.

판정은 직접 PostgreSQL 세션을 빌리는 서버 단위에 한정된다. 이미 DB에 전달된 SQL은 호스트의 기존 요청 배출 계약에 속한다. 제품 게시 저장소와 공개 어댑터의 실제 연결, 운영자 바인딩과 비공개 Storage·호스트 종료는 후속 범위다. 이전 결함 재현, 운영 DB 접속, 빌드·배포를 수행하지 않았다. [세션 검증 모듈](../../lib/public-showcase/publication-db-preflight.ts)
