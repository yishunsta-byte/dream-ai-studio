# T352-F1-R 프로젝트 상세 조회 범위 독립 재검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `e67884e` · Master 배정 `msg_357e904e8c71`

**판정은 통과.** T352-R에서 재현한 상세 조회 오판정 두 건이 해소됐다. 목록과 상세가 같은 범위 검사로 성공 응답의 `Content-Range`를 JSON 행 수와 대조한다. 상세의 한 행 제한과 요청 UUID 대조도 유지됐다.

| 상세 상류 응답 | 독립 확인 결과 |
| --- | --- |
| 빈 배열과 `*/1`, 한 행과 `0-0/2` | 503 `PROJECT_READ_UNAVAILABLE`, `no-store` |
| 범위 헤더 누락, 비정규·불일치 범위, 복수 행 | 503 `PROJECT_READ_UNAVAILABLE`, `no-store` |
| 정확한 `0-0/1`이나 응답 행 또는 내부 프로젝트 ID가 요청과 다름 | 503 `PROJECT_READ_UNAVAILABLE`, `no-store` |
| 빈 배열과 정확한 `*/0` | 기존 404 `NOT_FOUND`, `no-store` |
| 일치하는 한 행과 정확한 `0-0/1` | 기존 200 상세 DTO, `no-store` |

잘못된 **입력** ID는 기존 400이다. 목록의 전체 응답 검증·중복 처리와 인증 선행, 기존 목록·상세 계약도 회귀를 통과했다.

- 고정 범위는 어댑터, 해당 집중 시험, 작성자 인계 3경로다. 제공 어댑터 시험 45건을 포함한 집중 회귀 333건 통과·30건 조건부 건너뜀을 확인했다. 별도로 검수 사본에서 이전 두 실패, 응답 ID 두 형태, 정상 404·200의 캐시와 본문을 대조한 6건이 모두 통과했다.
- 소스 타입 검사, 변경 TypeScript ESLint 및 커밋 diff 공백 검사가 통과했다. 검수 사본을 정리했다. 실제 Supabase/Auth, 제품 라우트 연결과 운영은 범위 밖이다. 운영 접속·빌드·배포·새 세션 없이 결과를 반환했다.
