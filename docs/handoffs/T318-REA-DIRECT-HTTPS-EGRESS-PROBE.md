# T318 별도 HTTPS 송신 경계 격리 검증

2026-11-19 KST · Codes(Backend) · 설계 `fced9f9` · 화면 분리 기준 `5980904` · 배정 `msg_8f675f0952ae`

별도 Node 자식 프로세스 두 개가 각자 `127.0.0.1`의 임시 HTTPS 리스너와 TLS 소켓을 소유했다. 부모 시험 프로세스의 공통 제어기가 현재 세대·권한 리비전·송신 소유자와 일회 허가를 판정했다. 합성 사용자 세션과 JSON만 사용했다. 클라이언트는 이 실행에서 생성한 인증서의 신뢰와 루프백 IP, 피어 지문을 확인했다. [T316 결정안](T316-REA-PROTECTED-RESPONSE-TRANSPORT-OPTIONS.md) · [T317 분리 인계](T317-REA-CLOUD-ANALYSIS-PROTECTED-SHELL.md) · [T318 실행기](../../tests/reference-analysis/t318-direct-https-egress.loopback.mjs)

## 검증 방식과 실제 관측

| 조건 | 관측 결과 |
| --- | --- |
| 현재 소유자와 허가 | 다른 합성 세션에서 같은 허가를 쓰면 403 및 본문 0바이트였다. 두 리스너가 동시에 살아 있을 때 비소유 인스턴스와 현재 소유자의 반복 연결은 409 및 본문 0바이트였다. 정상 응답만 전체 JSON을 반환했고 전송 전·중·후 반복에도 첫 바이트 소비 1회였다. |
| 첫 보호 바이트 전 철회·만료 | 송신 프로세스가 허가를 받은 뒤 실제 소켓 쓰기 전에 멈췄다. 현재 리비전이 철회로 바뀌거나 제어 시계의 기한이 지나면 재개가 거절됐다. 클라이언트 수신은 각각 403/410과 보호 본문 0바이트, 허가 소비 0이었다. |
| 진행 중 전환과 종료 확인 | A에서 보호 접두부를 실제 수신한 상태와 별도 허가가 첫 바이트 전에 멈춘 상태를 함께 만들었다. 전환 요청으로 후자는 409·본문 0바이트였지만, 앞선 전송의 실제 소켓 종료 전에는 기존 세대와 신규 허가 정지가 유지됐다. 종료 및 기존 송신 경계 차단, 새 소유자의 준비 확인 후 B를 열었다. |
| 종료 보고가 사라진 경우 | B에서 접두부 전송 후 전환 취소를 요청했다. 클라이언트가 접두부만 받은 채 연결 종료를 관측했고 B가 차단 요청을 확인했지만, 제어기가 종료 보고를 잃은 상태에서는 새 세대를 열지 않았다. A/B 양쪽의 기존 허가 재사용은 409·본문 0바이트였다. 소유한 B 프로세스의 실제 종료와 해당 클라이언트 TLS 종료를 확인한 뒤에만 A로 전환했고 새 허가로 전체 JSON을 받았다. |
| 종료·자원 정리 | 두 자식 프로세스 종료, 이전 두 포트의 새 연결에 대한 `ECONNREFUSED`, 클라이언트 요청 0건, 임시 인증서 디렉터리 제거를 각각 확인했다. 마지막 활성 송신 인스턴스도 종료 직전 열린 소켓·송신 작업을 각각 0으로 보고했다. |

동일 스크립트의 루프백 실행 10회와 ESLint가 통과했다. Windows의 Git for Windows에 포함된 OpenSSL로 실행마다 루프백 IP SAN을 가진 임시 자체 서명 인증서를 만들었다.

```powershell
node tests/reference-analysis/t318-direct-https-egress.loopback.mjs
node node_modules/eslint/bin/eslint.js tests/reference-analysis/t318-direct-https-egress.loopback.mjs --max-warnings 0
```

## 실제 호스트에서 추가로 입증할 범위

- 이 시험의 제어 저장소는 부모 프로세스의 메모리이며 제어 메시지는 로컬 IPC다. 순서와 기한을 제어하는 합성 모델은 다중 호스트의 지속 원장, 제어 노드 장애·재시작 및 분할 상태에서의 판정을 입증하지 않는다. 첫 바이트는 송신자 큐 삽입과 독립 클라이언트 수신을 각각 관측했다. IPC의 권한 부여와 외부 호스트의 큐 삽입이 원자적이라는 보장은 검증하지 않았다.
- 실제 TLS 종료 지점과 후단 큐·프록시까지 포함한 최초 전송과 종료, 로드밸런서 우회 차단, 구 인스턴스 강제 격리와 잔여 세션 정리, 호스트별 실패 시 비활성 조건이 필요하다. 본 시험에서 구 송신자는 자식 프로세스 핸들로 종료했으며, 실제 인프라의 격리 방법은 별도 실증 대상이다.
- Auth 세션 교환, 공유 키·회전, 브라우저 캐시, 실제 Next·호스팅이나 운영 DB 경로는 연결하지 않았다. 제품·운영 자격·외부 호스트·배포 변경은 없었다.

**Master 전달문** · T318 두 독립 루프백 HTTPS 송신 인스턴스에서 현재 소유자 판정, 단일 허가 소비, 첫 바이트 전 0바이트, 전송 중 종료 대기와 보고 유실 시 실제 종료 증거 이전의 전환 보류를 확인했다. 10회와 리스너·프로세스·시험 인증서 정리를 확인했으며 독립 재현을 요청한다.
