## 원인과 수정
- 원인: `JoinBox`가 `planJoin(timeline,…)`이 만든 **전체 timeline**을 state에 두었어요. "이대로 연결"을 누르면 `setDraft(plan.timeline)`으로 그 시점의 초안 전체를 다시 썼어요.
- 수정 1: 미리보기 state는 이제 요청만 들고 있어요(`JoinRequest`: 두 곡, 겹침, 사람이 본 바뀌는 값 목록 `seen`).
  - 화면의 목록은 매 렌더마다 최신 초안으로 다시 계산해요(`joinPreview`).
  - "이대로 연결"은 `setDraft(old=>applyJoin(old,…))`로 바꿀 초안 위에서 다시 계획해요. 그래서 연결 필드 3개(앞 곡 끝 서서히, 뒷 곡 처음 서서히, 뒷 곡 시작)와 join만 바뀌어요.
- 수정 2: 미리 본 뒤 그 바뀌는 값이 달라지면(앞 곡 길이나 서서히 등) 조용히 적용하지 않아요.
  - 목록을 새 값으로 바꾸고 "미리 본 뒤 두 곡의 값이 바뀌어…" 안내를 띄워요. "이대로 연결" 대신 "바뀐 값 확인"이 나와요. 다시 확인해야 적용돼요.
  - 다음 곡이 빠지면 오류를 보여 주고 연결하지 않아요.
- 같은 종류의 덮어쓰기도 함께 막았어요.
  - 빼기 되돌리기: 그 순간의 초안 전체로 돌아가던 것을, 뺀 소리와 권리 행과 연결만 최신 초안에 돌려놓도록 바꿨어요(`restoreClip`).
  - 소리 넣기: 새 소리와 권리 행만 최신 초안에 더해요(`insertClip`).
  - 역할 바꾸기·기존 연결 겹침 칸: 함수형 갱신으로 바꿨어요.
  - 이제 소리 카드의 모든 `setDraft`가 `old=>`/`current=>` 형태예요(시험으로 확인).

## 검증
- 새 시험 `t152-audio-join-draft` 7개 통과
  - 원재현(미리보기 → -6 dB와 권리 메모 → 적용 → 둘 다 남고 연결 필드만 바뀜)
  - 다른 소리 추가·역할·영상 값 보존, 다음 곡이 빠지면 연결 안 함
  - 바뀐 값은 다시 확인을 기다림
  - 빼기 되돌리기와 소리 넣기가 최신 초안 보존
  - 컴포넌트 소스 가드(timeline state 없음, 모든 setDraft 함수형)
  - 가상 s5 사본 DB에서 적용 → 저장 → 다시 읽기: -6, 메모, 연결 그대로. 오래된 revision CAS는 거절
- `eslint .` · `tsc` 통과. vitest 전체 **58파일 통과·2 skip, 655 통과·17 skip**(T149 save/CAS/recovery 시험 포함). 운영 build와 `verify-build`는 안전 사본에서 통과했어요.
- **실제 앱**(ego-browser, 1280): 안전 사본 `next dev`와 OS 임시 폴더의 s5 가상 사본으로 했어요. 템플릿 snapshot은 그 사본 DB에서만 보정했어요.
  1. 원재현: A 10초에 끝 서서히 00:00.15, B를 넣고 연결 미리보기를 띄워요("A 끝 서서히 00:00.15→00:00.00, B 시작 00:10.00→00:09.00"). 그 뒤 A 크기 -6, 권리 메모 `F150-stale-plan-keep`을 넣고 적용했어요.
     - 적용 전후 입력 값: 크기 -6, 메모 그대로. 끝 서서히만 00:00.00이 되고 B는 9~29초예요.
  2. 저장(r3) → 새로고침(GET): -6, 메모, "다음 곡 'B'로 00:01.00 겹쳐 이어요"가 그대로예요.
  3. 연결을 풀고 다시 미리본 뒤 A 길이를 8초로 바꿨어요.
     - 목록이 "B 시작 00:09.00→00:07.00"으로 바뀌고 안내가 떠요. "이대로 연결" 버튼은 없어요.
     - "바뀐 값 확인" → 적용하면 B 7~27초, -6과 메모가 그대로예요.
  4. 미리보기를 연 채 느린 저장(4초) 중에 크기 -2, 메모 `during-save`를 넣었어요.
     - 저장 응답(r4) 뒤 "저장하는 동안 고친 내용은 아직 저장하지 않았어요"가 나오고, -2와 메모가 남아요.
     - 이때 열려 있던 미리보기는 닫혀서 곡을 다시 골라야 해요. 저장 응답 때 편집 칸이 다시 그려지기 때문이에요. 덮어쓰기는 없어요.
