# T368-R 검증된 비공개 PNG의 프로젝트 생성 독립 검수

**소유 PG17 후보 검수 통과.** 검수 기준은 `c6c49c55f59e9bbd29420b0ef8ed5108a8f85b9e`다. 실행 전 해당 커밋과 작업본의 추적된 서비스·시험 코드가 일치하는지 확인했다. 변경 8개 경로의 차이를 확인했고 `git diff --check`가 통과했다.

| 검수 항목 | PG17.12 및 루프백 Storage에서 직접 실행한 결과 |
| --- | --- |
| 권한과 철회 | T367로 등록한 소유 PNG 한 건을 기존 Storage SDK로 읽어 생성했다. 일반 API 역할의 후보 함수 실행과 전용 실행 역할의 직접 원장 접근이 거절됐다. 타인 자산과 검증 철회 자산으로는 저장소 읽기 전에 요청이 거절됐다. 공개 버킷과 변조된 바이트도 차단됐다. |
| 중복·응답 유실 | 동일 소유자의 동시 요청이 PostgreSQL 잠금에서 대기하는 것을 확인했다. 첫 COMMIT 뒤 응답을 잃어도 후속 동일 요청은 같은 프로젝트 ID를 받았다. 프로젝트 1건, 제작 단계 7건, 파일 링크·감사 기록·성공 원장 각 1건이 저장됐다. 입력을 바꾼 동일 요청 ID는 충돌했고 다른 소유자는 자기 자산으로 독립된 결과를 받았다. |
| 정책 변경 경합 | 검증 도중 정책 갱신은 생성 트랜잭션의 잠금 해제를 기다렸다. 갱신 뒤 신규 요청은 거절됐고, 이미 확정한 동일 요청은 추가 Storage 읽기나 DB 생성 없이 원래 ID를 반환했다. |
| 전체 롤백 | 감사 기록을 작성한 뒤 원장의 성공 갱신에 실패를 주입했다. 프로젝트·단계·링크·감사·요청 건수가 모두 시도 전과 같았다. 실패 주입을 해제하고 같은 요청으로 재시도하자 생성됐다. |
| 기존 호출·회수 | 권한 회수 뒤 기존 쓰기, 프로젝트와 생성 원장, ACL을 확인했다. 기존 B12 PG 생성 시험 20건과 B15 Storage 결합 생성 시험 19건이 통과했다. 별도 관련 Vitest 회귀는 1,171건 통과, 조건부 300건 건너뜀이었다. |

고정 T368 실행기와 기존 B12·B15 실행기를 사용했다. T368 실행기는 리스너·PG 프로세스·임시 클러스터 정리를 확인하고 정상 종료했다. B12·B15도 종료 코드 0으로 끝났고 실행기가 만든 로컬 증거는 각 시험 디렉터리에 보관됐다.

검증 범위는 소유 PG17.12, 합성 루프백 Storage 및 쇼핑숏츠용 PNG 한 건이다. 실제 Supabase 역할·Storage 정책과 제품 HTTP POST 연결은 미검증이다. 운영 접속·빌드·배포는 수행하지 않았다.
