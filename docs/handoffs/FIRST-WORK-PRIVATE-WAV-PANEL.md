# 로컬 비공개 WAV 등록 화면

Master 배정 msg_f04293d662c3. 0250ea3 설계를 선택형 PG17 새 프로젝트 화면에 연결했다. 쇼핑숏츠 제품 사진과 별도로 1 MiB 이하 PCM WAV를 선택해 기기에서 미리 듣고 500자 이내 권리 메모와 함께 등록한다. 등록된 ID로 소유자용 재생 경로를 연다. 화면은 서버 201 확인 후 ‘비공개 자료로 등록됨 · 프로젝트 연결 전’을 표시한다. 프로젝트 첨부 PUT/GET 고정본은 별도 인계 대상이다.

실제 Next 브라우저 폼과 소유 PG17에서 8 kHz 모노 16비트 PCM 시험 음원을 선택하고 1초 재생·일시정지를 확인했다. 한국어 메모를 입력한 후 서버 201 응답을 브라우저에서 한 번 유실했다. 같은 선택과 메모로 재등록한 두 POST는 동일 키·동일 음원 ID였다. 소유자 GET 재생기로 1초 음원을 재생·일시정지했고 연결 전 상태를 확인했다. 여기서 재생 검증은 브라우저 디코딩·재생 호출 기준이다. [전용 브라우저 시험](../../tests/postgres/private-wav-panel-screen.mjs)

관련 Vitest 44건 및 변경 화면·시험 ESLint 통과. 제작 화면 구현자 자체 시험이며 실제 운영 저장소·기기 청취는 별도다.

> Master 전달문 — WAV 선택·기기 미리 듣기·메모·비공개 등록·소유자 재생을 확인했습니다. 등록 성공만으로 프로젝트에 연결됐다고 표시하지 않습니다.

## 프로젝트 연결 및 키보드 복구

서버 1aae8b9와 UI c0a7635. 본인 쇼핑숏츠 상세 /cloud/projects/{id} 또는 생성 직후 화면에서 등록된 WAV를 PUT으로 연결한다. GET 목록에서 같은 ID를 확인한 뒤 연결됨을 표시한다. 상세를 새로 열 때마다 소유자 목록을 다시 읽으며 제목·재생 시간·권리 메모·비공개 재생기를 표시한다. 목록 조회 실패, 연결 결과 미확정, 빈 목록은 구분한다. 통합 담당에게 고정본과 경로를 전달했다(msg_03157c70bf96).

390px Chromium에서 기존 화면의 A 파일 권리 메모가 B 선택 후 남는 문제를 재현했다. 수정본에서 B를 선택하면 입력란이 비고, 같은 파일의 등록 응답 유실 후에는 입력 메모가 유지됐다. 등록 버튼에 초점을 두고 Enter로 재시도한 뒤 성공 안내가 초점을 받고 다음 Tab은 등록 음원 재생기로 이동했다. 기기 및 서버 파일 재생, 두 요청의 동일 ID·키를 실제 PG17에서 재확인했다. 전용 시험에 교체 및 키보드 경로를 추가했다. 공식 npm run typecheck와 ESLint 통과.
