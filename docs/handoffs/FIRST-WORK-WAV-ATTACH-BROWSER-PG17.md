# 비공개 WAV 프로젝트 첨부 및 새로고침 검수

화면 후보 `c0a7635`(서버 `1aae8b9` 포함)를 격리한 Next 개발 서버, Chromium, 소유 PostgreSQL 17에서 검수했다. 인증과 비공개 Storage는 루프백 시험 서비스였다.

1. 같은 소유자의 쇼핑숏츠 프로젝트를 준비하고 실제 상세 화면을 열었다. 프로젝트의 음원 연결은 0건이었다.
2. 파일 선택기로 합성 1초 WAV(8 kHz, 모노, 16비트 PCM)를 선택했다. 권리 메모 `QA synthetic tone`을 입력하고 ‘비공개 음원 등록’을 Enter로 실행했다. 등록된 음원 플레이어가 표시됐고 프로젝트 연결 목록은 비어 있었다.
3. ‘등록한 음원을 프로젝트에 연결’을 Enter로 실행했다. 새로 조회된 연결 목록의 플레이어 주소가 방금 등록한 WAV의 주소와 일치했다.
4. 상세 페이지를 새로고침했다. 같은 프로젝트 URL에서 목록에 같은 자산 ID의 플레이어 1개가 복원됐다. 파일명 `qa-project-tone.wav`, 길이 1초, 권리 메모가 표시됐다.
5. DB에서 소유자의 비공개 WAV가 1건 증가했고 해당 프로젝트에 `productionAudio` 연결 1건, `project.audio.attach` 감사 1건을 확인했다. 연결된 자산 ID·소유자·파일명·길이 1000ms·메모도 화면과 대조했다.

기존 T368/T371 소유 PG17 실행기의 실제 Next 서버 콜백 안에서 브라우저를 연결했다. 기존 HTTP·PG17 회귀까지 종료 코드 0이었으며 임시 클러스터와 리스너 정리를 확인했다. 이 검수는 로컬 통합 결과이며 운영 Supabase·Vercel 및 실제 기기에서의 청취는 별도다.

> Master 전달문 — `c0a7635`에서 기존 프로젝트의 WAV 선택·등록·첨부·새로고침 복원을 확인했습니다. 등록 및 복원 ID가 일치했고 DB에는 WAV 파일 1건 증가, 프로젝트 연결 1건, 감사 1건이었습니다.
