# T276-F1 REA 영수증 종결 시각과 보존 기한

2026-11-19 KST · Codes(Backend) · 기준 `37a0bfc45d827981acd6a8c9cb6c8ef7eefffa36` · 배정 `msg_19820d7a0200` · 독립 검수 대기

실행 시작 시 신뢰 시계에서 읽은 값은 권한, 분석 신선도와 대기 확인 만료를 판단할 때 사용합니다. 타임라인을 썼거나 변경 없음이 확정된 뒤, 같은 SQLite 트랜잭션에서 시계를 다시 읽어 `completedAtMs`를 기록합니다. `retainUntilMs`는 종결 시각에 보존 기간을 더한 값입니다. 실행 만료를 통과한 정상 쓰기는 그 만료 시각을 넘겨 끝나도 종결할 수 있습니다. 완료 시각은 영수증 쓰기 직전이며 제품 보존 정책에서는 그 이후 커밋까지의 지연도 고려해야 합니다. [수정 코드](../../lib/reference-analysis/synthetic-apply-store.ts) · [이전 독립 검수](T276-R-REA-ATOMIC-APPLY-RECEIPT-REVIEW.md)

종결 시각은 실행 시작 이상인 안전한 정수여야 하고, 보존 기한 덧셈도 안전한 정수 범위에 있어야 합니다. 시계가 역행하거나 잘못된 값을 반환하면 `REA_RECEIPT_COMPLETION_TIME_INVALID`로 종료하고, 같은 트랜잭션의 확인 소비·타임라인·워크플로·활동 로그 변경을 롤백합니다. 시계나 영수증 쓰기의 예상 밖 예외도 기존 롤백 경로를 따릅니다.

| 격리 합성 검증 | 결과 |
| --- | --- |
| 실행 시작 150ms, 활동 로그 트리거에서 시계 320ms, 보존 150ms | 적용 프로세스는 응답 없이 종료했습니다. 별도 프로세스가 320ms에 종결 시각 320ms의 영수증을 읽었습니다. 469ms에 재조회 성공, 470ms에는 만료됐습니다. |
| 149ms 역행, NaN, 무한대, 소수 및 덧셈 범위 초과 | 마지막 활동 로그 쓰기까지 진행한 뒤 검증에서 실패했습니다. DB 논리 스냅샷이 원상 복구됐고 정상 시계로 같은 확인을 적용할 수 있었습니다. |
| 종결 시계 예외, 영수증 기록 실패 | 확인, 타임라인, 워크플로, 활동 로그 전체 롤백을 확인했습니다. |
| `no_change` 150ms → 160ms | 종결 시각 160ms로 영수증을 남겼으며, 309ms 조회 성공과 310ms 만료를 확인했습니다. 타임라인 리비전과 저장 로그는 추가되지 않았습니다. |

합성 집중 시험 **9/9**, 기본 REA **99 통과·45 건너뜀**, 네이티브 REA와 타임라인·오디오 회귀 **180/180**을 확인했습니다. 기존 CAS, 두 연결의 경쟁, 철회·복원 세대 무변경 및 시작 잠금 회귀도 포함됩니다. 범위 TypeScript `tsc -p tmp/t276-rea-typecheck.json`와 변경 파일 ESLint `--max-warnings 0`도 통과했습니다. 실제 제품 연결과 저장소 시계의 운영 정책은 후속 범위입니다.
