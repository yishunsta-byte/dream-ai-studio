## 통과 범위와 후속 책임

- 실제 길이가 500ms로 주어진 단일 시간축에서 `490–500ms`는 통과하며, `490–1000ms`와 `500ms` 시작점은 거절됐다. 서로 다른 길이와 0도 거절된다. 길이 미확인 근거는 소유자 DTO에서 `seekable: false`이며 공유 요약에 시간 위치가 없다.
- 검증된 역할을 가진 별도 합성 소유자 간 표시·공유 거절을 확인했다. private 레코드의 원문·URL 경로·파일명과 임의 메타데이터는 소유자 화면용 구조에서 제거된다. 소유자 화면에는 접근이 제한된 근거 문구와 내부 근거 ID가 남으며 평문으로 렌더링해야 한다. 선택 공유는 분류와 허용된 위치·기술값만 내보내며 원문·비공개 문구·내부 ID를 제외했다. 서버가 세션과 원본 접근권을 먼저 확인하고 private 레코드를 소유자 범위에서 조회하는 것은 호출자 책임이다.
- 신고값 64 MiB 초과, 작은 신고값으로 제출한 실제 `64 MiB + 1` 파일과 관리 루트 밖 경로를 거절했다. 실경로 대조, 열린 파일의 크기 확인, 복사 중 byte 상한을 코드로 대조했다. 기존 Windows 로컬 검사에서 실제 MP4·WAV·PNG 메타데이터와 손상·확장자 불일치를 재검증했다. 제품 호출자는 변경을 통제하는 서버 관리 루트, 소유자에 귀속된 경로와 수신 중 byte 한도를 제공해야 한다.
- 실제 기존 도구로 실행 파일 부재와 비정상 종료의 분리를 확인했다. 별도 합성 파일의 1ms 기한과 이미 취소된 신호를 통해 `timed_out`과 `cancelled`를 구분했다. 네이티브 시험은 실제 합성 자식 프로세스에서 취소·시간 초과·실패 때 `close`가 반환 전에 발생함을 확인한다. 추가 실행 전후 전용 검사 사본 디렉터리 목록이 같았다. 진행 중 Node 파일 I/O와 프로세스 내부 sharp는 즉시 중단을 보장하지 않는다. 결과 반환은 진행 중 작업과 정리를 기다리므로 강제 종료 시한이 필요한 제품에는 별도의 작업 격리와 예산 관리가 필요하다.
