# T298 공개 목록·표지 새 조회 어댑터

T295 독립 검수 수용 기준 · Backend 자체 검증 · EnterpriseDB PostgreSQL 17.12 임시 루프백

서버 내부 `openIsolatedPublicationPublicReader`가 기존 `ShowcaseListStore`와 `CoverStore`에 T295의 `list_approved`와 `find_cover`를 연결합니다. 지정 형식의 임시 DB와 루프백 17.12, 서로 다른 목록·표지 로그인을 확인합니다. 각 로그인에 자기 함수 실행 권한만 있고 만료 조건이 없는 기존 T253 함수 권한이 없는 것을 조회한 뒤 실제 함수를 시험합니다. 확인에 실패하거나 설정이 없으면 기존 샘플 목록·비활성 표지 공급원을 반환합니다. [어댑터](../../lib/public-showcase/publication-public-reader.ts)

- 목록과 표지에 별도 읽기 전용 풀을 사용합니다. 조회는 `Idle`이 확인된 연결의 단일 오토커밋 SQL로 실행돼 매번 새 스냅샷을 얻습니다. 이전 트랜잭션이 남은 연결이나 취소·조회 실패를 겪은 연결은 폐기합니다. 마감·취소 후 도착한 연결은 쿼리를 실행하지 않습니다.
- 표지 메타데이터가 있으면 slug·세대·SHA에 결합된 주소와 크기를 확인합니다. 비공개 사본을 읽기 직전에 같은 세대를 새로 조회합니다. 그사이 만료·철회되면 파일 공급자를 호출하지 않습니다. 승인된 크기로 제한해 별도 서버 공급자에서 읽고, 기존 `serveCover`가 길이·해시·WebP를 최종 검증합니다.
- 표지가 처음부터 없으면 기존 HTTP 흐름이 404를 반환합니다. 표지 조회 뒤 권한이 바뀌거나 비공개 읽기·무결성이 실패하면 바이트 없이 503을 반환합니다.

## 검증

- 고정 T253·T293·T295 SQL 해시를 확인해 임시 PG17에 적용했습니다. 실제 역할 분리 및 권한 확대 시 비활성, 승인 작품·만료·철회·새 세대·이전 주소, 같은 PostgreSQL 연결 PID 재사용, GET/HEAD와 비공개 표지 실패를 확인했습니다. 테이블 잠금에 걸린 조회를 실제로 관측한 뒤 호출자 취소와 마감 초과를 검증했고 다음 조회는 성공했습니다. 임시 프로세스·리스너·클러스터를 정리했습니다. [네이티브 실행기](../../tests/public-showcase/publication-public-reader.native.ts)
- 집중 5개 시험에서 오염된 트랜잭션, 취소 뒤 늦은 체크아웃·쿼리·사본 응답, 주소·길이 검사를 확인했습니다. 공개·관리자 큐·REA 회귀 31개 파일 363건 통과, 1건 건너뜀. 범위 TypeScript와 변경 파일 ESLint도 통과했습니다. [집중 시험](../../tests/public-showcase/publication-public-reader.test.ts)

## 연결 범위

운영 DB와 비공개 스토리지는 연결 전입니다. 실제 라우트의 `no-store` 적용과 CDN·브라우저 캐시, 이미 전송이 시작된 응답은 운영 경로에서 별도 확인해야 합니다. 이번 시험은 기존 응답 함수에 격리 공급자를 직접 주입했으며, 제품 공급원·라우트와 공유 SQL은 변경하지 않았습니다.
