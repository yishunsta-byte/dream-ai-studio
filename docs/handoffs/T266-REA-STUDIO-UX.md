## 2. 기능

- 입력 방식 4가지: 합성 표본 · URL · 파일 · 본문.
  - URL은 열지 않아요.
  - 본문과 파일은 권한 체크를 해야 형식을 확인해요.
  - 파일은 이 브라우저에서 이름·크기·형식만 보고, 내용은 읽지도 보내지도 않아요.
- 안내 문구에 입력 원문(주소·본문·파일명)을 넣지 않아요.
- 모의 작업은 대기 → 분석 중 → 완료 / 완료·근거 없음 / 실패로 이어져요.
  - 진행 중에는 취소 요청을 받을 수 있어요. 취소 요청 → 종료 확인 순서로 끝나요.
  - 실패하거나 취소되면 같은 표본으로 다시 시도·다시 시작할 수 있어요.
- 결과 화면의 근거 탭에는 관찰(위치 표시), 파일 메타데이터, 추정(다른 가능성·연결된 관찰), 확인 불가가 있어요. 공개 문구 예시는 따로 분리했어요.
- 편집용 프롬프트 탭
  - 표현 방향, 복사 제외 메모, 복사할 문구가 있어요.
  - 복사가 거절되면 문구를 선택해 두어 직접 복사하게 해요.
- “합성 체험”임을 페이지 머리, 상단 안내, 결과 배지 세 곳에 표시해요.

## 3. T265-R 지적 반영

| 지적 | 반영 |
|---|---|
| P1 URL 제출 뒤 Tab·aria 안내 | 대체 안내가 나오면 초점을 안내 영역으로 옮겨요. 다음 Tab은 첫 대안(본문 입력)이에요. 필드는 `aria-describedby`로 안내와 이어요. 실제 오류일 때만 필드로 초점을 옮기고 `aria-invalid=true`로 표시해요. 알림 역할(`status`/`alert`)은 안내 문장에만 붙여서, 대안 버튼 이름까지 함께 읽히지 않게 했어요(c8dca94). |
| P1 새 입력·취소 후 이전/늦은 결과 차단 | 모든 모의 이벤트는 작업 번호를 달고 와요. 다른 작업이나 끝난 작업의 이벤트는 버려요. 취소를 요청한 뒤에는 종료 확인만 받아요. 새 입력을 확인하면 이전 결과를 닫고 “이전 결과를 닫았어요”라고 안내해요. 입력 방식을 바꾸면 권한 체크도 지워요(c8dca94). |
| P2 복사 중 초안·포커스 경합 | 복사 요청은 누른 시점의 요청 번호·초안 판·작업 번호에 묶여요. 응답이 왔을 때 하나라도 바뀌었으면 초점 이동·문구 선택을 하지 않고 “다시 복사해 주세요”라고만 안내해요. |
| P2 상태 영역 | 작업 상태 칸 하나(`role=status`)가 상태 이름과 설명을 함께 읽어요. |

- 작업이 진행되는 동안 초점과 상태 안내는 이렇게 바뀌었어요.

| 단계 | 초점 | 상태 안내 |
|---|---|---|
| 시작 직후 | 취소 요청 | 대기 중 |

  - 초점은 표현 방향 칸에 그대로 있고, 선택된 문구는 없었어요.
  - 안내: “복사하지 못했어요. 지금 문구로 다시 시도해 주세요.”
  - 바꾸지 않고 다시 누르면 초점이 복사할 문구로 가고, 지금 문구가 선택돼요.
- URL 대체 안내
  - 초점은 안내로 가고, 다음 Tab은 본문 입력, 그다음은 파일 선택이에요.

  - 이전 결과는 “이전 결과를 닫았어요”로 바뀌어요.
- `ftp://` 주소를 넣으면 초점이 필드로 가고 `aria-invalid=true`가 돼요.
- 취소: 진행 중(0.9초)에 취소를 요청했어요.
