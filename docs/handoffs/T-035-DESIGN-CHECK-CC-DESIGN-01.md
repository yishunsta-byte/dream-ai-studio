## 2. 발견

### D-1 (중요 · 막다른 길) 복원 확정 실패 뒤 "다시 검사" 길이 없음

- 서버: 복원 확정(`finish`) 중 `BACKUP_SOURCE_CHANGED`·`BACKUP_UPGRADE_FAILED`·재판정 불일치가 나면 검사 티켓을 `failed`로 만들고 staging을 지운다(`restore.ts` `invalidStage`).
- 화면: 오류 때 티켓을 비우는 경우는 `RESTORE_EXPIRED` 하나뿐(`settings-panel.tsx` `act()`의 `setTicket(null)`). 그래서 위 오류 뒤에도 검사 결과 상자가 남고, 버튼이 **"같은 검사로 복원 다시 확인"**으로 바뀐다. "검사하기" 버튼은 티켓이 없을 때만 보인다.
- 결과: 문구는 "다시 검사해 주세요"인데 누를 수 있는 것은 이미 실패 처리된 같은 검사로 다시 확정하는 버튼뿐이다. 다시 눌러도 같은 티켓이라 다시 실패할 것으로 보인다(실행 확인 안 함). 티켓이 브라우저 저장소에서 다시 읽히면 새로고침해도 남을 수 있다.
- 제안: 티켓을 다시 쓸 수 없는 오류 코드(`BACKUP_SOURCE_CHANGED`, `BACKUP_UPGRADE_FAILED`, `BACKUP_SCHEMA_MISMATCH`, 실패 처리된 티켓 응답)에서는 `RESTORE_EXPIRED`처럼 티켓·저장값을 비우고 "검사하기"를 다시 보여 준다. "같은 검사로 복원 다시 확인"은 `RESTORE_FAILED`(저장 공간 등 일시 원인)처럼 같은 검사로 다시 해도 되는 경우만.
- 시험 제안: 검사 후 원본 ZIP 한 바이트 변경 → 복원 → 오류 문구 + "검사하기" 버튼 보임 + "같은 검사로…" 버튼 없음.

### d-2 (사소) 오류 코드 줄 없음

T-017 8번은 문장 + 작은 코드 줄(`BACKUP_UPGRADE_FAILED`)을 제안했다. 설정 화면 오류는 지금 문장만 보인다. 다른 설정 오류와 같은 방식이라 후속 권장(T-013 R-a 패턴과 함께).
