## 구현 전 필수 수정

1. **권한 부여와 링크 변경을 상태 전이로 명문화.** 허용 용도 목록과 그 변경 권한, 최초 등록 승인 주체, 카운터 증가 및 비활성 유지 조건을 정의합니다. 링크 INSERT만으로 REA가 활성화되지 않아야 합니다. 동일 소유자의 `UPDATE`로 프로젝트·자산·용도를 옮기면 기존과 새 범위를 모두 계산하거나 해당 UPDATE를 막고 지정된 이동으로 처리합니다. 여러 용도가 남아 있는 삭제, 허용 범위 안팎으로 용도 변경, 동일 트랜잭션 내 삭제·재삽입, 보관 해제·재승인, 동일 자산의 여러 프로젝트를 상태표에 넣어야 합니다. 소유자 기준 행이 없는 동시 최초 등록은 고유 키에서 생성·잠금 경쟁을 해결하고, 기준 행 생성과 첫 승인 및 신규 링크를 하나의 직렬화 경계에 둡니다. 이관 중 구 쓰기 중단, 기준 생성, 새 변경 경로 활성화의 순서와 미등록 기본값을 확정합니다.
2. **역할·진입점·잠금 모드 매트릭스 확정.** `dream_api`와 `dream_worker`가 기존 링크, 보관 필드, 타임라인 포인터 등을 직접 변경할 때의 허용 범위를 열과 명령까지 적습니다. 회수할 권한과 바꿀 서비스, 모든 롤이 통과하는 제약이나 함수, 소유자 조건을 명시합니다. 범용 트리거만 적용하면 기존 서비스가 자산을 먼저 잠근 뒤 트리거가 소유자 잠금을 요청할 수 있습니다. 대량 변경, SQL5의 정책→객체 잠금, SQL4 전이까지 포함해 잠금 순서를 통합하거나 분리 경계의 무순환성을 입증해야 합니다. 잠금 시점과 이후 재조회 방식, 충돌·타임아웃·직렬화 실패 처리, 검증 만료를 판정할 시점을 지정합니다. 기존 T279 스냅샷을 쓰기 판정으로 재사용하지 않습니다. 스토리지 잠금을 위해 일반 API의 스토리지 쓰기 권한을 확대하지 않고 지정된 제한 잠금 경로를 설계합니다.
3. **외부 철회와 종결 영수증 계약 결정.** 계정·허용 목록·개별 세션 철회를 각각 누가 기록하고 언제부터 막는지 정합니다. UUID만 확인하는 현 계약으로는 이미 진행 중인 요청을 세션 철회와 같은 순서로 직렬화할 수 없습니다. 쓰기를 허용할 환경에서는 외부 변경보다 먼저 DB 차단을 커밋하는 관리 경로, 이미 들어온 요청 처리, 재승인 시 새 세대를 정의합니다. 일방적 외부 철회가 가능한 환경은 명시적으로 닫습니다. 완료 영수증은 현재 T275에서 저장소·복원·소유자·프로젝트·자료와 `receiptAccess`만 대조합니다. 재연결·재승인 뒤 이전 영수증을 다시 조회할 수 있는지 결정해야 합니다. 이전 권한 시기의 영수증도 계속 차단하려면 종결 행에 비공개 권한 세대 또는 동등한 무효화 기록이 필요합니다. 보호할 읽기는 영수증 조회와 완료 확인 재전송 모두입니다. 스토리지 객체 ID·검증 세대의 검증 위치도 확정해야 합니다. 현재 T275 실행 및 대기 확인은 엄격 스키마이며 이 필드를 직접 받지 않습니다. [T275 상태 계약](../../lib/reference-analysis/apply-lifecycle.ts#L18) · [종결 판정](../../lib/reference-analysis/apply-lifecycle.ts#L75)
4. **복원 게시를 실패 폐쇄 상태 기계로 확정.** 외부 게시자는 비재사용 세대와 실제 DB·스토리지 대상의 검증 가능한 식별자를 발급합니다. 외부 게시와 복원 DB 기록 사이에 단일 DB 트랜잭션은 없으므로 `차단 → 준비 → 승인` 전이를 정하고, 두 값 불일치·게시 이전 장애·서명은 유효하지만 오래된 게시에서는 계속 닫습니다. 승인 게시를 이전 값 기대 조건으로 갱신해 동시 게시의 승자를 하나로 제한합니다. 기존 연결과 예약 작업을 차단하는 집행 주체, 확인할 완료 조건 및 읽기·쓰기별 검증 시점을 명시합니다. 읽기에서도 같은 대상·세대 확인을 적용해야 오래된 풀에서 옛 영수증이 다시 나오지 않습니다. 장애 복귀나 원래 DB로 복귀하는 경우에도 새 세대로 진행하며, 구 런타임이 입장 차단을 우회할 수 있거나 무통지 PITR을 탐지할 근거가 없다면 권한을 계속 닫습니다.

## 격리 검증에 넘길 A/B 시험

| 시험 | 합격 근거 |
| --- | --- |
| SQL1–5, 후보 이관, 제한 역할 | 고정 소스·이관 이력과 카탈로그에서 실제 RLS/ACL, 함수 기본 공개 실행과 멤버십을 확인합니다. A/B 교차 읽기·쓰기와 PUBLIC·브라우저·worker·예약 역할의 직접 명령, 역할 변경·액터 재사용을 대조합니다. 허용된 콜백만 통과하며 풀 재사용에서 이전 액터가 남지 않습니다. |
| 링크 변경과 최초 등록 | 미등록 링크와 동시 최초 승인, `UPDATE` 이동·용도 변경, 다중 링크의 부분 삭제, SQL 한 트랜잭션 내 삭제/재삽입, 보관과 해제, 여러 프로젝트에 연결된 자료를 시험합니다. 실패·롤백 후 기존 권한/확인 및 B 상태가 보존됩니다. 정상 전이 후 새 세대에만 적용 권한이 생깁니다. |
| 쓰기와 철회 경합 | 실제 두 연결로 적용 우선과 DB 차단 우선을 각각 연출합니다. 철회 우선은 쓰기·영수증 0건, 적용 우선은 리비전과 영수증 한 건입니다. 링크·계정·스토리지 철회와 확인 수명 경계, 분석 완료 경쟁, 중간 실패, 응답 유실을 확인합니다. 늦은 분석은 읽은 세대나 타임라인 기준이 바뀐 사례에서 거절돼야 합니다. 잠금 오류와 확인 충돌을 구분합니다. |
| 재승인 및 복원 게시 장애 | 선택한 종결 영수증 정책을 `read_receipt`와 `confirm` 재전송에 동일하게 검증합니다. 복제본·동일 DSN PITR, 잘못된 스토리지 대상, 구 서명과 구 풀, 동시 게시, 준비와 승인 사이의 장애를 각각 시험합니다. 중간 상태는 모두 닫히고 새 세대 대상에서만 새 분석·확인·적용이 재개됩니다. |

이번 검토는 고정 저장소의 설계, SQL, 호출부를 읽어 대조했습니다. PostgreSQL이나 애플리케이션을 실행하지 않았고 제품 파일·SQL·환경을 변경하지 않았습니다. 위 표는 후속 시험의 합격 기준입니다.

**Master 전달문** — T280-R 설계 보완 후 구현. 권한 전이와 초기 승인, 기존 역할·쓰기 경로의 잠금 강제, 계정/세션 철회 및 영수증 재조회 정책, 외부 복원 게시의 실패 폐쇄 상태 기계를 먼저 확정해야 합니다. 새 PG17 A/B 시험의 합격 기준은 보고서에 정리했습니다.
