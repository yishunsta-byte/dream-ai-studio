# WAV 타임라인 저장 DB 독립 검수

MASTER 배정 `msg_f3e826e14588`에 따라 커밋 `562af29`의 별도 Git 사본에서 실제 Next.js HTTP·임시 PostgreSQL 17.12 시험을 실행했다. 종료 코드 0. 시험용 PostgreSQL 프로세스와 리스너, 임시 클러스터가 정리됐다.

| 시나리오 | 응답 및 DB 관찰 |
|---|---|
| 신규 프로젝트 | 제작 승인과 기준 타임라인이 모두 필요하다는 이유를 반환했다. 프로젝트의 현재 타임라인 포인터와 내용 리비전이 유지됐다. |
| 감사 기록 쓰기 실패 | HTTP 503. 프로젝트 포인터와 내용 리비전이 기준값을 유지했고, 타임라인 이력 2건·저장 감사 기록 0건에서 증가하지 않았다. |
| 동일 키 동시 저장과 재시도 | 두 HTTP 200 응답이 동일했다. 이력 3건·감사 기록 1건. 100ms WAV가 3프레임으로 저장됐고 기존 영상·기준 타임라인 JSON이 보존됐다. 편집은 진행 중, 검수·출력은 잠김으로 바뀌었다. |
| 같은 기준 리비전에 두 요청 경쟁 | 서로 다른 키를 사용한 저장 두 건 중 하나는 200, 다른 하나는 409였다. 최종 이력 4건·감사 기록 2건. |
| 음원 보관 후 | 새 요청은 404, 이전 성공 요청의 동일 키 재시도는 기존 결과를 반환했다. 프로젝트 상태와 이력·감사 건수가 유지됐다. |

성공 전제인 제작 승인·기준 타임라인은 시험용 데이터다. 미인증 요청 401, 타인 프로젝트 404, 길이 없는 기준 타임라인과 검토가 필요한 장면의 거절도 기존 시험에서 확인했다. 운영 검증은 별도다.

```powershell
$env:T371_VERIFY_HTTP='1'
node --conditions=react-server --import tsx tests/postgres/t368-run-private-image-project-create.mjs
```

## 제한 역할과 직접 쓰기 증분 검토

MASTER 후속 배정 `msg_aec2c346674f`. 고정 `562af29`의 SQL·호출 코드·기반 RLS를 정적으로 비교했다. 기존 동작 시험 결과는 위 기록을 따른다.

| 경계 | 판정 |
|---|---|
| 접속과 소유권 | 설치는 로컬 PG17 시험 DB와 시험 표식을 확인한다. 로그인은 고정 루프백 DB에서 제한 역할 하나에 연결되고, 서버가 인증 응답에서 얻은 사용자 UUID를 트랜잭션에 설정한다. 대상 테이블과 WAV 등록 표는 FORCE RLS를 사용하며 이 역할의 정책은 행 소유자를 대조한다. 앱 DB 자격은 신뢰된 서버에 한정해야 한다. DB의 행 소유자 대조는 서버가 설정한 값에 의존한다. |
| 잠금용 권한 | 자산·장면·프로젝트 첨부의 일부 열에 UPDATE 권한이 있다. `FOR SHARE`에 필요한 권한이며 해당 UPDATE 정책의 `WITH CHECK (false)`가 실제 수정 결과를 거절한다. 이 세 테이블에 INSERT·DELETE는 부여하지 않는다. |
| 실제 쓰기 | 프로젝트는 현재 리비전 포인터·내용 버전·갱신 시각을 바꿀 수 있다. 단계는 편집 진행 중 또는 검수·출력 잠김 정책을 만족하는 승인 상태 열을 바꿀 수 있다. 타임라인 이력·감사 로그는 테이블 단위 INSERT이며, RLS가 소유자와 `source='user'` 또는 `action='timeline.audio.add'`를 확인한다. 이 역할에 기존 이력의 UPDATE·DELETE는 부여하지 않았고 기반 트리거도 이력 변경을 거절한다. |
| 직접 SQL의 보장 범위 | 제작 승인, 첨부 WAV 유효성, 기대 리비전과 요청 키, 포인터·단계·감사의 동시 변경을 API 트랜잭션이 강제한다. 개별 테이블에 부여된 쓰기 권한과 RLS만으로 이 저장 절차 전체를 강제할 수는 없다. 예를 들어 단계 정책은 자기 소유와 결과 상태를 확인하며 상위 프로젝트의 보관 여부나 기준 리비전은 검사하지 않는다. 기반 제약은 소유자·동일 프로젝트 포인터·원문 해시와 내용 버전 감소 금지를 검사한다. |

로컬 신뢰 서버 후보의 정적 판정은 통과다. DB 역할 자체를 독립적인 저장 경계로 사용하려면 이력·감사 INSERT 열을 명시하고 대상 프로젝트와 상태 전이를 DB에서도 검사하며, 직접 테이블 쓰기를 단일 저장 경로로 제한할 필요가 있다. 근거는 [저장 권한 SQL](../../lib/db/postgres/private-wav-upload/timeline-save.sql), [서버 DB 접속](../../lib/cloud/local-wav-access.ts), [저장 트랜잭션](../../lib/cloud/local-timeline-audio.ts), [기반 무결성 제약](../../lib/db/postgres/0002_invariants.sql), [기반 RLS](../../lib/db/postgres/0003_rls.sql)이다.
