# T315-F2-R 설치 쓰기 오류 정리 독립 검수

**판정은 F315-F1-R1 해소.** 수정본에서 파일 데이터 쓰기 전에 배타 생성한 파일을 추적하며, 쓰기 도중 실패해도 그 파일을 되돌릴 수 있다. 제공된 Windows 회귀 18건을 고정 사본으로 두 번 실행해 모두 통과했다.

- 설치기는 `openSync("wx")`로 파일을 생성하고 `fstat`의 `dev·ino`를 얻어 데이터 쓰기 전에 정리 목록에 등록한다. 정리 시 열린 핸들을 닫고, 현재 경로의 일반 파일 식별자가 일치할 때 삭제한다. 파일 내용이 일부만 쓰인 경우에도 정리할 수 있다. 오류 객체를 유지하고 메시지에 정리 결과를 덧붙인다. [설치기](../../tests/reference-analysis/t315-next-response-egress/install-fixture.mjs)
- 기존 디렉터리 아래 세 번째 파일에서 쓰기 실패를 주입했을 때 부분 파일과 앞서 만든 파일들이 제거됐고 기존 `own.txt`는 유지됐다. 첫 파일에서 실패를 주입했을 때는 부분 파일과 새 디렉터리가 정리됐다. 실패 전 해당 파일을 교체한 경우 교체 파일만 남았고, 원래 쓰기 오류 메시지와 `replaced, preserved`가 함께 보고됐다. 앞선 정션·해시·전체 충돌 회귀도 통과했다. [제공 회귀](../../tests/reference-analysis/t315-next-response-egress/install-fixture.check.mjs)
- 제품 기준 `131fde6`을 임시 추출한 사본에 정상 설치했다. 설치 결과 5개와 LF 기준 매니페스트 8개의 SHA-256을 대조했고, 변경 스크립트 ESLint 및 고정 변경의 `git diff --check`가 통과했다.

실패는 제공된 부분 쓰기·교체 주입을 사용했다. 실제 장치 오류, `fstat` 자체 오류, 경로 식별 검사와 삭제 사이에 외부 프로세스가 개입하는 상황은 검증 범위 밖이다. 두 회귀의 합성 경로와 별도 설치 사본을 정리했다. 이전 결함을 재현하거나 새 시험 도구를 작성하지 않았다. Next 빌드·운영·배포는 수행하지 않았다.
