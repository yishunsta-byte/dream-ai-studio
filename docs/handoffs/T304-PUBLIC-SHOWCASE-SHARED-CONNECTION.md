# T304 공개 홈과 세대 표지의 공통 공급원

2026-11-19 KST · Codex(design) · 기준 `66d1870` · 배정 `msg_e920dc70744f`

공개 홈 GET과 `/media/public/<slug>/<generation>/cover.webp`의 GET·HEAD가 이제 같은 서버 전용 구성을 사용합니다. 시작 시 검증된 목록·표지 공급원과 표지의 최종 권한 확인 함수가 모두 준비돼야 연결을 사용합니다. 어느 한쪽이 빠졌거나 공급원을 여는 중 오류가 나면 홈은 기존 예시 모드, 표지는 비활성 404입니다. 배포 코드에는 검증 공급원이 주입돼 있지 않습니다. 요청의 쿼리·헤더·쿠키나 환경 플래그를 구성에 쓰지 않습니다.

완비된 연결에서는 홈이 요청마다 새 목록을 조회하고 표지 GET·HEAD는 기존 바이트 검증과 최종 권한 확인을 통과해야 합니다. 공급원이 연결된 뒤 목록 조회에서 오류가 나면 홈의 기존 장애 안내가 표시되고, 표지 조회·최종 확인 오류는 503으로 닫힙니다. 철회·만료·세대 불일치는 새 목록에서 제외되며 해당 표지 경로는 404입니다. 목록과 파일 읽기 역할을 검증할 책임은 공급원 초기화 단계에 있습니다. 운영 권한과 공급원 수명은 후속 운영 통합에서 확인해야 합니다.

## 자체 검증

- 집중 시험 4개에서 테스트 주입 없는 실제 제품 기본값, 불완전 연결·초기화 오류의 양쪽 닫힘, 정상 승인 목록 및 실제 WebP, 철회·만료·이전 세대, 목록과 최종 표지 확인 오류를 확인했습니다. 기존 T241·T255 시험은 허용된 서버 import와 모의 주입 지점만 조정했으며 공개 동작 단언을 유지했습니다.
- 격리 Next.js의 실제 HTTP에서 기본 구성, 최종 확인 함수가 없는 구성, 초기화 오류 구성이 모두 예시 홈과 표지 404로 닫혔습니다. 승인으로 위장한 쿼리, 헤더, 쿠키를 보내도 권한 공급자 호출은 0건이었습니다. 정상 격리 구성은 승인 홈, 표지 GET 200의 WebP 바이트, HEAD 200의 빈 본문, 이전 세대와 쿼리 포함 주소의 404를 확인했습니다. 철회와 만료 뒤 새 홈 응답은 승인 작품을 제외했고 표지 GET·HEAD는 404였습니다. 홈과 표지 응답은 `no-store`였습니다.
- 헤드리스 Chromium에서 CSP `script-src 'none'; style-src 'none'` 조건의 승인 영역 숨김과 로그인 대체 안내를 확인했습니다. 일반 문서의 관리자 로그인 링크를 연 뒤 권한을 철회하고 브라우저 뒤로 가기를 실행하자 홈이 공급원을 다시 호출했고 철회된 작품은 보이지 않았습니다. 해당 보안정책은 시험용 Next 사본에서만 헤더로 주입했습니다.
- `66d1870`에 T304 변경만 적용한 고정 사본에서 공용 인증·홈·공개 작품·네이티브 및 헤드리스 분석 35개 파일 500개, Next 타입 생성과 전체 `tsc --noEmit --incremental false`, 변경 경로 ESLint가 통과했습니다.

Next.js 16.4.6의 로컬 Node HTTP 응답 어댑터는 `Content-Length`를 전달하지 않습니다. 응답 객체 자체의 길이 계약은 집중 시험에서 검증했고, 실제 HTTP에서는 GET 바이트와 HEAD의 빈 본문을 검증했습니다. 승인 영역을 드러내는 기존 인라인 가드는 Next 개발 모드의 React hydration 경고를 남겼습니다. 기준 홈에 같은 격리 공급원을 연결한 비교에서도 경고가 재현됐으며 CSP 및 뒤로 가기 검증은 양쪽에서 통과했습니다. 격리 Next는 합성 공급원만 사용했습니다. 기존 공개 원본 처리·프록시·DB·운영 배포는 수정 범위 밖입니다.

**Master 전달문** — 홈과 표지를 공통 초기화 지점에 연결했습니다. 기본 및 부분 구성은 양쪽이 닫히고, 완전 구성은 실제 Next HTTP와 브라우저에서 승인·철회·만료·CSP·뒤로 가기를 통과했습니다. 운영 공급자는 미연결입니다.
