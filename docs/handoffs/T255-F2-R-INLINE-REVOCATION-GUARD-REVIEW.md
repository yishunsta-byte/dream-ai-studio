## CSP 조합과 활성화 판단

기본 로컬 홈 HTML·RSC에는 CSP 응답 헤더가 없었다. 프록시로 HTML에만 CSP를 주입해 실제 브라우저의 차단 이벤트를 기록했다. 테스트용 해시는 브라우저로 전송된 인라인 본문과 일치시켰다.

| 다른 인라인 스크립트와 번들을 허용하고 가드 스크립트만 차단 | 수화는 이뤄졌다. 승인 영역은 숨김, 접근성 트리의 승인 제목은 0. 대체 안내와 로그인 링크 3개가 유지됐다. 초기 승인 상태였던 대표 이미지는 화면에 표시되지 않아도 eager 요청으로 200을 받았다. 철회 후 이력 복원에서는 새 목록 조회 1회, 철회 제목과 커버 URL이 해당 새 문서에서 사라졌다. |

## 철회 후 새 응답과 브라우저에 남아 있던 자료

- **철회 후 새 응답.** 승인·철회 전후 HTML 및 최종 RSC 모두 200과 `private, no-cache, no-store, max-age=0, must-revalidate`를 유지했다. 철회된 제목과 커버 주소는 새 HTML·RSC에서 사라졌다. 동일 커버 URL GET·HEAD는 승인 중 200 `image/webp`, 철회 후 404 `no-store`였다. 승인 이미지의 바이트 해시는 합성 원본과 일치했다. 조건부 요청도 철회 후 404, Next 이미지 최적화 경유는 400이었다.
- **이미 받은 자료.** 스크립트가 꺼진 문서와 CSP 시험의 이전 문서에서 보인 이미지 자원 기록은 승인 때 받은 200이다. bfcache 복원 이후 이미지 값과 디코딩된 크기가 남을 수 있었다. 복원 당시 원본 커버 조회 로그에는 새 요청이 없었다. 두 사례는 철회 이후 서버가 응답을 새로 전달하는지와 별개다.
- **보호 경로.** `/studio`, `/admin`, `/cloud/projects`는 각각 기존 로그인 경로로 307, `/api/projects`는 401이었다. 두 로그인 화면과 고정 예시 이미지는 200이었다.
