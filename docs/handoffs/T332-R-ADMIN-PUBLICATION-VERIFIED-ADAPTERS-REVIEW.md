# T332-R 검증 세션 게시 어댑터 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `b93015d` · Master 배정 `msg_2fedb00fe226`

**판정은 통과.** 제공된 PG17/TLS 실행기에서 검증된 연결 그룹을 통한 관리자 쓰기, 공개 목록과 표지 읽기 및 실패 시 차단을 확인했다.

- 관리자 큐는 운영자 본인의 작품만 반환했다. 다른 운영자와 다른 소유자의 작품에 대한 게시 요청은 거절됐다. 동일 완료 UUID를 동시에 보냈을 때 결과가 일치했고 앱 요청 원장, 감사, DB 게시 요청에 각각 한 건만 남았다.
- 완료 전 표지 GET·HEAD는 404였다. 게시 후 홈 목록과 표지 GET·HEAD가 활성화됐다. 표지를 읽는 동안 철회하면 응답 직전 확인에서 404가 반환됐다. 철회 뒤 완료 요청을 재전송해도 공개 상태가 되살아나지 않았다. 새 세대 게시 후 이전 세대는 404였고 권리 만료 시 목록과 표지가 모두 내려갔다.
- 준비 시 애플리케이션과 DB의 권리 만료가 1ms 다르면 쓰기가 실패했다. 작품 리비전은 0이었고 앱 manifest, DB 고정 manifest, 두 요청 원장과 감사에 그 트랜잭션의 레코드가 남지 않았다.
- 운영자 매핑 불일치, 권리 조회 함수 누락 및 공개 목록 역할에 부여된 권리 조회 함수 실행 권한은 초기 조립을 비활성화했다. 실행 중 표지 역할을 철회하면 표지는 503, 관리자 큐는 실패, 홈 공급원은 사용 불가 상태였다. 어댑터의 두 열기 함수가 연결 초기화 Promise를 공유하는 것을 소스에서 확인했다.
- 제공 실행기에서 T328 TLS 사례 22건과 T330 세션 회귀도 통과했다. 종료 후 검사 세션 0건, 소유 PG 프로세스 0건을 확인했다. 실행기가 수신기와 임시 클러스터를 제거했고 검수용 고정 소스 사본도 정리했다.
- 관리자·공개·홈·인증·레거시 게이트 회귀는 22개 파일 560건이 통과했다. `tsc --noEmit --incremental false`, 변경 TypeScript 3개 대상 ESLint와 고정 커밋 diff 공백 검사를 통과했다.

시험은 고정 소스와 소유 루프백 PG17/TLS, 메모리 표지 데이터에 한정했다. 제품 기본 구성은 명시 승인 연결을 반환하지 않는다. 운영 DB, 권리 조회 함수, 운영자 자격 공급과 비공개 Storage 연결은 이번 판정 범위 밖이다.
