# T250 공개 쇼케이스 재생 상태

Codex design · CX-DESIGN-01. 배정 `msg_b966e4bd9d36`, 수락 `msg_8a204e58b657`. 상태는 ready_review입니다.

공개 작품의 영상과 음악은 기존 브라우저 컨트롤로 재생합니다. 사용자가 재생을 시작한 뒤 데이터가 기다려지면 로딩을 안내합니다. 브라우저가 미디어 오류를 보고하면 오류 안내와 재시도를 제공합니다. 재시도는 동일한 파일을 다시 불러오고, 포커스를 재생 컨트롤로 돌립니다. 사용자가 재생을 다시 선택할 때까지 정지 상태입니다. 안내는 polite 라이브 영역으로 전달합니다.

상세 닫기와 Escape에서 재생을 멈춥니다. 작품 ID, 미디어 종류 또는 URL이 변하면 플레이어를 교체하고 이전 플레이어를 일시 정지합니다. 작품이 사라져 상세가 닫힐 때는 작품 영역으로 포커스를 돌립니다. 미디어가 있으면 브라우저가 네이티브 컨트롤의 Tab 순서를 관리합니다. 샘플 안내는 예시로 표시된 작품에만 적용하도록 문구를 정리했습니다.

- 변경 경로는 공개 쇼케이스 TSX, 전용 CSS, 기존 테스트 및 본 보고서입니다.
- `node node_modules/vitest/vitest.mjs run tests/public-showcase` 통과. 2파일 34건이며, 신규 시험은 샘플과 재생 가능 작품 혼합 시 안내 문구를 확인합니다.
- 변경 TSX와 시험의 ESLint 및 격리 범위 TypeScript 검사 통과. 임시 tsconfig는 대상 파일과 import 의존성만 검사합니다.
- Ego Browser Chromium, 390px 및 1280px 자체 검증. 변경된 React 컴포넌트·CSS를 임시 esbuild 서버에 올리고 Next Image/Link만 일반 태그로 대체했습니다. 기존 합성 MP4 fixture와 임시 무음 WAV의 첫 응답은 503, 다음 응답은 200으로 구성했습니다. 로딩→오류→실제 재요청/로드→일시 정지 유지, 다시 재생 시 시간이 전진함을 각 미디어와 화면 폭에서 확인했습니다.
- Enter로 상세 열기, Tab으로 네이티브 컨트롤 접근, 재시도 후 포커스, Escape/닫기 후 정확한 트리거 복귀를 확인했습니다. 재생 중 같은 ID의 URL 교체에서 이전 플레이어 정지와 새 플레이어의 초기 상태를 확인했습니다. 오류 상태에서 닫고 같은 작품을 열었을 때 상태 초기화, 재생 중 목록에서 작품 제거 시 정지 및 작품 영역 포커스도 확인했습니다.
- 양쪽 폭에서 화면 및 대화상자의 가로 넘침은 0이었습니다. 영상 재시도 버튼은 약 189×48px입니다. 영상/음원 오류 화면 4장은 로컬 `tmp/t250/{video,audio}-error-{390,1280}.png`에 있으며, 영상 모바일·음원 PC를 직접 확인했습니다. 재현 코드는 같은 폴더의 `serve.mjs`, `qa.mjs`, `followup.mjs`입니다. 테스트 서버와 브라우저 공간은 종료했습니다.
