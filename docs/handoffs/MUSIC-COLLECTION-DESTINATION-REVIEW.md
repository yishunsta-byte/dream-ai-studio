# 뮤직 컬렉션 링크와 키보드 초점

Tester가 커밋 `2a90393`의 별도 로컬 Next 개발 서버에서 Ego Chromium으로 확인했다. 1280·390·320px 각각에서 새 문서를 열고 주 메뉴 링크와 본문 링크를 한 번씩 시험했다. 두 링크 모두 동일한 섹션 ID를 가리켰다.

6회 모두 출발 링크에 초점이 있는 상태에서 Enter를 누르면 ‘뮤직 컬렉션’ 제목이 있는 섹션에 초점이 도착했다. Tab으로 첫 음악 카드 LIQUID BLOOM에 이동해 Enter로 상세를 열고 Escape로 닫으면 같은 카드에 초점이 복귀했다. 세 폭 모두 카드 3개였고 문서 가로 넘침(scrollWidth − clientWidth)은 0이었다.

같은 문서에서 상세를 닫은 직후 자동화가 본문 링크로 초점을 옮겨 곧바로 Enter를 누르는 연속 시험에서는 390px 한 번, 320px 한 번 섹션 초점을 확인하지 못했다. 이 시험은 두 번째 Enter 직전 실제 출발 초점을 기록하지 않아 원인을 확정하지 못했다. 위 6회는 각 경로의 출발 링크 초점까지 기록한 결과다. 운영 사이트와 모바일 실기기는 검수 범위 밖이다.

## 같은 문서의 연속 키보드 입력 재검수

390px와 320px 각각 한 문서에서 키보드로 주 메뉴에 진입한 뒤 다음 순서를 세 번 반복했다. Tab으로 LIQUID BLOOM 카드에 이동해 Enter로 열고 Escape로 닫았다. 카드에 초점이 돌아온 것을 확인한 뒤 Shift+Tab으로 본문 ‘뮤직 컬렉션 ↗’ 링크까지 이동했다. 포커스를 코드로 지정하지 않았다.

두 폭 모두 3/3회 Enter 직전 활성 요소가 본문 링크였고, Enter 직후 활성 요소의 ID는 링크가 가리킨 섹션 ID와 일치했다. 섹션 제목은 ‘뮤직 컬렉션’이었고 문서 탐색 시작 시각도 각 반복에서 같았다. **판정은 정상이다.** 앞선 미확정 두 사례는 실제 키보드 이동 조건에서 재현되지 않았다. 앞선 자동화에서 결과가 달랐던 원인은 확인되지 않았다.
