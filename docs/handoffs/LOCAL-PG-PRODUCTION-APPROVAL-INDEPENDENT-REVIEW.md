# 로컬 PG 제작 승인 독립 검수

MASTER 배정 `msg_592414cd0b5c`. 고정 `664f09c`의 격리 Git 사본에서 실제 Next.js HTTP·Chromium·임시 PostgreSQL 17로 검수했다. 브라우저용 별도 프로젝트는 제품 API로 생성하고 브리프·기획 승인과 두 PNG 결과 등록까지 진행했다.

| 항목 | 관측 결과 |
|---|---|
| 결과 누락 | 두 장면의 결과를 선택하기 전 직접 승인 요청은 409 `SCENE_RESULTS_REQUIRED`였다. 승인 기록 0건, 제작 `todo`, 편집 `locked`, 타임라인 0건을 유지했다. 재확인 상태나 보관된 자료가 있어도 승인 요청은 409였다. |
| 화면 명시 승인 | 첫 장면만 선택했을 때 확인란과 승인 버튼이 비활성이었다. 두 번째 선택 뒤에도 확인란에 Space를 누르기 전까지 승인 버튼은 비활성이었다. Enter로 승인하면 편집 음원 화면에 도착했고 `첫 타임라인 저장` 버튼이 활성화됐다. |
| 재진입과 DB | 제작 화면에 다시 들어가면 두 결과의 `사용 중`, 승인 메시지와 편집 링크를 확인할 수 있었다. DB의 선택 ID가 두 결과와 일치했고, 승인 리비전은 두 선택으로 증가한 최신 리비전이었다. 제작 `approved`, 편집 `todo`, 승인 기록 1건, 타임라인 0건이었다. |
| 동시 승인 | 같은 기준의 두 요청은 200과 409였다. 승인 활동은 1건이었고, 편집 개방 상태를 다시 조회할 수 있었다. |
| 감사 실패 | 활동 기록 INSERT를 실패시키자 503이 반환됐다. 제작 승인·승인 포인터·편집 개방·감사 기록이 모두 이전 상태로 돌아왔다. |

기존 [HTTP 시험](../../tests/postgres/local-project-brief-http.mjs)에 격리 사본 전용 브라우저 독립 단언을 연결했다. 전체 실행 종료 코드 0. 브라우저 공간과 PostgreSQL 프로세스·리스너·임시 클러스터를 정리했다.
