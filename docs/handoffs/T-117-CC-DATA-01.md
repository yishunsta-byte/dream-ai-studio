## 2. 화면 구성 (T-102 4장)

1. 머리: "영상 만들기" + `저장됨 · 타임라인 r{n} · {비율}` + 내용 버전.
2. **새 영상 만들기**: 막는 이유 **전부**(같은 종류의 장면은 묶어 "장면 3, 장면 4"), 각 줄에 갈 곳 링크(편집/장면 제작)와 작은 코드. 이유가 있으면 버튼은 막히고 "위 이유를 고치면 만들 수 있어요." 처리기가 꺼져 있으면 "지금 요청해 두면 켜질 때 시작해요."(누를 수 있음).
3. **진행 카드**(대기·진행 중일 때만, 프로젝트당 1개): 제목 `h2 tabIndex=-1`, 상태 Pill, 본문, 3단계 `ol`(✓●○는 `aria-hidden`, "끝남/지금/남음"은 sr-only), 합치기는 `<progress>`(프레임 기준, `aria-valuetext="64% · 1분 40초 지남"`), **파일 확인 중은 막대·퍼센트 없이 "확인 중"**, 지난 시간·이전 기록이 있을 때만 남은 시간·시도 n/3, 취소(ConfirmPanel).
4. **만든 영상**: 최신이 위. 행마다 비율 칸, 파일 이름(서버 `fileName` = 받기 이름), 칩, 사양, "확인 안 한 것: 자막 표시 오차 측정 전 · 휴대폰 재생 확인 전"(`subtitleMeasure`·`phonePlayback`이 null이면 늘 이 문구), 시각·걸린 시간, 버튼.
5. **완성 영상 내보내기**: 잠김 + "소리를 붙이는 단계(P2-5)와 자막 파일(P2-6)이 끝나면 열려요. 편집용 묶음 내보내기는 지금처럼 쓸 수 있어요."

### 읽어 주기·초점 (T-102 5.1·5.2)
- live 영역은 진행 카드 안 **한 곳**, 단계가 바뀔 때만 글을 바꿔요("2단계 장면과 글자 합치기를 시작했어요."). 퍼센트는 읽지 않아요(막대의 valuetext).
- 끝·실패·취소는 Toast 한 번, live 글은 비워요.
- 요청하면 진행 카드 제목에 초점. 끝날 때는 초점이 카드 안에 있었을 때만 새 결과 행 제목으로, 아니면 그대로.
- 폴링 2초는 대기·진행 중일 때만.

### 편집 진입 버튼
- 편집 머리의 "새 글자 설정 저장" 옆. 저장하지 않은 변경이 있으면 막힌 버튼 + "편집에서 저장하지 않은 변경이 있어요. 영상은 저장한 타임라인으로만 만들어요." 없으면 `/projects/[id]/render` 링크(44px).

## 5. 남은 것·판단 필요
- **취소 확인 패널 버튼 이름**: 공용 `ConfirmPanel`의 닫기 버튼 글자가 "취소"로 고정이라 "취소 / 취소하기"가 나란히 보여요(T-102는 "계속 만들기"). 공용 부품은 이번 범위 밖이라 바꾸지 않았어요. 디자인 적용 때 닫기 글자를 받을 수 있게 하는 게 좋겠어요.
- R-16(렌더 중 다른 작업 화면에 "영상 만드는 중이라 기다려요")은 작업 대기열·장면 화면 쪽이라 이번 범위(렌더 화면·진입 버튼) 밖이에요. API의 `blockedBy`는 이미 있어요.
- "글자만 바뀌었어요" 안내는 요청 전에는 서버가 알려 주지 않아 만들기 칸에는 띄우지 않고, 결과 행에 "글자만 바뀜" 배지로만 보여요(`textOnlyChange`가 true일 때만).
- 검수 stale 안내(3장 마지막 줄)는 API에 값이 없어 띄우지 않았어요.
- 실제 휴대폰 재생·화면 읽기 프로그램 확인은 하지 않았어요(측정 전/확인 전으로 표시).
- 고정 s6 입력 mp4는 그대로 두었고, 위 3장처럼 현재 기준 확인 실패로 기록했어요.
