# T306-F1-R 관리자·공개 권리 증빙 일치 독립 재검수

- 기준 커밋 `f1f0a28`, Master 인계 `msg_65ebce1187a2`.
- 판정은 F306-1 해소. 시험 저장소에서 정상 종단과 불일치 롤백을 확인했다.

소유 루프백 PostgreSQL 17.12에서 해시를 고정한 T253·T293·T295 SQL로 배포된 `--scenarios`를 재현했다. 종료 시각이 같은 ms인 시한부와 무기한 게시가 정상 동작했다. 종료 시각 1ms 및 500µs 차이, 무기한·시한부의 양방향 불일치, 표시·원본 다이제스트 차이 여섯 건은 만료 전에 모두 거절됐다. 같은 UUID로 다시 보내도 리비전·원장·감사·manifest·활성이 바뀌지 않았다. 시한이 끝나면 공개 목록과 표지에서 즉시 빠졌고, 준비만 한 작품은 게시가 거절됐다.

준비 후 SQL 권리 증명을 변경한 경우에 더해, 임시 시나리오에서 앱의 원본 manifest만 변경한 경우도 시험했다. 두 경우 모두 게시가 롤백됐고 원래 증빙을 복구한 뒤 같은 UUID로 정상 게시됐다. 두 번째 경우에는 표지와 공개 목록에서 롤백과 복구를 각각 확인했다. 계정 B는 A의 권리 행을 읽을 수 없었고 공개 목록·표지 로그인은 내부 권리 함수에서 각각 `42501`로 거절됐다.

390px 숨김 Chromium과 격리 Next dev/webpack에서 인증·저장소·공개 리더 세 경계에 합성 계정과 같은 DB를 주입했다. 관리자 화면의 준비 → 게시 → 공개 → 철회를 실행했다. 표지 GET/HEAD는 404 → 200 → 404 순서로 바뀌었고 `no-store`였으며, 게시 중 GET의 SHA와 HEAD 빈 본문도 확인했다. 권리 불일치 작품의 준비·재시도는 원장과 감사 등 DB 스냅숏을 그대로 유지했고 표지는 404였다. 시한부 일치 작품의 정상 게시와 B의 관리자 목록 분리도 통과했다.

새 시나리오 파일은 소유 PG17 실행기의 `--scenarios`에서만 불린다. 고정 소스에서 Next 타입 생성 후 전체 TypeScript, 변경 fixture ESLint, 관리자·공개·공용 인증 Vitest 16개 파일 328/328을 통과했다. 브라우저 재현에서는 임시 제어 API의 코드에 명시된 `evidence=perpetual`을 사용했다. 공개 홈의 기존 인라인 가드가 `hidden`을 조기에 바꾸면서 개발 모드에서 hydration 경고가 관측됐고, 검수한 표시·철회 흐름은 통과했다. 운영 DB, 배포 및 이번 재검수의 프로덕션 빌드 브라우저 동작은 검증 범위 밖이다.
