# T336-R 게시 DB·비공개 표지 통합 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `add9493` · Master 배정 `msg_68fc0f9ff574`

**판정은 통과.** 소유 루프백 PG17/TLS와 설치된 Supabase SDK를 사용한 통합 실행기에서 T336과 T328 TLS 22건, T330·T332 회귀가 통과했다.

- 최상위 승인 관리자 UUID를 정규화해 DB와 표지 리더에 함께 바인딩했다. Storage 안쪽의 별도 운영자·버킷 값과 설정 생성 뒤 자격 변경은 적용되지 않았다. 잘못된 Storage 프로젝트 URL, 승인 운영자 불일치, 목록·표지 DB 역할 교환은 조립을 비활성화했고 Storage 요청은 0건이었다. 정상 흐름에서 SDK는 고정 비공개 버킷 메타데이터와 정규 객체 키에만 인증된 GET을 보냈다.
- 다른 운영자의 준비 명령을 거절했다. 승인 운영자가 준비한 표지는 공개 목록에 나타나지 않았고 404였다. 공개 버킷 응답과 Storage 503에서는 완료 요청이 실패했고 작품 리비전은 준비 상태에 머물렀다. 그 완료 UUID의 앱 원장·감사·DB 게시 기록은 모두 0건이었다. 같은 요청을 정상 Storage에 다시 보내 게시했고 목록, WebP GET 바이트와 빈 HEAD 응답을 확인했다.
- 같은 길이의 변조 바이트는 503이었다. 정지된 스트림은 제한 시간에 닫혔고 다음 표지 요청은 성공했다. 다운로드 중 철회하면 응답 직전 권한 재확인에서 404가 반환됐고 목록에서 작품이 사라졌다. 표지 DB 역할을 철회하자 표지·관리자·목록이 실패 상태로 전환됐으며 Storage 요청은 추가되지 않았다.
- 검사 대상 관리자 JSON, 공개 목록, 표지 헤더 및 실패 본문에서 내부 키·버킷·프로젝트 URL·자격·제공자 오류를 확인했으며 해당 값은 노출되지 않았다. Storage 리스너가 닫혔고 검증 DB 세션과 소유 PG 프로세스는 각각 0건이었다. 실행기가 PG 수신기와 임시 클러스터를 제거했고 검수용 소스 사본과 복사 도구도 정리했다.
- 관리자·공개·Storage·인증·홈·레거시 게이트 회귀는 27개 파일 696건이 통과했다. PG 시험과 함께 실행한 첫 회귀에서 기존 ffprobe 영상 검증 한 건이 제한 시간에 걸렸다. PG 종료 후 동일 후보·복사 도구·단일 워커로 다시 실행한 결과 696건 전부 통과했다. 소스 타입 검사, 변경 TypeScript 3개 ESLint와 커밋 diff 공백 검사도 통과했다.

이 판정은 명시 서버 구성과 합성 자격을 사용한 루프백 통합에 한정한다. 기본 운영 런타임 구성은 `undefined`를 반환한다. 실제 DB·Storage·운영 자격은 검증 범위 밖이며 빌드와 배포는 수행하지 않았다.
