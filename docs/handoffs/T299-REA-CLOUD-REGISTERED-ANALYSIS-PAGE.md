# T299 클라우드 작업실 등록 자료 분석 화면

2026-11-19 KST · Codex(design) · 기준 `1801d83` · 배정 `msg_08275052f97d` · 서버 어댑터 승인 `msg_0209e9c4292b`

`/cloud/reference-analysis`는 기존 클라우드 레이아웃의 세션 경계를 사용합니다. 서버는 기존 클라우드 페이지와 같은 인증·로그인 이동을 적용합니다. 미인증이면 로그인 뒤 이 주소로 돌아오도록 하고, 계정 거부와 인증 장애는 기존 오류 화면으로 이동합니다. 로컬 모드에서는 기존 작업실 안내를 표시합니다. `/studio/reference-analysis`는 기존 합성 체험 경로입니다.

서버 전용 목록 어댑터는 검증된 액터를 얻은 뒤 같은 등록 권한 공급자가 분석 API에도 연결돼 있는 경우에만 목록을 요청합니다. 목록 공급자는 현재 소유, 활성 등록, 분석 가능 여부를 보증하는 증빙 행을 제공해야 합니다. 잘못된 행, 타계정 혼입, 중복, 읽기 실패는 전체 목록 실패로 처리합니다. 클라이언트에 전달하는 자료 행에는 표시 이름, `projectId`, `assetId`만 담습니다. 목록은 요청마다 현재 계정을 기준으로 다시 읽으며 최종 분석 권한은 POST에서 다시 확인해야 합니다.

클라이언트 래퍼는 목록이 연결된 경우에만 T291 화면에 T292 공급자를 넘깁니다. 공급자는 상대 주소 `/api/studio/reference-analysis`로 두 ID를 보내고 클라이언트 기한 5초를 적용합니다. 빈 목록, 공급자 미연결, 목록 조회 실패는 각각 실행을 막습니다. 조회 실패 화면에는 같은 페이지를 새로 요청하는 동작이 있습니다. 제품 페이지에서는 목록 어댑터를 주입하지 않아 미연결 안내가 표시됩니다.

## 자체 검증

- 집중 시험 6개에서 로그인 이동, 목록 조회 전 인증, API 미연결 시 목록 호출 차단, A/B별 최소 DTO, 잘못된 목록과 빈 목록, 실행 비활성화를 확인했습니다.
- 격리 Next.js 16.4.6 사본에서 미인증 GET의 로그인 이동과 목록 호출 0건을 확인했습니다. 연결을 끈 세션도 목록 호출 없이 미연결 화면을 표시했습니다. 목록 오류는 다시 불러오기 안내만 보여 줬으며 합성 오류 상세는 HTML에 포함되지 않았습니다.
- 격리 사본에서 A/B/A 순서로 GET을 요청해 각 응답에 자기 자료만 포함되고 `no-store`임을 확인했습니다. A가 B의 ID를 지정한 POST는 거절됐고, B 세션에서 보낸 같은 ID는 B의 합성 PNG 결과를 반환했습니다. 390px 헤드리스 Chromium에서 A가 자신의 자료를 선택하고 같은 출처의 POST로 실제 T284 PNG 결과를 받아 관찰 근거와 초안을 확인했습니다. 같은 화면에서 API 실패를 받아 접근 불가 안내와 결과 미표시도 확인했습니다.
- `1801d83`에 T299 변경만 적용한 고정 사본에서 공용 인증과 네이티브·헤드리스 분석 시험 24개 파일 380개 통과, Next 타입 생성과 전체 `tsc --noEmit --incremental false` 통과, 변경 경로 ESLint 경고 0을 확인했습니다.

격리 Next 검증의 합성 세션·목록·PNG 공급자는 임시 사본에만 주입했습니다. 실제 운영 연결은 T288 세션·갱신 조건과 관리형 등록 자료 권한을 검증한 뒤 같은 서버 권한 공급자로 목록과 T296 POST를 함께 구성해야 합니다. 실제 Supabase와 운영 배포는 이번 범위 밖입니다.
