# 로컬 PG 타임라인 WAV의 실제 MP4 출력 검증

Master 배정 msg_7fac0173ef7d. 기존 로컬 PG 타임라인 저장 API와 WAV 첨부 API를 사용해 저장한 소리 클립을 기존 믹서에 전달했다. 실행 범위는 격리 로컬 PG17과 FFmpeg 검증이다. 실제 작업 큐·렌더 UI 및 운영 저장소 연결은 별도 범위다.

## 입력과 검증 결과

- 로컬 전용 읽기 역할의 repeatable-read 트랜잭션에서 검증된 소유자, 현재 타임라인 ID와 내용 리비전, 제작 승인, 타임라인 원문 SHA-256 및 v2 계약을 확인한다. 활성 productionAudio 첨부의 WAV 바이트·등록 SHA·크기·길이·PCM 범위를 대조한다.
- 임시 폴더를 작업마다 따로 만들고 검증된 WAV를 배치한다. 기존 mixAudio가 사본의 해시를 다시 확인하고 AAC를 생성·합성한다. 콜백이 끝난 뒤 현재 리비전과 소유 첨부를 다시 읽고, 성공·실패 모두 폴더를 정리한다. 배경 영상은 합성 검수용 PNG에서 만든 2초 H.264로 고정했다. PNG 바이트의 해시·길이를 PG 등록값과 확인했다.
- 실제 HTTP에서 서로 다른 두 PCM WAV를 업로드·첨부·저장했다. 저장된 300Hz는 시작 0·길이 12프레임, 600Hz는 시작 12·길이 18프레임이었다. 최종 MP4는 H.264 60프레임·AAC 1트랙이었다. AAC를 48kHz 모노 PCM으로 디코딩해 96,000샘플과 1부터 센 13–30프레임의 600Hz, 앞 구간의 300Hz, 뒤 구간의 무음을 확인했다.
- 타 계정, 이전 타임라인 ID, 첨부 해제, 같은 크기의 WAV 바이트 변조를 거절했다. 렌더 입력을 준비한 후 첨부 음원을 보관 처리하는 경우에도 최종 재확인에서 거절됐고 임시 폴더가 사라졌다.
- 이번 실행의 MP4 SHA-256은 5702ad68de7242a5f4805ef176c9c1d63513603832ef621de03b5e4259566b0c다. 타임라인 원문은 2110b32937f215d2eafdd903c0da8b8720e11893bf96bad3cbbd1db111e6f648이다. 합성 입력 WAV의 SHA-256은 300Hz 75def6dfa1719d10566f3dcbd17e12f4dfcb0906aa5c680feae229f5119ab067, 600Hz f8470838181a67d5550630e7daf09b6cd2f424bbb730095742e11e51753d13f3이다. 임시 검증 산출물은 정리됐다.
