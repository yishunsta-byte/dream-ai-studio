# T307-F1-R 등록 분석 DB 로그인 최소 권한 독립 재검수

- 기준 커밋 `4fe75c7`, Master 인계 `msg_c4d28226a3aa`.
- 판정은 F307-1 해소, 새 결함 없음. 소유 루프백 PostgreSQL 17.12에 고정 SQL1~4와 T281, T307 증거 fixture를 적용했다.

실제 최초 로그인 역할과 전환 읽기 역할에 CREATEDB, CREATEROLE, BYPASSRLS, SUPERUSER, REPLICATION을 각각 설정하고, 읽기 역할에는 LOGIN도 별도로 설정했다. 11건 모두 시작 검증 이후 자료 조회 또는 계획 요청을 수행하지 않았으며, 각 실패 뒤 대상 백엔드는 0개였다. 각 변경을 원복하면 공급자 초기화와 목록 조회가 정상적으로 이어졌다.

독립 보강에서는 최초 로그인에 NOLOGIN을 설정하거나 읽기 역할로의 전환 권한을 제거했다. 두 경우에는 역할 조회 이전에 차단됐다. 최초 로그인 CREATEDB와 읽기 역할 REPLICATION을 동시에 설정한 경우는 역할 조회에서 차단됐다. 세 경우 모두 자료 SQL 실행과 남은 연결이 없었다. 부여한 속성은 실험마다 원복했다.

기본 조합에서 A/B 목록과 단건 권한이 분리됐고 권한·링크·복원 증거 변동, 만료, 취소, 잠금 기한, DTO 및 정리 회귀가 통과했다. 두 실행의 소유 리스너와 임시 클러스터를 제거했다.

고정 소스 임시 사본에서 Next 타입을 새로 생성한 뒤 전체 TypeScript 검사와 변경 파일 ESLint가 통과했다. 공유 작업공간의 기존 생성물은 그대로 두었다. 보조 Vitest는 빈 `tmp` 디렉터리와 로컬 FFmpeg를 사본에 갖춘 뒤 391건 통과, 조건부 64건 건너뜀으로 완료됐다. 운영 DB·자료·배포는 검사 범위 밖이다.
