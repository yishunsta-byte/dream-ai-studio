# P2 G4 · 탭 전환 시 미리보기와 원본 오디오 정지 검증

2026-11-19. 통합 개발 플랜 6절과 T171/T173의 G4 잔여 항목 중 데스크톱 Chrome 탭 전환을 검증했다. Chrome 157.0.8103.50의 새 headless 모드에서 새 프로필로 2회 실행했다. 시험 대상은 T173 고정 앱(44b036a), 가상 프로젝트의 4초 영상과 4초 합성 음원이다. 현재 작업본 1b72e2e와 비교해 PlayerPanel과 Audition 소스는 줄바꿈을 정규화하면 두 파일 모두 일치했다.

## 재현 절차와 판정

1. T173 가상 runtime을 임시 디렉터리에 복사하고 해당 경로를 DREAM_DATA_ROOT로 지정한다. T173 앱에서 `node node_modules/next/dist/bin/next dev --webpack -H 127.0.0.1 -p 3187`로 시작한다.
2. Chrome의 같은 창에 탭 두 개를 연다. 첫 탭에서 `/projects/019b8b74-3f10-7137-8265-68b11d809f0c/edit`를 열고 미리보기 재생을 시작한다. 버튼이 ‘멈춤’이고 프레임이 진행한 것을 확인한다. 두 번째 탭으로 전환해 hidden 상태에서 정지를 관찰하고, 첫 탭으로 돌아와 정지 위치를 다시 확인한다.
3. 원본 듣기에서 합성 목소리를 재생한 뒤 같은 순서로 전환한다. currentTime, paused, ended를 확인한다. 두 시험 모두 CDP의 Target.activateTarget으로 실제 활성 탭을 전환했다. visibilitychange의 isTrusted와 document.visibilityState를 이벤트에서 기록했다.
4. 숨김 약 350ms 후 첫 상태를 읽고 450ms 뒤 다시 읽었다. 복귀 400ms 뒤에도 일시정지 상태와 위치가 같은지 단언했다.

| 회차 | 미리보기 | 원본 오디오 | 이벤트 |
|---|---|---|---|
| 1 | 재생 중 9프레임 → 숨김·복귀 모두 9프레임, 버튼 ‘재생’ | 0.305408초 재생 중 → 0.309083초 정지, 복귀 후 동일 | 두 시험 각각 hidden → visible, 모두 trusted |
| 2 | 재생 중 9프레임 → 숨김·복귀 모두 9프레임, 버튼 ‘재생’ | 0.297731초 재생 중 → 0.301358초 정지, 복귀 후 동일 | 두 시험 각각 hidden → visible, 모두 trusted |

모든 오디오 정지 관측은 paused=true, ended=false였다. 두 실행이 각각 종료 코드 0으로 통과했다. Ego 탭 전환은 이번에도 visible을 유지해 비교 관측으로만 기록했다. 첫 Chrome 시도는 초기 렌더 중 재생 버튼이 교체되어 중단됐다. 이후 페이지 준비 뒤 재실행한 두 회차가 표의 근거다. 앱 초기 이미지 로드에서 EncodingError 로그가 있었고, 이번 검증은 프레임 진행과 정지 상태만 판정했다. 시험 서버를 종료했다.

로컬 원자료는 `tmp/p2-native-tabs/first.json`, `result.json` 및 실행 코드 `probe.mjs`에 있다. 실기기 잠금·모바일 브라우저 전환·청취는 별도 항목이다.
