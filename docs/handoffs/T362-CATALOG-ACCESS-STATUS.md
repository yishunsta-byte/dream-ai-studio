같은 실행에서 T358의 권한·계정별 조회·복귀 시험도 통과했고 임시 클러스터와 리스너가 정리됐다. 종료 코드 0. 운영 DB 카탈로그 결과는 여전히 미확인이다.

## 역할별 실효 조회 권한 검사

로컬 PG17.12에서 anon 역할로 실행한 자체 시험은 종료 코드 0이었다. 설치 전 공개 뷰는 미확인으로 표시됐다. 정상 설치 후 273건이 일치했다. 합성 DB에서 PUBLIC에 소유자 열 조회를 추가하고 authenticated의 승인 ID 열 조회를 회수하자 예상한 네 행에서 차이가 검출됐다. 원복 후 전 항목이 다시 일치했고 T358의 계정별 읽기·복귀 시험과 임시 자원 정리도 통과했다.

## 쓰기와 권한 재부여 검사

[쓰기·재부여 권한 점검 SQL](T362-WRITE-AND-GRANT-PRIVILEGES.sql)은 세 API 역할의 스키마 CREATE, 테이블·열 쓰기 등 금지 권한과 GRANT OPTION을 확인한다. 대상이 없으면 해당 검사는 `unverified`, 금지 권한이 있으면 역할·대상·권한별로 `mismatch`가 나온다. 전부 확인되고 금지 권한이 없을 때만 `match` 한 행을 반환한다. 역할 전환, 향후 생성 객체의 기본 권한, RLS 정의는 별도 범위다.

PG17.12의 로컬 anon 읽기 전용 세션에서 미설치·정상 설치·과다 권한·원복을 차례로 검증했다. PUBLIC에 프로젝트 제목 수정권을 부여한 경우 세 역할에서 검출됐다. 승인 ID 조회권의 재부여, 공개 스키마 객체 생성, 작업 행 삭제 권한도 각각 검출됐다. 차이는 총 6건이었고 원복 후 정상 판정 한 행으로 돌아왔다. 기존 T358 계정별 읽기·설치 복귀 및 자원 정리까지 종료 코드 0이었다. 이 시험에는 운영 DB 접속이 없었다.

## 역할 전환 검사
