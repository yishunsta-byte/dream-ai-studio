# 격리 PCM WAV 등록과 분석 승인 검증

2026-11-20 KST · Codes(Backend) · Master 배정 `msg_be3b39aec19d` · 시간축 구현 `4d0d53b`

**기존 비공개 PCM 등록과 명시적 분석 승인을 한 소유 PG17에서 대조했다.** 유효한 본인 등록 자료만 실제 음악 결과를 반환했고, 제작용 링크·권리 메모·타인·철회·등록 세대 변경은 분석 결과를 만들지 못했다. [음악 권한 범위](REA-CLOUD-MUSIC-AUTHORITY-SCOPE.md) · [PCM 시간축](REA-REGISTERED-PCM-WAV-START.md)

## 시험의 연결과 경계

- 서명 확인과 소유 루프백 검사를 거치는 고정 T367 실행기의 사본을 사용했다. 기존 WAV 설치와 `localPrivateWav` 등록 핸들러가 실제 PG17.12에 두 계정의 원본, 등록 해시와 권리 메모를 썼다. Auth만 요청별 합성 계정으로 주입했다.
- `dream_test_t367`에 전용 시험 스키마 `pcm_fixture`와 읽기 역할을 설치했다. 기존 T307 저장소가 요구하는 `dream_test_t281`과 운영 권한을 건드리지 않았다. 시험용 등록 증거와 프로젝트별 승인에는 별도 세대를 두고, 본인 `rea-reference` 링크, 보관 여부와 현재 세대, 원본 해시·길이·시간을 같은 조회에서 대조했다.
- 전용 로그인은 WAV 쓰기 역할의 멤버가 아니다. 읽기 역할로 전환하면 승인된 해당 소유자 원본만 행 정책을 통과한다. 승인 확인 뒤 요청별 WAV 사본을 만들고 해시를 대조한다. 분석 시작과 반환 전 모두 현재 DB 증거를 읽었다. 실제 분석 경로는 기존 POST 핸들러와 `4d0d53b`의 FFprobe·FFmpeg 경로다. 테스트는 함수를 직접 실행했다.
