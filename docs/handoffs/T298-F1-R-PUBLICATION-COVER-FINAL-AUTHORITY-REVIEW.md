# T298-F1-R 표지 최종 권리 재확인 독립 재검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `a0df920` · 배정 `msg_4a690de91c9b`

**판정 · 통과.** F298-1의 파일 대기 중 권리 변경이 최종 응답에 반영됐습니다. 실제 격리 PG17에서 만료·철회·세대 교체 뒤 보류된 GET과 HEAD가 빈 404를 반환했습니다.

| 항목 | 독립 검증 결과 |
| --- | --- |
| 만료·철회·세대 교체 | 각 경우에서 GET과 HEAD를 동시에 시작해 실제 DB 재조회 뒤 파일 공급자에 들어왔음을 확인했습니다. 파일을 보류한 채 DB 만료 시각을 넘기거나, 철회하거나, 새 세대를 게시했습니다. 응답이 아직 생성되지 않은 상태에서 정상 WebP를 풀었습니다. 여섯 응답 모두 404, 빈 본문, 이미지 MIME·길이 헤더 없음, `no-store`였습니다. |
| 정상 표지·교체 세대 | 새 세대 GET은 200과 검증된 WebP 바이트, HEAD는 200과 일치하는 길이 및 빈 본문이었습니다. 두 응답 모두 `no-store`였습니다. |
| 최종 DB 조회에서 잠금 | 파일까지 받은 뒤 T253 슬롯 테이블 잠금을 걸어 최종 조회가 `pg_stat_activity`의 `Lock`에서 기다리는 것을 확인했습니다. 요청 신호 취소와 600ms 응답 기한은 각각 빈 HEAD 503을 반환했고 이미지 메타데이터가 없었습니다. 잠금을 해제한 뒤 동일 세대 HEAD가 200이었습니다. |
| 구 호출자 호환 | `confirmCover`를 구현하지 않는 기존 `CoverStore`의 GET·HEAD가 200과 `no-store`를 유지했습니다. 집중 시험에서 손상된 표지가 최종 확인으로 넘어가지 않는 동작과 바이트 복사본 보호를 확인했습니다. |

고정 T253·T293·T295 해시를 확인한 실제 PG17.12 네이티브 시험을 인계 실행기와 독립 시나리오로 각각 실행했습니다. 깨끗한 고정 사본의 Next 타입 생성과 전체 `tsc --noEmit --incremental false`, 변경 파일 ESLint가 통과했습니다. 관리자·공개·REA 회귀 **32개 파일 394건 통과, 62건 건너뜀**입니다. 두 소유 리스너와 임시 클러스터·사본을 제거했습니다.

검증 범위는 최종 DB 조회 결과를 반영한 응답 생성까지입니다. 마지막 조회 직후 권리 변경, 이미 전송이 시작된 응답, 운영 호스트 연결과 CDN·브라우저 캐시는 운영 통합 범위입니다.
