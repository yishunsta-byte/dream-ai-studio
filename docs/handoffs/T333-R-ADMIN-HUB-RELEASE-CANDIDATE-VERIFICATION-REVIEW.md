**고정 후보 검수 통과.** `ad82944b0eef492290fec7d5c68104e5d114e892`에 적용할 패치의 해시와 32개 경로, 인증·게시 기본 동작, 전체 회귀 결과가 인계 문서와 일치했다. 검수 당시 로컬 `origin/master`는 이 기준 커밋을 가리켰다. 실제 배포 버전과 운영 계정·환경은 검증 범위 밖이다.

## 고정 패치와 API 인벤토리

- `e990c777be2f9c500d6bc876d092af059177587d`에서 제품 21개와 전용 시험 9개를 추출하고, 인벤토리 시험 2개를 문서대로 조정했다. 두 번 생성한 3,356줄 패치는 바이트 단위로 일치했고 SHA-256은 `4601a80b2124522a88e0b6ec198cd7958f033fe2a7615eb2460181d24600f5e6`이었다.
- 기준 아카이브에 적용 후 32개 전부 패치의 결과 blob과 일치했다. 제품과 전용 시험 30개는 모두 `e990c77`의 blob과도 일치했다. 아카이브를 저장소 하위에 풀면 `git apply`가 상위 저장소를 발견해 경로를 건너뛸 수 있었다. 사본에 대해 `GIT_CEILING_DIRECTORIES`를 지정하여 상위 저장소 탐색을 막은 뒤 적용을 재현했다.
- `/api/admin/publications`의 GET·POST는 인벤토리에 등록돼 있었다. 후보에 없는 T296 참조 분석 경로는 각 인벤토리의 `e990c77`판에서 정확히 한 번 제거했다. 결과는 `tests/api-auth.test.ts` `28b17fe66f48906f87e521a8f941ef3c412b7511`, `tests/t198-legacy-gate.test.ts` `cedd5a80063e15601ad706a7465a3a9254fc4302`이다. 표지용 `proxy.ts`와 `admin-local-notice.tsx` 변경은 후보 경로에서 제외돼 있었으며, 두 기준의 T220·T243 시험 파일은 동일했다.

## 인증과 관리자 화면

- 메뉴와 포커스 대상 네 쌍을 검증했다. `#admin-overview` 개요, `#admin-project-list` 내 프로젝트, `#admin-review` 완성본 검수·게시, `#admin-account` 계정 설정 순서다. 연결된 기존 기능과 미연결 항목의 렌더링도 시험을 통과했다.
- 로컬 모드는 관리자 허브 대신 안내를 반환한다. 미인증·권한 거절·인증 서비스 불가 케이스는 페이지의 관리자 로그인 전환과 API의 응답 상태 시험을 통과했다. 인증된 계정에서도 외부 출처 및 Origin 누락 쓰기는 본문을 읽기 전에 403으로 거절된다.
- 게시 런타임 기본 구성은 `undefined`를 반환한다. 승인 계정의 GET은 200 `no-store` 및 `{"kind":"closed"}`, 같은 출처 JSON POST는 503 `PUBLICATION_UNLINKED`이며 쓰기 호출은 0이다. 관련 집중 회귀 6파일 268건이 통과했다.

## FFmpeg와 회귀

- 승인된 FFmpeg 9.0.2, ffprobe 9.0.2와 라이선스를 실파일로 복사했다. 세 파일의 원본·복사본 SHA-256이 모두 일치했다. `ffmpeg.exe` 해시는 `3256173f3f8bffd7df12227c68adf68025edb1832273a9530688a7bb1ed8edec`이었다. 두 실행 파일은 버전 확인 시 종료 코드 0을 반환했다.
- 빈 루트 `tmp/`와 복사한 의존성을 갖춘 격리 사본에서 전체 Vitest가 문서와 같은 결과를 냈다. 파일 113개 통과·10개 건너뜀, 시험 2,197건 통과·319건 건너뜀·실패 0이었다. 이전 FFmpeg 누락과 관련한 5파일을 따로 실행해 51건이 통과했다. 소스 타입 검사와 후보의 변경 TypeScript 파일 ESLint도 통과했다.
- 인계의 성공한 빌드와 로컬 HTTP 표는 합성 인증 및 로그인 모드가 꺼진 실행에 대한 보고다. 이번에는 후보 원본 소스와 테스트를 검증했으며 생산용 빌드나 HTTP 서버 실행을 반복하지 않았다. 검수 사본과 복사한 도구를 정리했다. 운영, 푸시, 배포는 수행하지 않았다.
