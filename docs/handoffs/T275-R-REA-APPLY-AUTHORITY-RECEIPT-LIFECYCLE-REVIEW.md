# T275-R REA 적용 권한·영수증 수명 독립 검수

2026-11-19 KST · Codex(Tester) · 기준 `9b1f625` · 배정 `msg_635f1d3e3418`

**합성 정책 단위 통과.** 대기 확인의 실행 권한과 완료 영수증의 재조회·보존 수명이 분리됐다. 이 정책을 영속 저장 설계에 사용할 수 있다. 실제 서버 연결에는 권한·파일·복원 세대의 서버 검증과 같은 트랜잭션에서의 소비·저장·영수증 기록이 선행한다. [구현 보고](T275-REA-APPLY-AUTHORITY-RECEIPT-LIFECYCLE.md) · [설계 독립 검토](T274-R-REA-SERVER-APPLY-INTEGRATION-REVIEW.md)

## 독립 합성 대조

- 별도 인메모리 표본으로 **26개 상태 판정과 3개 종결 영수증 조회**를 확인했다. 대기 확인은 발급 시각을 포함하고 실행 만료 시각을 제외했다. 분석 수명은 실행 만료와 별도로 평가됐다. 대기 읽기, 취소·철회·삭제·커밋 미확정과 잘못된 서버 시각은 `unavailable`이었다.
- 동일한 자료 해시라도 링크나 권한 세대가 달라지면 거절됐다. 다른 합성 바이트에서 계산한 SHA-256을 등록 해시와 분석 사본 해시에 각각 넣으면 `stale`이었다. 포인터만 바꾼 경우와 내용 리비전만 바꾼 경우 모두 `conflict`였다. 확인과 영수증은 각각 다른 저장소·복원 세대에서 반환되지 않았다. [정책 함수](../../lib/reference-analysis/apply-lifecycle.ts)
- 완료 시각부터 보존 기한 직전까지, 현재 조회권을 확인한 뒤 기존 영수증을 반환했다. 실행 기간이 끝나고 현재 실행 정보가 철회된 뒤에도 영수증 조회권이 있으면 원래 결과가 남았다. 조회권 거절과 보존 기한 도달은 `unavailable`이었다. `confirm` 재전송도 `applied` 또는 `no_change` 영수증만 반환했다. 공개 형태에는 결과 유형, 당시 타임라인 ID·리비전·내용 리비전, 완료 시각만 있었으며, 해시를 추가한 영수증은 엄격한 구조 검증에서 거절됐다.

## 실제 연결의 신뢰 경계

- 이 함수는 현재 권한이 `verified`로 전달된 사실을 구조로 대조한다. 실제 인증이나 조회권을 증명하는 일은 호출자가 맡는다. 요청의 식별자·해시·시각을 실행 권한으로 쓰지 않고, 서버가 인증한 액터와 같은 저장소에서 조회한 범위를 전달해야 한다. 영수증 조회권과 실행 권한은 독립이며, 취소·삭제·권한 철회 뒤 조회를 허용할 정책이 없다면 서버가 `denied` 또는 `unverified`를 전달한다. 현재 제품 호출 경로에서 이 함수는 호출되지 않는다. [서버 인증](../../lib/auth/resolve.ts)
- 현재 분석 사본 코드는 실제 파일 크기와 복사 바이트 수를 검사한다. 기능 연동 시 분석한 동일 사본의 SHA-256과 등록 자료의 해시를 서버에서 대조해야 한다. 백업은 DB를 복사하므로 복원 시 새 세대 발급과 대기 확인·진행 분석 무효화는 게시 경계에서 집행한다. 함수에 동일한 과거 세대를 그대로 넘기면 구조만으로 복제 여부를 알아낼 수 없다. [관리 사본](../../lib/reference-analysis/local-file.ts) · [백업](../../lib/services/backups.ts) · [복원 정규화](../../lib/services/restore.ts)
- `eligible`은 단일 상태 스냅샷의 판정이다. 영속 확인에는 서버가 확정한 적용 계획·대상 매핑을 함께 귀속하고, 조회·판정·확인 소비·타임라인 CAS·영수증을 같은 쓰기 트랜잭션에 묶어야 한다. 종결 영수증 재전송, 복원본의 이전 ID, 권한 철회 경합과 커밋 응답 유실은 통합 회귀 대상이다. 이번 검수는 정책 동작과 기존 경계의 정적 대조에 한정했다.
