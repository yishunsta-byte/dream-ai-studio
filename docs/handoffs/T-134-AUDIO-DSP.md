## 1. 모듈 구성
| 파일 | 역할 |
|---|---|
| `lib/audio/profile.ts` | 고정 프로필 `p2-5-local-v1` |
| `lib/audio/graph.ts` | 필터 구성. 검사한 정수와 고정 단어로만 만들어요. 호출한 쪽이 보낸 필터 문자열은 받지 않아요. 프레임 값은 샘플로 바꾸기 **전에** 정수인지 확인해요(1.5프레임×1600이 정수처럼 보이는 문제를 막음). |
| `lib/audio/run.ts` | 이 모듈이 소유하는 도구 실행기. 아래 표 참고 |
| `lib/audio/pcm.ts` | f32 PCM을 스트리밍으로 해시·피크·비유한 값·첫 신호 위치 확인 |
| `lib/audio/mix.ts` | `mixAudio(request, options)` 전체 파이프라인(2장) |

**고정 프로필 `p2-5-local-v1`의 값:**
- 기본: 48kHz, 30fps, 1프레임 = 1600샘플, stereo
- 음량: 목표 -14 LUFS, TP -2, LRA 7
- 출력: AAC-LC 192k
- 합격 기준: I ±1 LU, TP ≤ -1 dBTP
- 음악 낮추기: threshold 0.03, ratio 6, attack 20ms, release 300ms, makeup 1, rms, maximum
- 서서히: 일반 clip은 직선(`tri`), 곡 연결은 등전력(`qsin`)
- 길이: 정규화 최소 3초, 최대 10분, clip 100개

**도구 실행기(`run.ts`):**
- 인자를 배열로 넘기고 shell을 쓰지 않아요.
- 취소(AbortSignal)나 자체 시간 초과가 오면 자식 프로세스를 끝내고, **종료를 기다린 뒤에** 오류를 돌려줘요.
- 오류 문구와 ENOSPC/EDQUOT는 `DISK_FULL`로 분류해요.
- stderr는 상한까지만 보관하고, 경로는 가려요.

## 2. 처리 순서
1. **입력 검사:** v2 clip·join 스키마와 `audioIssues`를 써요. 출력 길이는 정해진 값이고, 겹침·서서히·연결 규칙도 함께 검사해요. 원본 정보가 빠지거나, 경로가 절대 경로가 아니거나, 결과 파일이 이미 있으면 거절해요.
2. **원본 고정:** 원본을 작업 폴더로 **복사하면서 해시**하고, 다르면 `SOURCE_CHANGED`예요. 사본은 읽기 전용으로 둬요. 원본은 읽기만 해요.
3. **원본 검사:**
   - 소리 스트림이 있어야 하고, 1채널이나 2채널이어야 해요. 아니면 `SOURCE_UNSUPPORTED`예요.
   - 48kHz로 끝까지 디코드한 샘플 수가 쓰려는 구간보다 적으면 `SOURCE_TOO_SHORT`예요. 늘리거나 반복하지 않아요.
4. **믹스:** 각 clip에 다음을 적용해요.
   - 사용 구간을 샘플 단위로 자르기, gain
   - 서서히: 곡 연결 쪽은 등전력 qsin
   - 샘플 단위 배치, 출력 길이까지 채우기
   - 목소리 버스를 둘로 나눠 그 신호로 **낮춤을 켠 음악만** sidechain 압축해요. 목소리가 없으면 압축하지 않아요.
   - 전체를 정규화 없이 합해서 f32 PCM으로 만들어요. 결과는 정확히 `출력 프레임×1600`이어야 하고, 아니면 `OUTPUT_INVALID`예요.
5. **분류:**
   - 피크가 0이면 `silent`. 음량을 맞추지 않아요.
   - 3초 미만이면 `too_short`. 음량을 맞추지 않아요.
   - 측정값이 비유한(-inf)이면 `LOUDNESS_UNMEASURABLE` 실패예요.
   - clip이 없으면 `no_audio`. 파일과 작업 폴더를 만들지 않아요.
6. **음량 2회 측정:**
   - 첫 측정값은 해당 PCM의 sha와 프로필, ffmpeg sha에 묶여요.
   - 두 번째 실행 전에 PCM을 다시 해시해서 하나라도 다르면 `STATS_MISMATCH`로 멈춰요.
   - **실측 중 발견해서 고친 문제:** 0 LUFS를 넘는 믹스는 loudnorm이 측정값을 받지 않았어요(`Result too large`). 그래서 첫 측정이 -1 LUFS를 넘으면 고정 f32 감쇠(목표 - 측정값 dB)를 적용하고, 다시 재서 그 PCM에 두 번째 실행을 해요. 적용한 값은 `preGainDb`로 기록해요.
7. **인코딩·결합:** AAC-LC 48k stereo 192k로 인코딩해요. 무음 영상을 주면 영상은 다시 인코딩하지 않고 복사해서 결합해요. 비트 단위로 같은 결과가 나오도록 플래그를 붙였어요.
8. **결과 검사:**
   - ffprobe로 aac LC, 48k, 2ch, 스트림 수를 확인해요.
   - **디코드한 샘플 수가 출력 길이와 정확히 같아야 해요.**
   - ebur128로 I·LRA·true peak를 **결과 파일에서 다시 재요.** 정규화한 결과가 기준 밖이면 `LOUDNESS_OUT_OF_RANGE`로 실패하고 결과 파일을 내놓지 않아요.
9. **게시:** 검사를 통과한 파일만 `outputPath`에 놓아요. 이미 있으면 덮어쓰지 않고, 놓은 뒤 해시를 다시 확인해요. 작업 폴더는 성공·실패·취소·시간 초과 모두에서 지워요(`keepWork`이면 남김).

## 4. 판단이 필요한 것 · 미검증
- **클릭처럼 띄엄띄엄 큰 소리만 있는 믹스는 현재 프로필로 -14±1을 맞추지 못해요.** loudnorm이 TP -2를 지키느라 dynamic으로 바뀌고, 최종 -15.8이 됐어요.
  - 지금은 실패로 막아요. 무음 영상 성공으로 돌리지 않아요.
  - 기준을 바꿀지(예: 효과음만 있는 경우 TP 우선 허용), 제품에서 어떻게 안내할지는 Master·사용자 결정이 필요해요.
- 낮춤 값(threshold, ratio 등)은 합성 신호에서 **-16dB 낮아짐과 사이 구간 회복**만 확인했어요. 실제 말소리의 pumping이나 알아듣기 쉬운지는 **듣지 않았어요.**
- 원본 형식은 이번에 WAV(s16/f32)만 실제로 돌렸어요. MP3·M4A, 44.1k↔48k 변환이 들어간 실제 파일, 디코더 지연이 있는 형식의 정밀 정렬은 C 단계 실제 앱 시험에서 해요(T-130 C1).
- 출력 상한(10분)에 가까운 긴 파일의 처리 시간과 디스크 사용량은 재지 않았어요. 취소·시간 초과 시험에서 10분 원본을 중간에 끊는 것만 확인했어요.
- 실제 디스크 가득 참은 만들지 않았어요. 오류 문구 분류와, 주입한 ENOSPC로 확인했어요.
- 렌더 작업·worker·RenderView 연결, 진행 단계, 다운로드는 후속 C예요. 화면은 후속 D예요.
