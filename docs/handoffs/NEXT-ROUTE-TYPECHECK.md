# 공식 타입 검사의 경로 타입 검증

기준 소스 `c72b332`에서 공식 검사 명령은 먼저 Next.js 경로 타입을 생성한다. 기존에는 TypeScript가 개발 서버의 예전 validator도 함께 읽어 사라진 홈 모듈에서 TS2307과 TS2344가 발생했다. 공식 명령에 전용 TypeScript 설정을 지정해 생성한 현재 경로 타입으로 검사한다. 개발 서버는 기존 tsconfig를 사용한다.

| 격리 사본 시험 | 결과 |
|---|---|
| 깨끗한 소스와 새 경로 타입 | 전체 타입 검사 통과 |
| 같은 소스에 기존 개발용 타입을 복사하고 기존 공식 명령 실행 | typegen 성공 후 삭제된 홈 경로의 TS2307·TS2344 재현 |
| 개발용 타입을 보존하고 수정한 공식 명령 실행 | 통과. 기준 입력 577개 중 dev 캐시 파일 4개만 제외. 제품 파일과 새 validator를 포함한 573개 검사 |
| 격리 사본에 잘못된 페이지와 제품 타입 오류를 추가 | 공식 명령이 새 경로 validator를 생성. 경로 계약 TS2344와 소스 TS2322를 검출해 종료 코드 2 |
| 해당 페이지를 유효한 컴포넌트로 수정 | 같은 공식 명령 종료 코드 0 |

검증은 Windows에서 `npm.cmd run typecheck`로 수행했다. 시험용 페이지와 캐시 조작은 임시 사본에 한정했다.

Tester가 `9d21558`을 새 디렉터리에 추출해 같은 명령을 독립 실행했다. 경로 타입 생성과 전체 TypeScript 검사가 종료 코드 0으로 끝났다. `tsc --listFilesOnly`로 최근 WAV 인증 분기를 다룬 `tests/api-auth.test.ts`와 새로 생성한 `.next/types/validator.ts`가 모두 입력에 포함됨을 확인했다.
