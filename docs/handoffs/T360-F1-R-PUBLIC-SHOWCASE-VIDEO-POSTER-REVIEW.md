# T360-F1-R 공개 쇼케이스 영상 표지 독립 검수

**판정: 통과.** 고정 커밋 `f5a155c068c5f81fcea8608c990ddefdda531616`에서 상세를 열거나 재생을 시도할 때 이미 실패한 표지를 다시 요청하던 문제가 해소됐다.

## 브라우저 결과

| 시나리오 | 관찰 결과 |
| --- | --- |
| 실패한 표지 | 카드에서 표지 요청이 404로 끝난 뒤, 상세 열기 전 → 열기 후 → 재생 실패 후 → 복구 재생 후의 누적 표지 요청 수는 **1 → 1 → 1 → 1**이었다. 영상의 `poster` 속성은 없었고, 재생 전 상세에 ‘표지를 불러오지 못했어요’가 보였다. |
| 영상 재생 실패와 복구 | 영상 파일이 404를 반환했을 때 표지 대체 표시가 유지되고 ‘재생 파일 다시 불러오기’가 나타났다. 파일을 복구한 뒤 이 버튼으로 다시 불러오고 재생하자, 실제 재생 시간이 0.15초를 넘었고 대체 표시가 사라졌다. |
| 좁은 화면 | 320px과 390px에서 가로 넘침이 없었고, 대체 표시 아래에 조작부를 위해 56px이 확보됐다. 포인터 적중 검사에서 영상 중앙과 조작부 위치 모두 영상 요소가 반환됐다. 표지 실패 상태에서 정상 미디어를 재생했을 때도 대체 표시가 사라졌고 표지 요청이 추가되지 않았다. |
| 정상·지연·새 세대 | 정상 표지는 상세의 포스터로 표시됐다. 지연 중에는 로딩 문구와 포스터 URL을 확인했고, 표지 로드가 끝나자 로딩 문구가 사라졌다. 이전 세대에서 404였던 작품은 새 세대에서 새 URL의 정상 표지가 연결되고 대체 표시가 사라졌다. |
| 음악·초점·철회 | 표지가 실패한 음악 상세에서 오디오 요소와 대체 문구를 확인했다. 키보드로 상세를 열었을 때 닫기 버튼에 초점이 들어갔고, Escape로 닫자 해당 카드 버튼으로 돌아갔다. 철회 응답을 받은 새 문서에서는 해당 카드와 상세가 없었다. |

## 확인 범위

- 고정 커밋에서 변경된 쇼케이스 컴포넌트, CSS, 테스트, 구현 인계 문서의 네 경로와 `git diff --check`를 확인했다.
- 공개 쇼케이스, 공개 홈 라우트, 레거시 게이트 집중 회귀 15개 파일 352건 통과. TypeScript 타입 검사와 변경 TSX·테스트의 ESLint 검사 통과.
- 기존 격리 시험 환경에서 합성 승인 작품과 VP8 WebM을 사용했다. 모바일 검사는 헤드리스 Chromium의 화면 폭과 포인터 적중을 기준으로 했다. 개발 콘솔에는 기존 공개 게이트의 `hidden` 속성 hydration 경고가 관찰됐다. 운영·배포 작업 없이 격리 복사본과 브라우저 프로필을 정리했다.
