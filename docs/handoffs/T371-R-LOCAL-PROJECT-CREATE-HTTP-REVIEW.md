# T371-R 프로젝트 생성 API 독립 검수

**로컬 후보 통과.** Master 배정 `msg_aa48c1348843`. 구현 커밋 `6164808607abe2a6031f4126cafec726c63a1939`의 별도 작업본에서 실제 Next 서버·프록시·PG17.12와 루프백 인증·Storage로 실행했다. 구현 및 시험 코드는 고정 커밋 그대로 사용했다.

| 시나리오 | 재현 결과 |
|---|---|
| 기본 생성 경로 | 신규 SQLite에 PNG 업로드 201, 기존 요청 형식으로 프로젝트 생성 201. 클라우드 읽기만 선택한 기존 설정에서는 LEGACY_DATA_UNAVAILABLE 503 |
| 로컬 PG 생성 경로 | 익명 401. 요청 키 누락, 본문에 소유자 추가, 타인 파일 참조 모두 400 |
| 동일 요청과 충돌 | 본인 생성 및 같은 키·입력 재시도 모두 201이고 ID가 일치했다. 같은 키로 입력을 변경하면 409 |
| 등록 철회 | 철회한 파일을 새 키로 요청하면 400. 전체 HTTP 시나리오에서 Storage 읽기는 성공한 파일의 버킷·객체 조회 한 쌍뿐이었다 |
| 저장 결과 | HTTP 시나리오 전후 프로젝트 +1, 단계 +7, 링크·감사·성공 원장 각 +1. 이어진 T368 서비스 시험에서 동시 재시도·응답 유실·전체 롤백·정책 순서도 통과 |

재현 시 PowerShell에서 `$env:T371_VERIFY_HTTP='1'` 설정 후 `node --conditions=react-server --import tsx tests/postgres/t368-run-private-image-project-create.mjs` 실행. 실행기가 PG 도구 디렉터리의 실제 경로를 검사하므로 격리 사본에 PG17.12 배포 파일을 복사했다. 최종 실행은 종료 코드 0이며 PG 프로세스·리스너·임시 클러스터 정리까지 확인했다.
