# 로컬 PG 브리프 승인 독립 검수

MASTER 배정 `msg_607baa47f6d7`. `53674a7`을 조상으로 포함하는 `72fbed2`의 별도 Git 사본에서 실제 Next.js HTTP와 임시 PG17을 실행했다. 기존 T371 시험의 브리프 검증에 이전 리비전·기획 화면·승인 이력 확인을 추가해 실행했다. 추가 단언은 검수 사본에만 적용했다.

| 시나리오 | 확인 결과 |
|---|---|
| 승인 전과 승인 후 기획 진입 | 신규 프로젝트의 요구 확인은 `todo`, 기획은 `locked`였다. 승인 전에는 기획 본문이 표시되지 않았다. 승인 후에는 요구 확인이 `approved`, 기획이 `todo`가 됐고 소유자의 실제 기획 페이지가 HTTP 200으로 열렸다. |
| 이전 버전과 다른 계정 | 현재 내용 리비전을 한 번 올린 뒤 기존 양수 리비전으로 승인하면 409. 다른 계정의 브리프 GET·POST는 404였고 기획 본문도 표시되지 않았다. 비로그인 승인 401, 승인 확인 미선택 400. |
| 동시 및 사후 중복 승인 | 같은 명령 두 건의 결과는 200과 409였다. 완료 후 재요청도 409였다. DB의 `brief.confirm`은 0건에서 1건으로 증가했고 저장된 이력 리비전은 승인한 버전과 일치했다. |
| 편집 잠금과 타임라인 | 승인 전후 모두 편집 단계는 `locked`, 타임라인 이력은 0건이었다. |
