## F315-F1-R1 · 쓰기 오류가 부분 파일을 남길 수 있음

`writeFileSync(..., { flag: "wx" })`가 성공한 뒤에만 해당 목적지를 `createdFiles`에 추가한다. 목적지가 생성된 뒤 데이터 쓰기에서 오류가 나면(예를 들어 저장 공간 부족) 현재 파일은 정리 목록에 없다. 기존 디렉터리 아래에 그 파일이 남는 경우에는 새로 만든 디렉터리의 삭제도 이 실패를 드러내지 못해 정리가 완료됐다고 보고할 수 있다. 제공된 오류 주입은 두 파일 쓰기가 성공한 뒤 세 번째 쓰기 전에 적용되므로 이 경로를 검증하지 않는다. 변경분의 코드에서 확인했으며 이 오류를 별도로 주입하지 않았다. [쓰기와 정리 코드](../../tests/reference-analysis/t315-next-response-egress/install-fixture.mjs#L102)

배타적으로 파일을 만드는 시점에 해당 파일의 소유 정보를 기록하고, 쓰기 실패 시 그 파일이 이 호출에서 만든 파일임을 확인해 정리하도록 보완한다. 이미 존재했거나 다른 파일로 대체된 목적지는 보존해야 한다.

두 회귀 실행의 자체 임시 경로와 별도 고정 사본을 정리했다. 이전 구현을 다시 실행하거나 별도 시험 실행기를 만들지 않았다. Next 빌드·운영·배포는 수행하지 않았다.
