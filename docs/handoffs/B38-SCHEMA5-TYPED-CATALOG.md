## Strict row/projection mapping

Each query returns only aliases `{server_major, search_path, isolation, read_only, catalog_row}`. Strict wrappers require actual-major18, pg_catalog search_path, supported RC/RR context and on/off read-only value; all rows match initial context. Before catalog/deparser lookup the private context SELECT uses only explicitly qualified pg_catalog.current_setting calls, checks canonical18xxxx version text and rejects a foreign search_path. This does not set up a transaction or make a shared/malicious port safe.

The14 raw categories and normalized properties follow B36; native OID/semantic links are validated before OID removal. No raw integer OID coercion, optional-field defaults, NULL boolean fallback, normalized native-name regex or numeric-text deletion is used. OIDs are exact canonical decimal strings in1..4294967295; PUBLIC0 is allowed only where appropriate. Hashes are exactly64 lowercase hex; trigger hex consumes the entire even-length string. Names remain exact UTF8 strings; role markers such as `$owner`, `PUBLIC` and JSON-looking text never become tags.

## Identity, auxiliaries and normalization

Native registry keys include catalog class, OID and column sub-ID. Native role OIDs resolve through the detached trusted slots; no name can impersonate owner/PUBLIC. Qualified native references must agree with the actual observed keyed object or an explicitly supplied trusted external mapping, including parent relation/domain/function signature/index identity. A duplicate native object, duplicate semantic identity under another OID, ambiguous alias or unresolved endpoint fails closed.

Named triggers retain literal name, definition and digits. Internal FK triggers use parent ConstraintRef + attached relation + qualified RI function/argument signature + typeBits + constraint-relation/index links; generated name and raw OID are not golden identifiers. Internal structuralSha256 is `SHA256("internal-trigger:v1\n" + canonical typed identity/properties/internal/version/parent fields)` excluding the digest itself. Declared constraint triggers require the matching t parent and literal name/relation; internal triggers require an f parent. Four exact FK action/check sides and required supporting-index observations are checked, including self-referential-relation-safe distinction by function/side/bits. Missing/extra/duplicate structural child or malformed argument terminators reject. Current nonpartitioned contract rejects parent cycles, dangling parents and nonnull inherited parent links. Valid type↔array reciprocal cycles are checked separately and are not treated as forbidden ancestry.

Private raw auxiliary fields close otherwise unresolved dependency identities; they are not general escape hatches or new top-level categories:

- Column defaultNativeOid exists iff the default expression exists, belongs to that exact qualified relation/column ordinal/name and is unique; pg_attrdef dependency endpoints reuse this key. Unknown/defaults without a column or multiple parents cannot resolve.
- Relation TOAST pointer is independently captured, so a failed auxiliary lookup cannot masquerade as no TOAST. A present auxiliary requires namespace pg_toast, relation kind t, unique index kind i, both owners M, exactly one internal parent equal to the owning relation and index-parent equal to that TOAST relation. Map only those exact native class IDs to `{kind:table-toast|table-toast-index, relation}` keys. Missing/multiple/orphan parent, wrong owner/kind/namespace, index alias into an owned class, pointer mismatch or unknown endpoint rejects. No OID/name regex or arbitrary foreign object is absorbed. The physical auxiliary does not become an extra business table/type; its stable parent identity remains in the dependency inventory. The native companion lookups are unexecuted source projections in B38.

Canonicalization sorts complete row sets, ACL tuples and policy-role sets while retaining column/index/argument/config order and definition/expression bytes. No deduplication: duplicate canonical rows/keys reject. Raw batches are descriptor-inspected, strictly parsed, detached and frozen before the next await; configuration/external facts/parameter arrays and port method are fixed before the first await. Data/getter coercion is rejected; JavaScript Proxy traps/trusted port internals are not sandboxed. Per-batch plain-data inspection is bounded by the existing helper (100000 nodes, depth32,4MiB total text/64KiB per string); each category is capped at10000 rows and external facts at2000. This capacity is unverified against the later full native reference, and overflow must fail rather than drop rows.
