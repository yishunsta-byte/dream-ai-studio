# 렌더 결과 카드의 실제 브라우저 200% 확대

T123에서 남은 브라우저 확대 검증 중 보관된 성공 결과 카드의 재생 조작을 확인했다. Windows의 Chrome 157.0.8103.50(headless), T173 격리 앱 44b036a 및 가상 프로젝트 사본을 사용했다. 현재 소스와 비교했을 때 렌더 패널의 후속 차이는 진행 중인 작업의 시도 횟수 문구에 있다.

창 외부 너비를 1280px로 유지한 채 Chrome 설정에서 배율을 100%에서 200%로 바꿨다. 설정값을 다시 읽고 내부 너비 1264 → 632 CSS px, DPR 1 → 2를 확인했다. 확대 후 문서 너비와 스크롤 너비는 모두 624 CSS px였다. CSS zoom과 visualViewport.scale은 1이었다.

1. 가상 프로젝트의 render 페이지에서 성공 결과의 ‘영상 보기’를 누른다. 버튼 중앙이 실제 버튼에 닿고 비디오가 열리는지 확인한다.
2. 보관된 1080×1080, 4초 MP4를 재생한다. 재생 위치는 두 실행에서 각각 0.136719초, 0.135903초까지 진행했다.
3. ‘이 기기에서 소리 켜기’와 ‘이 기기에서 소리 끄기’를 차례로 누른다. HTML 비디오의 muted 값이 true → false → true로 전환됐다.
4. ‘영상 닫기’를 누른다. 비디오 요소가 사라지고 페이지에 가로 넘침이 없었다. 네 버튼의 높이는 각각 44 CSS px였고 두 실행 모두 화면 너비 안에서 클릭할 수 있었다.

첫 시도에서는 영상 보기 클릭 뒤 비디오 요소를 발견하지 못했다. 초기 화면 표시 뒤 1초 기다리고 실제 클릭 대상까지 기록한 두 실행은 통과했다. 처음 표시되는 순간의 조작 성공이나 실제 스피커 청취는 미검증이다. 로컬 원자료는 tmp/p2-native-zoom/render-first.json과 render.json에 있다.

> 플래너 전달문 — 렌더 결과 카드의 데스크톱 Chrome 200% 확대 검증을 완료했습니다. 보관된 MP4의 재생, 음소거 전환, 닫기와 문서 가로 넘침 0px를 페이지 준비 후 두 번 확인했습니다.
