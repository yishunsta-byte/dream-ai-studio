## 통과 항목

- 고정 커밋의 빌드와 로그인 기능을 끈 격리 서버에서 `/studio`의 유일한 진입 링크로 보호 화면에 들어갔다. CSS 뷰포트 1280px은 두 열, 390px은 한 열이며 문서 너비가 각각 스크롤바 제외 너비와 같았다. 측정한 레퍼런스 화면의 노출 버튼·링크와 Studio 진입 링크는 최소 44px였다. 390px의 `/studio`, `/library`, `/jobs`, `/settings` 제목과 가로 넘침도 확인했다.
- 두 폭에서 잘못된 URL은 `aria-invalid=true`인 필드로 초점을 돌렸다. 정상 URL의 대체 안내는 필드의 `aria-describedby`로 연결됐고, 안내 초점의 다음 두 Tab은 본문과 파일 대안이었다. 본문 대안 활성화는 대상 필드로 이동했다. 상태 영역은 상태명과 설명을 함께 가진다. 실제 보조기기 발화와 물리 모바일은 시험하지 않았다.
- 키보드로 대기 → 진행 → 취소 요청 → 종료 확인을 확인했다. 취소 직전에 예정된 완료가 결과 탭을 열지 않았고 재시작할 수 있었다. 실패 → 재시도, 빈 결과에서 탭 숨김, 완료에서 근거 탭 초점, `ArrowRight`·`Home`·`End`, 관찰 위치의 `aria-pressed` 변경을 확인했다. 이전 결과는 새 URL 확인 시 닫혔고 다른 작업 및 완료 후 이벤트 거절은 집중 회귀에서 확인했다.
- 클립보드를 모의해 기본 복사 문자열이 미리보기와 같고, 합성 URL·본문·파일명·편집 메모 표지가 제외됨을 확인했다. 같은 작업에서 표현 방향을 바꾼 뒤 지난 복사가 실패해도 현재 표현 방향 필드의 초점과 선택이 유지됐다. 일반 거절은 미리보기 내용을 선택했다. 합성 입력 확인과 상태 전환에서 앱의 데이터 요청은 0건이었다. 실제 클립보드·파일 업로드·자료 조회는 사용하지 않았다.
- 보호 그룹, 공개 경로 분류, `legacyPageGate`가 렌더 전에 실행되는 순서를 확인했다. 실제 proxy와 `NextRequest`를 사용한 무세션 모의 검증에서는 `/studio/reference-analysis`, `/studio`, `/library`가 모두 `307`, `Cache-Control: no-store`와 각 경로를 보존하는 `/login?next=…`를 반환했다. 자동 승인 검토가 합성 인증 설정으로 두 번째 로컬 서버를 기동하는 명령을 `blocked by policy`로 거절해, 별도 서버의 HTTP 307은 독립 재현하지 못했다.
