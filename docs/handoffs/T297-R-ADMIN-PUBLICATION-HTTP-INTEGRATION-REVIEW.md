**판정 · HTTP 경계 수정 후 재검수.** 보호 화면과 준비·게시·재시도·철회는 통과했습니다. 동일 출처 판정과 초과 본문 응답에서 두 경계를 확인했습니다.

## 재현된 경계

**F297-1 · 별도로 등록된 출처도 현재 요청과 같은 출처로 처리됩니다.** 격리 Next에서 현재 접속 주소와 별도 허용 주소를 모두 설정했습니다. Fetch Metadata가 없는 정상적인 HTTP 테스트 클라이언트에서 현재 주소와 다른 등록 출처의 잘못된 JSON을 보내자 출처 거절 403 대신 본문 파싱 400이 왔습니다. 저장소 호출은 0건이었습니다. [`handlePost`](../../lib/public-showcase/admin-publication-http.ts#L99)는 공용 [`rejectCrossSite`](../../lib/auth/config.ts#L173)의 허용 목록을 사용합니다. 이 가드는 Fetch Metadata가 있을 때 `same-origin`을 확인하지만, 등록된 출처를 요청의 호스트·스킴과 직접 비교하지 않습니다. 동일 출처 계약은 신뢰 설정으로 확인된 요청 출처와 비교하는 테스트를 추가해 검증할 수 있습니다.

**F297-2 · 본문 상한을 넘긴 뒤 취소 완료가 지연되면 413도 대기합니다.** 격리 `Request`에 1,025바이트를 공급하고 생산자의 `cancel()` 완료를 보류했습니다. 초과를 감지해 취소 함수가 불렸지만 180ms 동안 요청이 완료되지 않았고, 취소를 해제한 뒤 413 `PAYLOAD_TOO_LARGE`가 도착했습니다. 저장소 트랜잭션은 0건이었습니다. [`readLimitedText`](../../lib/public-showcase/admin-publication-http.ts#L49)가 취소 프라미스를 기다립니다. 이 재현은 직접 스트림을 주입한 핸들러 경계이며, 완전히 전송된 실제 Next 요청의 413은 통과했습니다. 초과 판정 응답이 본문 정리의 완료에 의존하지 않도록 검증할 필요가 있습니다.
