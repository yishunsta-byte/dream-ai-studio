# 제작 승인 후 첫 타임라인 저장

| 항목 | 구현 및 검증 상태 |
|---|---|
| 대상 | 로컬 PG17 쇼핑숏츠 프로젝트 소유자가 제작 승인 뒤 첫 편집 타임라인을 명시적으로 저장한다. |
| 요청 | POST /api/projects/{id}/timeline/initial. 본문은 expectedContentRevision과 null인 expectedTimelineId, Idempotency-Key 헤더는 UUIDv7이다. |
| 장면 | 활성 장면을 지정 순서로 읽는다. 모든 장면에 재검토가 끝난 성공 이미지·영상 결과가 있어야 한다. 보관·모의 자산이나 길이를 모르는 영상은 거절한다. |
| 저장 결과 | SQLite와 공유하는 30fps 계산을 적용한다. 이미지는 장면의 계획 길이를 사용하고, 영상은 등록된 영상 길이와 계획 길이 중 짧은 쪽을 사용한다. 새 리비전·편집 상태·프로젝트 포인터·활동 기록을 함께 저장한다. |
| 동시 편집 | 같은 기준에서 서로 다른 최초 요청 두 건 중 한 건만 성공한다. 동일 키·동일 입력 재전송은 처음 저장한 결과를 반환한다. |
| 실제 HTTP 검증 | 격리 PG17에 시험 전용 승인·장면·성공 버전을 준비했다. 업로드 PNG는 2초 장면에서 60프레임, ffprobe로 측정한 30초 MP4는 4초 장면에서 120프레임과 끝 트림 780프레임이었다. 익명·다른 소유자·미승인·빈 장면·미선택·재검토·보관·내용 버전 충돌을 검증했다. |
| 서비스 연결 | 일반 사용자가 제작 승인과 장면 결과 선택을 마치는 경로 및 편집 화면의 최초 저장 동작 연결은 별도 작업이다. 운영 작품 검증과 배포도 남아 있다. |

통합 시험은 PowerShell에서 `$env:T371_VERIFY_HTTP='1'`을 설정하고 `node --conditions=react-server --import tsx tests/postgres/t368-run-private-image-project-create.mjs`로 실행한다.

## Tester 독립 검수

고정 커밋 `42314b4`를 별도 작업 트리에서 검수했다. 실제 Next.js HTTP와 임시 PG17에서 제작 미승인, 빈 장면, 결과 미선택, 재검토 중, 보관 자산은 저장이 거절됐다. 승인 및 결과를 갖춘 시험 상태에서는 PNG 2초가 60프레임, ffprobe로 측정한 MP4 30초 중 계획 4초가 120프레임과 끝 트림 780프레임으로 저장됐다. 서로 다른 최초 저장 요청을 동시에 보내면 200·409였고 성공 키를 재전송하면 같은 리비전이 반환됐다. 타임라인 리비전과 활동 기록은 각각 1건이었다.

공용 실행에는 브리프 승인과 WAV 추가 회귀도 포함됐고 종료 코드 0이었다. 인증 계약 자동 테스트 148건이 통과했다. 제작 승인과 결과 선택은 시험 데이터로 준비했으며, 임시 PG17 프로세스와 클러스터의 정리를 확인했다.

> Master 전달문 — 42314b4의 최초 타임라인 HTTP 독립 검수와 인증 계약 148건을 통과했습니다. PNG·MP4 프레임, 동시 저장 한 건, 성공 키 재전송 및 부적격 장면 거절을 확인했습니다. 앞선 실행에서 관찰된 브리프 503은 공유 역할 수정이 포함된 이 고정본에서는 재현되지 않았습니다.

## 첫 타임라인 저장 화면 독립 검수

고정 커밋 `03a7c7e`를 Chromium 390px에서 실제 로컬 Next.js·PG17 및 합성 소유자 계정으로 검수했다. 제작 승인과 선택된 PNG 장면은 시험 데이터로 준비하고, 프로젝트 생성과 WAV 첨부는 제품 API를 사용했다.

| 조건 | 화면과 저장 결과 |
|---|---|
| 제작 승인 전 | 첫 타임라인 저장과 배경 음악 저장 버튼이 비활성이며 제작 승인 안내가 표시됐다. |
| 제작 승인 후 장면 미준비 | 키보드 Enter 저장 요청 뒤 장면 결과를 선택하라는 오류 문구가 표시되고 초점이 이동했다. DB 타임라인과 초기화 기록은 0건이었다. |
| 첫 저장 성공 응답 유실 | 서버가 성공한 응답을 브라우저에서 보류했을 때 초점은 저장 영역에 있었다. 유실 후 결과 확인 안내에 초점이 갔다. Enter로 키·본문이 동일한 요청을 재전송했고 서버는 같은 결과를 반환했다. ‘첫 타임라인을 r1로 저장했어요’에 초점이 잡혔다. |
| 다른 요청이 먼저 저장 | 같은 기준의 별도 키 요청이 200, 화면 요청이 409였다. 충돌 문구에 초점이 갔고 최신 기준을 읽어 배경 음악 저장이 활성화됐다. |

성공과 충돌 복구 모두 새로고침 뒤 ‘기준 타임라인이 이미 저장돼 있어요’가 표시됐고 선택된 WAV의 저장 버튼은 활성 상태였다. 각 성공 프로젝트의 타임라인과 `timeline.initialize` 활동 기록은 1건씩이었다. 화면 자동 테스트 8건 및 브라우저를 포함한 전체 공용 HTTP 실행이 통과했으며 임시 PG17을 정리했다.
