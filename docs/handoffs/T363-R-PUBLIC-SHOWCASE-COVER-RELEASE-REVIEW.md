**판정: 요청된 후보 검수 범위 통과.** 후보 `90ac7d1ba8db1c6dda8a9be0570d2aee624bc711`, 부모 `3c57eff6724886d104faab1937059579647e5ffb`, 트리 `340e7cce881c5c45b369c4b606c073ff49722ff2`를 대조했다.

## 후보 범위와 예시 모드

- 부모 대비 변경은 `components/public-showcase/neon-showcase.tsx`, `components/public-showcase/neon-showcase.module.css`, `tests/public-showcase/neon-showcase.test.ts` 세 파일이다. `git diff --check` 통과. 공급원, 공개 홈·표지 라우트, 프록시·CSP와 Next 설정은 부모와 같다. 공개 홈은 기존 `SAMPLE_WORKS` 여섯 건을 전달하고, 화면의 기존 네 `next/link` 링크를 유지한다.
- 후보 원본 홈에서 예시 이미지가 `/_next/image`를 통해 정상 로드되고 표지 로딩 문구가 사라졌다. 새 안내는 “‘예시’로 표시된 작품과 크리에이터는 화면 소개용이에요. 예시 작품에는 재생 파일이 연결되어 있지 않아요.”이며, 적용 대상은 예시 작품으로 명시된다. 예시 영상 상세에는 “재생할 수 있는 영상 파일이 아직 연결되지 않았어요.”가 표시됐다.
- 합성 빈 목록·로딩·장애 상태에서 대표와 음악 영역이 각각의 상태에 맞는 문구를 표시했다. 집중 Vitest 2개 파일 30건, TypeScript 검사, 공개 홈·쇼케이스·관련 시험 ESLint 검사가 통과했다.

## 후보 브라우저 확인

| 항목 | 관찰 결과 |
| --- | --- |
| 이미 실패한 영상 표지 | 상세를 열기 직전, 연 뒤, 재생을 시도한 뒤의 브라우저 요청 수는 각각 **최적화 2건 / 원본 0건**이었다. 초기 화면의 요청을 기준으로 집계했다. 상세에는 `poster` 속성이 없고 ‘표지를 불러오지 못했어요’가 보였다. 별도의 영상 파일이 404를 반환한 뒤에만 재생 오류와 다시 불러오기 버튼이 나타났다. |
| 정상 영상 표지 | 카드가 최적화 주소를 1회 요청하고 상세를 열자 `video poster`가 원본 주소를 1회 추가 요청했다. **최적화 1 / 원본 0 → 최적화 1 / 원본 1**. 부모의 원본 `poster` 지정과 같은 동작이다. |
| 모바일·재생·초점 | 320px과 390px에서 가로 넘침이 없었고, 대체 표시가 영상 하단 56px을 비웠다. 조작부 위치의 포인터 적중 대상은 영상 요소였다. 정상 WebM의 재생 시간이 진행되자 대체 표시가 사라졌고 표지 요청 수는 유지됐다. 키보드로 연 상세는 닫기 버튼에 초점을 두었으며 Escape로 닫으면 연 버튼으로 돌아갔다. 표지 404인 음악 상세에서는 대체 문구와 오디오 요소가 함께 표시됐다. |
| 지연된 정상 영상 표지 | 합성 표지 응답을 6초 지연시켰다. 카드가 로딩 상태일 때 상세를 열자 원본 주소가 `poster`에 남아 있었고 실패 대체 표시는 없었다. 응답 후 카드 이미지가 디코드됐고 상세에도 실패 대체 표시가 나타나지 않았다. 이 영상 사례는 지연 후 성공을 검증했다. |
| 새 주소·철회 | 동일한 작품 ID를 새 표지 URL로 다시 공급한 후속 문서에서 정상 이미지와 새 `poster`를 확인했다. 작품을 뺀 후속 문서에는 카드와 상세가 없었다. 검증 범위는 새 문서의 주소 교체다. 운영 기준의 예시 모드에는 승인 세대 공급원이 없고, 열린 상세에서 세대가 실시간 교체되는 흐름은 이번에 검증하지 않았다. |

기존 격리 검수 방식으로 고정 후보를 복사해 루프백 Next 개발 서버와 헤드리스 Chromium에서 실행했다. 영상·음악·지연·새 주소·철회 및 목록 상태는 합성 입력을 사용했다. 운영 접속·빌드·배포 없이 검수했으며, 검수용 서버와 임시 사본을 정리했다.
