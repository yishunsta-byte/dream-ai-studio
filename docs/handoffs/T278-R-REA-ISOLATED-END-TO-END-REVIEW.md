**판정 — 수정 후 재검수.** 등록 파일에서 실제 컷을 추출하고 명시 확인으로 한 번만 저장한 뒤, 응답이 유실되어도 다른 프로세스에서 영수증을 복구하는 경로는 통과했습니다. 잘못된 장면 대상으로 준비가 거절될 때 앞서 발급한 확인까지 무효화하는 격리 픽스처 결함이 있습니다. [구현 인계](T278-REA-ISOLATED-END-TO-END.md)

## 필수 수정 F278-1 — 거절된 준비가 기존 확인을 무효화

1. 격리 S4 SQLite에 등록된 합성 MP4의 실제 `video-cut-1`로 두 기존 장면의 이동 확인을 준비합니다.
2. 같은 액터·자료·컷으로 다시 준비하되 `afterSceneId`에 타임라인에 없는 유효한 UUID를 넣습니다. 요청은 `unavailable`을 반환합니다.
3. 논리 스냅샷을 대조하면 `rea_e2e_analysis`만 바뀝니다. 분석의 ID와 리비전이 교체됩니다. 기존의 유효한 확인을 적용하면 `stale`이 반환되고, 새 타임라인 리비전이나 영수증이 생기지 않습니다.

픽스처가 분석 행의 업서트를 먼저 커밋합니다. 이후 별도 트랜잭션에서 확인을 준비하면서 대상 장면이 거절되어도 선행 커밋이 유지됩니다. 적용은 준비 시점의 분석 ID와 리비전을 현재 활성 분석과 대조하므로 앞서 발급한 확인이 영향을 받습니다. 후보 분석 공개와 확인 생성의 커밋 경계를 묶고, 잘못된 대상·준비 충돌에서 분석/확인 행과 앞선 유효 확인을 보존하는 회귀를 추가해야 합니다. [분석 게시](../../tests/reference-analysis/isolated-rea-fixture.ts#L150) · [확인 준비](../../lib/reference-analysis/synthetic-apply-store.ts#L74) · [활성 분석 대조](../../lib/reference-analysis/apply-lifecycle.ts#L98)

## 독립 대조 결과

| 경로 | 결과 |
| --- | --- |
| 등록 링크 → 사본 → 컷 → 미리보기 | 30fps 청색/황색 합성 MP4를 별도로 생성했습니다. 파일 SHA-256과 저장된 사본 증명을 대조했고, 467–500ms 컷 후보와 관측 PTS 500ms, 편집 격자 15프레임을 확인했습니다. 다른 소유자의 준비는 DB 논리 상태를 유지했습니다. |
| 명시 확인 → 저장 → 영수증 | `false` 확인은 전체 DB 논리 상태를 유지했습니다. 별도 프로세스가 적용 응답을 버린 뒤 실행 만료 이후 다른 프로세스가 영수증을 조회했습니다. 장면 순서는 한 번 변경됐고 `contentRevision`과 타임라인 이력은 각각 한 단계 증가했습니다. 오디오·텍스트·원본 파일은 유지됐습니다. 재적용은 동일 영수증을 반환했고 전체 DB 논리 상태도 동일했습니다. |
| 경쟁 타임라인 저장 | 준비 후 기존 타임라인 서비스로 경쟁 저장을 커밋했습니다. 옛 확인 적용은 `conflict`였고 해당 확인 행만 종결됐습니다. 타임라인·워크플로·활동 로그에 추가 쓰기가 없었고 영수증도 발급되지 않았습니다. |
| 철회·변경·복원·지연 | 전용 회귀에서 프로젝트 링크 제거/새 링크 세대, 같은 크기의 원본 변경, 복제 DB의 복원 세대 변경을 거절했으며 시도 전후 논리 스냅샷은 같았습니다. 독립 시험에서 분석이 끝난 직후 권한을 철회하자 준비가 거절됐고, 권한 테이블 외에는 변화가 없었습니다. 철회 후 기존 영수증 조회도 거절됐습니다. |
| 공개 출력 | 미리보기와 영수증에서 등록 해시, 파일명·경로, 픽셀, 분석 및 복원 식별자 제외를 확인했습니다. 영수증은 적용 결과, 타임라인 ID와 리비전, 콘텐츠 리비전, 완료 시각을 반환했습니다. |
