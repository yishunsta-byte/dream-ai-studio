# T278-F1 REA 적용 준비 실패 시 기존 확인 보존

2026-11-19 KST · Codes(Backend) · 기준 `b29062eaf8ba85cd0956d343cae95526e1f795c9` · 배정 `msg_a1ee33aff97f` · 독립 검수 대기

F278-1은 격리 픽스처가 분석 행을 먼저 커밋한 뒤 별도 트랜잭션에서 확인을 준비하면서 발생했습니다. 잘못된 대상을 거절한 응답 뒤에도 활성 분석 ID·리비전이 교체되어 기존 대기 확인이 `stale`이 됐습니다. 잘못된 대상과 준비 도중 경쟁 저장이 일어나는 회귀가 기준 코드에서 같은 분석 행 교체를 재현했습니다. [독립 검수](T278-R-REA-ISOLATED-END-TO-END-REVIEW.md)

합성 저장 어댑터의 `prepare`가 여는 쓰기 트랜잭션에서 시험 픽스처의 분석 게시와 확인 삽입을 함께 수행합니다. 같은 연결에서 분석을 게시한 뒤 현재 권한·기준 타임라인·이동 대상과 단일 확인 삽입을 대조합니다. 예상된 거절은 트랜잭션을 롤백한 뒤 `unavailable`을 반환합니다. 예상 밖 예외와 SQLite 쓰기 실패는 전체 롤백 후 원래 오류 경로로 전달합니다. 성공한 준비만 활성 분석과 새 확인을 함께 커밋합니다.
