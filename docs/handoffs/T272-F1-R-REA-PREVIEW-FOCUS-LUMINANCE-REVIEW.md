| 독립 검증 | 1280px·390px 관측 결과 |
| --- | --- |
| 프로젝트 복사 후 `Shift+Tab` 두 번 | 초점은 `원본 위치 보기`에 도달했다. 모의 거절 뒤 같은 버튼에 남았고 선택은 0자였다. 직접 선택하라는 상태 안내가 나왔다. |
| 복사 버튼에 머문 채 거절 | 초점이 복사 미리보기로 이동했고 표시 문구 전체가 선택됐다. 기존 수동 복사 경로를 유지했다. |
| 편집용 프롬프트의 같은 동작 | 복사 뒤 `Shift+Tab`으로 문구 상자에 이동했다. 거절 뒤 초점과 0자 선택이 유지됐고 해당 탭에 안내만 표시됐다. |
| 이전 작업의 지연 응답 | 영상 복사를 보류한 채 새 이미지 작업을 완료하고 선택 후 이전 거절을 전달했다. 새 작업에서 이전 알림과 선택이 나타나지 않았다. 다른 작업과 초안 변경 판정도 지정 회귀에서 통과했다. |
| 이미지 관찰과 안전 복사 | 영역→전체 순서에서 대표 상대 명도 `0.75–1.00`은 각각 100%, 90%였다. 네 구간은 각각 `0/0/0/100%`, `0/0/10/90%`로 서버 표본과 일치했다. 모의 성공은 같은 순서의 제안 문장 두 줄만 복사했다. 명도 범위와 상대 명도 비중 문구는 payload에 없었다. |

키보드만으로 프로젝트 탭과 첫 체크 상자에 도달했다. 두 폭에서 가로 넘침이 없었다. 상호작용의 fetch·XHR·beacon은 **0건**, 격리 SQLite 파일의 SHA-256과 전체 테이블 행 수는 전후 동일했다. 화면 시안이 사용하는 영상·음원·이미지 표본과 실제 서버 계약의 구조 일치, 접근·리비전·만료 회귀를 다시 확인했다.
