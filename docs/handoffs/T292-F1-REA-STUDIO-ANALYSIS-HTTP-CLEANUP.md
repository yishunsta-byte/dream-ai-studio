# T292-F1 작업실 분석 HTTP 오류 응답 정리

2026-11-19 KST · Codex(design) · 기준 `a2b09af` · 배정 `msg_5c01d32ad9ad`

HTTP 비성공 응답을 받으면 공급자가 전송을 즉시 중단하고 읽지 않은 본문에 취소를 요청한 뒤, 기존 `analysis_unavailable`을 반환합니다. 본문을 파싱하거나 취소 완료를 기다리지 않습니다. 요청 종료 후 도착한 응답도 본문을 읽기 전에 취소합니다. 본문 취소가 동기 예외를 던지거나 비동기로 거절돼도 기존 요청 상태와 새 분석 요청에 영향을 주지 않습니다. 호출자 취소, 기한 초과, 유효한 T284 DTO와 타이머·리스너 정리 동작을 유지합니다.

## 자체 검증

- 실제 `fetch`와 로컬 HTTP 서버로 503 헤더 및 JSON 첫 바이트를 보낸 뒤 본문을 계속 열어 두었습니다. 기존 `a2b09af`에서는 같은 자료의 다음 요청이 응답을 받은 뒤에도 첫 소켓이 닫히지 않았습니다. 수정본에서는 첫 요청을 `analysis_unavailable`로 종료하고 해당 소켓의 `close` 이벤트를 관측했으며, 같은 두 ID로 재시도한 응답을 정상 처리했습니다.
- 주입 전송에서 본문 취소가 미완료인 동안에도 실패 반환과 동일 자료 재시도가 가능했습니다. 취소 함수의 비동기 거절 및 늦게 도착한 응답의 동기 취소 예외도 확인했습니다.
- 집중 시험 18개와 네이티브 분석 포함 전체 20개 파일, 237개가 통과했습니다. 범위를 한정한 TypeScript 검사와 ESLint 경고 0을 확인했습니다.

이번 검증은 클라이언트 HTTP 전송 종료까지입니다. 서버 작업·임시 파일·실행 슬롯 정리는 실제 연결에서 검증할 항목입니다. 제품 라우트와 운영 배포는 작업 범위 밖입니다.
