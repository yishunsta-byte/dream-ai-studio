`/api/auth/session` 세부 계약:
- 인증 전용이에요. 기존 resolver를 1회 부르고(proxy까지 합치면 2회), 거절은 그대로 401/403/503 no-store예요.
- 같은 사이트·JSON 확인은 인증 뒤에 하고, 본문도 그 뒤에만 읽어요.
- DB·legacy·업무 서비스는 import하지 않아요. 응답에 이메일·id·토큰이 없어요.

알림·감시 방식:
- **알림 내용**: BroadcastChannel로는 `"changed"` 고정 문자열만 보내요. storage 신호에는 시각과 난수만 담아요. 토큰·이메일·UUID는 없고, 권한 근거로도 쓰지 않아요.
- **이전 계정을 바로 숨기는 경우**: 알림을 받았을 때와 실제로 `pageshow`(persisted) 복원이 됐을 때예요. 숨긴 뒤 서버에 다시 확인해요.
- **조용히 다시 확인하는 경우**: `focus`, 보이기 전환, `online`이에요.
  - 3초 간격 제한이 있어요.
  - 주기적인 확인·숨은 탭 poll·타이머는 없어요.
  - 확인 중에 알림이 또 오면 끝난 뒤 한 번 더 확인해요. 알림 전에 보낸 요청의 "같음" 답으로 이전 계정이 되살아나지 않게 하려는 거예요.
- **서버 답에 따른 처리**:
  - 같음 → 표시해요.
  - 바뀜 → 전체 문서를 다시 받아요(레이아웃·router cache 제거). 같은 탭에서 15초 안에 두 번째로 바뀌면 자동으로 다시 받지 않아요. 이메일을 숨긴 채 "다른 창에서 로그인 계정이 바뀌었어요" 안내와 새로 고침 버튼을 보여요.
  - 로그인 없음 → `/login?next=현재 경로`로 전체 이동해요.
  - 허용 밖 → `/login?error=forbidden`으로 전체 이동해요.
  - 확인 불가·오프라인 → 알림을 받은 상태(의심)면 이메일을 숨기고 정직하게 안내한 뒤 "다시 확인" 버튼을 보여요. 근거 없는 조용한 확인이었다면 표시를 그대로 둬요.

바꾸지 않은 것: auth resolver, proxy, DB, Backend, 기존 API guard, cloud 읽기 화면 기능.

## 한계(과장 금지)
- **숨은 탭 즉시 갱신은 보장하지 않아요.** BroadcastChannel·storage는 같은 브라우저 프로필 안에서만 전달돼요. 실제 브라우저가 백그라운드 탭을 멈추면 복귀(focus·보이기) 때 확인해요. ego 탭은 항상 `visible`로 보고돼서, 백그라운드 멈춤 상태는 따로 검증하지 못했어요.
- **알림 없는 변경**은 탭 복귀나 새 요청 때만 바로잡혀요. 메일 링크 로그인, 다른 브라우저·기기, 자연 JWT 만료, refresh 회전이 해당돼요(S3). 자연 만료는 검증하지 않았어요.
- **이메일만 숨겨요.** 오프라인·확인 불가·15초 제한 상태에서는 그 탭에 이미 그려진 본문(예: 이전 계정의 목록 카드)이 다시 받기 전까지 남아요. 새 데이터 요청은 기존처럼 서버가 막아요.
- 세션 확인 API는 화면에 이미 있는 이메일을 받아 같은지만 답해요. 다른 사람의 계정 존재 여부는 알 수 없어요. 로그인한 본인 기준으로만 비교해요.
- BFCache 복원은 `pageshow persisted`로 처리했지만, T-209처럼 no-store 때문에 실제 BFCache 복원은 관측하지 못했어요.
- 실제 Supabase, 다른 브라우저, managed DB는 검증하지 않았어요.
