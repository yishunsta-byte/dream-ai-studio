# 로컬 PG 제작 장면 진입 독립 검수

MASTER 배정 `msg_52f8ac47eb93`. 고정 `fbce784`의 격리 Git 사본에서 실제 Next.js HTTP·Chromium·임시 PG17로 검수했다. 실제 프로젝트 생성, 브리프 승인, 기획 저장과 승인까지 진행했다.

| 확인 항목 | 결과 |
|---|---|
| 두 화면 진입 | 승인된 기획과 프로젝트 상세에서 `장면 제작으로 이동` 링크에 초점을 맞추고 Enter를 눌렀다. 두 경로 모두 같은 제작 페이지에 도착했다. |
| 저장된 순서·길이·상태 | 기획 버전 2의 두 장면을 제목·설명과 함께 저장 순서대로 확인했다. 길이는 5초·3초였다. 최초 API 조회는 둘 다 결과 대기 상태였고, 시험 자료로 첫 결과를 선택하고 둘째에 재확인 표시를 설정한 뒤 브라우저에서 각각 `결과 선택됨`, `다시 확인 필요`를 확인했다. 두 진입 모두 새로고침 전후 표시가 일치했다. |
| 타인과 잠금 | 다른 계정의 제작 페이지·API는 404였고 익명 API는 401이었다. 제작 잠금 상태의 소유자 요청도 페이지·API 모두 404였다. |
| 승인 포인터 불일치 | 프로젝트의 승인 포인터를 유지하고 기획 단계 포인터만 NULL로 바꾸자 소유자 API가 404를 반환했다. 브라우저는 제작 장면을 찾을 수 없다는 메시지를 표시했고 장면 목록은 표시되지 않았다. 포인터 복구 뒤 이전 데이터가 그대로 반환됐다. |
| DB 보존 | 두 링크와 재조회 전후 장면 ID·순서·제목·설명·길이·선택·재확인 상태가 동일했다. |

기존 [HTTP 시험](../../tests/postgres/local-project-brief-http.mjs)에 검수 사본 전용 화면 및 포인터 불일치 확인을 연결했다. 종료 코드 0. 브라우저 공간, PostgreSQL 프로세스·리스너·임시 클러스터 정리를 확인했다.
