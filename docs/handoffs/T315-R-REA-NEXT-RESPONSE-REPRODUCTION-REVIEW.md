# T315-R Next 보호 응답 재현 자료 독립 검토

기준 `766b3ef` · 제품 기준 `131fde6` · Master 인계 `msg_ad7c4e4638ba` · Codex(Tester)

**판정은 기록 대조 통과, 설치 경계 보완 필요.** Main PC의 production 실험은 고정 로그와 요약으로 검토했다. Tester는 빌드하거나 Next 서버를 실행하지 않았다. 설치기만 별도 폐기용 Windows 디렉터리에서 검사했다.

## 고정 자료와 설치 경계

- Git 원본의 LF 기준 SHA-256을 다시 계산했다. 매니페스트 파일 7개가 모두 일치했고, 원시 로그·요약 4개의 다이제스트도 인계의 공개 접두·접미와 일치했다. 두 원시 파일은 각 1,197행·34개 사례였고, 사례 및 요청 ID 기준으로 68개의 요약을 대조했다. 원시 필드는 합성 티켓, 요청 UUID, 시험 URL 경로, 시간, 상태·헤더·바이트 수였다. 자료는 합성 문자열을 생성하고, 응답 본문 대신 길이·해시·표식 수를 남긴다.
- 제품 기준에서 바뀐 것은 문서와 시험 폴더다. 정상 격리 사본에서 다섯 파일을 설치했고, 대상 루트에 `.git`이 있으면 쓰기 전에 거절했다. 대상 파일이 이미 있으면 기존 파일은 그대로 유지했다.
- **F315-1 · 설치 대상 경계를 우회할 수 있다.** 대상 `app`이 다른 합성 디렉터리의 Windows 정션일 때 설치가 성공하고 지정 루트 밖에 파일이 생성됐다. 또 마지막 목적지 한 곳에 기존 파일이 있으면 설치는 실패하지만 앞선 네 파일이 이미 기록됐다. 둘 다 폐기용 경로에서 재현해 제거했다. 설치 전 대상의 실제 경로와 상위 Git 작업 트리, 경로 정션 및 모든 목적지 충돌을 먼저 검사하고 전체 대상이 검증된 뒤 설치해야 한다. 수동 재현에는 일반 디렉터리로 만든 새 `git archive` 사본을 사용한다. ## 원시 사건과 요약 대조

| 항목 | 독립 확인 |
| --- | --- |
| 반환 전·첫 pull 차단 | 반환 전 철회·만료는 대기 구간에 헤더가 없고, 최종에는 403/410과 빈 본문이었다. 반환 뒤 첫 pull에서 멈춘 경우는 각 실행 6개 모두 헤더·상태 없이 `ECONNRESET`과 0바이트였다. `handler:return`과 대기 기록 뒤 철회·만료가 적용됐고, 허가 소비와 enqueue가 없었다. 정상 합성 API 3종과 느린 수신 사례는 예상 본문을 재구성해 요약의 SHA-256까지 대조했다. |
| 적용 종료 후 추가 수신 | 512KiB 사례에서 두 앱 종료 신호가 모두 기록됐을 때 클라이언트 데이터 콜백은 65,529바이트였다. 재개하면 철회 여부와 관계없이 458,759바이트를 더 받고 정상 종료했다. 4MiB 철회 사례는 589,831바이트를 더 관측한 뒤 철회가 pull에서 확인됐고, enqueue 655,360바이트를 유지하며 중단됐다. 숫자는 서버 enqueue와 클라이언트 콜백의 차이다. 버퍼 위치나 패킷 통과 시점은 이 자료로 판정할 수 없다. |
| 실제 App Router RSC·프리페치 | 실제 RSC 요청의 307 `&_rsc` 리다이렉트와 후속 200을 원시 헤더에서 확인했고, 렌더 허가 소비 1회와 요약의 보호 표식 1개가 대응했다. 기본 프리페치는 `_rsc` 해시 리다이렉트 후 277바이트, 렌더 사건 0, 보호 표식 0이었다. 일반 페이지의 렌더 뒤 철회는 두 실행 모두 6,006,691바이트를 정상 수신했고, 클라이언트 코드가 같은 3MB 블록을 두 번 셌다. |
| Suspense·취소 | Suspense 철회·만료는 대기 중 이미 200과 공개 셸 6,780바이트, 보호 표식 0이었다. 최종에도 보호 표식은 없었고 정상 대조군에서는 보호 표식 2개와 렌더 소비가 기록됐다. 취소 두 유형에서는 abort·cancel·after가 기록됐고 enqueue가 늘지 않았다. |

실제 Next 페이지의 비어 있지 않은 본문은 보존되지 않아 페이지 표식 수·본문 해시는 고정 클라이언트의 측정 결과에 의존한다. 원시 로그는 상태·헤더·수신량과 서버 렌더 이벤트를 뒷받침한다. 첫 pull의 만료는 시험 제어 API가 상태를 바꾸는 모델이다. 실제 호스트의 헤더·버퍼링·하위 큐, 전체 프리페치, 브라우저 캐시 및 제품 경로는 후속 범위다.

인계는 Main PC의 서버와 격리 사본 정리를 보고한다. 현재 이 검토 환경에서 포트 43315의 리스너는 0개였다. 보존된 응답 로그에는 당시 서버 종료·사본 삭제의 호스트 측 기록이 없어 과거 정리 작업은 독립 입증할 수 없다. Tester가 사용한 설치 시험 임시 경로는 삭제했다. 고정 변경의 `git diff --check`가 통과했고 운영과 배포는 변경하지 않았다.
