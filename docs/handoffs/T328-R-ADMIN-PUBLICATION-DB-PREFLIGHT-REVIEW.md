# T328-R 게시 DB 대상·역할·TLS 독립 검수

기준 `023ac39` · Master 인계 `msg_cebfe783cdd5` · Codex(Tester)

**판정은 제공된 사전 검사 계약 통과.** 고정 사본의 원본 실행기로 소유 루프백 PostgreSQL 17.12·TLS 사례 21건을 재현했다. 합성 인증서와 폐기용 시험 로그인 세 개를 사용했다. [실행기](../../tests/public-showcase/t328-publication-db-preflight.pg17.ts)

| 검증 | 독립 확인 |
| --- | --- |
| 정상과 대상 고정 | 관리 쓰기·공개 목록·표지 로그인 세 개의 정상 설정과 복구 설정이 `verified`였다. 연결의 로그인·현재 역할, DB·포트, PG17의 클러스터 식별자와 TLS 상태를 대조한다. 설정 누락, 계정 누락·중복, 잘못된 DSN DB 또는 고정 클러스터 ID, 인증 실패, 비신뢰 CA와 호스트 불일치 설정에서는 전체가 비활성이었다. |
| 역할 경계 | 목록·표지 로그인 교환, 권한이나 스키마 접근 누락, 읽기 로그인 쓰기 권한, 구형 게시 함수, 원본 컬럼 접근, 별도 역할 경로와 부여 권한, RLS 우회, 관리자 읽기 전용 세션을 거절했다. 사전 검사에서 권한을 조회하는 쿼리는 실제 게시 함수를 실행하지 않는다. |
| 실패와 정리 | 한 로그인에서 클러스터 식별자를 조회할 수 없으면 전체가 닫혔다. 각 사례마다 `pg_stat_activity`의 검사 연결이 0건이었으며 권한을 원복한 뒤 다시 정상 검증됐다. 실행 종료 후 PID 파일·루프백 리스너·임시 클러스터 제거를 확인했고, 별도 호스트 조회에서도 소유 PostgreSQL 프로세스와 T328 임시 경로가 0개였다. |

고정 코드의 반환값은 검사 당시 세 연결에 대한 관측이다. 실제 게시 저장소·목록·표지 어댑터는 새 연결을 열 때 같은 대상, TLS, 역할과 필요한 쿼리를 자체 검증해야 한다. 같은 주소로 복원하거나 이후 연결을 달리 배정하는 운영 플랫폼의 동작은 이번 시험에 포함되지 않았다. 제품 런타임의 기본 구성은 미연결 상태다. [사전 검사](../../lib/public-showcase/publication-db-preflight.ts) · [공용 TLS 풀](../../lib/db/postgres/connection.ts)

관리자·공개·인증·기존 홈 및 게이트 회귀 21개 파일 557/557, Next 생성물 없는 고정 사본의 TypeScript, 변경 파일 ESLint와 `git diff --check`가 통과했다. 이전 구현을 재현하거나 별도 검증 도구를 작성하지 않았다. 운영 DB·제품 빌드·배포를 수행하지 않았다.
