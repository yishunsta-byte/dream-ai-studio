# T255-F1-R 공개 홈 철회 독립 재검수

**판정.** 정상적으로 초기화된 홈에서는 T255-R의 F255-R1을 재현하지 못했다. 다만 홈의 첫 클라이언트 스크립트 요청이 실패한 조건에서 Chromium의 bfcache 복원이 철회 카드를 새 조회 없이 다시 표시했다. 초기 로딩 실패에도 철회가 반영되어야 한다는 기준에 따라 실제 승인 피드 활성화 보류를 유지한다.

대상은 제품 `c4afb29fada5d0bfb9c45e522ce4607e73ad5724`, 작업자 보고 `8356aef5809d694eb9a191d46c061827b1b99005`다. Orca 배정 `msg_bb4c9fec47c8`을 확인하고 제품 변경 4경로와 새 보고서 경로의 점유 충돌이 없어 `msg_06d1d4932bc6`으로 수락했다. Front가 이전 브라우저 작업을 종료한 것을 확인했고 별도 검수 공간을 사용했다.

## 초기 스크립트 미실행 상태에서 재현 · 활성화 차단

홈의 최초 요청에서 앱의 JavaScript 자원만 브라우저 시험 설정으로 차단했다. 스크립트 태그 8개가 포함된 상태에서 스크립트 수신은 0건이었다. 서버 렌더링된 승인 카드와 일반 관리자 로그인 링크는 작동했다. 관리자 로그인 문서에 도착한 뒤 차단을 해제하고 대표 카드를 철회했다.

뒤로 가기에서 `pageshow.persisted=true`였고, 이전 홈과 같은 문서 ID가 확인됐다. 홈은 표시 상태였으며 철회된 대표 카드가 1초 관찰 후에도 남아 있었다. 샘플 2회 모두 카드가 보였고 새 공급원 호출은 0건이었다. 새로고침을 실행하자 새 문서와 공급원 호출 1회가 확인됐고 남은 카드만 표시됐다. 동일 조건의 독립 재실행에서도 초기화 전 홈이 bfcache에서 복원되어 새 조회 없이 철회 카드가 보였다.

현재 `pagehide`·`pageshow` 리스너는 `NeonShowcase`의 React `useEffect`가 실행될 때 등록된다. 서버 렌더링만 완료된 홈은 승인 내용을 표시할 수 있지만, 이 조건의 문서에는 복원 가드가 등록되지 않는다. 실제 승인 피드 활성화 전에 가드 초기화 실패 상태에서도 승인 카드가 새 조회 없이 복원되지 않도록 보완하고, 정상 탐색과 초기 스크립트 실패 조건을 다시 확인할 것을 권고한다.

## 프리페치와 HTTP

- 관리자 로그인 화면이 열린 뒤 2초 동안 홈 RSC 자원 0건과 공급원 호출 0건을 확인했다. 홈 링크를 누르면 새 문서로 이동해 공급원을 1회 호출했다. 홈의 브랜드 링크와 일반 새로고침도 각 1회 새 조회를 발생시켜 철회를 반영했다.
- HTML과 최종 RSC는 모두 200에 `private, no-cache, no-store, max-age=0, must-revalidate`였다. RSC는 `_rsc` 307 이후 `text/x-component`였고 남은 작품만 전달했다. HTML에서 홈 링크 1개, 관리자 로그인 1개, 크리에이터 로그인 2개의 `<a>`를 확인했다.
- `/studio`, `/admin`, `/cloud/projects`는 각각 기존 로그인 주소로 307을 반환했다. `/api/projects`는 401, 두 로그인 진입은 200이었다. 관리자 인증 모드의 공개 홈 링크는 HTTP와 브라우저에서 확인했고, 인증이 꺼진 관리자 안내의 링크는 관련 회귀 시험 범위에 포함됐다.

## 범위와 증거

- 브라우저 검증 범위는 Windows의 ego lite Chromium 156이다. Firefox, Safari, 모바일 및 다른 Chromium 배포판은 미검증이다. 실제 DB·Storage, 운영 계정, CDN, 이미 내려받은 커버 바이트의 회수는 이 판정 범위 밖이다. F255-R2 문구와 F255-R3 시간 상한은 이번 재검수의 대상이 아니다.
- 로그와 하네스는 `D:/starwork/t255-f1-r-snapshot-13931e76/tmp/`에 보관했다. 근거는 `browser-independent.log`, `feed-calls.log`, `http-check.log`, `vitest.log`, `typecheck.log`, `lint.log`, `build-active.log`다. 정상 조건은 `browser-round01.mjs`와 `browser-round04.mjs`, 초기 스크립트 오류 조건은 `browser-round03.mjs`와 `browser-round05.mjs`에서 기록했다.
- 검수용 브라우저 공간을 닫고 루프백 서버를 종료했다. 포트 57204의 `ECONNREFUSED`와 사본에 복원한 공급원 파일의 Git blob 일치 `e0c363f0f2024b125ae4d17e37e6cb2faba1c9b4`를 확인했다. 공유 저장소에는 이 보고서만 추가했고 기존 파일과 미추적 결과를 보존했다.
