# T367-F1 등록 파일의 수신 정리 재시도

2026-11-19 KST · Codes(Backend) · Master 배정 `msg_fb08866b9a6d` · 기준 `1f66427`

등록 후 수신 파일 삭제가 503으로 실패한 상태에서도 소유자가 정리를 다시 시도할 수 있게 했다. 등록된 요청에 대한 `cancel`은 해당 수신 파일의 정리를 마치고 `registered`를 반환한다. `complete`는 기존처럼 현재 정책의 파일 검증 기록을 확인한다. 정책 세대가 바뀌면 `CLOSED`를 반환하며, 수신 파일을 정리해도 이전 검증 기록은 다시 활성화되지 않는다. [서버 서비스](../../lib/services/postgres/private-image-upload.ts) · [독립 검수의 발견 사항](T367-R-PG17-PRIVATE-IMAGE-UPLOAD-REVIEW.md)

- 정리 역할에서 등록 상태, 요청 소유자, 객체 ID를 확인한다. 정리 장부 항목 하나가 해당 예약의 수신 버킷·키·예약 ID와 일치해야 한다. 공급자가 수신 객체의 쓰기 종료와 부재를 확인한 뒤 동일한 장부 항목만 완료로 바꾼다. 이미 완료된 요청의 재시도는 Storage 호출 없이 종료한다.
- 최종 파일 삭제를 실행하는 미등록 취소 경로와 등록 후 수신 정리 경로를 분리했다. 다른 소유자의 요청은 `NOT_FOUND`로 거절하고, 최종 파일의 데이터·현재 검증 포인터·기존 검증 기록은 보존한다.

## 검증

기존 코드에 회귀 시험을 먼저 추가해 등록 후 `cancel`이 수신 정리를 건너뛰는 문제를 재현했다. 수정 후 동일한 소유 PG17.12·루프백 Storage 시험에서 통과했다. 최초 삭제는 수신 파일을 유지한 채 503을 반환하도록 구성했다. 정책 갱신 후 일반 완료는 `CLOSED`였고, 다른 소유자의 취소는 Storage 호출 없이 거절됐다. 첫 재시도를 늦춘 사이 두 번째 재시도가 수신 파일을 정리했다. 늦게 끝난 첫 요청과 후속 요청을 포함해 수신 DELETE만 두 번 발생했고 장부 리비전은 한 번만 증가했다. 최종 바이트와 검증 포인터는 같았으며, 미완료 때 차단됐던 후보 권한 회수가 정리 뒤 성공했다. [격리 실행기](../../tests/postgres/t367-private-image-upload.pg17.mjs)

- `node --conditions=react-server --import tsx tests/postgres/t367-run-private-image-upload.mjs` 통과. 기존 T367 예약·완료·경합·복귀 시험과 소유 프로세스·리스너·임시 클러스터 정리도 확인했다.
- 관련 회귀 1,171건 통과, 환경 조건부 300건 건너뜀. 변경 파일 ESLint와 기존 `.next` 생성 검증 파일을 제외한 소스 TypeScript 검사 통과.

기존 SQL, 제품 POST, 운영 설정은 그대로다. 실제 Supabase의 정리 권한과 쓰기 종료 보장은 이번 검증 범위에 포함되지 않는다.
