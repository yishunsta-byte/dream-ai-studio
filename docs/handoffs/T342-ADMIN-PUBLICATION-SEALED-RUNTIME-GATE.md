# T342 위임 설치 확인과 게시 런타임 연결

2026-11-19 KST · Codex(Backend) · Master 배정 `msg_d8ed29ad8572` · 기준 `a8ea68c`

서버 전용 `createSealedPublicationRuntime`은 T341로 검증된 DB를 T336의 관리자 게시·공개 목록·공개 표지 공급원에 연결한다. 호출자는 승인된 T341 작업 잠금을 최초 `get()`이 끝날 때까지 유지하고 런타임을 닫는다. 제품 경로의 기본 `loadPublicationRuntimeOptions()`는 `undefined`다.

1. 명시적인 서버 설정과 승인 계획을 복사한다. 검증 계정 DSN과 T336 대상의 호스트·포트·DB를 대조하고, 클러스터 식별자와 승인된 게시 역할 OID 관계에 로그인 구성을 맞춘다. 권리 조회는 고정 카탈로그에 포함된 `t295.rights_state`를 사용한다.
2. 별도 인증서 검증 TLS 세션에서 T341을 실행한다. T341은 실제 DB·계정 OID, 고정 SQL·계획·카탈로그 해시, 최초 설치 이력, 임시 권한 회수와 기존 설치 세션 종료를 대조한다. `sealed` 확인 뒤 세 공급원의 조립을 시작한다.
3. 검증 세션을 공급원 조립이 끝날 때까지 유지한다. 공급원을 공개하기 직전에 새 읽기 전용 트랜잭션에서 이력을 대조한다. 설정 누락, 권한 회수 대기, 이력 변경, 인증·TLS 오류 또는 조립 장애가 있으면 세 공급원을 함께 비활성으로 처리하고 열린 자원을 정리한다. 공개 홈은 기존 비활성 동작에 따라 샘플을 노출하며 실제 작품과 커버는 노출되지 않는다.

## 소유 로컬 환경 검증

- `node --conditions=react-server --import tsx tests/public-showcase/t328-publication-db-preflight.pg17.ts --sealed-publication-runtime`으로 루프백 PostgreSQL 17 직접 TLS 및 합성 비공개 표지 Storage SDK 경로를 실행했다.
- 설치 직전, 커밋 후 회수 대기, 권한을 회수했지만 이전 설치 세션이 남은 상태에서 관리자 게시·목록·표지가 함께 비활성으로 유지됐다. 잘못된 대상·로그인·인증서·권리 조회 설정, 부분 조립 실패, 이력 불일치, 초기 확인과 최종 확인 사이 이력 변경, 초기화 중 종료, 잠금이 끝난 이전 승인으로 새 런타임을 열 수 없는 상태를 확인했다.
- `sealed` 상태에서 관리자 HTTP 게시 준비·게시, 실제 공개 목록과 비공개 Storage에서 읽은 WebP 표지, 철회 후 목록 제거 및 404를 확인했다. 검증 계정과 런타임 DB 세션, 루프백 Storage 서버를 종료했다.
- `sealed`는 이 시점의 **시험 DB 설치 상태**다. 이 후보는 최초 공급원 조립 시 적용되고 가동 중 설치 상태는 별도 운영 절차가 맡는다. 관리형 환경의 직접 TLS·대상 OID 승인·역할 발급과 회수·기존 세션 종료, 실제 저장소와 제품 호스트 연결은 후속 운영 검증 항목이다.
- 기존 PG17/TLS 기본 모드와 T341 독립 모드, 소스 TypeScript 검사(생성된 `.next` 검증기 제외), 변경 파일 ESLint를 통과했다. 병렬 Vitest에서 기존 Storage 스트리밍 시험 한 건이 제한 시간에 걸렸고, 동일 범위의 단일 워커 재실행에서 299건이 통과했다.
