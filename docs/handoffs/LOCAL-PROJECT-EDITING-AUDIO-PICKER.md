## 두 음원 전환과 재시도 독립 검수

Tester가 `9253d1a`의 실제 Next 페이지, 합성 로그인, 격리 PG17에서 Alpha.wav(330Hz, 0.5초)와 Bravo.wav(440Hz, 1초)를 업로드하고 같은 프로젝트에 첨부했다. Chromium에서 두 파일을 차례로 선택했을 때 선택 제목, 플레이어 접근성 이름, URL의 track ID, 재생 중인 currentSrc가 같은 자산을 가리켰다. 두 파일 모두 예상 길이에서 재생이 끝났다. 새로고침 후에도 Bravo 선택과 주소가 복원됐다.

Bravo 미디어 요청만 차단해 오류를 발생시킨 뒤 차단을 해제하고 ‘연결 상태 다시 확인’에서 Enter를 눌렀다. 오류가 사라지고 Bravo 플레이어가 일시정지 상태로 복구됐다. 재생을 다시 시작하자 1초에서 정상 종료했다. **키보드 초점은 BODY로 빠졌다.** 오류 버튼 제거 후 음원 선택기나 복구된 플레이어로 초점을 반환할 필요가 있다. 실제 스피커 출력은 측정하지 않았다.

## 재시도 초점 수정본 독립 검수

고정 커밋 `f39b85f`의 로컬 Next.js와 임시 PG17에서 Alpha.wav(0.5초)·Bravo.wav(1초)를 같은 프로젝트에 첨부했다. 390px에서는 Alpha, 1280px에서는 Bravo를 선택했다. 두 폭 모두 음원 교체와 새로고침 뒤 선택값·URL의 `track`·플레이어 이름·재생 주소가 일치했다.

- **재생 실패 후 복구:** 미디어 요청 차단을 해제하고 ‘연결 상태 다시 확인’에서 Enter를 누르면 해당 음원 플레이어에 초점이 잡혔다. Space로 시작한 재생은 두 폭 모두 같은 주소에서 예정 길이까지 끝났다.
- **목록도 실패한 뒤 복구:** 재생 오류에서 Enter를 누를 때 목록 요청을 차단하면 ‘목록 다시 확인’ 버튼에 초점이 잡혔다. 목록 차단을 풀고 Enter를 누르면 이전 선택이 유지됐고 플레이어 초점과 Space 재생이 복구됐다.

초점 자동 테스트 2건과 위 브라우저 시나리오는 통과했다. 첫 브라우저 실행의 대기 시간 초과는 직접 재시도용 문서를 새로 열어 재실행한 뒤 재현되지 않았다. 후속 공용 HTTP 실행은 이 고정본 이후 `72fbed2`에서 수정된 브리프 어댑터 분기에서 503으로 끝났다. 임시 PG17과 브라우저를 종료했다.
