| 복귀 | 소유 시험 세션에서 별도 SQL로 추가한 정책·ACL과 역할·표식만 회수한다. 미완료 예약 또는 남은 정리 작업이 있으면 철회가 거절된다. 기존 기반 이력과 SQL4의 완료 기록을 보존하며, 별도 후보 데이터도 SQL4의 이력 제약을 따른다. [복귀 SQL](../../lib/db/postgres/private-image-upload/0001_remove.sql) |

## 자체 검증과 적용 경계

- `node --conditions=react-server --import tsx tests/postgres/t367-run-private-image-upload.mjs`가 통과했다. 고정 T281 실행기의 소유 PG17 준비·검증·종료를 같은 시험에서 재사용한다. 잘못된 설치 설정, 부분 설치, 변형된 SQL4 트리거, 역할 교차 쓰기, 기존 객체로의 쓰기를 차단했다. 실제 로컬 HTTP에 PNG를 쓰고 읽으며 A/B 격리, 중복 예약·완료, 잘못된 이미지, 정책 변경과 완료의 경합, 등록 파일 보존을 확인했다. [격리 실행기](../../tests/postgres/t367-private-image-upload.pg17.mjs)
- DB에서는 실제 COMMIT 뒤 호출자가 응답을 잃는 상황을 주입했다. HTTP에서는 최종 쓰기와 수신 파일 삭제 응답을 잃는 상황을 시험했다. 정리가 지연된 최종 쓰기를 기다리는 동안 DB의 상태가 종결되지 않았고, 해당 쓰기가 끝난 뒤에만 제거와 정리 완료가 확정됐다. 이후 유입 쓰기와 재등록은 거절됐다. 복귀 전후 기존 프로젝트 쓰기·기반 이력·ACL과 검증 기록을 대조했다.
- PostgreSQL·파일 업로드·기존 로컬 가드 회귀 1,171건 통과, 환경 조건부 300건 건너뜀. 신규 실행기와 서비스 ESLint 및 기존 `.next` 생성 검증 파일을 제외한 소스 TypeScript 검사 통과. 소유 리스너·프로세스·임시 클러스터를 정리했다.

Storage는 경로별 쓰기 차단 및 이미 수락한 쓰기의 종료를 명시적으로 알려주는 **루프백 시험 공급자**다. 실제 Supabase의 같은 보장, TTL과 역할, 자동 재조정 작업은 검증하지 않았다. HTTP 호출에는 제한 시간이 있고, 정리 재시도는 서비스의 명시 호출로 시험했다. 후보는 PNG 한 건, 루프백 Storage, 소유 PG17으로 제한된다. 기존 제품 POST·SQL·운영 설정은 그대로이며, 프로젝트 생성 조립은 후속 배정 범위다.
