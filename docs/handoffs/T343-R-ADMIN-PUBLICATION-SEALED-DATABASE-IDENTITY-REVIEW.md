# T343-R 승인 DB 식별자 결합 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `5eecc8e` · Master 배정 `msg_323892ecf0b5`

**격리 검수 통과.** 소유 PG17 직접 TLS에서 승인 DB OID가 관리자 게시·공개 목록·표지의 실제 세션과 일치함을 확인했다. 일치하지 않으면 신규 조립 또는 작업 콜백 전에 차단됐고 관련 자원을 정리했다.

- T342는 독립 설치 검증이 끝나면 계획의 `databaseOid`를 게시 DB 구성에 전달한다. 서버 설정으로 OID를 별도 제공하면 먼저 계획과 일치해야 한다. T330은 기동과 각 작업의 새 TLS 연결에서 현재 OID를 읽고 콜백 전에 대조한다. 승인값이 없는 기존 직접 호출은 첫 검증 연결을 기준으로 삼으며, 호스트·포트·DB·클러스터로 구성된 `targetId` 반환 형식을 유지한다.
- 기본 실행 모드에서 관리자·목록·표지별로 실제 세션의 OID가 승인값과 같았다. 같은 클러스터의 복제 DB로 이름을 교체하자 각 역할을 단독으로 시도한 세 그룹 모두 작업 콜백에 진입하지 못했고 그룹 전체가 닫혔다. 원래 OID로 여는 새 검증과 잘못된 형식의 OID도 거절됐다. 복제 DB의 새 OID를 직접 지정한 별도 T330 검사가 통과했다. 그 검사는 연결 대상 확인이다.
- `--sealed-publication-runtime`에서 승인 계획 또는 명시 서버 구성의 OID를 다르게 하면 관리자 목록은 닫히고 쓰기는 503, 공개 홈은 샘플, 표지는 404였다. 비공개 Storage 호출은 추가되지 않았다. 같은 승인 OID의 명시 구성은 조립됐고 정상 흐름에서 관리자 준비·게시, 공개 피드, 비공개 Storage에서 읽은 WebP, 철회 뒤 피드 제거·404가 통과했다.
- 기본 T328 TLS 22건과 T330·T332·T336, 위임 설치 T341 및 연결 조건 T342가 통과했다. 두 실행에서 검증·런타임 세션과 Storage 서버, PG 수신기·임시 클러스터를 정리했다. 소유 PG 프로세스 0건과 검수 사본 제거를 확인했다.
- 관련 회귀 26개 파일 642건과 PG 종료 뒤 단일 워커로 실행한 비공개 자산 회귀 1개 파일 54건이 통과했다. 소스 타입 검사, 변경 TypeScript 4개 ESLint와 커밋 diff 공백 검사도 통과했다.

작업마다 실제 DB OID를 확인한다. 가동 중 설치 이력 재검증은 이번 판정 범위 밖이며, 별도 관리형 대상·실제 운영 Storage·제품 활성화도 검증하지 않았다. 기본 제품 구성은 비활성이다. 운영·빌드·배포 변경은 없었다.
