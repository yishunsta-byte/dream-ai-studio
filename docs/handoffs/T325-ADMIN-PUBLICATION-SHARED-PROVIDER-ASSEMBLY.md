# T325 관리자 게시 저장소와 공개 리더의 서버 조립

2026-11-19 KST · Codes(Backend) · Master 배정 `msg_2b45fc25e2ca` · 기준 `0cd4b61`

서버 초기화에서 `assemblePublicationProviders()`에 승인 대상으로 삼을 DB 식별자와 관리자·공개 공급원 초기화 함수를 전달한다. 관리자 쓰기, 공개 목록, 공개 표지 연결이 각각 확인한 대상이 모두 일치하고 기존 저장소 계약을 충족하면 한 번에 활성 상태를 반환한다. 같은 이름을 가진 별도 DB가 구분되도록 식별자에 클러스터와 DB를 함께 포함한다. 초기화 함수는 실제 서버 자격과 권한을 확인한 뒤 대상 식별자를 반환할 책임이 있다. 이번 모듈은 초기화 함수가 확인한 결과를 대조한다. 요청의 헤더·쿼리나 환경변수를 직접 읽는 경로는 없다. [서버 조립](../../lib/public-showcase/publication-provider-assembly.ts)

- 관리자 공급원은 기존 `AdminPublicationStore.transaction` 계약을 유지한다. 공개 공급원은 T304 `createPublicationShowcaseConnection()`으로 목록과 표지 저장소, 표지 바이트 읽기와 전송 직전 확인을 함께 검증한다. 어느 한쪽이라도 누락·대상 불일치·초기화 실패가 발생하면 관리자 저장소는 `null`, 공개 목록은 예시 모드, 표지는 비활성 상태로 반환한다.
- 초기화에 실패하면 이미 반환된 공급원 핸들을 닫는다. 성공한 조립의 종료는 호출자가 소유하며, 종료를 여러 차례 호출해도 같은 작업을 기다린다. 둘 중 하나가 종료에 실패해도 나머지 종료 시도를 끝까지 기다린다. 초기화 함수 자체가 핸들을 반환하기 전에 실패하면 해당 초기화 함수가 자원을 정리한다.
- T293의 트랜잭션 계약, T295의 공개 세대·권리 만료 조건, T306의 관리자 쓰기와 공개 읽기를 동일한 커밋에 연결하는 흐름을 시험의 기준으로 삼았다. 신규 시험은 합성 저장소와 메모리 안의 WebP를 사용한다. 기존 HTTP·게시 서비스와 공개 목록·표지 공급원으로 준비, 게시, 철회, 새 세대 재게시, 권리 만료를 실행한다. 이전 표지의 GET·HEAD는 계속 `404`이며, 바이트를 읽는 도중 권리가 만료되면 전송 직전 확인에서 `404`로 응답한다. ## 독립 검수와 다음 연결 조건

Tester는 승인 대상 불일치 시 세 공급원이 함께 닫히는지, 백엔드 커밋과 공개 조회가 같은 세대·만료 결과를 따르는지, 부분 초기화와 종료 오류에서 각 자원이 정리되는지 확인한다. 이후 실제 신뢰 서버 초기화 함수에서 DB 식별·제한 역할·TLS를 검증하고 비공개 표지 Storage를 연결한 뒤, 제품 진입점 연결을 별도 작업으로 검증한다. 이번 변경은 서버 모듈·시험·이 문서 세 경로에 한정한다. 관리자와 공개 홈의 기본 공급원은 현재 상태로 유지된다.
