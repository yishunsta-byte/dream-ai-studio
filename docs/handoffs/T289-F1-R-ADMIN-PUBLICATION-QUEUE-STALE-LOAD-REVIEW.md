**판정 — 수정 후 재검수.** 원래의 동시 조회·쓰기 재현은 차단됐고, 유효한 같은 버전의 목록은 기존 UUID를 보존합니다. 목록 실패 뒤 같은 버전으로 복구하는 경로와 `initial`만 바뀐 경로에서 상태 유실을 각각 재현했습니다. [F1 인계](T289-F1-ADMIN-PUBLICATION-QUEUE-STALE-LOAD.md) · [원 검수](T289-R-ADMIN-PUBLICATION-QUEUE-REVIEW.md)

## F289-F1-A — 목록 실패가 미확정 UUID를 삭제

1. 준비를 완료해 v1을 만든 뒤 게시 응답이 유실된 상황을 주입했습니다. 공급자는 게시를 커밋하기 전에 오류를 반환했고 화면에는 같은 요청 재시도가 표시됐습니다.
2. 목록을 새로 불러올 때 오류를 주입했습니다. 실패 화면을 통해 다시 요청하자 공급자는 이전과 같은 v1/준비 세대 1을 반환했습니다.
3. 기존 재시도 버튼이 사라졌습니다. 권리를 다시 확인해 게시하자 최초 게시와 다른 UUID가 전달됐습니다.

실패 응답이 `setRows({})`에 해당하는 분기를 타면서, 권위 있는 새 버전을 보기 전에 재시도 상태가 삭제됩니다. 조회 실패에는 미확정 요청을 유지하고, 정상 목록에서 동일 버전인지 확인한 뒤 같은 UUID를 복구하는 회귀가 필요합니다. [목록 처리](../../components/admin/publication-queue.tsx#L88)

## F289-F1-B — `initial`만 교체하면 이전 응답이 새 화면을 덮음

v0의 목록 응답을 보류한 채 부모에서 `initial`을 새 제목과 v5로 교체했습니다. `load`와 `apply` 참조는 그대로 유지했습니다. 화면은 새 제목과 v5로 초기화됐지만 이전 응답을 풀자 옛 제목과 v0으로 되돌아갔습니다. 초기화 조건은 `initial`, `load`, `apply`를 비교하며, 응답을 무효화하는 효과는 `load`와 `apply`가 바뀔 때만 실행합니다. 화면 초기화와 요청 세대 폐기 조건이 일치해야 합니다. [초기값 교체](../../components/admin/publication-queue.tsx#L77) · [응답 세대 판정](../../components/admin/publication-queue.tsx#L93)
