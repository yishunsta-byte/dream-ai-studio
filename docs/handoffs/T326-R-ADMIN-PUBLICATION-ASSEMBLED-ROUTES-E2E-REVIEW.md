## F326-1 · 동시 합성 표지 요청이 하나의 트랜잭션을 공유함

정상 재게시 이후 허용된 다음 세대 6에 동일한 `/cover` 요청 12건을 보냈다. 12건 모두 HTTP 500이었다. 한 건은 `cover_objects_pkey` 중복 키를 반환했고, 나머지는 중단된 트랜잭션으로 실패했다. 제어 HTTP 핸들러의 `BEGIN`·행 잠금·조회·쓰기·종료가 공유 `admin` 클라이언트에 걸려 있어, 동시 요청의 문장이 같은 세션 트랜잭션에 섞인다. 한 요청이 잡은 행 잠금은 같은 트랜잭션 안의 다른 처리와 직렬화하지 않는다. 시험 제어 경로에서 재현했으며 관리자 게시 API의 원장 경합 검사는 통과했다. [제어 핸들러](../../tests/admin/t306-publication-e2e-native.ts#L241) · [표지 작성 트랜잭션](../../tests/admin/t306-publication-e2e-native.ts#L280)

표지 요청마다 별도 DB 연결의 트랜잭션을 사용하거나 제어 연결 전체의 사용을 직렬화한 뒤, 동시 동일 세대에서 한 번만 생성하고 나머지는 재사용되는 회귀가 필요하다.

## 회귀와 정리

기존 T306 `--scenarios`에서 시한 일치, 불일치 6종 롤백, 42501 읽기 역할 경계 및 만료를 재현했다. 관련 Vitest 19개 파일 541/541, 고정 사본의 생성물 없는 TypeScript 검사, 변경 실행기·주입 ESLint 및 `git diff --check`가 통과했다. 개발 서버 재현 첫 시도는 종료 명령 오류로 중단됐고, 두 번째 시도에서 소유 프로세스 종료와 모드별 리스너 0을 확인했다. 소유 PG 클러스터와 임시 사본을 정리했다.

대상 증명은 격리 루프백 주소·포트·DB 및 실제 시험 역할 기준이다. 운영 클러스터 식별·TLS·비공개 Storage 또는 production의 호스트 동작은 별도 범위다. 제품 진입점, 운영 DB·Storage와 배포를 변경하지 않았다.
