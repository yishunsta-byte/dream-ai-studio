# T338 게시 SQL 설치 후보와 적용 이력 검증

2026-11-19 KST · Codes(Backend) · 기준 `a908c55` · Master 배정 `msg_19ae6682fab7` · 격리 실행기 승인 `msg_82de5fa18401`

게시 전용 고정 버전 1 SQL을 추가했다. T253의 세대·상태 전환, T293의 작품·요청 원장·감사, T295의 권리·유효기간·공개 읽기, T332 `rights_state()`를 하나의 설치 후보로 구성했다. 기존 `0001`~`0005`와 이관 CLI·manifest·이력은 그대로 쓴다. 루프백 fixture의 고정 승인자·로그인, 합성 시드, 표지 바이트와 자격은 설치 후보에 포함하지 않았다. [게시 SQL](../../lib/db/postgres/publication/0001_publication.sql)

## 권한과 외부 입력

- 승인된 별도 운영 담당이 기존 제한 DB 로그인 OID와 실제 Auth UUID를 `t293.actor_bindings`에 연결하고 `t253_showcase.publishers`에 게시 권한을 등록한다. `t_publication_authority`는 이 두 업무만 수행하는 NOLOGIN 그룹이다. 실제 로그인과 그룹 부여는 외부 관리 입력이다.
- `t293.actor()`는 세션 로그인 OID와 해당 트랜잭션의 검증된 UUID가 모두 맞을 때만 반환한다. 같은 이름으로 재발급한 로그인은 새 OID에 대한 바인딩이 필요하다. 관리자 로그인은 바인딩 테이블을 직접 읽거나 구형 쓰기 함수를 호출할 수 없다. 기존 T330 검사와 같이 `t295_writer`의 내부 호출만 허용하며 `t295_list`와 `t295_file`은 각 공개 읽기 함수만 사용한다.
- 실제 원본·완성본·권리 증빙과 표지 객체의 공급은 후속이다. `t293.cover_objects` 합성 바이트 테이블을 배제했으며, 표지는 기존 서버 전용 Storage 의존성을 쓴다.

## 설치와 검증 계약

`publicationInstallation()`은 승인된 별도 유휴 TLS 세션과 예상 DB 이름·클러스터 식별자·포트·설치 로그인만 받는다. 같은 세션에서 PG17 주 서버, TLS 사용, 대상 및 실제 세션 역할을 확인한다. 연결 자체와 호스트의 인증서 검증은 호출자가 소유한다. `verify`는 읽기 전용이며, `install`은 트랜잭션 잠금 뒤 상태를 다시 읽는다. [설치·검증 코드](../../lib/db/postgres/publication/installation.ts)

- 고정 SHA-256 `0d675b8f5f2b523da02a004fbe410d640ff6fb468ed7fb092e79904ad0a2b26f`의 소스만 읽는다. 새 상태에서는 SQL, 권한 및 카탈로그 검증, `t_publication_install.history` 행을 같은 트랜잭션으로 확정한다. 같은 대상에 다시 실행하면 이력 시각과 카탈로그를 보존한다.
- 설치 이력의 소스 해시와 대상 DB의 카탈로그 해시를 대조한다. 대상 스키마·테이블·열·제약·인덱스·정책·함수·ACL과 내부 역할 간선을 검사한다. 외부 로그인 발급과 승인 데이터 행은 카탈로그 이력에 넣지 않는다. 이력이 없는 일부 객체, 권한 차이 또는 공개 ACL이 있으면 그대로 중단한다.
- 중간 실패는 롤백한다. 쓰기 COMMIT의 응답을 잃으면 `unknown`을 반환한다. 승인된 대상의 이력과 카탈로그를 새 세션에서 `verify` 한 뒤 재실행 여부를 결정한다. 설치 상태 확인을 이유로 이력을 고쳐 쓰거나 일부 객체를 채택하지 않는다.

## 자체 검증

`node --conditions=react-server --import tsx tests/public-showcase/t328-publication-db-preflight.pg17.ts --publication-installation`으로 기존 소유 PG17.12·TLS 실행기를 사용했다. 새 모드는 기존 시험 SQL 대신 설치 후보를 적용한다. [전용 설치 시험](../../tests/public-showcase/t338-publication-installation.pg17.ts)

- 잘못된 대상, 진행 중인 세션, 부분 역할 상태를 차단했다. 게시 스키마와 역할을 일부 만든 시점에 시험 전용 DDL 이벤트로 예외를 발생시켜, 스키마·역할·이력이 전부 사라지는 것을 읽기 검증으로 확인했다.
- 서로 다른 두 세션에서 동시에 설치하면 한 번만 적용됐다. 이후 재실행은 최초 이력 시각과 해시를 보존했다. 목록/표지 권한 교차, 공개 테이블 ACL, 이력 해시 불일치는 차단됐다.
- 설치 뒤 별도 로그인과 외부 운영자 바인딩을 만들었다. 관리자 역할의 직접 읽기·구형 쓰기, 다른 로그인 UUID 위조와 같은 사용자 이름 재발급 때 예전 바인딩 사용을 거절했다. T332 어댑터로 준비·실제 게시·동일 요청 재전송·공개 표지 조회·철회를 확인했다.
- 무인자 기존 T328/T330/T332/T336 실행기와 관리자·공개·Storage 회귀 299건이 통과했다. 두 소유 PG17 실행의 리스너와 임시 클러스터를 모두 정리했다. 변경 TypeScript ESLint 및 생성된 `.next` 검증 파일을 제외한 소스 529개 진입 파일 타입 검사도 통과했다.
