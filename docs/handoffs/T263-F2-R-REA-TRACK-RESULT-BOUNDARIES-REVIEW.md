**기존 세 재현은 해소됐다. 합성 UX와 로컬 검사는 진행할 수 있으며, 실제 영상 시간 탐색·공유 연결은 첨부 표지 보완까지 보류한다.** 정렬, 작업 종료 finding, 신고 크기 분리의 변경 방향은 확인했다. 추가 합성 MP4에서 정지 표지 이미지를 재생 가능한 영상 트랙으로 처리하는 경계 결함을 재현했다. [보완 설계](T263-F2-REA-TRACK-RESULT-BOUNDARIES.md) · [직전 독립 검수](T263-F1-R-REA-CONTRACT-BOUNDARIES-REVIEW.md)

## P1 · 첨부 표지가 영상 시간축으로 인정됨

- 음원 1500ms와 정지 PNG 표지만 담은 합성 MP4에서 실제 ffprobe는 표지를 `codec_type=video`, `disposition.attached_pic=1`로 반환했다. 검사기는 완료와 영상 트랙 `0–1500ms`를 반환했다. 같은 결과에 `900–1000ms` 영상 근거를 추가할 수 있었고 소유자 DTO의 `seekable`이 `true`였으며, 선택 공유에도 이 시간 범위가 들어갔다. [ffprobe 항목 및 트랙 판별](../../lib/reference-analysis/local-file.ts)
- 실제 500ms 영상·1500ms 음원에 같은 표지를 붙인 합성 MP4에서는 재생 영상과 표지가 모두 영상 트랙 후보로 집계됐다. 결과에서 재생 영상 트랙이 누락됐고, 유효 영상 탐색에 필요한 시간축을 잃었다. 실제 영상 트랙이 두 개 있는 표본에서 시간축을 미확인으로 두는 동작은 설계와 일치했다.
- 최소 보완은 ffprobe의 `stream_disposition.attached_pic`을 읽고, 영상 트랙 수·치수·시간축과 필수 트랙 존재를 판정할 때 첨부 표지를 제외하는 것이다. 음원과 표지만 있는 `.mp4`는 영상 트랙이 없으므로 현 영상 분류에서는 유효하지 않은 파일로 처리한다. 정상 영상과 첨부 표지가 있는 MP4는 유일한 재생 영상 트랙의 구간을 유지한다. 두 표본을 회귀 시험에 포함해 소유자 탐색과 공유 위치를 함께 확인한다.

## 통과한 범위

- 별도 합성 MP4와 실제 ffprobe에서 영상·음원·컨테이너 길이 **500 / 1500 / 1500ms**를 다시 관측했다. 로컬 검사는 영상 `0–500ms`, 음원 `0–1500ms`를 반환했다. 영상 `490–500ms`는 채택돼 소유자 탐색이 가능했고, `500ms` 시작점과 `900–1000ms`는 거절됐다. 300ms 시작 지연을 준 실제 영상은 `300–800ms`로 정렬돼 `299ms` 시작을 거절했다. 영상 두 개와 음원 하나를 넣으면 영상 근거는 소유자 화면에서 참고용으로 남고, 공유 위치는 생략됐다.
- `cancelled`, `timed_out`, `inspection_failed`, `local_tool_failed`, `local_tool_unavailable`는 상태와 같은 원인의 전체 범위 `file_metadata` 미확인 항목 하나를 통과시켰다. 이전 관찰, 추가 항목, 다른 원인·주제는 거절됐다. 소유자가 종료 항목을 선택해 공유하면 분류와 한정된 원인만 나왔다. 네이티브 시험에서 실행 파일 부재·실패와 실제 합성 자식 프로세스의 취소·타임아웃 및 종료를 재검증했다. [결과 스키마](../../lib/reference-analysis/result.ts) · [표시·공유 투영](../../lib/reference-analysis/projection.ts)
- 로컬 검사의 `observedBytes`는 실제 합성 파일 크기와 같았으며 표시·공유의 `sizeBytes`로 전달됐다. `values.sizeBytes`에만 있는 신고값, 실제 크기와 불일치하는 `observedBytes`, 완료 상태 없는 관측 크기의 거절·제외를 확인했다. 공유에는 합성 비공개 파일명과 관찰 문구가 들어가지 않았다. [표시·공유 투영](../../lib/reference-analysis/projection.ts)
- 이전 정상 v1 JSON을 새 스키마가 읽었다. 이전 길이 메타데이터는 표시되며, 별도 트랙 시간축 없는 근거는 `seekable: false`이고 공유에 시간 범위가 없다. 이전 스키마의 엄격한 객체 형태는 새 `timeline`·`observedBytes`를 수용하지 않으므로 생산자와 판독기는 함께 갱신해야 한다. 실제 저장, 사용자 권한, 작업 세대 귀속과 원자적 종료 반영은 후속 연결 범위다.
