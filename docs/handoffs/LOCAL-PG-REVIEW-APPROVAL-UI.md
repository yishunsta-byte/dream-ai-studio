# 로컬 PG 편집 완료와 검수 승인 화면

## 범위

설계 `4a15bfd`, 검수 API `722c7c7`, 렌더 도착 초점 `8a65859`를 기준으로 로컬 PG 쇼핑 숏폼의 편집·검수 화면을 연결했다. 편집 화면에서 리비전을 확인하고 검수로 이동한다. 검수에서는 공통·분야별·조건별 항목과 필수 통과 수를 확인한다. 항목별 판정과 메모를 함께 저장하며, 입력 중인 메모가 있으면 승인 전에 저장하도록 안내한다. 승인한 버전은 판정과 메모를 읽기 전용으로 표시하고 영상 만들기 화면으로 연결한다.

다른 탭의 수정으로 리비전이 바뀌면 최신 상태를 다시 읽고 입력 중인 메모를 유지한다. 승인 응답을 잃으면 ‘승인 상태 다시 확인’에서 GET으로 현재 결과를 조회한다.

## 인계

통합 검수는 `8a65859` 이후 화면에서 승인한 현재 리비전으로 렌더 요청을 이어서 확인할 수 있다. 이 화면 검증은 로컬 Next와 PG17에서 렌더 화면 진입까지 수행했다. 운영 환경과 사용자 실자료는 이번 브라우저 검증 범위 밖이다. 서버의 렌더 요청 허용 조건은 [Tester의 별도 PG 검수](FIRST-WORK-PG-REVIEW-APPROVAL.md)에 기록되어 있다.

## Tester 독립 검수와 실제 렌더 접수

고정 커밋 `c2ca978577f09a4dd59e088b604233fa26db3c76`에 렌더 도착 초점 수정 `8a65859`가 포함된 것을 확인했다. 실제 로컬 Next.js·임시 PG17과 Chromium 390px·1280px를 사용했다. 폭마다 새 합성 프로젝트를 열었고, 제작 승인 및 검증 PNG 한 장의 선택을 시험 데이터로 준비했다. 첫 타임라인과 WAV 첨부·저장은 제품 HTTP로 생성했다.

- 편집 완료를 Enter로 실행하자 검수 화면의 ‘현재 버전 검수’ 제목에 초점이 갔다. 필수 13개를 키보드로 판정했으며 각 통과 후 해당 항목 제목에 초점이 돌아왔다. 음악 권리만 남아 있어도 승인 버튼은 접근 가능한 비활성 상태였다.
- 음악 권리 통과 후 승인하자 승인 결과 제목에 초점이 갔다. Tab은 ‘영상 만들기로 이동’ 링크로 갔고, Enter 후 경로는 `/render#local-render-heading`였다. 두 폭 모두 도착 제목이 실제 활성 요소였고 가로 넘침은 0px였다.
- 렌더 요청은 실제 202였다. 첫 응답을 브라우저에서 유실시킨 뒤 같은 키와 본문으로 재확인했고, 별도 키로 같은 기준을 다시 요청해도 같은 job ID였다. ‘대기 중’ 및 결과 초점을 확인했다. 390px의 작업은 `01a1f48a-59ae-7408-a46a-d73e21544f22`, 1280px의 작업은 `01a1f48a-91c7-7590-9bca-fe45b1eb4f86`였다. 프로젝트마다 완료·승인·접수 활동과 대기 작업은 각각 1건이었고 렌더 결과는 0건이었다.

렌더 화면 자동 테스트 8건 및 브라우저를 포함한 HTTP·PG17 실행이 통과했다. 첫 실행의 편집 화면 대기 초과는 진단을 추가한 다음 실행에서 재현되지 않았고 원인은 확인되지 않았다. 서비스 및 임시 PG17은 종료했다.
