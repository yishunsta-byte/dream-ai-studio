# T288 작업실 분석 전용 Supabase 인증 전송

기준 `868e3c2` · Backend 자체 검증 · `@supabase/ssr` 0.12.7 · `supabase-js`와 `auth-js` 2.119.0

루프백 합성 환경에서 요청별 SSR 클라이언트 하나로 `getUser()`의 사용자 조회와 만료 세션 갱신을 검증했습니다. SDK가 호출하는 두 정확한 주소에만 요청 기한과 취소 신호를 전달합니다. 응답은 전체 JSON이 256 KiB 이내로 도착해야 SDK에 전달됩니다. 취소, 전송 실패, 리디렉션, 5xx, 비정상 응답은 내부 `AUTH_UNAVAILABLE`로 닫습니다. SDK가 네트워크 예외와 5xx로 갱신을 재시도하는 동작을 확인하고, 이 경로에서는 전송 실패를 재시도하지 않는 SDK 오류로 변환했습니다. [구현](../../lib/reference-analysis/studio-analysis-auth.ts)

쿠키는 요청 시작 시 사본으로 읽습니다. 정상 갱신으로 받은 토큰은 같은 클라이언트의 후속 사용자 검증에 쓰이며 분석 응답은 검증된 사용자 ID와 이메일만 반환합니다. 분석 클라이언트에는 외부 `setAll` 저장소나 쿠키 게시 경로가 없습니다. 취소된 요청에는 이후 인증 결과를 반환하지 않습니다. 기존 공용 Auth와 제품 라우트는 그대로 사용합니다.

## 루프백 검증

- 집중 10/10 통과. 실제 SDK의 만료 쿠키 갱신 POST, 갱신 토큰을 사용한 사용자 GET, 같은 요청과 다른 요청의 세션 격리를 확인했습니다. 쿠키 속 사용자 정보와 사용자 조회 응답을 다르게 제공해 조회 응답이 사용됨을 확인했습니다.
- 사용자 조회와 갱신 각각에서 헤더 또는 본문을 지연했습니다. 요청 취소와 기한 초과 시 서버에서 미완료 연결이 닫혔고, 늦은 성공을 보내도 추가 전송·인증 성공·외부 쿠키 변경이 없었습니다. 갱신 직후 사용자 조회를 취소해도 같은 결과였습니다. [집중 시험](../../tests/reference-analysis/studio-analysis-auth.test.ts)
- REA·비공개 저장소·타임라인·오디오·공용 API 인증 **22개 파일 410/410** 통과. 범위 TypeScript와 변경 TypeScript ESLint `--max-warnings 0`을 통과했습니다.

## 운영 연결 전 확인 범위

HTTP 연결 종료로 서버가 이미 처리한 갱신이나 갱신 토큰 회전이 취소되지는 않습니다. 루프백은 외부 쿠키 격리와 후속 읽기 차단을 검증했습니다. 실제 연결 전에는 분석 요청과 공용 세션 갱신의 책임, 동시 갱신 및 회전 후 재시도 동작을 검증해야 합니다. 테스트는 로컬 합성 쿠키·키만 사용했습니다.
