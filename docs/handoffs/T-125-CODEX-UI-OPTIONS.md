## 2. 새로 만든 세 방향

세 안 모두 같은 가상 콘텐츠(온기를 담은 하루 / 가볍게 떠나는 주말 / 우리 동네 작은 가게)를 사용한다. 색만 바꾸지 않고 탐색·작업실 우선순위·편집 패널·렌더 배치를 다르게 구성했다.

| | 01 스튜디오 데스크 | 02 플로우 컨트롤 | 03 포커스 캔버스 |
|---|---|---|---|
| 방향 | 익숙한 흐름에서 다음 행동을 분명하게 | 진행 작업·막힌 작업을 먼저 | 내가 만드는 콘텐츠를 먼저 |
| 탐색 | 글자 있는 왼쪽 사이드바, 모바일 메뉴 | 좁은 아이콘 레일 + 항상 보이는 작업 요약, 모바일 메뉴 | 위쪽 탐색과 여백, 모바일 메뉴 |
| 작업실 | 상태 요약 → 이어서 편집 → 프로젝트 목록. 오른쪽 진행·활동 패널 | 확인할 작업 / 만드는 중 / 이어서 편집의 세 작업 열 | 큰 작품 미리보기와 문구 편집 진입 → 작품 모음 |
| 편집 | 미리보기와 글자 목록·설정의 두 열 | 글자 목록 / 미리보기 / 설정의 세 열 | 넓은 미리보기 + 오른쪽 설정 묶음 |
| 렌더 | 진행·결과 왼쪽, 포스터·사양 오른쪽 | 큰 진행 카드·결과 + 작업 대기·사양 패널 | 큰 작품 포스터 왼쪽, 진행·사양 오른쪽, 결과 아래 |
| 모바일 | 다음 할 일 → 프로젝트 → 작업 상태 | 확인 필요 → 진행 → 편집 순서 | 작품 미리보기 → 편집 진입 → 작품 목록 |
| 장점 | 현재 앱에서 이어가기 쉬움. 행동과 상태의 균형 | 여러 프로젝트의 막힘·진행을 찾기 쉬움 | 장면의 느낌을 넓고 편안하게 볼 수 있음 |
| 단점 | 구조 변화의 새로움은 상대적으로 적음 | 정보량이 많고 아이콘 레일의 학습이 필요 | 작업 비교를 위해 더 내려야 함. 모바일 렌더에서 포스터 뒤에 상세 진행이 옴 |

**추천 순위: 01 → 03 → 02.**

현재 개인 작업실의 기능·경로를 유지하면서 개선하기에는 01이 가장 안정적이다. 장면에 집중하는 인상을 우선한다면 03이 두 번째 선택이다. 여러 프로젝트의 처리 상황을 자주 오가는 사용 방식이 우선이면 02의 순위가 올라간다. 비교 페이지의 01 추천은 디자인 의견이며 사용자 선택 완료로 처리하지 않았다.

01은 기존 선택 A의 사용 연속성을 참고했지만, 기존 HTML을 복사해 덮지 않았다. 흰색 사이드바·다음 행동 카드·상태 패널·새 코드 기반 제품 그림으로 새로 제작했다. 02·03도 기존 T115 파일과 독립된 새 마크업·스타일이다.

## 3. 현재 기능과 정직한 상태 표시

- 수정·조립 하위의 영상 만들기를 유지하고 제작 단계 7개를 늘리지 않았다. 이후 단계가 잠기는 이유를 연결했다.
- 저장된 타임라인·내용 버전, 필수 광고 표기와 시간 고정, PC 타임라인·390 제한을 보여 준다.
- 렌더는 준비 / 장면과 글자 합치기 / 파일 확인의 세 단계다. 64%·프레임·지난 시간은 **가상 상태**라고 명시한다. 근거 없는 남은 시간·실제 완료를 만들지 않았다.
- 결과에는 샘플, 지금 내용과 다름, 확인 실패, 소리 없음, 자막 오차 측정 전·휴대폰 확인 전을 구분한다.
- 가상의 '파일 확인 통과'에는 '예시'를 붙였다. 실제 파일이 없어 내려받기를 막고 이유를 안내한다. 확인 실패에는 재생·download를 만들지 않았다.
- T119 최신 명칭인 **계속 만들기 / 취소하기**, **영상 보기**를 참고했다. 시안의 재생 아이콘은 실제 영상이 없음을 설명하며 성공한 재생을 연출하지 않는다.
- 모든 화면에 가상 데이터·동작 미연결 표시를 두고, 화면별 독립 상태라는 점을 설명한다. 화면 안 입력은 textContent로 미리보기에만 반영하고 서버·localStorage에는 저장하지 않는다.
- 그림은 CSS로 그린 가상의 텀블러·여행 풍경·제품이다. 사진·외부 AI·이미지 생성 서비스는 사용하지 않았다. 원본 사진·실제 상품 결과로 표시하지 않는다.
