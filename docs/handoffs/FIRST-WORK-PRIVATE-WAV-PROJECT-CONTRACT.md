## 최소 변경 제안

기존 쇼핑숏츠 프로젝트에 **선택적 제작용 음원 한 건을 연결**하는 로컬 전용 PUT과 해당 자료 목록 GET부터 진행한다. 제안 경로는 PUT /api/projects/{id}/audio-assets/{assetId}, GET /api/projects/{id}/audio-assets다. purpose는 서버가 productionAudio로 고정한다. 업로드 경로나 메뉴 정의에 클라이언트 지정 역할과 소유자 입력을 추가할 필요가 없다.

- 기존 검증 세션에서 소유자를 얻는다. 별도의 제한된 서버 역할·RLS로 같은 소유자의 프로젝트, 보관되지 않은 audio/wav 자산, local_wav.files의 검증 등록을 단일 DB 트랜잭션에서 대조한다. 파일 ID·해시·크기·재생 시간·저장 키의 일치를 확인한다. local_wav의 업로드 권한이나 생성자 역할을 확대하지 않는다.
- 프로젝트와 자산의 보관·변경 경합을 직렬화하고, 동일 자원 PUT은 같은 첨부를 반환한다. 기본키로 동시 중복을 막고, 최초 삽입과 활동 기록 한 건을 같이 커밋한다. 재시도 요청에도 현재 소유권·파일 상태를 다시 검사한다. 행 잠금에 필요한 권한은 로컬 역할 설치 시험에서 확인한다.
- 이 연결은 편집 전 자료 선택이다. 타임라인, 렌더, 기존 승인본 또는 입력 스냅샷을 바꾸는 작업은 별도 계약이 필요하다. 목록은 내 프로젝트에서 사용할 음원 ID·제목·재생 시간·권리 메모만 반환한다. 범위 선택 전에는 기존 프로젝트 상세 응답을 확장하지 않는다.

## 완료 시험

1. 실제 로컬 HTTP로 PNG 쇼핑숏츠를 생성하고 WAV를 올린 뒤 연결한다. 목록을 별도 요청으로 다시 열어 저장된 제목·길이·메모를 대조한다. 기존 제품 이미지 첨부와 프로젝트 생성 재시도 결과가 유지되는지 확인한다.
2. 같은 PUT을 동시에 보내고 응답 유실을 재현한다. 음원 첨부와 활동 기록이 각각 하나이고, 감사 기록 쓰기 실패 시 둘 다 롤백돼야 한다.
3. 타인 프로젝트·타인 WAV·미등록 및 보관 자산·PNG의 음원 사용을 거절한다. 조회에서도 타인 자료를 노출하지 않는다. 첨부 중 보관 경합 시 일관된 결과를 확인한다.
4. 익명·운영·불완전 설정, 기본 SQLite 및 기존 PNG 저장·읽기 회귀를 검사한다. 독립 검수용 고정 커밋을 전달한다.
