# 로컬 PG 프로젝트 기획 초안 저장

Master 배정 `msg_282aa101cc44`. 브리프 승인 구현 `53674a7` 및 공유 PostgreSQL 연결 `72fbed2`가 포함된 작업본에서 기존 기획 화면을 이어서 구현했다.

- 프로젝트 소유자가 대본과 장면 제목·설명·대사·길이를 입력하고 **초안 저장**을 누르면 새 버전이 생긴다. 기획 페이지를 다시 열면 마지막으로 저장된 초안이 표시된다.
- 프로젝트 내용 리비전과 마지막 초안 버전을 모두 확인한다. 두 탭에서 같은 버전을 저장하면 한 건만 성공하고, 충돌한 탭에서는 입력을 복사하거나 저장된 초안을 다시 불러올 수 있다.
- 기존 기획 입력 스키마와 `dream.plans`의 장면 형식을 재사용했다. 테스트 DB 쓰기 역할에는 초안 INSERT만 부여했다. 승인된 기획과 장면·캐릭터·자료 참조가 있는 기존 초안은 이 화면에서 읽을 수 있다. 승인, 장면 제작, 편집은 각 단계의 별도 경로를 따른다.

변경 경로는 프로젝트 기획 화면과 `/api/projects/[id]/plan`, 공용 기획 입력 스키마, 로컬 PostgreSQL 권한, 인증 및 실제 HTTP 회귀 시험이다.

- `npm.cmd run typecheck` 통과.
- `node node_modules/vitest/vitest.mjs run tests/api-auth.test.ts tests/t198-legacy-gate.test.ts tests/planning.test.ts` 256건 통과.
- `T371_VERIFY_HTTP=1`로 `node --conditions=react-server --import tsx tests/postgres/t368-run-private-image-project-create.mjs` 종료 코드 0. 실제 Next.js 서버와 임시 PG17에서 미승인 브리프, 익명·타인 접근, 다른 출처 요청, 구버전 리비전·초안, 동시 저장, 재조회 및 승인·제작·편집 상태를 확인했다. 새 계획은 초안으로만 저장됐고, 프로젝트 승인 포인터는 비어 있었으며 제작·편집은 잠긴 상태였다.
- 같은 HTTP 시험 서버에 연결한 ego-browser에서 초안을 Enter로 저장했다. 첫 탭을 새로고침해 대본과 장면 설명의 저장을 확인했다. 구버전 상태인 둘째 탭에서는 충돌 안내와 입력 보존을 확인한 뒤 **저장된 초안 불러오기**로 최신 버전을 열었다.
