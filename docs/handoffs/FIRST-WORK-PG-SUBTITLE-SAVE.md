# 로컬 PG 자막 읽기와 저장

| 항목 | 계약 |
|---|---|
| GET /api/projects/{id}/timeline/subtitles | 소유자의 현재 timelineId, contentRevision, timelineRevision, subtitles, videoFrames, maxEndFrame, blockedReason을 한 스냅샷에서 읽는다. subtitles는 편집 가능한 자막만 포함한다. |
| POST /api/projects/{id}/timeline/subtitles | expectedContentRevision, expectedTimelineId, subtitles와 UUIDv7 Idempotency-Key를 받는다. 자막 항목은 id, content, startFrame, endFrame이다. 같은 기준의 전체 편집 가능한 자막 목록을 보낸다. 기존 항목이 목록에서 빠지면 삭제하고 새 항목은 뒤에 추가한다. |
| 보존 | 자막 내용과 시간만 수정한다. 기존 자막의 글꼴·스타일·위치, 잠긴 표기, 다른 종류의 글자, 장면·오디오 및 이전 타임라인을 보존한다. 설정상 필요한 표기가 빠진 경우 기존 필수 표기 규칙으로 생성하고 잠근다. |
| 저장 결과 | timelineId, timelineRevision, contentRevision, changed를 돌려준다. 내용이 같으면 changed=false이고 기존 승인과 리비전은 유지된다. 같은 요청 키 재전송용 활동 기록은 남긴다. |
| 충돌과 롤백 | 변경이 있는 저장은 새 버전과 포인터 갱신, 편집·검수·내보내기 단계 변경, 활동 기록을 함께 커밋한다. 이전 기준의 다른 요청은 409다. 같은 키·같은 본문은 이후 저장 뒤에도 최초 결과를 반환한다. |

실제 로컬 Next.js·PG17 시험에서 기존 제목·음원·광고 표기를 보존하고 명시된 설정에 따른 고정 AI 표기를 추가했다. 새로 읽은 한글 여러 줄 자막이 요청과 일치했고, 보호 레이어 ID와 시간 범위 초과를 거절했다. 활동 기록 쓰기가 실패했을 때 리비전과 기존 승인이 롤백됐다. 변경 없는 저장, 같은 키 동시 재시도, 서로 다른 키의 두 탭 충돌, 자막 삭제도 검증했다.

이번 범위는 저장 API다. 화면 연결, 승인 리비전의 SRT·VTT 파일 다운로드 및 MP4에 글자를 넣는 기능은 후속 작업이다.

```powershell
$env:T371_VERIFY_HTTP='1'
$env:T371_VERIFY_RENDER_AUDIO='1'
node --conditions=react-server --import tsx tests/postgres/t368-run-private-image-project-create.mjs
```
