# T275 REA 적용 권한과 영수증 수명

2026-11-19 KST · Codes(Backend) · 기준 `166a3e1c6e3d5cddf0d26f3efd8310ab9fe48551` · 배정 `msg_9917d484b761` · 독립 검수 대기

`evaluateReferenceApplyLifecycle`은 서버가 읽은 현재 권한과 저장 레코드를 받아 정책 결과를 반환합니다. 입력의 구조, 확인 ID와 저장소·복원 세대·소유자·프로젝트·자료 범위를 먼저 대조합니다. 같은 ID가 복제·복원본에 있어도 현재 저장소나 복원 세대가 다르면 대기 실행과 영수증 조회가 모두 거절됩니다. 복원본 게시 전 새 세대를 사용하고, 대기 확인과 진행 분석을 무효화해야 합니다. 이전 세대 영수증을 백업에서 보존하는 경우에는 이력으로만 취급합니다. [현재 정책 함수](../../lib/reference-analysis/apply-lifecycle.ts) · [T274 독립 검토](T274-R-REA-SERVER-APPLY-INTEGRATION-REVIEW.md)

## 신뢰 입력과 계약

| 입력 | 서버 책임 |
| --- | --- |
| 확인 요청 | 발급된 확인 ID와 검증된 의사 `confirm`, 또는 읽기 의사 `read_receipt`만 정책에 전달합니다. |
| 공통 권한 | 검증된 서버 액터, 현재 저장소/복원 세대, 동일 소유자·프로젝트·자료의 범위를 실제 저장소에서 확정합니다. 영수증의 현재 조회권은 `granted`, `denied`, `unverified`로 제공합니다. 로그인 비활성 모드나 요청의 식별자만으로 검증 상태를 만들 수 없습니다. |
| 실행 권한 | 활성 링크·권한 세대와 소스 리비전, 등록 자료 SHA-256, 같은 범위에서 활성인 분석의 당시 링크·권한·소스 리비전과 사본 SHA-256, 분석 ID·리비전·완료/만료 시각, 현재 타임라인 ID·내용 리비전을 제공합니다. 분석에 사용한 **그 사본의 바이트**를 서버가 해시해야 합니다. |
| 레코드와 기준 시각 | 권위 저장소에서 읽은 버전 1 대기 확인 또는 커밋된 완료 영수증과 신뢰 가능한 서버 시각을 제공합니다. 확인 ID는 조회 키이고, 권한의 증거는 서버 액터와 권위 저장소에서 얻습니다. |

상태값 `verified`와 해시 문자열의 형태 검증은 호출자 책임을 대신할 수 없습니다. 권한 조회자는 실제 소유권·활성 관계와 영수증의 현재 공개 가능 여부를 확인해야 합니다. 철회·아카이브·연결 해제·삭제 이후 현재 조회권이 없다면 `denied` 또는 `unverified`를 전달합니다. 세대는 재사용하지 않고 연결과 권한의 부여·철회·복원을 구별해야 합니다. 실제 자료 해시·권한 확인과 세대 발급은 이 로컬 합성 단위의 통합 선행조건입니다. ## 상태별 수명

- **대기 확인.** 명시적 확인만 실행 후보가 됩니다. 현재 링크·권한 세대가 확인의 기준과 일치해야 합니다. 실행 구간은 발급 시각 포함, 만료 시각 제외입니다. 등록 해시와 현재 분석의 사본 해시가 확인 당시 사본과 모두 일치해야 합니다. 분석 ID·리비전과 분석 당시 소스 및 권한 세대, 분석 유효기간을 검사한 뒤 타임라인 ID와 내용 리비전을 대조합니다. 각각 `expired`, `stale`, `conflict`를 반환할 수 있습니다. `eligible`은 현재 입력에 대한 정책 판정입니다. 실제 적용에서는 조회·판정·확인 소비·타임라인 CAS·영수증 기록이 같은 쓰기 트랜잭션에 있어야 합니다.
- **완료 영수증.** 같은 범위에서 현재 조회권이 있고 완료 시각 이상·보존 기한 미만이면 결과를 반환합니다. 실행 만료, 분석 재실행, 이후 타임라인 변경과 무관하게 이미 적용된 리비전을 가리킵니다. `applied`와 `no_change` 모두 종결 영수증으로 반환하며 재전송은 실행 판정으로 이어지지 않습니다. 반환하는 데이터는 결과 유형, 타임라인 ID·리비전·내용 리비전, 완료 시각입니다.
- **거절.** 없음·형식 불일치·권한 미확인·범위 불일치·취소·철회·삭제·커밋 미확정은 공통 `unavailable`입니다. 보존 기간이 지난 영수증도 같은 결과를 반환합니다. 현재 권한에서 접근할 수 없는 기록의 존재나 원본 해시·경로가 응답에 드러나지 않습니다. 커밋 미확정 요청을 실행 가능한 대기로 되돌리는 처리는 이 정책에 포함되지 않습니다.

## 검증

합성 집중 시험 8개로 동일 해시의 옛 링크·권한 세대, 분석 당시의 옛 세대, 두 해시의 각각 불일치, 만료 경계, 취소·철회·삭제·불명 결과, 조회권 없는 완료, 보존 만료, 새 타임라인에서도 원래 완료 영수증 재조회, 복제 저장소·복원 세대를 확인했습니다. 기본 REA 11개 파일에서 **90 통과·45 건너뜀**, 네이티브 포함 **135/135**를 확인했습니다. 범위 TypeScript `tsc -p tmp/t275-rea-typecheck.json`와 변경 파일 ESLint `--max-warnings 0`도 통과했습니다. 새 정책은 제품 호출 경로에 연결되지 않았으며, 실제 권한·해시·복원 및 다중 프로세스 쓰기는 후속 통합 검증 대상입니다.
