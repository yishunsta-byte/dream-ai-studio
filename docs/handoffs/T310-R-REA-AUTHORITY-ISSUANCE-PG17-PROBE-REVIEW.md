# T310-R 발급 요청 직렬화 PG17 독립 재현

기준 `0ec5166` · T309 설계 `ae3431e` · Master 인계 `msg_fd7bda8ddb35` · Codex(Tester)

**판정은 소유 루프백 PostgreSQL 17.12 시험 계약 통과.** 고정 커밋을 임시 사본으로 추출해 실행기를 수정 없이 두 번 재현했다. 실행기의 서명·버전 검사와 SQL1–4·T281·T307 해시 검사를 통과했다.

| 검증 | 독립 재현 결과 |
| --- | --- |
| 예약 COMMIT 대기와 원장 부재 | 지연 제약 트리거가 원래 백엔드를 실제 `COMMIT` 내부에 멈췄고, 별도 연결에서 차단 PID와 대기 상태를 확인했다. 원장 행은 없었다. 같은 요청의 잠금 기한 초과는 `55P03`, 해당 트랜잭션의 후속 조회는 `25P02`였다. 원래 COMMIT 후 같은 키·지문은 기존 예약을 읽었고, 같은 키·다른 지문은 충돌했다. 원장 1행과 포인터 리비전 0을 유지했다. |
| 발급 COMMIT 대기와 예약만 보이는 상태 | 별도 연결은 커밋된 예약과 리비전 0만 관측했다. 원래 발급 COMMIT 후 잠금 대기 중이던 동일 요청은 `changed=false`와 기존 결과를 반환했다. 재조회 후에도 자료 세대가 같았고 포인터는 리비전 1이었다. |
| COMMIT 취소와 롤백 후 재시도 | 발급·최초 예약을 실제 COMMIT에서 각각 취소했다. `57014`와 연결의 트랜잭션 종료를 확인했다. 예약만 남았던 발급은 재시도로 한 번만 반영해 리비전 2가 됐고, 최초 예약은 롤백 확인 후 같은 키로 새 예약만 기록했다. 예약 없이 처리하거나 같은 트랜잭션에서 예약 직후 처리하려는 호출도 거절됐다. |
| 폐기와 늦은 발급 | 폐기가 리비전 3으로 확정된 후 리비전 2를 전제로 한 발급은 `stale_pointer`였다. 이전 성공 조회와 이전 작업 번호의 요청도 포인터를 변경하지 않았다. 최종 상태는 리비전 3의 폐기와 빈 자료 세대였다. |
| 제한 역할과 정리 | 직접 원장 조회, 포인터 변경, 내부 잠금 함수와 보호 역할 전환이 거절됐다. 종료 전에 열린 발급 트랜잭션과 연결이 0건이었다. 두 실행 모두 PID 파일·리스너·임시 클러스터 정리를 통과했고, 별도 호스트 조회에서도 소유 실행 파일의 PostgreSQL 프로세스 및 T310 임시 클러스터가 0개였다. |

시험은 T309의 동일 요청 예약·발급·재시도 직렬화, 잠금 획득 후 READ COMMITTED 조회, 원장·포인터 원자성과 폐기 리비전 보존을 뒷받침한다. T310은 고정된 SQL4 등록 증거를 별도 시험 테이블에 복사하고 합성 소유자 한 명으로 실행한다. 격리 발급자 권한 검사 범위는 테이블·내부 함수·역할 호출이다. 실제 발급 범위와 A/B 권한 행렬, 현재 SQL4 정책·재검증·GC 쓰기 경합, 관리형 풀러의 연결 귀속은 후속 제품 검증이다.

같은 키의 성공 재조회와 실제 COMMIT 취소를 확인했다. 서버 커밋이 성공한 상태에서 네트워크 응답만 유실되는 장애, 서로 다른 발급·폐기 요청의 동시 경합, 실제 복원 조정자와 플랫폼 호출, 보호 HTTP 전송은 별도 시험 대상이다. 실행기 ESLint(`--max-warnings 0`)와 고정 변경의 `git diff --check`가 통과했다. 운영 DB 사용·제품 빌드·배포는 수행하지 않았다.
