## 3. F-016-1 명세 — 장면 실패·대기 표시

### 3.1 필요한 데이터 (구현 담당 판단에 맡기되 아래 값은 화면에 필요)

버전마다 `job` 묶음을 붙인다: `status`, `errorCode`, `errorMessage`(제공자·처리기 원문, 키·경로 제거), `retryable`, `willRetryAt`(대기 중 자동 재시도 시각 = nextRunAt), `attempts`, `queuePosition`(queued일 때), `startedAt`(running일 때). `/jobs`의 `jobsService.list`와 같은 판정(`retryable` 집합)을 재사용해 두 화면 결과가 달라지지 않게 한다.

### 3.2 오류 문장 표 (`lib/ui/errors.ts` 한 곳)

화면 순서: **굵은 첫 문장** → 이유(있을 때, 제공자 원문 한 줄) → **다음 행동** 문장 + 버튼 → 작은 코드 줄.

| 코드 | 굵은 첫 문장 | 다음 행동 문장 | 버튼 | 작은 코드 줄 |
|---|---|---|---|---|
| CONTENT_REJECTED | 제공사가 이 장면을 만들 수 없다고 했어요. | 장면 설명이나 참조 자료를 바꾼 뒤 새로 만들어 주세요. 기획을 고치면 다시 승인해야 해요. | 링크 "기획 고치기"(→ `/projects/[id]/plan`), "자료 바꾸기"(→ `/library`). **다시 시도 버튼 없음** | 코드 CONTENT_REJECTED · 자동 재시도 안 함 · 청구 없음(샘플) |
| STORAGE_FAILED | 결과는 받았지만 저장하지 못했어요. | 저장 공간을 확인한 뒤 저장만 다시 해 주세요. 다시 만들지 않아요. | "저장 다시 시도" | 코드 STORAGE_FAILED · 시도 n회 · 청구 없음(샘플) |
| PROVIDER_DOWN · RATE_LIMITED (대기 중 재시도 예정) | 제공사가 잠시 응답하지 않아요. / 잠시 요청이 많아요. | {시각}쯤 자동으로 다시 시도해요. | (없음) · 취소만 | 코드 … · 시도 n회 |
| PROVIDER_DOWN · RATE_LIMITED · TIMEOUT (실패 확정, retryable) | 제공사가 잠시 응답하지 않아요. / 시간이 너무 오래 걸려 멈췄어요. | 같은 내용으로 다시 시도해 보세요. | "다시 시도" | 코드 … · 시도 n회 · 청구 없음(샘플) |
| INVALID_INPUT | 만들 때 필요한 내용이 빠졌어요. | 기획의 장면 설명을 확인해 주세요. | 링크 "기획 보기" | 코드 INVALID_INPUT |
| BUDGET_EXCEEDED (P3) | 이번 달 예산을 넘어 시작하지 않았어요. | 한도를 올리거나 다음 달에 다시 시도해 주세요. | 링크 "설정 > 예산" | 코드 BUDGET_EXCEEDED · 예약하지 않았고 청구 없음 |
| UNKNOWN · 그 밖 | 결과를 만들지 못했어요. | retryable이면 "다시 시도해 보세요", 아니면 "작업 대기열에서 자세히 확인해 주세요." | "다시 시도" 또는 링크 "작업 대기열 보기" | 코드 … |

- 이유 줄: 제공자 원문이 첫 문장과 같은 뜻이면 생략. 샘플 시나리오 원문("시험용 콘텐츠 거절 시나리오예요…")은 이유 줄에 그대로 써도 된다. 샘플 모드 표시가 화면에 따로 있으므로 숨기지 않는다.
- 청구 문구: P1은 항상 "청구 없음(샘플)". P3부터 DESIGN 6.10 CostTag 규칙을 따른다.
- "다시 시도"·"저장 다시 시도"는 `/api/jobs` retry를 그대로 쓴다. 버튼을 누르면 Toast "장면 1을 다시 시도해요."가 뜨고, 상자는 대기 상태로 바뀐다.

### 3.3 자리 표시 (`ResultPreview`를 상태 기반으로)

| 상태 | 썸네일 자리 | 글자 |
|---|---|---|
| 버전 없음 | 빈 회색 칸 + 이미지 아이콘 | 아직 만들지 않았어요. |
| queued | 시계 아이콘 | 대기 중 · 작업 대기열 {n}번째 |
| running | 흐르는 막대(진행률 모름) + 도는 아이콘 | 만드는 중 · {초}초 지남 |
| failed | 빨간 경고 아이콘, 배경 `--st-danger-bg` | 만들지 못했어요. |
| canceled | 회색 x 아이콘 | 취소했어요. |
| succeeded인데 파일 없음 | 경고 아이콘 | 결과 파일을 읽지 못했어요. 저장 위치를 확인해 주세요. (지금 문구 유지) |

**"결과를 기다리고 있어요."는 queued·running이 아니면 절대 쓰지 않는다.**

### 3.4 장면 카드 기본 화면 규칙

"최근 시도" = 그 장면에서 version 번호가 가장 큰 버전.

| 경우 | 카드 | 썸네일 | 본문 |
|---|---|---|---|
| 최근 시도 실패 + 선택한 성공 결과 없음 | Card `tone=danger`(선만 빨강) | 실패 자리 표시 | 실패 상자 |
| 최근 시도 실패 + 선택한 성공 결과 있음 | 기본 Card | 선택 결과 그대로 | 실패 상자 + 상자 안 첫 줄 위에 작은 글자 "선택한 v{n}은 그대로예요." |
| 최근 시도 queued/running | 기본 | 선택 결과가 있으면 그대로, 없으면 대기·진행 자리 표시 | 한 줄 "v{n} 대기 중 · {n}번째" / "v{n} 만드는 중 · {초}초" + 취소 버튼 |
| 최근 시도 성공·취소 | 지금과 같음 | | |

- 이름 줄의 StatusPill: 위 경우에 맞춰 `failed`/`queued`/`running` 하나를 추가. 선택 결과가 있으면 기존 "선택 v{n}" 문장은 유지.
- 실패 상자는 장면마다 **최근 실패 하나만** 보여 준다. 더 오래된 실패는 "버전 비교" 안에만 둔다.
- 버전 비교 안의 실패 버전: 같은 실패 상자를 작게(코드 줄 포함) 보여 주고 **"이 버전으로 되돌리기" 버튼을 숨긴다**(고를 수 없음은 칩 점선 + 상자로 충분). 버전 칩은 DESIGN 5.3대로 점선 빨강.
- 폴링 중 상태가 실패로 바뀌면 Toast(error, `role=alert`) "장면 {n}을 만들지 못했어요. 이유를 장면 카드에 적어 뒀어요." 한 번만.

### 3.5 크기·배치

- **1280:** 실패 상자는 본문 열(설명 아래, 폭 = 본문 열) 안에 둔다. `--st-danger-bg` 배경, `--st-danger-line` 1px 테두리, radius `--radius-sm`, 안쪽 여백 `--sp-3` `--sp-4`. 첫 문장 `--weight-semibold` `--text-sm` `--st-danger-fg`. 본문 `--text-sm` `--fg-default`. 코드 줄 `--text-xs`(13px 하한, DESIGN 9장) `--fg-muted`. 행동 버튼은 기존 오른쪽 버튼 열 맨 위(primary 하나). 링크형 행동은 상자 안 마지막 줄.
- **390:** 썸네일 72px, 제목 줄 옆. 실패 상자는 카드 전체 폭으로 제목·설명 아래. 버튼은 상자 아래 꽉 찬 폭. 코드 줄은 `overflow-wrap:anywhere`로 줄바꿈해 가로 넘침이 없게.
- 한글 줄바꿈 `word-break: keep-all` 유지. 색만으로 구분하지 않음: 아이콘 + "실패" 글자 + 문장.

### 3.6 접근성

- 실패 상자는 `<section aria-labelledby>`(제목 = 굵은 첫 문장). 늘 보이는 정보라 `role=alert`는 쓰지 않는다(알림은 Toast 한 번).
- "다시 시도" 버튼의 접근 이름에 장면을 포함: `aria-label="장면 1 다시 시도"`.
- 자리 표시 글자는 화면에 보이는 글자 그대로(이미지 대체 글자 아님).

### 3.7 완료 확인 (재검수 항목)

1. `fail:CONTENT_REJECTED` → 장면 카드 기본 화면에 실패 상자, "기다리고" 문구 없음, 다시 시도 버튼 없음, 자동 재시도 없음, 기존 선택 유지.
2. 저장 실패 재현(V8 방식) → "결과는 받았지만 저장하지 못했어요." + "저장 다시 시도" → 다시 생성하지 않고 성공(제공자 ID 같음).
3. `fail:PROVIDER_DOWN` 첫 시도 → 대기 중 "{시각}쯤 자동으로 다시 시도해요" → 성공 후 상자 사라짐.
4. 1280·390에서 가로 넘침 0, 실패 버전 비교에 되돌리기 버튼 없음.
5. 오류 문장이 `lib/ui/errors.ts` 한 곳에서만 나오는지 확인(단위 테스트: 코드별 첫 문장·행동·재시도 여부).

## 4. F-016-2 명세 — 내보내기 미리보기·완료 행

### 4.1 만들기 전 미리보기 카드 (버튼 위)

제목 "묶음에 들어갈 것" + 오른쪽 Badge("샘플 포함", 샘플 장면이 하나라도 있으면) + 한 줄 "예상 약 {크기} · 파일 {n}개".

폴더 나무(`--font-mono`, `--text-sm`, 배경 `--bg-sunken`, radius `--radius-sm`). 기본은 접힌 요약:

```
editing-…_SAMPLE.zip
├─ README.txt
├─ manifest.json
├─ scenes/        장면 5개 · 이미지
├─ script/        script.txt · plan.md
├─ edit/          text_overlays.json
├─ subtitles/     manual.srt
├─ provenance/    generations.json · rights.md
├─ review/        checklist.md
├─ fonts/         PretendardVariable.woff2
└─ LICENSES/      Pretendard-OFL.txt
```

- 목록은 `runClaimedExport`가 실제로 넣는 경로와 같아야 한다. 경로 목록을 만드는 함수를 하나로 두고 미리보기와 실제 묶음이 함께 쓴다. `subtitles/`는 자막이 있을 때만 보인다.
- 펼침 `<details>` "파일 이름 모두 보기": 장면 파일 전체 이름(`scenes/01_…_v1_SAMPLE.png`)과 파일별 크기. 이 부분만 `overflow-x:auto` 상자 안(긴 ID 때문에 390에서 가로 스크롤 허용, 페이지는 넘치지 않음).
- 예상 크기 = 장면 결과 파일 `size_bytes` 합 + 글꼴 파일 크기 + 글자 파일 추정(수 KB). 표시 "예상 약 2.4MB". PNG·woff2는 거의 압축되지 않으므로 압축 전 합계를 쓰고 "약"을 붙인다.
- 검수 승인 전에도 미리보기는 보여 준다. 만들기 버튼만 잠김 + 이유(지금 문구 유지).
- 장면 파일이 하나라도 없으면 나무 해당 줄에 경고 아이콘 + "파일 없음", 만들기 버튼 비활성 이유 "장면 {n}의 결과 파일을 찾을 수 없어요."
