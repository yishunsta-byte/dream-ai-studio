## 격리 Next.js 브라우저 검증

고정 커밋을 별도 디렉터리에 풀어 Next.js 개발 서버를 `localhost:51972`에 실행했다. 실제 공개 홈과 검사용 `/media-qa` 모두 Next.js의 `Image`와 `Link`를 사용했다. 검사용 경로에는 합성 영상·음원과, 최초 요청에 HTTP 503을 반환하고 재시도에 HTTP 200을 반환하는 로컬 응답을 연결했다. 서버 로그에서 영상과 음악 각각 두 화면 너비의 503 → 200 요청을 확인했다.

| 확인 항목 | Chromium 390px | Chromium 1280px |
| --- | --- | --- |
| 합성 미디어 시나리오 | 18/18 PASS | 18/18 PASS |
| 공개 홈 `/` 예시 작품 | PASS | PASS |
| 문서 및 상세창 가로 넘침 | 0px | 0px |
| 오류 시 재시도 버튼 높이 | 48px | 48px |

- 영상·음악 모두 Enter로 상세창을 열면 닫기 버튼으로 포커스가 이동했고, Tab으로 미디어 요소에 도달했다. 처음에는 정지 상태였고 자동 재생이 꺼져 있었다.
- 명시적으로 재생을 시작하면 로딩 상태가 표시됐다. 첫 요청 실패 후 오류와 재시도 버튼이 표시되고 상태 메시지는 `aria-live="polite"`로 노출됐다. Enter로 재시도하면 같은 미디어 요소가 재생 준비 상태에 도달했고, 포커스와 정지 상태가 유지됐다. 다시 재생을 요청한 뒤에는 실제로 재생 시간이 진행됐다.
- 같은 영상 작품의 URL을 바꾸면 이전 요소가 정지하고 새 요소가 정지 상태에서 시작했다. 새 영상을 재생 중 닫기 버튼을 누르면 정지하고 해당 카드를 열었던 버튼으로 포커스가 돌아왔다.
- 음악 재생 중 Escape를 누르면 정지하고 상세창에서 플레이어가 제거됐으며 원래 버튼으로 포커스가 돌아왔다. 다시 열면 이전 상태 메시지가 사라져 있었다. 재생 중 작품을 목록에서 제거했을 때도 미디어가 정지하고 포커스가 작품 둘러보기로 돌아왔다.
- 실제 공개 홈의 `DESERT MOTION` 예시 작품 상세에 대표 이미지와 재생 파일 미연결 안내가 표시됐다. Escape 후 원래 카드 버튼으로 포커스가 돌아왔다.

## 검증 범위와 증거

첫 390px 실행에서 브라우저가 상세창을 닫은 직후 React의 플레이어 제거가 반영되기 전에 검사해 실패가 기록됐다. 닫힘, 플레이어 제거, 포커스 복귀를 모두 기다리도록 검수 스크립트를 수정한 뒤 두 너비에서 처음부터 다시 실행해 통과했다.

재생 시작은 브라우저의 `HTMLMediaElement.play()`로 실행했다. 실제 재생 시간의 진행과 정지를 관찰했고 Enter, Tab, Escape 동작은 키보드로 확인했다. 재생 버튼 자체의 조작, 실제 기기, 스크린 리더, 운영 배포는 이번 검증 범위 밖이다.

로컬 증거는 `tmp/t250r-a50e821/`에 있다. `media-mobile-final.json`과 `media-desktop-final.json`에 최종 미디어 검사 결과, `public-route.json`에 공개 홈 결과, `video-390.png`, `audio-390.png`, `video-1280.png`, `audio-1280.png`에 오류 상태 화면을 남겼다. 검수 전용 브라우저 공간 68과 포트 51972를 정리했다.
