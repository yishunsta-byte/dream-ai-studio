## P2 · 30fps 환산이 참조 영상의 배타적 끝을 가리킴

별도로 합성한 1초·120fps MP4의 마지막 화면만 빨강에서 청록으로 바꿨다. 실제 로컬 분석은 **`983–992ms`** 컷 후보를 반환했다. `992ms`의 대표 프레임 관찰과 `[0,1000)ms` 트랙은 유효하다. 미리보기는 기존 반올림으로 `referenceFrame: { fps: 30, frame: 30 }`을 제공했다. 이를 재생 시각으로 환산하면 **1000ms**로, 원본 트랙의 배타적 끝이며 관측된 프레임이 없다. 관찰·추정 쪽의 실제 PTS는 정확하다. [미리보기 변환](../../lib/reference-analysis/project-preview.ts#L74) · [타임라인 변환](../../lib/edit/timeline.ts#L126)

실제 탐색에는 관찰의 PTS를 사용한다. 30fps 값이 편집 격자의 근사 제안이라면 DTO와 UI에서 그 의미를 명시하고 탐색 동작에 사용하지 않는다. 재생 가능한 30fps 참조를 계약으로 제공하려면 환산한 위치가 `[trackStartMs, trackEndMs)` 안에 있는지 확인하고, 유효 격자점이 없을 때는 해당 값을 생략한다. 트랙 끝과 지연 시작 앞쪽에서의 환산을 회귀로 확인할 수 있다. `cut`과 `durationFrames: 0`은 기존 타임라인 클립 스키마를 통과했으며 별도 계약이다.

## 독립 확인 범위

- 실제 합성 MP4, ALAC/M4A 펄스와 한쪽이 투명한 PNG를 각각 로컬 분석기에서 미리보기까지 연결했다. 영상 관찰은 RGB 변화와 실제 프레임 시각을 내보냈고 컷은 그 ID를 참조하는 추정이었다. 음원 RMS 창과 에너지 상승은 관찰, 120 BPM은 추정, 음악 역할·프롬프트는 창작 제안이었다. 이미지의 불투명 영역은 방향 기준 위치·색 구간·명도와 창작 초안을 반환했고 완전 투명한 선택 위치는 거절했다. 요청 선택 순서도 유지됐다.
- 확인된 소유자 외 액터, 복제한 레코드 토큰, 다른 프로젝트를 거절했다. 소스·소스 리비전·분석 리비전 불일치, 분석 전으로 돌아간 시각과 만료 초과를 `stale`로 반환했다. 정확한 만료 경계는 현재 계약대로 포함됐다. 빈 선택, 중복, 미확인 위치, 잘못 매칭된 근거와 취소·실패 분석에서는 후보가 나오지 않았다. [범위 검증](../../lib/reference-analysis/project-preview.ts#L181) · [미리보기 검증](../../lib/reference-analysis/project-preview.ts#L210)
- 레코드는 프로세스 내부 `WeakMap`에 있으며 생성 시 호출자가 검증한 소유자·프로젝트·분석의 귀속을 신뢰한다. 취소된 분석의 결과 거절은 확인했다. 이후 동일 리비전의 저장 작업을 취소하거나 접근권을 회수하는 경우는 서버 호출자가 현재 접근권과 작업 상태를 확인하고 리비전을 무효화해야 한다. 실제 사용자 세션·저장 작업의 철회와 동시 적용은 이번 범위에 포함되지 않았다.
- 별도 세 매체 DTO에는 소유자·프로젝트·소스·리비전 표지, 비공개 파일명·사본 경로, 픽셀·PCM, 원문, 프로젝트 클립 위치·gain 값이 없었다. 생성을 호출하거나 타임라인·DB·스토리지에 기록하는 의존성이 없음을 코드에서 확인했다. 합성 원본 해시와 관리 폴더 내용은 실행 전후 같았고 검사 사본이 남지 않았다. 반환값 변경이 저장된 후보에 전파되지 않는 집중 시험도 통과했다.
