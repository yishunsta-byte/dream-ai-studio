## 철회 이후 원본 HTTP와 이전 브라우저 자료

- 승인 중 HTML·최종 RSC는 200과 `private, no-cache, no-store, max-age=0, must-revalidate`를 반환했다. 철회 후에도 캐시 헤더는 같았고, 새 HTML·RSC에서 철회 제목과 커버 URL이 사라졌다. 원본의 최종 RSC는 `_rsc` 리다이렉트 뒤 `text/x-component`였다.
- 동일 커버 URL의 GET·HEAD는 승인 중 200, 철회 후 404 `no-store`였다. 승인 GET의 WebP SHA-256은 합성 원본과 일치했다. 조건부 GET도 철회 후 404였고 Next 이미지 최적화 경유는 400이었다. CSP 복원 뒤 브라우저에서 별도로 보낸 새 요청도 404 `no-store`였다.
- 숨긴 문서도 승인 시점에 eager 대표 커버를 요청했고, JavaScript 완전 끔에서는 두 작품의 커버가 200으로 수신됐다. bfcache에서 복원한 문서의 DOM 및 디코딩된 이미지 값은 철회 전에 받은 자료였다. 승인 콘텐츠를 숨긴 이력 문서가 복원되는 동안 자동 새 커버 요청은 관측되지 않았다.
- `/studio`, `/admin`, `/cloud/projects`는 기존 로그인 주소로 307, `/api/projects`는 401이었다. 두 로그인 진입과 기존 예시 원본은 200이었다.
