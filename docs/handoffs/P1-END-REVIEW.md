# P1 종료 독립 검수 안내서

작성: 플래너 · 2026-11-15 · 기준: PLAN v2.4 (18장 P1 종료, 19장 V1~V13, 20.2·20.3), DESIGN v1.3
대상: 검수 담당(Codex) — **구현에 참여하지 않은 담당**이 수행한다. P1-1~P1-9는 연속 진행 방식으로 자체 검수만 거쳤으므로(REVIEW R-004~), 이 검수가 첫 독립 검수다.

## 0. 시작 조건

| 확인 | 기준 |
|---|---|
| 마일스톤 | P1-7·P1-8·P1-9가 커밋되고 PROGRESS·인계 문서가 있다 |
| 작업 트리 | `git status` 깨끗함. 검수 대상 커밋 ID를 REVIEW 첫 줄에 적는다 |
| 열린 항목 | QUESTIONS에 "플래너 답변" 없는 항목이 있으면 목록으로 적고 계속한다(막지 않음) |

## 1. 규칙

- 코드를 고치지 않는다. 문제는 REVIEW에 **필수 수정 / 권장**으로만 적는다.
- **격리된 복사본에서만 시험한다.** 은영님 실제 `data/`·`storage/`·`backups/`를 건드리지 않는다.
  ```
  git worktree add ..\dream-ai-studio-p1review <커밋ID>
  cd ..\dream-ai-studio-p1review
  npm.cmd ci
  npm.cmd run db:migrate
  ```
  끝나면 `git worktree remove ..\dream-ai-studio-p1review`.
- 실제 개인정보·실제 API 키 사용 금지. 샘플 모드(`MOCK_MODE`)만.
- 서버는 127.0.0.1에서만. 외부 공개·푸시 금지.
- 각 항목은 **직접 실행한 결과**로만 판정한다. 테스트 이름이나 PROGRESS 문장만 보고 통과 처리하지 않는다.

## 3. 흐름 1건 (P1 종료 시나리오)

`npm.cmd run build` → `npm.cmd run start`와 `npm.cmd run worker`를 각각 실행하고 브라우저(1280px)로:

1. 작업실 → 쇼핑숏츠 → 새 프로젝트. 필수 칸을 비운 채 저장 → 칸 옆 오류·첫 오류 칸 포커스 확인. 가상 상품으로 채워 저장. `isAd` 켬.
2. 자료: 이미지 2장 업로드(가상 이미지). 이름만 `.jpg`인 텍스트 파일 업로드 → 거절 문구 확인.
3. 요구 확인 → 확인 완료.
4. 기획 → 장면표 확인 → 승인.
5. 장면 제작: 모든 장면 생성 → 버전 선택.
6. 수정·조립: 글자 1개 추가, 광고 표기 레이어 존재·삭제 불가 확인 → 확인 완료.
7. 검수: 항목 통과·보류(사유 필수) 동작 → 모두 통과 → 승인.
8. 내보내기: 편집용 묶음 생성 → 내려받기.

막힌 단계·실패가 실패로 안 보인 곳·샘플 표시가 빠진 곳을 모두 기록한다. 화면 캡처는 `tmp/p1-review/`(git 제외)에 저장하고 경로만 REVIEW에 적는다.

## 4. V1~V13 재현

API 경로는 각 단계 인계 문서(`docs/handoffs/P1-*.md`)와 `app/api/` 기준으로 확인해서 쓴다. 아래 "방법"은 최소 절차다.

| # | 방법 | 통과 기준 | 남길 증거 |
|---|---|---|---|
| V1 | 기획 미승인 프로젝트에 장면 생성 요청을 **API로 직접** 보낸다(`/api/projects/[id]/production` 등) | 4xx 거부, 작업 생성 0 | 요청·응답 코드·본문, jobs 건수 전후 |
| V2 | 승인된 기획을 수정 | 새 draft 버전 생성, 그 draft로 생성 요청 시 거부, 승인 원본 내용 불변 | 버전 목록, 거부 응답, 원본 비교 |
| V3 | 장면 3만 다시 만들기 → 이전 버전으로 되돌리기 | 다른 장면 선택 그대로, 되돌리기 = 이전 버전 재선택(파일 삭제 없음) | 장면별 `selected_version_id` 전후 |
| V4 | 같은 장면 선택 요청 두 개를 동시에 보낸다(두 탭 또는 병렬 요청) | 한쪽만 저장, 다른 쪽 "다른 선택이 먼저 저장됨" 안내 | 두 응답, 최종 선택값 |
| V5 | 같은 생성 요청을 같은 키로 연속 두 번 | 작업 1개 | jobs 건수 |
| V6 | 시나리오 `delay:10s`로 생성 → 실행 중 워커 강제 종료 → 재시작 | 작업 이어서 완료, 같은 제공자 작업 ID로 폴링(재제출 없음) | 작업 기록의 제공자 ID 전후, 로그 |
| V7 | 시나리오 `cancel-late`로 생성 → 바로 취소 | 결과는 새 버전으로 저장되지만 자동 선택 안 됨, 화면에 "취소 후 도착" | 버전 목록, 선택값 |
| V8 | 저장 폴더를 쓰기 불가로 만든 뒤 생성(복사본 폴더 권한 변경) | `STORAGE_FAILED` 표시, 성공 표시 없음, 다시 생성하지 않고 저장만 재시도 가능 | 화면·작업 상태 |
| V9 | 검수 승인 후 글자 하나 수정 | 내용 버전 +1, 검수·내보내기 자격 무효, 이미 만든 묶음과 manifest는 그대로 | 내용 버전 전후, 내보내기 버튼 상태 |
| V10 | 장면 파일 하나 삭제 / `../` 포함 경로 요청 / 디스크 부족 흉내 | 각각 사용자 문장 오류, 경로는 거부 | 응답·화면 |
| V11 | 내보낸 ZIP을 새 폴더에 풀기 | manifest의 모든 파일 존재·sha256 일치, 절대경로·`.env`·키 문자열 없음, 샘플 파일명 `_SAMPLE` | 해시 비교 결과, `grep` 결과 |
| V12 | 백업 생성 → 새 격리 폴더로 복원 | 복원본에서 모든 프로젝트·자료 참조 유효, 원래 데이터 불변, 복원 실패 시 되돌림 | 참조 검사 결과 |
| V13 | 1280·390px로 3장 흐름 화면 전부 | 가로 넘침 0, 키보드로 끝까지 조작, 확인 패널 포커스 이동·Esc·복귀, 오류 문장 표시 | 화면별 `scrollWidth`, 캡처 경로 |

- 필수 수정이 있으면 구현 담당이 고친 뒤 **해당 항목만** 다시 검수한다.
