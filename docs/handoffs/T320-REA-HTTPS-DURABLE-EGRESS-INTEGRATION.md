# T320 HTTPS 송신과 영속 제어 원장 통합 검증

2026-11-19 KST · Codes(Backend) · 고정 기준 T318 `6ed3a46`, T319 `ae326ed` · 배정 `msg_2b6e97755410`

소유 루프백 PostgreSQL 17.12에 고정 T319 시험 원장과 T320 시험 확장을 적용했다. 실제 HTTPS 리스너 두 개를 서로 다른 Node 프로세스에서 실행하고 제어 프로세스는 별도로 두었다. 클라이언트는 임시 자체 서명 인증서의 신뢰·루프백 IP·피어 지문을 검증했다. 보호 JSON과 주체 ID는 합성 값이다. [T318](T318-REA-DIRECT-HTTPS-EGRESS-PROBE.md) · [T319](T319-REA-EGRESS-DURABLE-CONTROL-PROBE.md) · [시험 SQL](../../tests/reference-analysis/t320-https-durable-egress.sql)

원장은 현재 송신 세대·제어기 번호·권한 리비전·주체·연결에 허가를 묶는다. 송신자마다 다른 제한 DB 로그인으로 현재 송신자와 연결을 대조했다. 허가 소비와 시작 기록은 PostgreSQL에 남겼다. 송신자는 첫 쓰기 직전에 실제 원장에 다시 확인하고, 소켓 종료를 관측한 뒤 종료를 기록한다. 직접 원장 조회, 송신자의 제어기 초기화 및 감독 역할의 허가 소비는 거절됐다.

| 검증 항목 | 실제 관측 |
| --- | --- |
| 동시 허가 소비 | 동일 허가를 대상으로 현재 송신자의 실제 TLS 요청 두 건을 겹치고 비소유 송신자도 요청했다. 한 요청만 전체 JSON과 HTTP 200을 받았다. 나머지는 409·본문 0바이트였다. 원장의 소비 및 시작 기록은 각각 한 건이었다. |
| 제어기 재시작 확정 뒤 첫 쓰기 | TLS 요청을 `starting`에 보류하고 기존 제어 PID를 강제 종료했다. 다른 PID가 원장의 제어기 번호 증가를 커밋한 뒤 기존 TLS 요청을 풀었다. 클라이언트 응답은 403·보호 본문 0바이트였다. 원장은 시작 보고 없이 취소로 끝났다. |
| 권한 철회 확정 뒤 첫 쓰기 | 첫 쓰기 전 보류 사이에 현재 권한 리비전과 주체 상태를 커밋했다. 재개 응답은 403·보호 본문 0바이트였고 새 발급도 거절됐다. |
| 원장이 중지된 상태 | 소유 postmaster를 정상 정지한 동안 신규 발급·활성화 호출은 `ledger_unavailable`로 닫혔다. 보류한 실제 TLS 요청은 503·보호 본문 0바이트였다. 원장에 종료를 쓸 수 없었고, 같은 클러스터 재시작 후 미종결 소비 상태가 유지됐다. 중지 중 요청한 신규 허가 행은 없었다. |
| 전송 중 전환과 종료 근거 | 실제 클라이언트가 보호 접두부를 받은 동안 활성화를 요청했다. 기존 세대는 유지됐고 새 발급은 차단됐다. 한 연결은 나머지 본문을 전송하고 실제 소켓 종료 후 `finished`가 기록됐다. 다른 연결은 취소로 접두부만 남고 실제 소켓이 닫혔으나, 송신자가 종료 보고를 버리도록 시험에서 설정했다. 원장은 `sending`을 유지하고 전환을 기다렸다. 잘못된 PID도 격리 근거로 받아들이지 않았다. |
| 복구와 자원 정리 | 실제 구 송신 PID가 종료돼도 감독 역할이 격리를 기록하기 전에는 전환을 열지 않았다. 기록 후 미종결 허가는 `isolated`가 됐고, 다음 세대가 새 허가로 전체 JSON을 보냈다. 구 허가의 재사용은 409·본문 0바이트였다. 제한 DB 세션, 마지막 송신 인스턴스의 소켓·작업, 클라이언트 요청이 각각 0이었다. Node·PG 프로세스, PG PID/리스너, 임시 클러스터와 인증서를 정리했고 이전 두 TLS 포트의 연결 거절도 확인했다. |

**실측과 모의 범위.** HTTP 상태·수신 바이트·클라이언트 및 송신자의 소켓 종료, 제어기/송신 PID 종료, PostgreSQL 정지·재시작 및 커밋 상태를 실제로 관측했다. 보호 데이터와 주체, 마지막 원장 확인 전 보류, 종료 보고 유실은 시험 모델이다. 마지막 DB 판정과 실제 소켓 첫 쓰기 사이의 원자성, 다중 호스트 네트워크 분할, 프록시 하위 큐, 운영 인증·호스팅은 검증하지 않았다. 제품·운영·배포 변경은 없었다.
