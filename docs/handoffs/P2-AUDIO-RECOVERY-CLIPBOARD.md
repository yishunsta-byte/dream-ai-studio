# P2 V7 · 오디오 편집 복구 자료 복사

T150에서 다운로드로 확인한 오디오 복구 자료를 Chrome 157의 실제 클립보드 경로로 검증했다. 로컬 앱과 가상 DB, 고유 Windows 윈도 스테이션을 사용했다. 브라우저 스레드가 시험 전용 데스크톱에 연결됐는지 확인한 뒤 복사했다.

1. 첫 탭의 타임라인 저장 응답을 보류하고 제목을 다시 고쳤다. 음성 클립을 선택해 크기를 -12dB로 바꾸고 시작 칸에 미완성 값 `00:x`를 입력했다.
2. 두 번째 탭에서 첫 저장본을 불러와 다른 제목을 저장한 뒤 첫 탭의 응답을 풀었다. 두 요청 모두 HTTP 200이었다. 첫 탭의 편집란에는 두 번째 탭의 제목이 표시됐고 복구 상자에 첫 탭의 초안이 남았다.
3. ‘복구 자료 복사’를 실행했다. 성공 안내 후 navigator.clipboard.readText로 읽은 JSON에서 보낸 제목과 나중에 고친 제목, 선택한 오디오 ID, 해당 클립의 gainDb=-12, audioFields의 원시 시작 값 00:x가 각각 일치했다.
4. 같은 탭에서 클립보드 쓰기 권한을 거부하고 다시 복사했다. 수동 복사 입력란의 값은 줄바꿈을 LF로 통일했을 때 앞선 복사 내용과 일치했다(UTF-8 10434바이트). 입력란에 초점이 있고 전체 문자열이 선택됐으며, 외부 최신 제목도 보존됐다.

판정은 로컬 Chrome과 가상 오디오 편집 충돌 범위다. 재현 코드·요약은 tmp/p2-audio-clipboard/probe.mjs 및 result.json에 있다.

> 플래너 전달문 — 실제 저장 경합 후 오디오 복구 자료를 격리된 클립보드에서 읽어 값까지 대조했습니다. 쓰기 권한을 거부해도 같은 자료가 수동 복사란에 전체 선택되고 다른 탭의 최신 저장본이 보존됐습니다.
