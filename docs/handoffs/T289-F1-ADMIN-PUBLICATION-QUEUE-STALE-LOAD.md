## 고친 내용

| 검수 지적 | 고친 방식 |
|---|---|
| F289-1 늦은 목록이 성공한 준비(v1)를 v0으로 덮음 | 아래 세 가지를 함께 적용했어요. |
| 상단 `목록 다시 불러오기` 1280px 32px | `size="sm"`을 빼고 `.reload { min-height: 44px; }`를 넣었어요. 390·1280 모두 44px이에요. |

F289-1에 적용한 세 가지는 다음과 같아요.

1. **조회와 쓰기를 서로 막아요.**
   - 목록을 불러오는 동안에는 줄마다 권리 체크, 준비·게시·철회, 같은 요청 재시도, 줄 안의 다시 불러오기가 모두 꺼져요.
   - 쓰기가 진행 중일 때는 상단·줄 새로고침이 꺼져요. 시작 함수도 같은 조건으로 한 번 더 막아요.
2. **늦은 응답을 걸러요(`createSyncGate`).** 목록 응답은 아래 조건을 모두 만족할 때만 반영해요.
   - 가장 최근 조회일 것
   - 조회를 시작한 뒤 시작된 쓰기가 없을 것
   - 진행 중인 쓰기가 없을 것
   - 공급자 세대가 같을 것

   조건이 맞지 않으면 응답을 버리고 “불러오는 사이 다른 작업이 끝나서 이번 목록은 반영하지 않았어요” 상태 문구를 보여 줘요.
3. **새로고침해도 처리 미확정은 남겨요(`rowsAfterLoad`).**
   - 같은 UUID 재시도는 그 줄의 새 목록 버전이 재시도 당시 버전(`retryBase`)과 같으면, 요청과 안내를 그대로 남겨요.
   - 버전이 바뀌었으면 지워요. 서버가 이미 처리했거나 다른 변경이 있었다는 뜻이라, 화면은 새 목록을 기준으로 해요.
   - 그 밖의 줄 상태(권리 체크, 충돌 표시)는 새 목록 기준으로 초기화해요.

**공급자 교체:** `initial·load·apply`가 바뀌면 받은 값으로 화면을 새로 시작해요. 그 뒤 도착하는 이전 공급자의 조회·쓰기 응답은 버리고, 진행 중 쓰기 수도 비워요.
