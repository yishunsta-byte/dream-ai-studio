# PG 자막 포함 MP4 독립 검수

MASTER 배정 `msg_899fd3bdc430`. 고정 `f03a881`의 격리 사본에서 실제 Next.js HTTP, 임시 PG17, Remotion, FFmpeg를 실행했다. 제품 HTTP로 서로 다른 합성 PNG 두 장, WAV와 한글 자막을 저장하고 기획·제작·검수를 승인했다. 별도 검수 스크립트가 응답 바이트와 DB 출력 기록을 대조했다.

| 항목 | 측정 결과 |
|---|---|
| 다운로드 | 71,614바이트 H.264, 1080×1920, 30fps, 90프레임, 3초, AAC 한 트랙. 파일·서버 응답·DB SHA-256 모두 `c86f5e51dc67f554129518ecbcc537f010c5e4b496ee18e63c46cb58597a1930`. |
| 한글 두 줄 | 30프레임에서 ‘첫 번째 줄 가나다’와 ‘두 번째 줄 라마바’를 직접 확인했다. 저장 범위는 0기준 `[15,70)`, 두 줄 모두 같은 검출 기준에서 15~67프레임에 표시됐다. 마지막 검출 프레임은 저장 종료 경계보다 두 프레임 이르다. 두 줄 모두 등장·퇴장 쪽의 검출 픽셀 수가 구간 중간보다 적었다. |
| 광고와 대조 영역 | 잠긴 ‘광고’ 표기는 0~89프레임에 검출됐다. 빈 대조 영역은 검출 0프레임이었다. 광고가 필요한 프로젝트에서 표기 없이 승인한 버전은 실행 409 `RENDER_REQUIRED_DISCLOSURE_MISSING`, 파일 조회 404였다. |
| 새 버전의 승인 필요 | 자막을 저장한 직후 검수 승인 없이 현재 리비전의 렌더를 요청하면 409 `REVIEW_APPROVAL_REQUIRED`였다. 이전 버전의 작업 1건만 남았고 출력은 0건이었다. 별도 실HTTP 재실행은 종료 코드 0이었다. |
| 컷·오디오 | 29·30·89프레임의 중심 RGB는 각각 `[254,0,0]`, `[0,1,255]`, `[0,1,255]`. 48kHz 모노로 디코딩한 144,000샘플에서 600Hz가 0~17프레임에 검출됐다. 후반 대조 프레임의 진폭은 기준 미만이었다. |
| 취소와 재시도 | 자막 렌더 임시 작업 폴더가 생성된 뒤 HTTP 요청을 중단했다. `RENDER_CANCELED`, 시도 1, 임대 NULL, 완료 기록·출력 0건으로 정리됐다. 같은 작업 재시도와 재호출 뒤 시도 2, 완료·출력 각 1건, 동일 결과였다. 타인 다운로드는 404였다. |

첫 실행은 검수 스크립트에서 선언 이름이 겹쳐 중단됐다. 이름을 정리한 실제 다운로드 재실행은 종료 코드 0이었으며 작업 폴더·임시 PostgreSQL과 리스너 정리가 확인됐다.
