## 문제
- T249-FIX의 달력 검사는 `Date.UTC`가 만든 날짜를 원문과 대조했어요.
- 그런데 `Date.UTC`는 0~99년을 1900~1999년으로 바꿔요. 그래서 원래 받던 `0001-01-01`, `0000-02-29` 같은 날짜까지 거절했어요.

## 수정
- `Date.UTC`를 쓰지 않고 달력을 직접 계산해요.
  - 윤년 규칙: 4로 나누어떨어지고 100으로는 나누어떨어지지 않거나, 400으로 나누어떨어지면 윤년이에요.
  - 월별 일수표로 날짜를 확인해요. 1~12월, 1일~그달 마지막 날만 받아요.
- 시 0~23, 분·초 0~59, 시간대 시 0~23·분 0~59, `24:00` 거부는 그대로예요. 실제 시각은 이전처럼 `Date.parse`로 구해 미래인지 검사해요.

## 시험(추가 1건)
- **통과 7종**
  - `0000-02-29`, `0004-02-29`(윤일)
  - `0001-01-01`, `0099-12-31T23:59:59Z`, `0050-06-30T23:59:59.5Z`
  - 시간대 표기 `0001-01-01T09:00:00+09:00`, `0099-12-31T18:59:59-05:00`
  - `0400-02-29`도 통과해요.
- **제외 8종**
  - 평년 윤일 `0001-02-29`, `0100-02-29`
  - 없는 날짜 `0099-04-31`, `0099-00-01`, `0001-01-00`, `0004-02-30`
  - 시각 오류 `0000-01-01T24:00:00Z`, `0099-12-31T23:59:60Z`
- **정렬:** 같은 순간(UTC와 +09:00)은 id 순, 더 이른 0000년은 뒤로 가요.
- **기존 회귀 유지:** T249-FIX의 잘못된 날짜·24:00 12종과 정상 5종 시험이 그대로 통과해요.
