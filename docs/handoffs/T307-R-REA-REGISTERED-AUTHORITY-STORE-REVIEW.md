**판정 · 격리 권한 조회 통과, 로그인 최소 권한 검증 보완 필요.** 목록과 단건 조회는 같은 권한 근거를 확인했습니다. 시작 시 로그인 역할 자체에 부여된 일부 관리 속성을 놓치는 경계를 확인했습니다.

## F307-1 · 시작 검증이 `session_user`의 관리 속성을 확인하지 않음

소유 격리 PG17에서 읽기 역할을 그대로 둔 채 합성 로그인에 `CREATEDB` 또는 `CREATEROLE`을 각각 부여했습니다. 두 설정에서 어댑터가 활성화됐습니다. 높아진 속성은 관측 후 모두 원복했고, 그 속성으로 관리 작업을 실행하지 않았습니다. [`capability` 조회](../../lib/reference-analysis/studio-analysis-authority-store.ts#L32)는 `SET LOCAL ROLE` 뒤 `current_user`의 관리 속성과 `session_user`의 일부 그룹 가입을 확인합니다. `session_user` 자체의 두 속성은 비교하지 않습니다. 격리의 기본 제한 역할은 정상이고, 실제 읽기 트랜잭션은 제한 역할과 RLS를 유지했습니다. 운영 연결의 최소 권한 판정에는 로그인과 전환한 읽기 역할 양쪽의 관리 속성을 확인하는 검증이 필요합니다.

## 독립 검증 결과

| 항목 | 결과 |
| --- | --- |
| 실제 SQL1–4와 T281 | 소유 루프백 PG17.12의 두 실행에서 고정 SQL1–4와 T281 해시를 확인했습니다. 기존 등록 제약과 트리거를 거쳐 저장 객체·검증 기록을 만들었습니다. 지정 스키마·RLS가 빠진 경우 어댑터가 닫혔고, 정상 제한 로그인은 다른 계정 자료와 등록·권한 변경에 접근할 수 없었습니다. |
| 목록/단건, A/B 및 증거 | 양방향 A/B, 링크 용도·재링크·소유자와 범위 권한 해제/복구, 버킷·크기 제한을 확인했습니다. 검증·증거 만료와 누락, 객체 증거 다이제스트 불일치, 스토어·복원 세대 불일치는 두 조회 모두에서 자료를 제외했습니다. 올바른 복원 및 자료 세대로 다시 결합한 뒤 단건은 새 세대를 반환했습니다. |
| 스냅샷·기한·취소 | 실제 PG 잠금에 걸린 두 조회 중 단건을 취소했습니다. 다른 목록 조회는 이미 고정한 스냅샷을 유지했고, 다음 두 조회는 커밋된 철회를 반영했습니다. 권한 재승인 뒤 새 세대, 실제 잠금 기한과 시간 경과 중 증거 만료를 확인했습니다. 종료 전 열린 트랜잭션 0건, 닫은 뒤 어댑터 연결 0건이었습니다. |
| 공개 DTO | 실제 DB 목록을 기존 페이지 로더로 전달했습니다. 브라우저에 갈 자료의 키는 `assetId`, `label`, `projectId` 세 개였습니다. 원본 객체 키·해시·세대는 단건 서버 경계에 남았습니다. |

깨끗한 고정 사본에서 Next 타입 생성, 전체 `tsc --noEmit --incremental false`, 변경 파일 ESLint가 통과했습니다. 분석·공용 인증 선택 회귀 **335건 통과, 63건 건너뜀**이었습니다. 두 소유 루프백 리스너, 임시 PG17 클러스터와 사본을 제거했습니다.

현재 복원·자료 증거 발급과 로그인은 격리 전용입니다. 운영에는 복원 DB와 독립적인 발급 경로와 자료 검증 증거의 관리·철회, 실제 인증과 최소 권한 확인이 필요합니다. 운영 자료·라우트·배포는 검수 범위 밖입니다.

**Master 전달 문구** · T307-R `7955059` 실제 PG17 권한·세대·스냅샷·취소·공개 DTO는 통과. F307-1은 `session_user` 자체의 CREATEDB/CREATEROLE을 시작 검증에서 놓치는 경계입니다. 335건 및 깨끗한 전체 타입·린트, PG 정리를 확인했습니다.
