# 두 번째 PNG 연결 독립 검수

MASTER 배정 `msg_b91ecec2f897`, 제작 담당 고정본 `63c8ed92b8c897d1dd30ea72b0ff27c6264dcfbb`. 격리 Git 사본의 실제 Next.js HTTP·Chromium·임시 PG17에서 검수했다. 이미 첫 PNG가 저장된 프로젝트를 제품 API로 생성하고 브리프와 기획을 승인해 기존 제작 화면을 열었다.

| 확인 항목 | 관측 결과 |
|---|---|
| 브라우저 연결 복구 | 녹색 합성 PNG와 권리 메모를 입력했다. 업로드는 201 한 번이었다. 연결의 첫 실제 201 응답을 유실시킨 뒤 파일 선택이 보존됐다. 같은 버튼을 다시 누르면 두 번째 업로드 없이 같은 요청 본문으로 연결 200을 받고 동일한 자료 ID를 표시했다. |
| 두 장면의 서로 다른 선택 | 장면 1에 첫 PNG, 장면 2에 추가 PNG를 등록하고 명시적으로 선택했다. 새로고침 후 각각의 결과·이름·`사용 중` 표시가 같았다. DB에서 선택 결과가 서로 다른 두 자료 ID를 가리켰다. |
| 원본·중복 | 최초 입력의 `productAssets`에는 첫 ID만 남았다. 최초 연결 한 건과 추가 `productionImage` 한 건, 추가 감사 기록 한 건을 확인했다. 두 번째 PNG의 원본 SHA-256과 권리 메모가 DB와 일치했다. 기존 HTTP 시험의 동시 연결은 201·200으로 같은 ID를 반환했고, 같은 SHA의 별도 자료는 409였다. |
| 거절 | 타인 프로젝트·타인 자료 및 보관 프로젝트·자료 요청은 404였다. 이전 리비전은 409였다. 화면 선택 후에도 제작 단계는 `todo`였다. |

기존 [HTTP 회귀](../../tests/postgres/local-project-brief-http.mjs)에 검수 사본 전용 브라우저 대조를 연결했다. 전체 실행 종료 코드 0. 브라우저 공간, 임시 PostgreSQL 클러스터와 리스너를 정리했다.
