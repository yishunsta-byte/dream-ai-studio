## 통합 조건

- 확정 예약과 같은 소유자·요청 지문을 요구한다. `READ COMMITTED`에서 전환 제어 행과 요청 잠금 뒤 정책 → 객체 → 검증 작업 → 자료/검증 상태 → 자료 포인터 순으로 확인한다. 정책 ID·epoch·digest, 현재 검증 포인터, 상태와 세대를 대조한다. 바뀐 원본이나 자료 포인터로는 이전 요청을 적용할 수 없다.
- 포인터 변경과 원장 종결은 한 트랜잭션이다. 완료된 요청을 조회하거나 같은 키로 재호출하면 기존 처리 결과가 나온다. 자료 조회는 현재 정책·검증 증거·권한 및 폐기 상태를 별도로 판정한다.
- 갱신은 새 검증 ID와 더 높은 스토리지 세대를 요구한다. 폐기 시 포인터 리비전과 당시 활성 스토리지 세대를 남긴다. 폐기 후 새 요청도 그 시점보다 뒤의 검증 기록으로만 발급할 수 있다.

## 실제 관측

| 시험 | 결과 |
| --- | --- |
| 갱신 COMMIT·같은 키 재시도·정책 교체 | 새 검증 ID 및 스토리지 세대로 갱신했다. 원래 COMMIT을 실제 대기시키면 별도 문장에서 원장은 예약, 포인터는 이전 리비전이었다. 같은 키 재시도와 정책 교체가 각각 기다리는 것을 확인했고, 짧은 잠금 기한은 `55P03`으로 끝났다. 원래 응답은 시험 호출자에게 전달하지 않았다. 별도 연결이 한 번의 커밋 결과를 조회했고, 정책 변경 이후 그 기록의 재조회가 자료 가시성을 복구하지 않았다. |
| 재검증 성공·실패가 먼저인 같은 키 경쟁 | 실제 SQL4 성공은 새 기록으로 포인터를 옮겼고, 실패는 기존 성공 기록을 보존하면서 상태를 철회하고 세대를 올렸다. 각 경우 첫 시도는 객체 변경을 기다렸고 같은 키 재시도는 첫 시도를 기다렸다. 두 호출 모두 이전 증거로 원장이나 자료 포인터를 변경하지 못했다. |
| 대기 중인 발급 COMMIT 취소 | `57014`와 트랜잭션 종료를 확인했다. 별도 문장에서 원장과 자료 포인터가 모두 이전 상태였다. 이후 같은 키의 한 번의 처리에서 두 변경이 함께 확정됐고 조회가 복구됐다. |
| 폐기와 지연 발급 | 자료가 여전히 SQL4 현재 검증 조건을 충족하는 경우에도 자료 증거 폐기와 원장 종결은 한 번에 확정됐고 조회는 닫혔다. 폐기 전 리비전으로 예약한 발급과 폐기 당시 기록을 재사용한 새 요청은 거절됐다. 폐기 이후 새 검증 기록으로 발급하면 조회가 다시 열렸다. |
| A/B 격리와 정리 | 상대 목록·단건·발급·원장 조회 및 상대 키 재사용을 거절했다. A 자료의 교체·폐기 중 B의 증거는 유지됐다. 직접 원장 수정·보호 역할 전환·시험용 우회 발급도 거절됐다. 제한 연결과 열린 트랜잭션 0건을 확인했다. |
