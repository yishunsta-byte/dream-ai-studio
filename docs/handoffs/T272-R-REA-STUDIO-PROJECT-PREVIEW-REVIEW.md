## 통과 범위

- 영상·음원·이미지의 선택 가능한 전 항목을 실제 서버 미리보기 계약에 넣어 고정 브라우저 표본과 정확히 비교하는 시험을 재실행했다. 다른 액터, 변경 리비전, 만료와 빈 선택 검증도 통과했다. 보호 페이지는 `legacyPageGate` 뒤에 표본을 전달하고, 분석·소유권 판정은 브라우저 번들에서 실행되지 않는다. 격리 빌드의 정적 클라이언트 청크에 두 서버 함수 이름이 없었다. [계약 대조 시험](../../tests/reference-analysis/studio-project-preview.test.ts)
- 1280px·390px에서 키보드 `End → Tab → Tab → Space`로 탭 패널과 첫 체크 상자에 도달했다. 방향키 탭 순환·빈 선택 안내를 확인했다. 컷 → 0초 프레임, 이미지 영역 → 전체의 선택 순서가 각각 유지됐다. 컷에는 관찰·추정·제안이 구분됐고, 음악은 정규화 RMS만 표시하는 음량 카드로 나왔다. 두 폭에서 문서 너비가 스크롤바를 제외한 뷰포트와 같았으며 측정한 노출 버튼·링크의 최소 높이는 44px였다.
- 컷 카드의 **원본 관찰 0.340초**와 **30fps 편집 격자 10번 프레임**은 별도로 표시됐다. 위치 버튼은 0–0.500초 막대에서 x=272/400에 표시하고 같은 PTS를 `aria-live` 문장으로 알렸다. 화면에 실제 재생기가 연결되지 않았다는 문구가 있었고 `<video>` 요소가 없었다. 음악·이미지에 영상 위치 막대가 표시되지 않았다. 실제 재생·스크린리더 발화는 검수 범위 밖이다.
- 모의 클립보드 성공에서 표시된 선택 순서의 제안 문장만 전송됐고 관찰 수치, 근거 ID, 원본 위치와 파일명은 제외됐다. 복사 대기 중 선택 변경은 알림만 갱신했다. 다른 탭으로 옮겼을 때 해당 탭의 상태 영역은 바뀌지 않았고, 다음 작업에 이전 실패 알림·선택이 적용되지 않았다. 진행 중 취소는 종료 확인 후 결과 탭 없이 끝났고 다시 시작하면 선택이 초기화됐다. 실제 OS 클립보드는 사용하지 않았다.
- 페이지가 열린 뒤 합성 작업과 프로젝트 미리보기 상호작용 중 fetch·XHR·beacon 요청은 **0건**이었다. 격리 로컬 SQLite의 모든 테이블 행 수와 파일 SHA-256이 브라우저 실행 전후 같았다. 프로젝트·작업·타임라인 신규 행이나 외부 요청은 없었다.

## 실행 범위 및 정리

고정 커밋과 해시가 일치한 변경 파일을 기존 격리 사본에 반영하고 빈 로컬 데이터 루트를 사용했다. `next build`, `scripts/verify-build.mjs`, 생성 경로 타입을 포함한 `tsc --noEmit --incremental false`, 변경 화면·표본·시험의 ESLint 경고 0 검사 통과. Studio Lab·Studio 미리보기·Backend 미리보기·T200 지정 4개 파일 기본 **161 통과·2 건너뜀**, 로컬 네이티브 설정 **163/163 통과**. 이번 검수에서는 전체 스위트를 재실행하지 않았다.

Tester 전용 브라우저 공간과 격리 서버를 닫았다. 이전에 거절된 별도 인증 서버와 재귀 정리는 재시도하지 않았다. 기존 격리 사본은 남아 있고 공유 작업공간에는 이 보고서 한 파일을 추가했다.
