## 격리 합성 SQLite 계약

`syntheticReferenceApplyStore`는 테스트에서 설치한 전용 테이블을 사용합니다. `prepare`는 서버에서 확인을 마친 컷 선택과 장면 매핑을 검증된 기준 레코드에 묶습니다. 중복 ID는 이전 계획을 덮어쓸 수 없습니다. 서버가 확인 ID, 실제 분석 후보 및 장면 매핑을 확정하는 것이 선행조건입니다. 이 단계에서 타임라인은 저장하지 않습니다. [어댑터](../../lib/reference-analysis/synthetic-apply-store.ts) · [합성 테이블 및 권한 픽스처](../../tests/reference-analysis/atomic-apply-fixture.ts)

`apply`는 현재 액터, 확인 ID, 명시적 `true`를 받습니다. 같은 연결의 최상위 `BEGIN IMMEDIATE` 안에서 현재 권한·복원 세대·분석·기준 타임라인을 다시 조회하고 T275 정책을 평가합니다. 대기 상태 한 행을 조건부 소비하고 기존 장면 이동과 `timelineService.save`의 CAS를 재사용합니다. 같은 트랜잭션에 확인 종결, 타임라인·워크플로 및 최소 영수증을 기록합니다. 소비·종결 갱신에서 한 행이 바뀌었음을 확인합니다. 편집 위치는 선택한 기존 장면 ID로 계산합니다. [T275 정책](../../lib/reference-analysis/apply-lifecycle.ts) · [기존 장면 적용](../../lib/reference-analysis/project-apply.ts) · [타임라인 쓰기](../../lib/services/timeline.ts)

처음 성공한 적용은 `applied` 또는 `no_change`만 반환합니다. 현재 조회권·보존 기한을 통과한 `readReceipt`나 동일 확인 재전송은 커밋된 결과 유형, 당시 타임라인 ID와 두 리비전, 완료 시각을 반환합니다. 실행 기준의 만료나 후속 타임라인 변경은 영수증에 영향을 주지 않습니다. 종결 시 내부 범위와 보존 기한을 유지하고, 대기 계획·사본 해시·분석 근거를 제거합니다. 취소 및 권한을 확인한 만료·오래된 분석·충돌은 대기 상태를 종료합니다. 미확정 상태나 권한을 검증할 수 없는 조회는 `unavailable`입니다. 소유권 거절은 다른 사람의 대기 확인을 소비하지 않습니다.

쓰기 시작 전에 확인된 네이티브 `SQLITE_BUSY`만 `busy`, `retryable: true`로 반환합니다. 이후 예외는 기존 오류 경로로 전달하고 자동 재실행하지 않습니다. 응답을 잃으면 동일 저장소의 영수증을 조회합니다. 복사된 이전 세대의 확인과 영수증은 새 세대에서 거절됩니다.

## 합성 검증

- S4 합성 SQLite 사본에서 확인을 준비하고 연결을 닫았습니다. 별도 Node 프로세스가 적용하고 응답을 남기지 않은 뒤 종료했습니다. 또 다른 프로세스가 실행 만료 이후 같은 ID로 원래 영수증을 읽었습니다.
- 두 연결로 동일 ID 재전송과 별도 확인의 CAS 경쟁을 재현했습니다. 타임라인과 저장 로그는 한 번만 진행됐고, 늦은 별도 확인은 `conflict`였습니다. 시작 잠금 대기 초과 중 DB가 그대로였으며 잠금 해제 후 같은 확인이 적용됐습니다.
- 타임라인·워크플로 쓰기 뒤 영수증 저장에서 실패를 주입했을 때 전체 논리 DB 스냅샷이 원상 복구됐습니다. 실패 요인 제거 후 같은 확인으로 한 번 저장했습니다.
- `no_change`는 타임라인이나 저장 로그를 추가하지 않고 종결 영수증을 남겼습니다. 취소, 권한 철회, 보존 만료, 이전 복원 세대와 미확정 소비를 거절했습니다. 실제 SQLite 복제본에서 픽스처가 새 세대를 발급한 뒤 이전 확인 실행 및 영수증 조회가 거절되고 복제본이 그대로인 것도 확인했습니다.
