# T313-R 권한 전환·응답 전송 독립 재현

기준 `131fde6` · Master 인계 `msg_1e0991a2b530` · Codex(Tester)

**판정은 소유 루프백 HTTP 시험 계약 통과.** 고정 실행기를 임시 사본에서 엄격한 미처리 거부 옵션으로 10회 재현했다. 별도 Node HTTP 클라이언트가 실제 TCP 소켓으로 받은 보호 바이트를 검사했다.

| 검증 | 독립 재현 결과 |
| --- | --- |
| HTML·RSC 유사 본문·분석 POST | 세 유형 모두 HTTP 200, 정확한 Content-Type, `private, no-store`, 합성 본문의 정확한 바이트 일치를 확인했다. 전송 전·중·후 같은 허가를 반복하면 모두 409 및 빈 본문이었다. 정상 허가는 유형마다 한 번만 소비됐다. |
| 첫 보호 바이트 전 차단 | 각 유형에서 철회와 만료를 적용한 6건 모두 403 또는 410, 실제 본문 0바이트, 허가 소비 0건이었다. 전환 중 보류된 이전 허가와 늦은 재호출 역시 409 및 빈 본문이었다. 새 세대의 새 허가는 정상 전송됐다. |
| 전송 중 완료·취소 | 기존 HTML 응답의 전체 본문과 실제 소켓 종료를 확인하기 전에는 새 세대가 열리지 않았다. RSC 전환 취소 시 클라이언트에는 이미 받은 접두부만 남았다. 연결 종료 뒤 새 세대가 열렸다. |
| 종료 불명 | POST의 첫 부분을 받은 클라이언트가 소켓을 끊었다. 종료 상태를 의도적으로 누락하자 새 허가가 닫히고 전환이 멈췄다. 옛 요청은 409 및 빈 본문이었다. 같은 시험 전송 경계의 소켓 종료 관측을 확인한 뒤에만 다음 세대가 열렸다. |

추가로 고정 실행기에 인메모리 검증만 삽입해 두 실제 전송을 동시에 열었다. 하나를 완료한 뒤에도 다른 응답이 남아 세대는 유지됐다. 두 번째 응답의 시험 시계를 만료까지 진행한 뒤 나머지 전송을 시도하자 추가 바이트가 차단됐다. 클라이언트에는 접두부만 남았고 실제 종료를 확인한 뒤 전환됐다. 이 시험에서 만료 처리는 나머지 전송 시도에 의해 실행됐다. 전송 시도가 없는 상태의 자동 종료 타이머는 별도 검증 범위다.

모든 실행에서 리스너와 서버 소켓·클라이언트 요청이 0건으로 정리됐다. 변경 실행기의 ESLint와 고정 변경의 `git diff --check`가 통과했다. 시험은 단일 Node 프로세스의 직렬화에 기반한다. 실제 Next HTML/RSC·프리페치·스트리밍, 호스팅 프록시, 장애 후 운영 전송 소유자 교대, 하위 큐의 종료 증명과 우회 차단은 후속 범위다. 제품, 운영, 배포를 변경하지 않았다.
