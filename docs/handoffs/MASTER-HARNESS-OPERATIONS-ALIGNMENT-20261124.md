| 실제 점검 | 전체 점검 시각은 Controller의 inspection 사건에 남긴다. 일반 Orca 보고 처리 시각은 별도다. 작업 선행 조건 대기와 관리자 요청 대기를 구분한다. |

## 검증 및 운영 반영

- node --check 두 스크립트 및 격리 하네스 회귀 시험 종료 0. 기존 배정 중복, 충돌 차단, 직접 전송 제한, 답변 수신 후 요청 유지, 외부 승인 없는 후속 호출 방지, 전체 점검 시각을 검증했다.
- 10:27 KST에 새 전송만 잠그고 기존 Windows 예약으로 Controller를 교체했다. PID 73952에서 80180으로 전환했고, 기존 작업 224건과 영수증의 변경 0건, 열린 요청 4건을 확인했다. 작업자 프로세스에는 중지 신호를 보내지 않았다.
- 새 배정 전송을 다시 열었고 생존 신호, 실제 점검 사건, RUNNING_WITH_HUMAN_PENDING을 확인했다. 제품 배포·운영 데이터 변경은 이번 하네스 작업에 포함되지 않았다.
- Orca 영수증을 받은 네 활성 세션은 Claude(Front), Claude(Backend), Claude(Tester), Codex design이다. 이전의 Codex Tester와 Codex(Front) 터미널은 수신 연결이 없었다. 연결이 다시 확인되면 같은 지침을 전달한다.
