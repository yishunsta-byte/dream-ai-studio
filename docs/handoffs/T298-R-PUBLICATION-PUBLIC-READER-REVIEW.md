**판정 · 새 DB 조회 계약 통과, 표지의 응답 전 만료 경계는 보완 후 재검수.** 같은 연결에서도 한 문장마다 최신 공개 상태를 확인했습니다. 파일 대기가 만료를 넘긴 뒤 첫 표지 응답이 200으로 생성되는 경우를 재현했습니다.

## F298-1 · 비공개 파일 대기가 만료를 넘기면 첫 응답이 200

루프백 PG17에 시한부 세대를 게시하고, 정상 표지 GET이 활성 세대를 재확인해 비공개 파일 공급자에 도달한 뒤 파일 응답을 보류했습니다. DB 시각이 종료 시각을 지나자 새 목록에서 해당 작품이 빠졌고 새 표지 요청은 저장소 호출 없이 404였습니다. 이때 첫 요청은 응답 객체를 아직 반환하지 않았습니다. 정상 WebP 바이트의 보류를 풀자 첫 요청은 만료 뒤 200과 원본 표지 바이트를 반환했습니다.

[`readObject`](../../lib/public-showcase/publication-public-reader.ts#L133)는 파일 읽기 직전에 최신 세대를 확인합니다. 파일 수신·무결성 확인 뒤 응답을 생성하기 전에는 권리와 세대를 다시 조회하지 않습니다. 응답 시작 전에 만료나 철회가 확인된 경우 표지 바이트를 제공하지 않는 경계를 검증할 필요가 있습니다. 호스트·CDN 캐시와 이미 전송을 시작한 응답은 별도 범위입니다.

| 오토커밋과 PID | 철회·만료 전후 같은 목록과 표지 PID를 관측했고, 조회 후 각 연결은 `idle`이고 `xact_start`는 `NULL`이었습니다. 같은 PID의 새 조회가 만료·철회를 반영했고, 새 세대를 게시한 뒤 예전 표지는 404, 새 표지는 200이었습니다. |
| 잠금·기한·취소 | 실제 테이블 잠금에 걸린 조회를 관측한 뒤 호출자 취소와 기한 만료가 `timeout`으로 끝났고 다음 조회는 성공했습니다. 실제 풀의 체크아웃 완료 전달을 지연시켜 취소한 별도 시험에서 늦게 도착한 연결은 SQL 0회, 폐기 1회였으며 다시 조회할 수 있었습니다. 집중 시험은 트랜잭션이 남은 연결 폐기와 늦은 파일 응답 무시도 확인합니다. |
