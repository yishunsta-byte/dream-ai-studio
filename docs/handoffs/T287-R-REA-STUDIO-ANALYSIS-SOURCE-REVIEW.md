## 필수 수정 F287-1 — 재인증 대기에 걸린 취소와 시간 제한

실제 루프백 reader와 HTTP 수신 스트림으로 PNG 사본을 생성했습니다. 같은 액터를 반환할 사본 완성 직후의 두 번째 `resolveAuth()`만 제어 가능한 대기로 두고, 실제 수신 및 해시 검사는 완료시켰습니다.

| 재현 | 관측 |
| --- | --- |
| 호출 제한 700ms 경과 | 두 번째 인증이 시작된 뒤 900ms를 기다려도 요청이 완료되지 않았습니다. `dream-studio-source-*` 아래 `reference.png`가 등록 크기 그대로 남았습니다. |
| 사본 완성 뒤 재인증 중 호출자 취소 | 취소 120ms 뒤에도 같은 파일이 남았고 요청은 대기 중이었습니다. |
| 후속 요청과 최종 정리 | 두 사례 모두 `maxConcurrent: 1`의 새 요청은 `source_unavailable`이었습니다. 재인증 대기를 해제한 뒤에만 원 요청이 각각 `timed_out`·`cancelled`로 완료되고 파일이 삭제됐습니다. |

합성 권한 조회와 스트림 공급자는 모두 신호를 처리했습니다. 사본 직후 재인증은 신호 없이 `await resolveAuth()`를 호출합니다. 타이머가 신호를 중단해도 이 대기가 해제되기 전에는 `finally`의 정리 및 슬롯 반환에 도달하지 못합니다. T284가 호출하는 최초 인증과 분석 후 재인증도 같은 인증 함수 형식을 씁니다. 공통 인증 단계에 취소 가능한 대기 경계를 적용하고, 지연된 인증 결과가 이후 조회나 디코딩을 시작하지 않도록 검증해야 합니다. 사본 이후 인증이 끝나지 않는 상태에서 시간 제한과 취소 각각에 대해 결과·파일·슬롯을 확인하는 회귀가 필요합니다. ## 독립 합성 루프백 대조

| 범위 | 확인 결과 |
| --- | --- |
| A/B 격리와 실제 이중 수신 | 서로 다른 두 PNG로 본인 분석과 서로 다른 팔레트를 확인했습니다. 교차 요청은 두 방향 모두 reader·수신 HTTP 요청이 0건이었습니다. 정상 흐름에서 버킷 비공개 확인, 자격이 있는 객체 GET, 독립 수신 GET 순서를 기록했습니다. 응답에 키·해시·계정 및 자료 ID·세대·임시 경로·자격 문자열은 없었습니다. |
| 필수 증거 | 활성 링크·소유 세대 누락, 등록과 검증 스토리지 세대 불일치, 교차 소유 자료, 용량 한도 초과, T279 관측 형태를 네트워크 접근 전에 거절했습니다. 바이트 검증 대상은 기존의 소유자·객체키·파일 크기 계약을 통과했습니다. |
| 크기·해시·응답 오류 | 기존 reader의 바이트가 바뀌면 별도 수신으로 진행하지 않았습니다. 수신 GET에서 등록 크기와 같은 다른 바이트, 짧은 바이트, 초과 바이트 및 중간 전송 오류를 모두 거절했습니다. |
| 사본 이후 확인 | 사본 직후 철회·링크 재연결과 디코딩 후 복원·자료·스토리지 검증 세대 갱신에 모두 결과가 없었습니다. 사본 직후 및 분석 후 계정 변경도 폐기됐습니다. 정상 흐름은 인증과 권한을 각각 세 차례 확인했습니다. |
| 협조하는 대기·스트림의 종료 | 신호를 처리하는 조회는 60ms 제한에서 `timed_out`이었습니다. 별도 HTTP 스트림을 읽다가 취소하자 서버 연결이 닫혔고 이 요청의 사본이 삭제됐습니다. 같은 어댑터로 정상 재시도가 성공했고, 작업 루트에 둔 별도 표식 파일은 모든 정리에서 보존됐습니다. |
