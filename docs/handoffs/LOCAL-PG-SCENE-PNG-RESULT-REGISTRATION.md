# 승인된 로컬 PG 장면에 검증 PNG 결과 등록

Master 선행 배정 `msg_1f5e2e410ea1`. 기준 `fbce784`에서는 승인 후 장면 두 개와 프로젝트 PNG 한 개가 존재했다. 실제 HTTP로 기존 생성과 선택을 요청하면 SQLite 전용 가드가 503을 반환했고 PostgreSQL 장면 결과와 선택은 각각 0건이었다. 초기 보고는 `msg_e36f25f7713d`다.

승인 기획의 장면 카드에서 프로젝트에 연결된 PNG를 고르고 **PNG 결과 등록**을 누른다. 새 결과의 버전과 원본 이름을 같은 장면에서 조회할 수 있다. 등록 성공 후에도 **선택한 결과 없음**과 제작 **할 일** 상태가 유지된다.

- 기존 PNG 검증 함수로 현재 검증 영수증과 저장 객체, 정책과 원본 동일성을 확인한다. 원본 파일과 자료 행을 보존하고 성공 결과가 해당 자료를 가리키도록 저장한다. 결과에 원본 SHA-256과 권리 메모를 기록한다.
- 서버가 소유자, 현재 승인 기획, 프로젝트 내용 리비전, 보관 여부, 프로젝트 자료 연결과 장면 소속을 확인한다. 같은 기획·장면·PNG의 반복 요청은 같은 성공 결과를 반환하며 DB 기록과 활동 기록은 한 건씩이다.
- 범위는 프로젝트에 이미 연결된 PNG 원본이다. 새 결과는 제작 목록에 표시되며, 별도 결과 선택 절차의 입력이 된다.
- 로컬 시험 DB에는 기존 `local.sql`과 T368 설치 뒤 `scene-result-source.sql`을 적용한다. HTTP 시험은 이 함수를 설치하고 T368을 해제하기 전에 제거한다.

## 자체 검증

- 전체 타입 검사, 관련 회귀 시험 269건과 변경 파일 ESLint 통과.
- `T371_VERIFY_HTTP=1`로 `node --conditions=react-server --import tsx tests/postgres/t368-run-private-image-project-create.mjs` 종료 코드 0. 접속권한, 보관 자산·장면·프로젝트, 구버전 내용과 기획 ID, 다른 출처를 거절했다. 동시 요청은 201/200과 동일 결과를 반환했고 원본 SHA·권리 메모와 선택·제작 상태가 유지됐다.
- 실제 Chromium에서 신규 프로젝트에 PNG와 권리 메모를 업로드하고 브리프 확인, 초안 저장, 기획 승인, 제작 화면 진입, 장면 1의 PNG 결과 등록을 순서대로 수행했다. 새로고침과 프로젝트 상세에서 재진입한 뒤에도 같은 결과 ID, 원본명, 버전을 읽었다. 업로드 파일의 SHA-256 및 권리 메모가 결과 기록과 일치했고 승인 상태와 활동 기록을 로컬 PG에서 확인했다.
