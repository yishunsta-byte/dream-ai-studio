# T311-R 현재 스토리지 증거·정책 경합 독립 재현

기준 `b6e910b` · Master 인계 `msg_4bcf7f9e151f` · Codex(Tester)

**판정은 소유 루프백 PostgreSQL 17.12 시험 계약 통과.** 임시 고정 사본에서 원본 실행기를 두 번 재현했다. 소유 바이너리와 고정 SQL 해시 검사를 거쳐 실제 SQL4 테이블·제약·트리거를 사용했다. 두 실행 뒤 호스트에서도 소유 PostgreSQL 프로세스와 T311 임시 클러스터가 0개였다.

| 변경 | 변경 작업 선행 | 발급 선행 |
| --- | --- | --- |
| 정책 epoch·digest 교체 | 발급은 정책에서 대기했다. 기존 검증 포인터가 유지돼도 정책 커밋 뒤 이전 증거의 쓰기·조회가 거절됐다. A/B 모두 새 정책으로 검증하고 발급한 뒤 조회됐다. | 정책 갱신이 발급의 공유 잠금 뒤에서 대기했다. 먼저 발급한 증거도 정책 커밋 뒤 숨겨졌다. |
| 재검증 성공 | 발급은 객체에서 대기했다. 새 검증 ID와 스토리지 세대의 커밋 뒤 기존 증거가 빠졌고, 새 증거를 발급한 뒤 A의 조회가 회복됐다. | 재검증이 객체 공유 잠금에서 대기했다. 성공 커밋 뒤 이전 발급은 조회에서 제외됐고, 새 증거 발급 뒤 다시 조회됐다. |
| 재검증 실패 | 객체 세대가 전진하고 자료는 철회됐다. 이전 성공 검증 포인터가 남아 있어도 발급과 조회는 거절됐다. | 발급 뒤 실패를 직렬화했다. 실패 커밋 뒤 이전 증거는 숨겨졌고, 재검증 성공과 새 발급을 모두 마친 뒤 다시 조회됐다. |

`pg_blocking_pids`로 여섯 경우 모두 차단한 백엔드를 확인했다. 정책에서 대기할 때는 객체 잠금에 진입하지 않았고, 객체에서 대기할 때는 검증 작업과 상태 잠금에 진입하지 않았다. 반대편의 짧은 요청은 `55P03`으로 끝났고, `25P02`로 트랜잭션 실패를 확인한 뒤 롤백했다. 짧은 경합 시도는 포인터나 스토리지 상태를 바꾸지 않았다. 재검증만 변경한 경우 B의 증거와 조회는 유지됐다.

A/B 상호 목록·단건과 발급이 분리됐다. 읽기 역할의 발급 호출, 발급 로그인에서의 포인터 직접 수정·정책 변경·보호 역할 전환은 거절됐다. 정책·객체·검증 필드 일곱 개의 불일치와 예전 포인터 리비전도 각각 거절됐다. 열린 트랜잭션과 발급·읽기 연결 0건, 소유 서버·PID·리스너·임시 경로 정리를 확인했다. 변경 실행기의 ESLint와 고정 변경의 `git diff --check`가 통과했다.

T310의 제어 행은 재사용했다. 요청 원장·발급 결과의 결합, GC 및 외부 객체 삭제, 실제 바이트·제공자 버전, 운영 마이그레이션과 복원·전송은 후속 범위다. 격리 실행기는 발급자가 먼저 잠그는 경우를 만들기 위해 동일한 현재 검증 튜플로 새 증거 리비전을 발급한다. 제품에서는 T309의 새 검증 ID를 요구하는 갱신 규칙과 복원 증명까지 포함한 발급 기한을 별도로 검증해야 한다. A/B는 시험에서 주입한 현재 actor 기준이며 인증부터 DB actor 전달까지는 별도 범위다. 제품 빌드·운영 DB·배포는 사용하지 않았다.
