## 기준 후보의 차이와 후속 요청

**이미 Master가 Front에 요청한 사항 — 중복 새 결함으로 계수하지 않음:**

1. `manage/page.tsx:49`: 빈 응답에서 “아직 클라우드에 옮긴 프로젝트가 없어요 / 지금까지 만든 작품은 내 PC 작업실에 있어요”라고 단정. “이번에 불러온 목록에 프로젝트가 없어요”로 한정 필요.
2. `page.tsx:48~58`: empty branch에서 실제 성공 0·조회 시각이 빠짐. 성공 빈 결과에 표시하고, failure는 계속 숫자를 표시하지 않아야 함. 기존 시험의 과거 empty 기대값도 새 요구에 맞춰 확인 필요.
3. `page.tsx:19,38,57`: invalid latest date가 Intl formatter를 깨뜨릴 수 있는 표시 방어. upstream에서 정상 Date를 변환하더라도 요청된 fallback을 후속 후보에서 별도로 대조해야 함.

**추가 소스 차이 / 필수 정합:**

- `page.tsx:41,53` + `page.module.css:9`: 재조회 안내와 “기록 상태 / 실제 실행 확인 아님”이라는 중요한 문장을 13px `--text-xs`로 렌더. T230 5절의 중요 본문 최소15px와 다름. 날짜 등 메타와 중요 안내 문장의 클래스를 나누어 후자는 `--text-md`로 표시할 것. 조회 시각에는 사용자에게 한국시간 기준을 알리는 문구도 보완할 것.
- `page.tsx:40,47,59`의 새 다시 불러오기·목록 링크와 projects/(list)의 새 관리 링크에는 조작44px을 확보하는 전용 스타일이 보이지 않음. 공통 PageHeader.actions도 flex일 뿐 최소높이가 없음. **실측 FAIL이라고 주장하지 않으며**, 해당 새 링크의 실제 anchor hit box를 양폭에서 측정하고 부족하면 T229 허용 CSS 안에서44px을 확보해야 함. 별도 주 버튼을 만들지 않은 이 화면에 48px 주 버튼을 추가하도록 요구하지 않음.

**미검증 행동 / 증거 요청:**
