# T282 REA 적용 결과 기록의 권한 세대 판정

2026-11-19 KST · Codes(Backend) · 기준 `96a7c9612a57f7f409f473a8f8fd342834ebea94` · 배정 `msg_cac1c767ae93`

적용 결과 기록 **v2**는 종결 시점의 링크·범위 권한·소유자 권한 세대를 내부 판정에 저장합니다. 복원 세대는 기존 저장소·소유자·프로젝트·자료 범위에 포함됩니다. `read_receipt`와 완료된 `confirm`의 재전송은 같은 분기에서 현재 조회권과 네 세대의 일치 및 보존 구간을 검사합니다. 권한 철회 뒤 재승인해도 새 세대는 이전 적용 결과 기록을 열 수 없습니다. 사용자 응답은 종전처럼 결과 유형, 타임라인 ID와 두 리비전, 종결 시각만 담습니다. ## 기존 호출 영향

| 경계 | 변경 및 동작 |
| --- | --- |
| v1 대기 확인 | 대기 스키마는 유지합니다. 합성 저장소의 준비·적용에서는 동일한 권위 조회로 받은 링크 및 범위·소유자 세대가 대기 기준과 일치해야 합니다. 범위·소유자 세대는 고정 순서와 버전을 갖는 SHA-256 합성값으로 기존 `permissionGeneration`에 묶습니다. 증거가 없거나 옛 방식으로 발급돼 결합을 입증하지 못한 대기 확인은 쓰기에 진입하지 않습니다. |
| v1 종결·미확인 | `unavailable`을 반환합니다. 현재 권한에서 과거 세대를 소급 추정하지 않으며 기존 행을 덮어쓰거나 다시 적용하지 않습니다. 종결된 `no_change`도 v2 적용 결과 기록에 같은 판정을 사용합니다. |
| v2 종결·현재 세대 일치 | 현재 조회권과 종결 시각 이상·보존 기한 미만이면 원래 적용 결과 기록을 반환합니다. 이후 분석 상태, 대기 실행 만료 및 최신 타임라인 변경이 적용 결과 기록의 결과를 바꾸지 않습니다. |
| 제품 경로 | 호출부 검색에서 순수 판정과 합성 저장소 밖의 제품 연결은 확인되지 않았습니다. 새 적용 결과 기록에는 세대를 넣되 공개 DTO에는 포함하지 않습니다. 실제 권한의 서버 출처, DB 경합·트랜잭션 재검증, 타임라인의 `content_revision`/포인터/`stage_states` 쓰기 연계는 후속 범위입니다. |

## 검증

- 순수 함수에서 링크·범위·소유자·복원 세대를 각각 바꿔 조회와 재전송을 거절했습니다. 권한 미확인·부족, 세대 없음 및 레거시 종결도 두 요청에서 닫혔습니다.
- 합성 저장소에서 종결 세대를 모르는 확인이나 대기 기준과 합성 권한 세대가 다른 확인은 쓰지 않았습니다. v2를 기록한 뒤 사용자 응답에는 세대가 없음을 확인했습니다. 소유자 및 실제 시험 DB의 범위 재승인 뒤 조회와 재전송은 거절됐고, 거절 시 DB 스냅샷은 유지됐습니다.
- 같은 세대에서 실제 별도 테스트 프로세스의 응답 유실 후 조회, 보존 경계와 `no_change`, 복원본 거절 및 기존 롤백을 재검증했습니다.
