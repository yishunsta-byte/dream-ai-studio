**조건부 통과.** 로컬 컷 후보, 실제 프레임과 시간 위치, 자원·종료 경계는 검증했다. 음원·이미지 로컬 단위는 진행 가능하다. 영상 대표 프레임을 실제 화면이나 구도 관찰에 연결하기 전에는 비정사각 픽셀 영상의 표시 비율을 보완해야 한다. [구현 보고](T267-REA-LOCAL-VIDEO-FEATURES.md)

## P2 · 표시 화면비 왜곡

별도로 합성한 빨간 MP4는 ffprobe에서 저장 치수 32×32, 픽셀 비율 `SAR=2:1`, 표시 비율 `DAR=2:1`이었다. REA는 성공을 반환했으나 64×36 파생 프레임에서 빨간 영역은 36×36으로 측정됐다. 현재 `scale`을 거친 뒤 `setsar=1`을 적용하면 저장 픽셀 비율로 축소한 콘텐츠의 표시 비율 정보가 사라진다. 화면에서 영상이 눌려 보이고 여백을 포함한 RGB 차이의 가중치도 달라진다. [영상 필터](../../lib/reference-analysis/video-features.ts#L62)

기존 FFmpeg에서 `scale`의 `reset_sar=1`과 비율 유지 축소를 함께 적용한 뒤 여백을 추가하니 같은 프레임의 빨간 영역이 64×32로 측정됐다. 코드 변경 없이 별도 로컬 실행으로 확인한 보완 후보다. 지원 도구에서 동작을 고정하고 `SAR=1`과 `SAR=2:1` 표본의 실제 색 영역을 회귀로 검증한다. 결과 위치와 원본의 프로브 치수는 유지한다.

## 통과 범위

- 별도 8fps 단색 합성 영상은 8프레임과 실제 `0–875ms`, 컷 후보 0개를 반환했다. 8fps 녹색→자홍 합성 영상에서는 실제 이전 프레임 `375ms`와 이후 `500ms` 사이 후보 한 건을 반환했다. 대표 프레임의 중앙 픽셀은 각각 `[0,127,0]`, `[253,0,252]`였고 서버 파생물은 프레임당 6,912 byte였다. 결과의 컷 표시는 프레임 차이에 근거한 추정이다.
- 네이티브 시험에서 300ms 지연 트랙의 실제 시작 `300ms`와 마지막 디코딩 시각 `1200ms`, 후보 `700–800ms`를 재검증했다. 표지를 포함한 영상은 정상 후보·프레임을 유지했고, 표지만 있는 MP4는 영상 입력을 거절했다. 복수 영상과 관련 없는 PTS 로그는 각각 `track_unverified`, `frame_timing_unverified`였다. [시험](../../tests/reference-analysis/video-features.test.ts)
- 실제 소스 1960×1080과 후보 24건을 초과하는 흑백 교대 표본은 `analysis_limit`과 파일 메타데이터만 반환했다. 네이티브 시험의 21초, 270프레임, 관리 파일 64 MiB 초과도 거절됐다. 입력 바이트, 프로브 치수, 시간·프레임·후보 수와 출력 버퍼 한도는 확인했다. 프로브 치수는 디코더의 가변 해상도·실행 자원을 보장하지 않으므로 실제 자료 연결에는 실행 격리와 자원 제한이 필요하다.
- 관리 루트 밖에서 읽기 요청을 거절했다. 프로브와 디코더가 같은 관리 사본을 쓰는 경계를 코드와 사본 경로 관측으로 확인했다. 이미 취소된 신호와 1ms 기한은 `cancelled`와 `timed_out`으로 분리됐다. 네이티브 시험에서 진행 중인 합성 자식의 종료 이벤트 및 사본 폴더 부재를 결과 반환 전에 확인했다. 별도 실물 성공·실패 시험 전후에 검사 사본 폴더 목록이 같았다. private 검사 JSON·소유자·공유 출력에는 로컬 절대경로와 픽셀이 없었다. 서버 전용 `video.frames`에만 파생 픽셀이 남는다.
