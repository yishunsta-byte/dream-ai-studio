# T307 등록 자료 목록과 분석 권한 PostgreSQL 연결

T301의 등록 자료 목록과 T302의 단건 분석 권한 조회가 한 DB 어댑터를 사용하도록 구현했다. 이 어댑터는 명시적으로 제공된 격리 PostgreSQL 17.12 루프백 구성에서 열 수 있다. 기존 Auth, API, UI의 연결 구성은 그대로이며 운영에서 분석을 활성화하려면 아래 증거 계약이 필요하다.

## 권한 판정

- 검증된 서버 인증 사용자의 ID를 트랜잭션 범위에 설정한다. 전용 읽기 역할과 RLS가 조회 범위를 제한한다. 목록과 단건은 각각 새 `REPEATABLE READ READ ONLY` 트랜잭션에서 같은 SQL을 실행한다.
- 활성 프로젝트와 실물 이미지·영상, 같은 소유자의 `rea-reference` 연결, 활성 소유자·자료별 분석 권한, 등록 스토리지 객체와 현재 스토리지 검증 기록이 모두 필요하다. 등록 객체의 버킷, 키, MIME, 크기, 해시, 식별 다이제스트, 스토리지 세대가 각 근거와 일치해야 하며 DB 시계상 검증과 증거의 유효 기간이 남아 있어야 한다.
- 자료 증거는 현재 스토어·복원 세대와 정확한 소유자, 자료, 스토리지 객체, 객체 식별 다이제스트, 스토리지 검증 기록 ID 및 스토리지 세대에 결합한다. 분석에는 소유자·범위 권한, 연결, 복원, 자료, 스토리지 세대를 함께 반환한다.
- 서버 목록에는 소유자·프로젝트·자료 ID, 이미지나 영상의 표시 이름, 두 상태 플래그만 전달한다. 기존 T301 페이지는 브라우저에 프로젝트·자료 ID와 표시 이름만 보낸다. 스토리지 키·경로, 해시, 세대는 단건 서버 경계에서만 사용한다.
- 해당 자료에 증거가 없거나 만료되면 목록에서 제외하고 단건은 결과를 반환하지 않는다. 필수 스키마나 권한에 문제가 있거나 취소·기한을 초과하면 일반화된 실패를 반환하고 사용 중인 DB 연결을 폐기한다.

## 운영 연결의 전제

격리 테스트는 고정 SQL1–4와 T281에 테스트 전용 증거 테이블과 읽기 역할을 추가한다. SQL1–4와 T281에는 운영 복원 세대와 자료 세대의 신뢰 가능한 발급 경로가 없다. 별도 운영 마이그레이션과 발급·복원 절차에서 다음 사항을 입증해야 한다.

1. 복원·승격·재바인딩 시 스토어 ID 및 복원 세대를 서비스 제공 전에 확인한다. 이전 DB 백업에서 복사된 세대가 복원을 승인하지 못하도록 복원된 DB와 독립적인 신뢰 원천에서 새 세대를 발급한다.
2. 서버 전용 발급자가 현재 등록 자료와 검증 기록을 대조해 자료별 증거를 발급한다. 자료 교체·재검증·복원 시 갱신하고 이전 자료 세대를 재사용하지 않는다. 검증·복원 증거 누락이나 갱신 실패 시 해당 행을 비활성으로 유지한다.
3. 앱 읽기 계정에 테넌트 RLS가 적용되는 최소 조회 권한을 부여한다. 등록·검증·복원·권한 변경은 별도 역할에 두고 권한 변경과 읽기 간 일관성을 운영과 동일한 격리 환경에서 검증한다. T301 페이지와 T302 분석은 동일하게 검증한 서버 연결을 사용해야 한다.
