# T278 REA 등록 자료에서 적용 영수증까지 격리 통합

2026-11-19 KST · Codes(Backend) · 기준 `6d823e264993c27f616dcc8ac24b2fcd036e5a9a` · 배정 `msg_7ea6b32309ef` · 독립 검수 대기

격리된 합성 S4 SQLite 사본에 실제로 합성한 MP4의 크기·MIME·SHA-256과 프로젝트 자료 연결을 등록했습니다. 서버 전용 시험 픽스처는 기존 `projects`·`project_assets`·`assets`와 합성 소유·세대 테이블을 조인합니다. 검증된 합성 액터, 활성 연결 및 현재 저장소·복원 세대가 맞는 자료만 분석 대상으로 선택합니다. 소유·권한용 행과 액터는 테스트 구성입니다. 제품 SQLite의 사용자별 소유권을 입증하는 근거로 사용할 수 없습니다. [격리 연계 픽스처](../../tests/reference-analysis/isolated-rea-fixture.ts)

## 연결한 흐름

1. 서버 권한 조회를 통과한 경로만 T277에 전달했습니다. T277이 등록 SHA-256과 관리 사본을 결합했으며, 분석 완료 뒤 현재 소유·링크·세대 및 파일을 다시 확인하고 사본 해시와 분석 식별자를 시험 DB에 저장했습니다.
2. 30fps 합성 MP4의 실제 영상 변화에서 **967–1,000ms** 컷 후보와 **1,000ms** 관측 PTS를 얻었습니다. 기존 T271 미리보기는 이를 관찰·추정·창작 제안으로 분리하고 편집 격자 **30번 프레임**과 0프레임 컷을 반환했습니다. 원본 시각과 근사 프레임을 프로젝트 위치로 쓰지 않고, 확인에 묶인 두 기존 장면의 위치를 사용했습니다.
3. 준비만 했거나 확인이 거짓이면 타임라인은 유지됐습니다. 별도의 Node 테스트 프로세스가 확인 ID로 현재 권한·파일·분석·타임라인을 같은 SQLite 연결에서 다시 확인했습니다. T276이 단일 확인 소비·기존 CAS와 타임라인·워크플로 쓰기·최소 영수증을 한 트랜잭션으로 커밋했습니다.
4. 적용 프로세스가 응답을 버리고 종료한 뒤 다른 프로세스가 실행 확인 만료 이후 원래 영수증을 조회했습니다. 재전송도 원래 영수증만 반환했고, 타임라인은 1개 새 리비전과 1개 저장 활동 로그만 추가했습니다. 기존 텍스트·오디오와 합성 원본 바이트를 보존했습니다. 미리보기와 영수증에 해시·파일명·경로·픽셀·분석/복원 식별자를 노출하지 않았습니다.

## 제품 연결 전 선행조건

로컬 제품에서는 확인된 작업공간 권한이나 실제 행 소유권을 읽기·쓰기·철회 전반에 적용해야 합니다. 자료 사본의 경계·해시, 링크/권한 세대 전환, 신뢰할 복원 세대 발급과 보존 정책을 실제 서버에서 검증해야 합니다. 통합 픽스처의 파일 재해시는 작은 합성 파일에만 적용하며 제품의 저장소 권한·파일 불변성 계약을 대신하지 않습니다.
