# 로컬 PG 장면 PNG 결과 등록 독립 검수

MASTER 배정 `msg_20f61013ef0b`. 합격 기준 `bb7b6b1`을 포함한 `a2f06f7`의 격리 Git 사본에서 실제 Next.js HTTP·Chromium·임시 PG17로 검수했다.

| 확인 항목 | 관찰 |
|---|---|
| 신규 프로젝트와 첫 등록 | 브라우저에서 102바이트 합성 PNG 및 권리 메모 업로드, 프로젝트 저장, 저장한 프로젝트 열기, 브리프 승인, 기획 저장·승인, 제작 진입을 수행했다. 업로드와 프로젝트 저장은 각각 201이었다. 장면 1의 등록도 201이며 버전 1이 표시됐다. |
| 중복과 재진입 | 같은 본문을 다시 보내면 200과 같은 결과 ID·버전·PNG ID가 반환됐다. 결과와 감사 기록은 각각 1건이었다. 새로고침과 프로젝트 상세에서 다시 진입한 뒤에도 제작 API와 화면에서 동일한 결과를 확인했다. |
| 원본과 선택 | 실제 PNG 바이트의 SHA-256 `32bdf79928e59803015b60b0222e4c763d5b175309f842083aae621686ada5c7`과 입력한 권리 메모가 원본 행과 결과 입력 기록에서 일치했다. 첫 등록 뒤 선택은 NULL이었다. 별도 시험 자료로 버전 1을 선택한 뒤 다른 검증 PNG를 연결·등록하자 버전 2가 추가됐고 기존 선택은 버전 1에 남았다. 두 경우 제작은 `todo`였다. |
| 거절 | 다른 계정·다른 소유자 자료·프로젝트에 연결되지 않은 같은 소유자의 자료·보관 원본/장면/프로젝트·없는 장면은 404였다. 이전 내용 리비전과 다른 기획 ID는 409였다. 거절 뒤 등록 결과는 증가하지 않았다. |

기존 [HTTP 시험](../../tests/postgres/local-project-brief-http.mjs)에 격리 사본 전용 브라우저·DB 대조를 연결했다. 초기 브라우저 실행에서 PNG와 WAV 입력을 함께 가리킨 선택자와 화면 밖 클릭을 바로잡았다. 키보드로 조작한 최종 실행은 종료 코드 0이었다. 브라우저 공간, PostgreSQL 프로세스·리스너·임시 클러스터 정리를 확인했다.
