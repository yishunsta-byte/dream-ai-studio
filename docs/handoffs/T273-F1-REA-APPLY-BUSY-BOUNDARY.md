# T273-F1 REA 타임라인 쓰기 잠금 대기 초과

2026-11-19 KST · Codes(Backend) · 기준 `5a48dccdcb3334714bb4fe91a0d340434b1935f3` · 배정 `msg_4c3c44c9a4d2` · 독립 검수 대기

REA의 `apply`에서 최상위 `BEGIN IMMEDIATE`를 얻는 중 네이티브 SQLite `SQLITE_BUSY`가 발생하고 작업 본문에 진입하지 않았으면 `{ status: "busy", retryable: true }`를 반환합니다. 이 분기에서 호출자가 받는 값은 두 필드이며 SQLite 메시지를 포함하지 않습니다. 호출자가 명시적 확인을 다시 제출하면 소유권, 분석 유효성·신선도와 타임라인 CAS를 새로 검사합니다. [이전 독립 검수](T273-R-REA-EXPLICIT-PROJECT-APPLY-REVIEW.md) · [서비스](../../lib/reference-analysis/project-apply.ts)

쓰기 본문 진입 이후와 커밋 단계의 오류는 기존 오류 경로를 따릅니다. 커밋 결과가 불명확한 경우에는 상위 호출자가 현재 타임라인을 다시 읽어 판단해야 합니다. 서비스에서 자동 재시도를 수행하지 않습니다. 기존 `conflict`, `no_change` 및 예상 밖 오류·롤백 경계를 보존했습니다. 제품 연결과 공용 SQLite 설정은 기존 범위 그대로입니다.

| 격리된 합성 SQLite 두 연결 | 결과 |
| --- | --- |
| 한 연결이 쓰기 잠금 유지, 반대 연결은 20ms 대기 | `busy` 응답, 전체 논리 DB 스냅샷 동일 |
| 잠금만 해제하고 같은 확인 재시도 | 리비전 1건 저장 |
| 잠금 해제 후 다른 확인이 먼저 커밋 | 지연된 확인의 재시도는 `conflict`, 추가 리비전 없음 |
| 롤백 저널 모드에서 읽기 연결이 쓰기 커밋 차단 | 마지막 활동 로그 쓰기 도달 후 `SQLITE_BUSY` 예외 유지, 전체 롤백 확인 |

적용 집중 7/7, 기본 REA 82 통과·45 건너뜀, 네이티브 REA와 기존 타임라인·오디오 포함 12개 파일 **163/163** 통과. `tsc -p tmp/t273-rea-typecheck.json`과 변경 파일 ESLint `--max-warnings 0`도 통과했습니다. 합성 S4의 임시 DB 사본과 테스트 연결에서만 대기 시간 및 저널 모드를 조정했습니다. [집중 시험](../../tests/reference-analysis/project-apply.test.ts)
