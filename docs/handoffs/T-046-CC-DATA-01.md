## 2. 시험 (`tests/k6-t044-guard.test.ts`, 25 → 27개)

- **F045-1 (새로 추가)**
  - 경로가 빈 채로 시작해서 `afterProbe`에서 원시 DELETE DB(`survivor`/`keep`)를 만들면, 거부되고(종료 1, 출처 확인 불가 문장) 바이트·머리글(1/1)·내용이 그대로예요. `-wal` 파일과 스냅샷도 없어요.
  - 경로가 빈 진짜 새 준비(4단계)와 이미 최신인 no-op(바이트 그대로), DELETE s3 정상 올리기(사본)가 그대로 돼요.
  - 기존 "있던 경로에서 기록 행을 지우는" 경합 시험도 그대로 통과해요.
- **F045-2 (예전 시험을 바꿈)**
  - T-045처럼 진짜 사본을 복사해 업무 행만 바꾼 사본을 만들었어요. integrity ok이고 구조와 기록이 같아요.
    - 지문 있는 기록: 거부해요.
    - 지문을 지운 예전 기록: 바꿔 넣은 사본도, **진짜 사본도** 모두 확인 못 함 문장이고 코드는 `MIGRATION_FAILED`예요.
  - 새 기록에서 맞는 지문은 확인되고, 틀린 지문은 거부해요. 확인해도 사본 바이트가 그대로예요.
- **되돌려 보기:** `wal:!existed`로 되돌리면 F045-1 시험 1개가, 예전 fallback으로 되돌리면 F045-2 시험 1개가 실패해요. 원래대로 돌리니 모두 통과했어요.
