# T292 작업실 분석 공급자 취소와 응답 기한

2026-11-19 KST · Codex(design) · 기준 커밋 `645575f` · 배정 `msg_7b584fcfe593`

`createStudioRegisteredAnalysisProvider({ materials, uri, transport, timeoutMs })`는 T291의 `RegisteredAnalysisProvider`를 반환합니다. 작업실에서 공급자 객체를 안정적으로 유지하고, 통합 측에서 URI, `fetch` 호환 구현, 양의 정수 밀리초 기한을 명시합니다. 요청은 선택한 프로젝트와 자료 ID만 JSON `POST`로 전송합니다. `fetch`의 동일 출처 자격 증명만 사용하고, 캐시와 리디렉션은 허용하지 않습니다.

| 상황 | 공급자 동작 |
| --- | --- |
| 기한 안에 정상 JSON 응답 | HTTP 성공 응답의 T284 버전 1 DTO를 검증합니다. 영상의 관측 프레임과 추정의 근거 참조를 확인하며, 서버가 반환한 유효한 `cancelled` 및 다른 상태를 전달합니다. |
| 사용자가 먼저 취소 | 전송 신호를 중단하고 `analysis_unavailable`로 즉시 종료합니다. 기존 UI가 취소 완료를 확인할 수 없다고 표시하고 같은 자료를 다시 실행할 수 있습니다. |
| 응답 기한 초과 | 전송과 본문 읽기에 같은 기한을 적용합니다. 두 단계 중 어느 쪽이 멈춰도 전송 신호를 중단하고 `timed_out`을 반환합니다. 기한은 실제 응답 결과를 채택하기 직전에도 확인합니다. |
| 전송 오류·HTTP 오류·본문 오류·DTO 불일치 | 외부 오류 내용 없이 `analysis_unavailable`을 반환합니다. HTTP 오류 본문은 읽지 않습니다. |

각 호출은 별도의 타이머와 중단 신호를 사용합니다. 종료되면 타이머와 호출자 취소 리스너를 정리합니다. 종료 뒤 도착한 응답은 새 실행과 이전 실행의 화면에 반영되지 않습니다. 브라우저가 중단 신호를 보내는 시점과 서버 파일·동시 실행 슬롯 정리가 끝나는 시점은 별도입니다. 실제 서버 연결에서 T287의 정리, 실행 제한, 취소 응답과 HTTP 상태 매핑을 확인해야 합니다. 기존 UI, 라우트, 인증, Supabase와 운영 배포는 수정 범위에 포함되지 않았습니다.

## 자체 검증

- `DREAM_REA_NATIVE_TEST=1`로 `node node_modules/vitest/vitest.mjs run tests/reference-analysis`를 실행했습니다. 집중 시험 15개를 포함해 20개 파일, 234개가 통과했습니다. 집중 시험에서 T284 계약이 합성 분석 결과로 생성한 PNG·MP4·WAV DTO, 헤더 및 본문 미완료, 기한 만료, 취소, 늦은 응답, 같은 자료 재시도, 비정상 HTTP·JSON·DTO, 리스너와 타이머 정리를 확인했습니다.
- 변경 모듈과 시험 파일을 포함한 집중 TypeScript 검사, ESLint 경고 0을 확인했습니다.
- ego-browser의 격리 화면에서 실제 T291 UI와 새 공급자를 연결했습니다. 키보드로 취소한 뒤 미확인 안내와 즉시 재실행을 확인했습니다. 이전 요청의 늦은 서버 취소 응답은 무시됐고, 두 번째 요청의 본문 기한이 지나자 같은 자료를 다시 실행해 실제 T284가 합성 MP4에서 생성한 결과를 표시했습니다.

**Master 전달문** — T292 클라이언트 공급자 완료. 재시도 시 같은 자료에서 키보드로 작업을 이어갈 수 있음을 격리 UI에서 검증했습니다. 실제 URI 결정과 T287 서버 종료·파일 정리·동시 실행 제한은 후속 서버 연결에서 검증해야 합니다.
