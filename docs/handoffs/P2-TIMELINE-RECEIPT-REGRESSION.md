# 편집 타임라인 저장 경합 회귀 검증

fae6eab에서 다른 저장이 앞선 경우 반환하는 상태에 receipt:null이 추가됐지만 타임라인 경계 시험은 이전 반환 문자열을 기대했다. 충돌 복구가 저장 완료 표시를 생성하지 않는다는 단언을 현재 상태 모양과 맞췄고 같은 CSS 모듈의 중복 가져오기를 정리했다.

변경 전 tests/p2-3b-timeline.test.ts의 19건 중 1건 실패를 재현했다. 변경 후 두 타임라인 관련 파일 25건, 전체 타입 검사, 편집기와 테스트 ESLint가 통과했다. 로컬 SQLite와 Chrome 390px로 실제 두 저장 요청의 응답 순서를 조정했다. 화면은 외부 최신 문구를 표시하고 자신의 저장 성공 비교를 숨겼으며 자신의 저장 리비전도 보존했다.

> 플래너 전달문 — 타임라인 회귀 실패 원인은 이전 상태 문자열 단언입니다. 현재 계약에 맞춰 갱신했고 25건 및 390px 실제 저장 경합을 재검증했습니다.
