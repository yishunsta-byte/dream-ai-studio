# T322-F1-R 송신자 격리 복구 독립 검수

기준 `9747734` · Master 인계 `msg_dc9958a94b16` · Codex(Tester)

**판정은 F322-1 해소, 고정 시나리오 통과.** 소유 루프백 HTTPS와 PostgreSQL 17.12에서 원본 실행기를 두 번 실행했다. 정상 종료와 감독 격리 경로는 실행마다 별도 클러스터에서 통과했다. [실행기](../../tests/reference-analysis/t322-egress-intent-revocation.pg17.mjs)

| 검증 | 독립 재현 결과 |
| --- | --- |
| 실제 송신자 종료와 감독 기록 | 두 전송 의도가 미종결인 상태로 소유 송신자 PID를 종료했다. 첫 채널은 보호 본문 0바이트, 두 번째는 이미 받은 접두부만 남았다. 두 TLS 요청이 닫힌 뒤에도 감독 기록 전에는 철회 완료와 새 세대가 보류됐다. |
| 잘못된 대상·채널 | PID 증거가 없거나 다른 PID, 다른 송신자, 이전 세대인 요청은 거절됐고 원장 스냅숏이 유지됐다. 종료한 송신자의 의도 채널을 다르게 주입하자 `23514 / T322_ISOLATION_INTENT_MISMATCH`가 반환됐다. 그 시점의 기존 허가·의도·송신자·이벤트는 모두 유지됐다. |
| 원자성과 역할 | 감독 트랜잭션 내부에서 격리 처리 후 별도 연결에서는 이전 스냅숏만 보였다. 명시 롤백 뒤에도 무변경이었다. 올바른 감독 커밋에서만 두 허가와 대응하는 의도가 함께 `isolated`가 됐고, 반복 호출에도 추가 변경이 없었다. 제어 역할의 결합 격리 호출과 감독 역할의 T319 직접 호출은 거절됐다. |
| 처리 범위와 복구 | 이전 세대의 비교용 허가·의도 및 다른 송신자의 행을 보존했다. 격리 종료가 기록된 뒤 철회가 완료됐고, 완료 재조회는 권한 리비전을 중복 증가시키지 않았다. 지난 허가는 409·0바이트였고 새 송신자는 새 허가로 정상 HTTPS 응답을 보냈다. 정상 소켓 종료 경로도 통과했다. |
| 정리 | 두 실행에서 제한 DB 연결, 소켓·요청, 소유 Node·PG 프로세스와 리스너, 임시 클러스터·TLS 파일을 정리했다. 별도 호스트 조회에서도 소유 프로세스와 임시 경로가 0개였다. 실행기 ESLint와 고정 변경의 `git diff --check`가 통과했다. |

감독 함수는 T319와 같은 게이트 잠금을 사용한다. 허가와 의도의 채널·세대·송신자·주체·제어기 번호·권한 리비전이 일치하는 경우에만 종결한다. 대상 범위의 미종결 의도가 남으면 앞선 격리 변경도 같은 트랜잭션에서 실패한다. [결합 격리 함수](../../tests/reference-analysis/t322-egress-intent-revocation.sql#L115)

감독자가 소유 자식 프로세스의 종료를 실제로 관측했다. DB 함수는 제출된 증거와 원장의 식별자를 대조한다. 최초 송신 보고 누락과 채널 불일치는 시험 주입이며 실제 네트워크 유실을 시험하지 않았다. 분산 환경의 기존 송신자 격리·프록시 큐·실제 운영 증거 수집, DB 판정과 첫 쓰기의 물리적 원자성은 후속 검증 범위다. 제품·운영·빌드·배포는 변경하지 않았다.
