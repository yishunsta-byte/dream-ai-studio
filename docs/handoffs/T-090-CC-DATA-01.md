## 2. 저장 중 편집 (T-091 9장, Master 확인 요청)

- **재현함.** 운영 빌드에서 저장 POST의 응답만 늦춰(요청은 실제로 보냄) 그 사이 타임라인 클립을 옮기고 편집 칸 문구를 고침 → 고치기 전 코드는 `router.refresh()` 뒤 편집기가 새로 붙어 그 값이 사라지는 구조였음(편집 칸·타임라인 모두 같은 위험).
- **선택한 해결: 저장 시점 이후 초안 보존**(잠금 대신). 지금 구조에 가장 작게 맞음.
  - 응답이 새 버전이면, 보낸 초안과 지금 초안이 내용이 다를 때(canonicalJson 비교) 지금 초안을 새 버전 위의 "저장하지 않은 변경"으로 다시 얹음. 고른 글자도 유지.
  - 저장 상태 글: "저장됨 · 타임라인 rN · … · 저장하는 동안 고친 내용은 아직 저장하지 않았어요." (초점은 기존대로 저장 상태 글)
  - 실패·409: 초안을 건드리지 않음(그대로 남음).
  - 바뀐 것 없음(noop): 편집기가 새로 붙지 않으므로 그대로.
  - 남긴 값은 그 저장 직후 새로 고침에만 씀(같은 프로젝트·다른 revision·30초 안). 렌더가 버려져도 다시 쓸 수 있게 읽을 때 지우지 않고 화면에 붙은 뒤 지움.
- 그래서 타임라인·편집 칸 모두 저장 중에도 조작할 수 있고 조용히 잃지 않음. TL-6의 "저장 중 잠금"은 이 보존으로 대신함(디자인과 공유).

## 5. 명세와 다르게 한 것·남은 것

- TL-6 저장 중 잠금 → **보존**으로 대신(2장). 잠금보다 사용자가 잃는 것이 없고 편집 칸까지 같은 규칙.
- 키 반복은 rAF로 모으고, 창이 느려 rAF가 늦을 때를 위해 100ms 안에 반영되게 함(확인 환경에서 rAF가 1초에 1번쯤으로 느려 발견).
- 재생 위치선은 Player `frameupdate` 값을 저장소로 받아 그림(재생 중 클립 줄 다시 그리기 없음).
- 장면 경계 글자에 바탕을 깔아 눈금 선과 겹치지 않게 한 마지막 CSS 한 줄은 빌드만 확인, 화면 캡처는 그 전 것.
- 실제 휴대폰·화면 읽기 프로그램·터치 펜은 미확인(가상 pointercancel만).
- DESIGN 4장·6.8 고침 제안(T-091 10장)은 Master 배정 대상, 손대지 않음.
