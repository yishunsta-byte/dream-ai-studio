# 음원 저장 화면 독립 검수

MASTER 배정 `msg_d0aee5089ccd`. 고정 `2ca3f6c`의 별도 Git 사본에서 실제 Next.js·Chromium·임시 PG17로 검증했다. 합성 계정이 업로드하고 첨부한 100ms WAV를 편집 음원 페이지에서 선택했다. 제작 승인과 기준 타임라인은 같은 임시 DB의 기존 시험 fixture로 준비했다.

| UI 시나리오 | 브라우저와 DB 결과 |
|---|---|
| 신규 프로젝트 | 제작 승인과 기준 타임라인 필요가 각각 표시됐고 저장 버튼은 비활성이었다. 타임라인과 저장 감사 기록 모두 0건. |
| 저장 응답 유실과 재시도 | 첫 클릭의 실제 HTTP 200 응답을 브라우저에 전달하지 않았다. 화면의 동일 요청 다시 확인 버튼을 클릭하자 키와 본문이 모두 같았고, HTTP 200의 클립·리비전 ID도 같았다. 첫 저장 이력 r3에는 3프레임 클립 1개가 있었고 그 요청 키의 DB 감사 기록도 1건이었다. |
| 구버전 충돌 이후 재조회 | 같은 프로젝트에서 별도 요청을 먼저 저장하자 화면이 보낸 구버전 요청은 HTTP 409를 반환했다. 새 기준을 읽은 뒤 저장 버튼이 다시 활성화됐고 실제 다음 클릭은 새 키·새 기준으로 HTTP 200에 성공했다. |
| 최종 건수 | 기준 이력 2건·저장 감사 0건에서 이력 5건·감사 3건으로 증가했다. 성공한 논리 저장은 첫 UI 저장, 별도 요청, 재조회 뒤 UI 저장의 세 건이다. |

최초 실행은 브라우저 검수 스크립트의 대기 함수 인자 오류로 중단됐다. 검수 사본의 스크립트를 수정한 재실행은 종료 코드 0이었다. 브라우저 검수 공간을 닫고 PostgreSQL 리스너와 임시 클러스터 정리를 확인했다. 이 기록의 결과는 로컬 환경과 합성 자료에 해당한다. [기존 UI 검증 함수](../../tests/postgres/private-timeline-audio-screen.mjs) · [기존 HTTP 시험 환경](../../tests/postgres/t371-project-create-http.mjs)
