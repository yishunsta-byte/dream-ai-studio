# 검수 화면에서 현재 MP4 확인

검수 화면에 서버에서 읽은 타임라인 번호를 표시한다. 출력 목록에서 같은 프로젝트의 내용 리비전과 타임라인 ID가 일치하고, 취소되지 않은 성공 결과의 파일 크기가 기록과 일치할 때 해당 카드로 이동한다. 결과가 없으면 영상 만들기 영역을 연결한다. 현재 장면과 저장 타임라인이 어긋난 경우에는 기존 재저장 안내를 사용한다.

로컬 SQLite 샘플에서 편집 완료 후 Chrome 390px와 1280px로 검수 화면을 열었다. r39 링크가 실제 r39 결과 카드의 ID로 이동했고 카드에 현재 저장본 r39가 표시됐다. 이어 자막을 고쳐 r40으로 저장하고 출력 전에 검수에 들어갔다. 이전 r39 MP4가 남아 있어도 현재 영상 링크가 사라지고 결과 없음 안내와 영상 만들기 링크가 표시됐다. 링크를 눌러 실제 만들기 영역 도착을 확인했다.

관련 테스트 38건, 변경 파일 ESLint 및 해당 파일과 의존성 타입 검사 통과. 공유 작업 트리의 전체 타입 검사에서는 진행 중인 별도 brief 라우트의 local_project_brief 타입 오류가 관찰됐다.

## Tester 키보드 독립 검수

고정 커밋 `3360330`의 로컬 Next.js와 합성 프로젝트의 SQLite·MP4 사본을 사용했다. 사본에서 r39와 r40의 현재 타임라인·내용 리비전을 각각 구성했고 r39 MP4의 파일 크기를 DB 기록과 대조했다. Chromium 390px와 1280px에서 Tab으로 검수 링크에 이동한 뒤 Enter를 눌렀다.

| 검수 시점 | 390px와 1280px 결과 |
|---|---|
| 타임라인 r39 · 내용 r43 | ‘이 버전 MP4 확인’의 주소와 화면에 보이는 카드 ID가 일치했다. 카드에는 ‘현재 저장본 · 타임라인 r39’가 표시됐다. 다음 Tab은 같은 카드의 ‘소리 확인 세부 정보’로 이동했다. |
| 타임라인 r40 · 내용 r44 | r39는 ‘보관본’으로 남았고 현재 MP4 링크가 없었다. ‘영상 만들기로 이동’은 `#render-make`와 ‘새 영상 만들기’ 제목에 도착했다. 시험 상태에서 만들기 버튼은 비활성이었고 다음 Tab은 보관 r39 카드의 ‘소리 확인 세부 정보’로 이동했다. |

두 분기 모두 목적지가 화면에 보였고 Enter 직후 `document.activeElement`는 `BODY`였다. 목적지 선택은 4/4 통과했으며 도착 제목에 초점이 직접 잡히지는 않았다. 이번 검수는 검수 화면에서 출력 카드나 만들기 영역으로 이동하는 동작을 확인했다.
