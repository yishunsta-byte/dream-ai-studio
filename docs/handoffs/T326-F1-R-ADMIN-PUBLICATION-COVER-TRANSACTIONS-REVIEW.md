# T326-F1-R 합성 표지 준비 트랜잭션 독립 검수

**판정은 F326-1 해소.** 임시 고정 사본에서 제공된 `--cover-check`와 기존 `--scenarios`를 소유 루프백 PostgreSQL 17.12의 합성 자료로 실행했다. [실행기 및 표지 준비](../../tests/admin/t306-publication-e2e-native.ts)

`/cover`와 `--cover-check`는 동일한 `prepareCover`를 사용한다. 코드에서 요청마다 전용 DB 연결을 열고, 작품 행 잠금·충돌 시 기존 바이트 확인·증빙 업데이트를 한 트랜잭션에서 처리하며 마지막에 연결을 닫는 것을 확인했다. 공유 관리자 연결을 사용하는 나머지 제어 경로는 별도로 직렬화한다.

Main PC 인계는 격리 production HTTP의 12건 병렬 요청에서도 생성 1건·재사용 11건이며, 실패 3모드와 게시·철회·재게시·만료를 통과했다고 보고했다. Tester는 수정본의 PostgreSQL 함수 검증과 기존 시나리오를 직접 실행했다. production HTTP를 다시 실행하거나 빌드하지 않았다. 이전 구현 재현이나 별도 시험 도구 작성도 수행하지 않았다. [Main PC 인계](T326-ADMIN-PUBLICATION-ASSEMBLED-ROUTES-E2E.md)

관련 Vitest 19개 파일 541/541, 고정 소스 TypeScript, 변경 파일 ESLint와 `git diff --check`가 통과했다. 두 모드의 소유 리스너·클러스터 및 고정 사본을 정리했고, 별도 호스트 조회에서도 소유 PostgreSQL 프로세스와 T306 임시 클러스터가 0개였다. 제품 진입점, 운영 DB·Storage·배포를 변경하지 않았다.
