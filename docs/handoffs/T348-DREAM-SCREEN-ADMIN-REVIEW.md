# T348 Dream Screen 관리자 변경 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `865d2691031377094f2a6d26a6c839404982c713` · Master 배정 `msg_c96b0c5a2def`

**관리자 접근·탐색·미연결 안내·모바일·키보드 회귀 통과.** 화면의 새 선택 강조에 접근성 상태 전달 누락 한 건을 기록한다. 통합 판정은 Master가 맡는다.

- 변경은 `app/admin/page.tsx`, `components/admin/admin-hub.tsx`, `components/admin/admin.module.css` 세 경로다. 고정본의 관리자·인증·세션 보호·비밀번호 재설정·프로젝트·게시 집중 시험 13파일 352건, 변경 TSX ESLint 및 diff 공백 검사가 통과했다.
- 기존 T329 개발 검증기와 합성 인증·목록 fixture를 가리키도록 경로를 조정해 격리 사본에서 실행했다. 미인증 `/admin`은 307로 `/admin/login?next=%2Fadmin`에 이동했다. 확인 계정의 기본 화면에서 프로젝트 읽기 미연결과 게시 서버 미연결, 실행 버튼 없는 운영 연결 범위를 확인했다. 합성 연결·빈 목록·조회 실패 상태도 각각 구분됐다. 기존 클라우드 관리·프로젝트 및 비밀번호 변경 링크를 확인했다.
- 창이 표시되지 않는 Chromium에서 1280px 왼쪽 탐색과 390·320px 본문 위 2열 탐색을 확인했다. 세 폭의 문서 가로 넘침은 0이었다. 메뉴 터치 영역은 1280·390px에서 모두 48px, 320px에서는 48~60.8px였다. 기존 검증기의 Tab·Enter 시험에서 메뉴 네 개가 각각 해당 영역으로 초점을 보냈고, 계정 설정 다음 Tab은 비밀번호 변경 링크였다. 데스크톱 미연결과 390px 빈 목록 전체 캡처를 직접 대조했다.

## 재현 가능한 접근성 관찰

**새 메뉴 강조의 현재 위치 상태가 시각에만 전달된다.** 확인된 개발 세션에서 `내 프로젝트` 또는 `계정 설정` 메뉴를 활성화하면 주소의 프래그먼트와 본문 초점이 이동한다. 해당 링크는 CSS `:target`에서 색·배경을 바꾸지만 링크 마크업에는 `aria-current` 상태가 없다. 키보드 이동 자체는 통과했다. 새 강조를 스크린 리더에서도 현재 위치로 전달하려면 프래그먼트에 대응하는 현재 링크 상태를 추가해 확인할 수 있다. [메뉴 마크업](../../components/admin/admin-hub.tsx) · [메뉴 강조 CSS](../../components/admin/admin.module.css)

기존 검증기의 Next 개발 서버와 합성 인증만 사용했다. 실제 운영 계정·공급자, 물리 모바일 기기와 스크린 리더 음성은 검증 범위 밖이다. 작성자 파일·운영 환경·프로덕션 빌드·배포의 변경은 없었다. 새 창이나 worktree 없이 검수 사본과 실행 자원을 정리했다.
