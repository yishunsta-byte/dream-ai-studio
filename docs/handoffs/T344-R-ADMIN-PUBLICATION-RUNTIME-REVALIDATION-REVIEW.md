# T344-R 게시 가동 중 읽기 검증 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `59778be` · Master 배정 `msg_4ac62196f4fd`

**격리 검수 통과.** 소유 PG17/TLS와 루프백 SDK에서 설치 잠금 해제 후 작업 재검증, 요청 취소 분리, 승인 상태 변경 시 일괄 비활성과 표지 보호를 확인했다.

- 위임 설치·관리·초기 검증은 기존 승인 잠금을 요구한다. 무인자 기본 PG 모드와 T341 별도 설치 모드가 통과했고, 최초 조립 뒤에는 잠금 없이 승인된 검증 로그인으로 독립 읽기 전용 세션을 열었다. 실제 DB·검증 계정 OID, 설치 시각·해시·카탈로그, 권한과 설치 세션 종료 상태를 재확인했다. T343의 개별 런타임 연결 OID 대조도 통과했다.
- 관리자 트랜잭션, 목록 조회, 표지 권한 조회·다운로드·최종 권한 확인에서 검증을 적용한다. 동시 목록 요청 두 개가 하나의 읽기 세션을 공유했다. 한 요청은 `AbortError`로 끝났고 공용 검증과 다른 요청은 완료됐다. 검증 쿼리가 잠금에서 대기 중일 때 런타임을 닫는 시험에서 해당 요청과 검증 세션이 정리됐다.
- 설치 시각 변경, 설치 계정에 DB `CREATE` 재부여, 검증 로그인 차단은 일괄 비활성을 유발했다. 기존에 받은 공급원 참조도 이후 관리자·목록 작업과 Storage 다운로드에 진입할 수 없었다. 이력 변경을 뒤늦게 발견한 시험의 관리자 트랜잭션은 이미 콜백에 들어가 있었지만, 정리 시작 뒤 그 트랜잭션의 후속 SQL은 진행되지 않았다.
- 정상 게시와 WebP 전달, 철회 후 목록 제거와 404를 확인했다. 표지 다운로드 중 설치 시각을 바꾸자 최종 확인에서 503이 반환됐고 이미지 바이트가 전송되지 않았다. 새 `get()`은 공급원 참조를 돌려주며, 가동 중 판정은 각 작업에 진입하기 전 검증 스냅숏을 기준으로 한다. 이미 성공한 커밋이나 응답 전송을 소급해서 되돌리는 보장은 없다.
- T344·T342·T341와 무인자 T328 TLS 22건, T330·T332·T336·T343 회귀가 통과했다. 관련 Vitest 26파일 642건과 PG 종료 후 단일 워커 비공개 자산 1파일 54건이 통과했다. 소스 타입 검사, 변경 TypeScript 3개 ESLint와 커밋 diff 공백 검사도 통과했다. 검증·런타임 세션, 루프백 Storage 서버와 세 PG 실행의 리스너·임시 클러스터를 정리했다. 소유 PG 프로세스는 0건이었고 검수 사본도 제거했다.

기본 제품 설정은 비활성이다. 이번 판정은 소유 루프백의 명시 구성에 한정하며 관리형 DB와 실제 운영 활성화는 범위 밖이다. 운영·빌드·배포 변경은 없었다.
