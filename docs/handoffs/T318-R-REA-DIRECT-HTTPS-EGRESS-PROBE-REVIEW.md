# T318-R 직접 HTTPS 송신 경계 독립 재현

기준 `6ed3a46` · Master 인계 `msg_89fd91088fba` · Codex(Tester)

**판정은 소유 루프백 HTTPS 시험 계약 통과.** 고정 실행기를 임시 사본에 추출해 10회 실행했다. 두 Node 자식 프로세스는 서로 다른 PID·루프백 포트에서 실제 TLS 연결을 처리했다. 독립 클라이언트는 임시 인증서를 신뢰 루트로 사용해 루프백 IP와 피어 지문을 확인했다. 두 프로세스는 시험 인증서를 공유하며, 송신 소유권은 부모 제어기가 판정했다. [고정 실행기](../../tests/reference-analysis/t318-direct-https-egress.loopback.mjs)

| 검증 | 독립 재현 결과 |
| --- | --- |
| 소유자와 단일 허가 | 합성 세션 불일치는 403, 비소유 프로세스와 같은 허가 반복은 409였다. 보호 본문은 모두 0바이트였다. 유효한 송신자만 정상 JSON 전부를 보냈고 해석과 별개로 수신 바이트 자체가 일치했다. 첫 바이트 허가 소비는 한 번이었다. |
| 첫 바이트 전 철회·만료 | 송신자가 허가를 받은 상태에서 실제 쓰기를 보류했다. 부모가 철회하거나 시험 시계를 만료까지 진행한 뒤 재개를 거절했다. 클라이언트는 403/410과 보호 본문 0바이트를 받았고 소비는 0이었다. |
| 전송 중 전환 | 첫 보호 접두부를 보낸 A 채널과 별도로 보류한 A 채널을 동시에 사용했다. 보류 채널은 409·0바이트로 끝났고, 앞선 전송의 실제 소켓 종료를 관측하기 전까지 세대와 신규 허가 차단이 유지됐다. A의 송신 권한 중지와 종료를 확인하고 B의 소유권 응답을 받은 뒤 전환을 마쳤다. |
| 종료 보고 유실·복구 | B 전송을 취소하자 클라이언트에는 접두부만 남았다. 부모가 종료 사건을 의도적으로 종결 판정에서 제외하자 클라이언트 요청 종료와 B의 차단 응답이 있어도 전환은 계속 보류됐다. 양쪽 기존 허가 재사용은 409·0바이트였다. B의 실제 프로세스 종료까지 확인한 뒤 A가 새 세대의 정상 응답을 보냈다. |
| 종료 정리 | 두 자식 프로세스 종료, 두 포트 재접속 `ECONNREFUSED`, 클라이언트 요청 0, 마지막 소유자의 소켓·작업 0, 임시 TLS 파일과 디렉터리 제거를 10회 확인했다. 별도 호스트 조회에서도 실행기의 소유 송신 프로세스와 임시 TLS 디렉터리가 각각 0이었다. |

제어기 메모리와 로컬 IPC를 한 부모가 소유한다. 철회·만료는 허가 후 첫 쓰기를 보류하고 별도 재개 확인을 거친 사례다. 보류하지 않은 IPC 허가와 수신 프로세스의 최초 큐 삽입을 분산 환경에서 원자화하는 검증은 후속 범위다. 종료 보고 유실은 시험 제어기에서 모사했다. 지속 원장, 제어기 장애·재시작, 다중 호스트 네트워크 분할, 운영 인증·TLS 종료·프록시/하위 큐의 종료와 우회 차단은 실제 호스팅에서 별도 입증이 필요하다.

실행기 ESLint와 고정 변경의 `git diff --check`가 통과했다. 제품 빌드·운영·배포를 수행하지 않았다.
