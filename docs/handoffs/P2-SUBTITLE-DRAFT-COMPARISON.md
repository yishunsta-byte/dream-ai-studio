# 저장 전 자막 문구 비교

선택한 자막의 문구 입력란 아래에서 마지막 저장 리비전과 현재 입력값을 대조한다. 저장 리비전은 타임라인 번호를 사용한다. 기존 저장본의 동일 레이어 ID에서 이전 값을 읽고 현재 값은 초안에서 읽는다. 첫 저장 전과 기존 리비전에 새로 추가한 자막을 구분해 표시한다.

격리된 Chrome과 SQLite에서 같은 문구를 인접한 두 장면에 배치했다. 390px 세로 비교와 1280px 가로 비교의 실제 좌표, 가로 넘침 0px, 화면의 리비전 번호와 저장소 번호 일치를 확인했다. 양쪽 너비에서 두 번째 자막 문구 수정 → 첫 번째로 이동 → 두 번째로 복귀 → 변경 취소 순으로 이전값·현재값을 매번 확인했고 리비전은 생성되지 않았다. 390px에서 다시 수정해 실제 저장한 후 다른 자막과 영상 배열, 이전 리비전 JSON 보존을 확인했다. 타입 검사와 변경 TSX의 ESLint 통과.

## 저장 전 독립 검수

Tester가 고정 커밋 `1f2ef74`와 합성 프로젝트 SQLite 백업을 사용했다. Chromium 390px·1280px에서 첫 장면과 둘째 장면에 서로 다른 임시 문구를 입력했다. 두 장면을 다시 선택할 때마다 ‘이전 저장본 · r37’에는 해당 장면의 원문, 수정본에는 해당 장면의 임시 문구가 표시됐다. ‘변경 취소’를 한 번 실행한 뒤 두 장면 모두 원문으로 복귀했다. 390px에서는 두 값이 위아래, 1280px에서는 좌우에 표시됐고 가로 넘침은 모두 0이었다.

브라우저 시험 전후 SQLite에서 현재 타임라인 ID, 프로젝트 내용 리비전 41, 타임라인 이력 37건, 전체 이력의 ID·번호·JSON에 대한 SHA-256이 모두 일치했다. 이 검수는 저장 전 흐름을 대상으로 했다.
