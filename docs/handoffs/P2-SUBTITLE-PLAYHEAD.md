# 자막 목록에서 현재 재생 위치 확인

자막이 있는 글자 목록 위에 미리보기의 프레임 시간과 해당 장면을 표시한다. 기존 미리보기의 프레임 상태를 표시 문단만 구독한다. 장면 경계가 지나도 행 선택과 키보드 초점은 사용자 조작을 따른다.

로컬 SQLite 프로젝트와 Chrome 390px·1280px에서 재생 위치 00:00.00 장면 1, 두 번째 자막 처음으로 이동 후 00:02.00 장면 2, Enter로 한 프레임 되돌린 뒤 00:01.29 장면 1을 각각 확인했다. 한 프레임 전에서 재생해 장면 2 표시로 갱신됐고 두 번째 자막의 선택은 유지됐다. 두 폭 모두 가로 넘침 0px, 리비전 ID 변화 없음. 타임라인·프리뷰·자막 장면 테스트 38건, 전체 타입 검사, ESLint 통과.

> 플래너 전달문 — 자막 목록에 현재 재생 위치와 장면이 표시됩니다. 두 화면 폭에서 실제 이동·한 프레임 되돌리기·재생 경계 및 선택 보존을 확인했습니다.

## Tester 독립 검수

고정 커밋 `7cf0254`의 로컬 Next.js와 SQLite 사본에서 길이 60프레임인 장면 두 개를 확인했다. Chromium 390px·1280px에서 키보드로 두 번째 자막을 선택하고 ‘이 글자 처음으로’를 실행했다. 다음으로 한 프레임 뒤로, 앞으로, 다시 뒤로 이동한 뒤 재생했다.

| 위치 | 두 화면 폭의 표시 |
|---|---|
| 시작, 프레임 0 | `00:00.00 · 장면 1` |
| 경계 직전, 프레임 59 | `00:01.29 · 장면 1` |
| 경계, 프레임 60 | `00:02.00 · 장면 2` |

두 폭에서 한 프레임 이동 뒤 초점이 해당 버튼에 남았다. 59프레임에서 Enter로 재생하자 ‘멈춤’ 버튼에 초점이 유지됐고 60프레임에서 장면 2가 표시됐다. 두 번째 자막 선택이 유지됐고 가로 넘침은 0px였다.

현재 타임라인 ID, 내용 리비전 49, 타임라인 이력 45건과 전체 ID·리비전·JSON 해시가 시험 전후 일치했다. 관련 자동 테스트 38건도 통과했다. 첫 자동 실행에서 제품의 ‘멈춤’을 ‘일시정지’로 잘못 단언해 시험을 수정했다.

> Master 전달문 — 7cf0254 독립 검수에서 390px·1280px 모두 59프레임에 장면 1, 60프레임에 장면 2가 표시됐습니다. 키보드 이동과 재생 중 조작 초점·자막 선택이 유지됐고 기존 타임라인 이력은 변경되지 않았습니다. 관련 테스트는 38/38입니다.
