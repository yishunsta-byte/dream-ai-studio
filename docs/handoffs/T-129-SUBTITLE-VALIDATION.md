## 2. 측정 도구 보완 (`scripts/remotion/measure-subtitle.ts`)
| T-128 지적 | 보완 |
|---|---|
| ROI 행 넘김 (x840 w200이 640 폭에서 다음 줄로 넘어가 그럴듯한 경계를 냄) | `assertRect`: 정수·비어 있지 않음·프레임 밖으로 나가지 않음(x+w≤폭, y+h≤높이). `band()`와 `bandCounts()`가 모든 ROI·기준 띠를 먼저 확인해요. |
| 치수 | `assertFrameSize`: 유한한 양의 정수, 지나치게 큰 프레임 거부. 띠 중심 y는 (0,1) 안이어야 해요. |
| 임계값 −1/NaN/256 | `assertThreshold`: 정수 0~254(255는 넘을 수 없어 무의미). |
| 최소 화소 0 | `assertMinPixels`: 양의 정수. 개수 배열은 음이 아닌 정수만. |
| 프레임 바이트·개수 | 디코드가 끝났을 때 남는 바이트가 있으면 거부해요(치수가 틀림). 0프레임이면 거부, 기대 프레임 수(본 측정은 120)와 다르면 거부해요. |
| 점수 입력 | 자막 시각은 유한·0 이상·끝>시작이어야 해요. 검출값은 둘 다 null이거나 0≤first≤last 정수여야 해요. |
| 오차 정밀도 | 영상 오차를 정수 프레임으로 기록(`maxErrorFrames`)하고, 판정도 프레임으로 해요(0.2초 = 6프레임). 초는 1밀리초 반올림 표시값이에요. SRT는 정확값(`maxErrorSec`)과 표시값(`maxErrorSecDisplay`)을 따로 기록해요. |
| CLI 모르는 옵션 / `--out` 값 없음 / `--out --keep` | `parseArgs`: `--out <파일>`·`--keep`만 한 번씩 받아요. 그 밖은 아무것도 만들기 전에 거부해요. |
| 실패해도 종료 0 | 종료 코드 **0 = 모두 통과**, **1 = 측정이 돌았지만 실패(report.pass false)이거나 실행 오류**, **2 = 잘못된 명령줄·입력(판정 안 함)**. 작업 폴더는 성공·실패·오류 모두에서 지워요(`--keep` 제외). |

- 잘못된 입력은 모두 `MeasureInputError`로 거부해요. "아무것도 안 보임"으로 처리하지 않아요.

## 4. 확인 못 한 것 · 그대로인 것
- 실제 렌더가 실패하는 경우의 종료 1은 일부러 만들지 않았어요. 실행 오류 경로(ffmpeg 없음)로만 확인했어요. 판정 실패(report.pass false) → 종료 1은 코드 경로로 같아요.
