# T332 검증된 PostgreSQL 세션에 게시 어댑터 연결

2026-11-19 KST · Codes(Backend) · 기준 `9693f24` · Master 배정 `msg_b2cd9cf24159` · 실행기 재사용 승인 `msg_4b3b67c3760e`

`createVerifiedPublicationRuntimeOptions()`는 승인 DB 설정, 관리자 로그인에 매핑할 운영자 UUID, 권리 조회 함수, 관리자·공개 표지 읽기 함수를 받아 T327 공용 런타임에 전달할 설정을 만든다. 관리자·목록·표지는 같은 T330 연결 그룹을 공유하며 SQL을 실행할 때 해당 역할의 실제 세션 검증을 거친다. 초기화에서 계정 매핑, 제한된 권리 조회 함수, 목록 및 표지 조회 중 하나라도 실패하면 그룹을 닫고 조립은 비활성 결과를 반환한다. 운영자 UUID는 서버 설정에서 지정하고, 요청의 검증된 운영자와 PostgreSQL의 `t293.actor()` 바인딩을 모두 대조한다. 현재 설정 하나는 관리자 DB 로그인과 운영자 한 명에 대응한다. [서버 어댑터](../../lib/public-showcase/publication-verified-adapters.ts)

- **관리자 게시.** T293의 소유 작품 잠금과 요청 UUID 원장을 같은 트랜잭션에서 검사한다. 요청 잠금 뒤 게시자 권한을 다시 확인하고, T295 상태 전환 결과와 서비스의 판정을 대조한다. 준비·완료 단계에는 고정 manifest, 권리 참조와 정확한 만료 시각을 비교한다. 완료 시 DB 승인 시각을 저장하고, 한 단계라도 어긋나면 작품 상태·manifest·요청 원장·감사 기록을 함께 롤백한다.
- **공개 목록·표지.** 목록과 표지는 각각 T295의 현재 승인 목록과 정확한 세대 조회를 사용한다. 표지 바이트를 읽기 전에 키·세대·길이를 권한 행과 대조하고, 기존 표지 응답 코드에서 바이트와 SHA-256을 검사한 뒤 응답 직전에 현재 권한을 다시 확인한다. 사용 중 한 역할의 연결 검증이 실패하면 공유 그룹이 닫혀 관리자 요청과 공개 읽기가 모두 실패 상태로 전환된다.

## 자체 검증

`node --conditions=react-server --import tsx tests/public-showcase/t328-publication-db-preflight.pg17.ts`는 소유 PG17·TLS 클러스터에서 아래 사례를 실행한다. 기존 T328/T330 검증과 정리는 동일한 실행기로 수행한다. [T332 전용 시나리오](../../tests/public-showcase/t332-publication-verified-adapters.pg17.ts)

- 본인 작품만 관리자 큐로 조회하며 다른 운영자와 다른 소유자의 명령을 거절했다. 공개 전 표지는 404였다. 같은 게시 UUID를 동시에 두 번 보내도 양쪽 응답이 일치하고 원장·감사·게시 요청은 각각 한 건이었다.
- 게시 후 홈 공급원에 작품과 활성 세대 표지가 나타났다. 표지 바이트 읽는 동안 철회하면 응답 직전 검사에서 404가 반환됐다. 철회 뒤 게시 결과를 재조회해도 공개 상태가 되살아나지 않았고, 새 세대 게시 뒤에도 과거 표지는 404였다. 권리 만료 시 목록과 표지가 함께 내려갔다.
- 서비스 증빙과 DB 권리 만료의 1ms 차이를 발견한 트랜잭션에서 작품 리비전, 고정 manifest, 두 원장 및 감사가 모두 보존됐다. 구성 운영자 불일치, 권리 조회 함수 누락과 공개 역할에 잘못 부여된 함수 실행 권한은 시작 시 비활성으로 처리했다. 실행 중 표지 역할을 철회하자 이미 조립된 세 공급원이 요청을 거절했다. 검사 세션 및 임시 클러스터를 정리했다.
- 지정 관리자·공개·홈 회귀 231건과 변경 TypeScript ESLint 통과. 생성 `.next` 검증 파일을 제외한 소스 523개 진입 파일 타입 검사에서 오류 0건.

## 운영 연결에 남은 범위
