## 0. 요약

- 방향은 기준과 맞다: 정적 편집기 유지, 열기만으로 버전 안 만듦, 명시 저장·같은 내용 생략, 저장 뒤 다시 검수 안내, 빈 자리·바뀐 선택·영상보다 긴 글자 경고, 예전 저장 410, 이관 오류 쉬운 문구.
- **실제 코드 결함 3건(작음, 화면 문구·표시):** B1 소수점 긴 초 표시, B2 잠긴 필수 표기에 "끝 시간을 직접 줄여 주세요"(고칠 수 없는 칸), B3 저장 시각 시간대 미지정.
- **구현 완료 전 필수 확인 1건 + 브라우저 수용 목록:** A1 끝(초) 칸의 브라우저 최대값이 서버의 "옮긴 글자는 자르지 않음"과 충돌할 수 있음.

## 3. 구현 완료 전 필수 확인

| # | 내용 | 근거 | 추천 | 수용 조건 |
|---|---|---|---|---|
| A1 | 끝(초) 칸의 `max={data.maxEndSec}`(= 상한) 때문에, 옮긴 일반 글자가 상한보다 길면 **브라우저가 폼 제출 자체를 막아** 다른 고침도 저장하지 못할 수 있다. 서버는 이런 글자를 그대로 통과시키므로 두 규칙이 어긋난다. 발생 조건: 기획 장면 합 > 프로젝트 길이이고 영상 길이가 줄어든 경우(s4 프로젝트 1은 상한 30초 = 표기 끝 30초라 해당 없음, 잠긴 칸은 비활성이라 검사 제외) | `editing-panel.tsx:30` `max`, `lib/services/timeline.ts:50-53` carried | 칸 `max`를 `max(상한, 그 글자의 지금 끝)`으로 하거나 `max` 없이 서버 문구로 안내 | 고정 시험: 상한을 넘는 옮긴 자막 1개 + 다른 글자 문구 수정 → 저장 성공, 그 자막 그대로·경고 표시 |

**브라우저 수용(구현 완료 뒤, 1280·390, 127.0.0.1, production 빌드):**
1. s4 사본 0005 뒤 편집 화면: 옮긴 글자 위치·크기·색이 P1 미리보기 캡처와 같음, 머리 "저장됨 · 타임라인 r1 · … · P1 글자 설정에서 옮김".
2. 화면을 열고 닫기만 → 내용 버전·검수 상태 그대로.
3. 저장 → r2, 성공 문구, 검수 다시 필요. 안 바꾸고 저장 → "바뀐 내용이 없어…".
4. 두 창 저장 → 늦은 창에 충돌 문구. 옛 창의 예전 저장 → 410 문구가 오류 칸에.
5. 만들기 단계에서 선택 바꾼 뒤 편집 화면 → 바뀐 선택 경고, 완료 버튼 이유, 저장 뒤 해제.
6. 결과 없는 장면 → 빈 자리 경고·배지, 내보내기 막힘 이유.
7. 시작 점검 화면에서 MIGRATION_SOURCE 문구(원문 하나 빠진 사본 앱 폴더).
8. 가로 넘침 0, Tab 순서·초점 링 전부, 새 경고들이 390에서 줄바꿈으로 읽힘.
