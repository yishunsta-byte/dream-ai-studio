# T267 REA 3 로컬 영상 컷 후보·대표 프레임

기준 `c6bf125aee5c680de69e409578d8264ae893413b`, 배정 `msg_ef9c51f59e75`, 수락 `msg_ba9ec8da8ca8`. [REA 3 개발표](../MASTER_DEVELOPMENT_PLAN.md#rea-구현-배정과-검수-기준) 및 [T263-F3-R](T263-F3-R-REA-ATTACHED-PICTURE-REVIEW.md)의 로컬 영상 경계를 따른다.

## 분석 방법과 결과

1. [관리 파일 검사](../../lib/reference-analysis/local-file.ts)의 64 MiB 상한, 신뢰된 관리 루트, 실경로와 한 개의 관리 사본을 재사용한다. ffprobe가 확인한 첨부 표지 제외 단일 재생 영상의 스트림 번호, 시간축 및 치수로만 디코딩한다. 복수 영상, 미확인 스트림 또는 정렬이 불분명한 경우 컷 시간축을 만들지 않는다.
2. [영상 분석](../../lib/reference-analysis/video-features.ts)의 `analyzeLocalReferenceVideo`는 같은 관리 사본에서 FFmpeg로 지정 스트림만 디코딩한다. 원래 재생 시각을 기준으로 하고 프레임을 비율 유지·검정 여백의 64×36 RGB24로 작게 만든다. FFmpeg의 실제 `showinfo` PTS를 프레임 번호·개수·선택 트랙 범위와 대조한다. 기록이 빠졌거나 순서가 잘못되면 `frame_timing_unverified`다. 분석 범위에는 검증된 트랙 경계와 실제 첫·마지막 디코딩 시각 및 프레임 수가 각각 있다.
3. 인접 프레임의 RGB 채널별 절대 차이 평균을 0–1로 정규화한다. 고정 임곗값 **0.22** 이상인 경우 두 관측 프레임 사이를 컷 **후보**로 분류한다. 대표 프레임은 첫 디코딩 프레임과 각 후보 직후의 픽셀이다. REA 관찰에는 실제 프레임 위치·차이를, 추정에는 근거 ID가 붙은 컷 후보를 기록한다. 색 차이가 큰 플래시·움직임을 컷으로 추정하거나 비슷한 색의 컷을 놓칠 수 있다. 페이드·카메라 움직임·제작 기법을 확정하는 방법은 아니다.
4. `{ inspection, video }`에서 `inspection`은 기존 private REA 계약이다. `video`의 성공 결과에는 설정·분석 범위·후보·대표 프레임이 있다. 프레임 픽셀은 각 최대 6,912 byte RGB24의 서버 전용 메모리 파생물이다. 파일 경로나 원본 bytes를 반환하지 않고 REA JSON·화면/공유 DTO에 파생 픽셀도 넣지 않는다. 소비자가 임의로 `video` 객체를 공유 경계로 보내면 안 된다.

원본 프로브 치수 2,073,600화소, 트랙 20초, 최대 디코딩 240프레임, 최대 후보 24건, subprocess stdout/stderr 각각 2 MiB를 적용한다. 프레임 상한 감지를 위해 최대 241개까지 요청하며 상한을 넘기면 부분 결과를 버린다. probe와 decode는 기존 호출 전체 기한을 공유한다. 파일/pipe 프로토콜만 허용하며 프레임은 파이프로 받아 별도 프레임 파일을 생성하지 않는다. 취소·타임아웃에는 자식의 close와 사본 정리를 기다리고 이전 관찰을 반환하지 않는다.
