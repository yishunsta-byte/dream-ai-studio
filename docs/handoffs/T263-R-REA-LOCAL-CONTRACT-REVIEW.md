**REA 2는 합성 표본을 쓰는 결과 UX 작업부터 착수 가능하다.** 실제 자료 연결 전에는 시간 근거를 관측된 길이로 검증하고, 사용자별 비공개 결과와 화면·공유용 출력을 구분하며, 업로드 크기와 작업 종료 상태의 책임을 정해야 한다. URL 대체 안내는 현재 계약으로 구현할 수 있다. 공급자 자동 조회를 연결하기 전에는 지원 URL의 정규화와 검증을 보완해야 한다. [원 설계](T263-REA-LOCAL-CONTRACT.md) · [REA 개발 계획](../MASTER_DEVELOPMENT_PLAN.md#rea-구현-배정과-검수-기준)

| P1 · 근거 시간 검증 | 메타데이터에 `durationMs: 500`이 있고도 같은 파일의 `490–1000ms` 관찰이 결과 검증을 통과했다. 스키마는 정수·순서·매체 종류를 검사하며 실제 길이와 대조하지 않는다. 영상이나 음원의 근거 버튼이 재생 불가능한 지점을 가리킬 수 있다. | 실제 파일 탐색을 연결하기 전에 검사기가 관측한 길이와 시간 근거를 대조한다. 초과 근거는 거절하고 길이 미확인 상태에서는 탐색 버튼을 비활성화한다. 종료점과 같은 점, 초과 구간, 길이 미확인을 따로 검증한다. REA 전체 작업 기한이나 취소 인자는 없다. `ENOENT`는 도구 부재로 나오지만, 실물 실행 파일의 비정상 종료는 `invalid_file`로 표시됐다. 타임아웃도 공용 검사기에서 같은 오류로 매핑된다. | 실제 작업을 연결하기 전에 서버에서 업로드 또는 임시 파일의 실제 byte 상한을 집행하고, 소유권이 확인된 서버 관리 경로만 검사기로 넘긴다. 실행 계층은 전체 기한, 취소와 자원 정리, 뒤늦은 결과의 무효화를 맡는다. UX는 취소·타임아웃·도구 부재·손상된 입력을 구분하고 서버가 종료를 확인한 뒤 취소 완료를 표시한다. [로컬 검사](../../lib/reference-analysis/local-file.ts#L12) · [공용 검사기](../../lib/media/inspect.ts#L27) |

## 통과한 범위와 확인 방법

- URL·파일·본문 분류와 대체 상태를 확인했다. 제공된 접근 제한, 권한 미확인, 미열람 URL과 대표 프로필 주소는 본문·캡처·파일을 안내한다. 자격이 포함된 주소, 허용 외 스킴과 파일명 경로는 거절된다. 파일의 MIME 힌트와 지원 확장자 충돌도 걸러진다. 이 검수에서 URL 요청은 발생하지 않았다.
- 계약 시험에서 관찰·제작자 공개 문구·파일 메타데이터·추정·확인 불가의 별도 분류와 JSON 왕복을 확인했다. 정확한 인용과 원본 UTF-16 범위, 다른 매체의 위치와 이미지 경계 초과, 중복 ID와 직접 근거가 없는 추정의 거절을 확인했다. 포맷·치수·길이는 아래 실제 도구 관측이다. 컷·BPM·구도·제작 방식은 합성 결과 표본 범위다.
- 고정 커밋과 관련 소스·테스트·도구 코드 차이가 없음을 확인하고 `DREAM_REA_NATIVE_TEST=1`로 Vitest **26/26 통과**를 재현했다. 기존 범위 TypeScript 검사와 ESLint 경고 0도 통과했다. 로컬 ffprobe 9.0.2와 sharp 0.35.5에서 MP4 32×24·500ms, WAV 500ms, PNG 12×8을 확인했다. 추가 AAC/M4A도 `audio/x-m4a`·500ms로 확인했다.
- 별도의 합성 임시 파일로 손상 PNG, PNG의 MP4 위장, 신고 크기 불일치와 상대 경로를 거절하는지 확인했다. 실물 자식 프로세스에서 실행 파일 부재와 비정상 종료를 각각 확인하고, 기존 `runMedia`에 짧은 타임아웃을 주어 합성 Node 프로세스의 종료를 확인했다. REA의 실제 30초 시간 초과는 코드에서 매핑을 대조했다. 생성한 합성 파일은 제거했다.

작업 범위는 로컬 파일과 기존 도구의 격리 검증이다. 이 보고서 한 파일을 추가했다.
