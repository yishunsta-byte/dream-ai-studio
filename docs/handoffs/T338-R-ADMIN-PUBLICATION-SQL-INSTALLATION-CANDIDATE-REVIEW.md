# T338-R 게시 SQL 설치 후보 독립 검수

2026-11-19 KST · Codex(Tester) · 고정 커밋 `7cbd9da` · Master 배정 `msg_e4e9d4874e34`

**판정은 통과.** 소유 루프백 PG17.12/TLS에서 설치 전용 모드의 버전·이력, 권한 분리, 재실행·동시 처리, 중간 실패 롤백과 설치 후 게시·철회를 독립 실행했다.

- 설치 버전은 1이다. 설치기와 같은 줄바꿈 정규화 후 SQL의 SHA-256은 `0d675b8f5f2b523da02a004fbe410d640ff6fb468ed7fb092e79904ad0a2b26f`로 일치했다. 잘못된 클러스터 식별자, 사용 중인 세션, 설치 이력 없이 역할만 있는 상태를 거절했다. 기존 트랜잭션을 가진 세션은 그 상태를 유지했다.
- 설치 도중 DDL 이벤트가 실패하면 스키마·역할·설치 이력이 남지 않았다. 서로 다른 TLS 세션 두 개에서 동시에 설치했을 때 한 번만 적용됐다. 읽기 검증과 이후 재실행에서 최초 설치 시각과 소스·카탈로그 해시가 보존됐다. 목록·표지 함수 간 교차 권한, 테이블의 공개 ACL, 변경된 이력 소스 해시를 거절했다. 쓰기 COMMIT 응답 유실 시 `unknown`으로 처리하는 분기는 소스에서 확인했다.
- 기본 설치 직후 승인자와 로그인 바인딩은 비어 있었다. 별도 권한 역할은 승인자·바인딩 등록에 성공했으며 공개 목록 함수는 실행할 수 없었다. 앱 관리자도 바인딩 테이블과 구형 쓰기 함수에 직접 접근할 수 없었다. 다른 로그인에서 운영자 UUID를 사용하거나 같은 이름으로 재발급된 로그인에서 예전 OID 바인딩을 사용하면 운영자로 인식되지 않았다.
- 설치된 스키마에서 T332 어댑터로 게시 준비·완료·동일 완료 요청 재전송을 수행했다. 공개 목록과 표지 바이트를 확인했고 철회 뒤에는 목록에서 제거되고 표지는 404였다. 무인자 기존 실행기에서도 T328 TLS 22건과 T330·T332·T336이 통과했다.
- 두 PG 실행에서 수신기와 임시 클러스터 정리를 확인했다. 설치 후 검증 DB 세션 0건, 소유 PG 프로세스 0건을 확인했고 검수용 고정 소스 사본과 복사 도구를 정리했다.
- 관리자·공개·Storage·인증·홈·레거시 게이트 회귀는 27개 파일 696건이 모두 통과했다. 소스 타입 검사, 변경 TypeScript 3개 ESLint 및 커밋 diff 공백 검사도 통과했다.

이번 판정은 별도 게시 설치 후보를 빈 소유 클러스터의 bootstrap 세션으로 실행한 결과다. 기존 PostgreSQL `0001`~`0005`, v2/v3 마이그레이션 경로와 기본 런타임 구성은 커밋 변경 경로에 없다. 기존 스키마 적용 대상에 후보 설치를 병행하는 검증, 관리형 제한 설치 역할의 DDL·소유권 이전, 복원 후 카탈로그 재검증 및 COMMIT 응답 유실의 실제 재현은 범위 밖이다. 운영·스테이징·빌드·배포 변경은 없었다.
