## 3. 앱 안 이동 때 초안 버림 (지금 정책) — 평가

| | 내용 |
|---|---|
| 직접 본 것 | 문구를 고친 상태("저장하지 않은 변경")에서 편집 화면 안 링크 "이전 편집용 묶음 보기 →"를 누름 → **확인 없이** 내보내기 화면으로 이동 → 돌아오면 저장본(r3), 변경 표시 없음, 고친 문구 없음 |
| 정책 | 떠날 때 확인은 새로고침·창 닫기(`beforeunload`)만(T-079 3.6·T-080 8장). 앱 안 이동(링크·단계 탭·옆 메뉴)은 확인하지 않고 초안을 버림. T-094 보고 4장도 같은 내용을 "기존 동작·범위 밖"으로 적음 |
| 자동 저장처럼 오해하게 하는가 | **아니다.** 화면에 "자동" 저장을 말하는 문구가 없고(첫 Callout은 "저장하면 새 타임라인 버전…"), 머리 글은 늘 "저장됨 · r{n}" + 따로 "저장하지 않은 변경". 저장 중 고침 안내도 "아직 저장하지 않았어요"라고 분명히 말함. 돌아왔을 때도 저장본만 보이고 "이어서" 같은 말이 없음 |
| 위험 | 저장 중 고침까지 지켜 주게 되면서, 사용자가 "이 화면은 고친 것을 알아서 지켜 준다"고 **기대할 수는 있다.** 그런데 링크 하나로 조용히 사라짐 |
| 판정 | **C**(지금 정책 안, 문구가 거짓을 말하지 않음) |
| C-1 제안 | ① "저장하지 않은 변경" Badge 옆이나 아래에 한 줄 "다른 화면으로 가면 저장하지 않은 변경은 사라져요."(변경이 있을 때만). ② 후속: 편집 화면 안 링크(이전 편집용 묶음 보기·수정 확인 완료)에 변경이 있을 때 ConfirmPanel "저장하지 않은 변경이 있어요. 그래도 이동할까요?" — 단계 탭·옆 메뉴까지 막는 것은 앱 전체 이동 규칙이라 Master 판단 |
